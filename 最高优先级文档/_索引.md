### 3.1 单位与粒度（`02`）

| 结论 | 指针 |
|---|---|
| **三层单位**：**小格子**（1/16 地块）＝最高精度 ｜ **坑位**（1/4 地块）＝资源点占位 ｜ **地块**（1）＝显示单位 | `02` §二 |
| **逻辑最小单位＝小格子**；寻路／可走／占格／落位／采集寻址全走它 | `02` §三 |
| **建筑尺寸**：对外说地块（1×1／2×2／3×3），**内部 ×16 小格子**；换算**全库只准一处** | `02` §四 |
| ⭐ **`R1` 正解＝采集寻址到坑位**（`A`/`B`/`C`/`D` 四案作废） | `02` §五 |

### 3.2 地图与存在（`03` §一~§五）

| 结论 | 指针 |
|---|---|
| **判据**：「位置」是不是这个东西的身份 ⇒ 是则进地图 | `03` §一 |
| **地图 ＝ 格表**（一行一小格子）**＋ 建筑表**（一行一建筑）；格表存 id 指向建筑表；**两向 O(1)** | `03` §二 |
| **接入协议＝宽箱子**：所有类型共用一组栏，**各链只取自己那几栏**；加东西＝填箱、加链＝声明取栏 | `03` §三 |
| ⭐ **启动全表自检** ＋ **死字段自动报警**（有栏无链 ⇒ 报警）＝ `L-01` 自动探测器 | `03` §三 |
| **ID 制度**：**类型 ID＝命名式**（禁数字号段）／**实例 ID＝不动用坐标、动分配号**／地表不给 id | `03` §四 |
| **锚点机制**：锚点＝**对象身上的一个字段**（`anchorProvide`／`anchorRequire`，**前缀匹配**）；一个锚点可被任意多方引用 | `03` §五 |
| **锚点生命周期**：建造 ⇒ **消费**（锚点消亡）；**删除 ⇒ 返还**（不只矿山） | `03` §五・§7.8 |
| ⚠️ **分层**（`D752`）：**本层＝存在**（位置/占格/登记/锚点）／**高级层＝实体·功能·引用·AI·结算** | `03` §6.2 |

### 3.3 「增」（`03` §六）

| 结论 | 指针 |
|---|---|
| **边界**：造世界（0→1）**不算增**；铺东西（1→N）算增；两者**共用「落点器」** | `03` §6.1 |
| **对象**：资源点（完整生命周期）／建筑（存在＋占格＋锚点返还）／单位（**只借"存在标记"**） | `03` §6.2 |
| **时机 3 种**：铺 · 重生 · 放置 | `03` §6.3 |
| **入口**：`Place(什么, 在哪)`；**门内七步须完整**，中途不许断 | `03` §6.4 |
| **底层校验 3 条**：不重叠 · 底面允许 · 在界内 | `03` §6.5 |
| **特有规则 3 条**：生成 · 重生 · 放置（建筑/单位共用，**允许面可配不写死**） | `03` §6.6 |
| ⛔ **建造"顺手抹树"禁止** ⇒ **先采才能建** | `03` 差异清单 #3 |

### 3.4 「删」（`03` §七）

| 结论 | 指针 |
|---|---|
| ⭐ **删不是增的镜像，是逆序**（栈式：**谁后加的先拆**） | `03` §7.1 |
| 本层删的**不是"那个东西"，是"本层赋予它的那几样"**（位置/占格/登记/锚点/重生资格） | `03` §7.2 |
| **入口**：`Remove(什么, 在哪/哪个 id)` —— **唯一、不区分死因**；七步：存在性 → 锚点返还 → 清表 → 释放占格 → 注销 → 出重生池 → 广播 | `03` §7.3 |
| **校验对偶**：增＝位置**空闲**；删＝**它确实在**（不通过 ⇒ **幂等跳过**） | `03` §7.4 |
| **本层不判"能不能删"**（业务归高级层／数据栏） | `03` §7.5 |
| **高级层自订广播**收尾（回池/摘编队/清任务/结算/死因统计/拆除产物） | `03` §7.6 |
| **特例落法**：**加栏**（静态）＋**钩子**（动态），**主干不绕开** | `03` §7.7 |

### 3.5 「查」（`03` §八）

| 结论 | 指针 |
|---|---|
| ⭐ **造基础件，不按需求接接口** —— 下层**不因"某系统要 XXX"而加方法** | `03` §8.1 |
| **条件只用下层知道的事实**；"敌人／威胁"由**上层翻译**成事实组合 | `03` §8.1 |

| **事实菜单**：地表／气候／可走／建筑／单位／资源点／归属／坑位／界内 ＋ ⭐**邻接 · 距离 · 计数**（后三类是**派生量，不入格表**） | `03` §8.3 |

### 3.6 「改」（`03` §九）

| 结论 | 指针 |
|---|---|
| 本层「改」**只有两条腿**：**存在替换**（封装的先删后增）／**字段变更**（直接覆写） | `03` §9.1 |
| ⚠️ **单值字段只有两个**：**归属**（领土）／**地表**（挖山填河） | `03` §9.2 |
| ❌ **可走不是「改」的对象** —— 它是**派生缓存**（地表＋占格＋桥）；**禁开"改可走"入口** | `03` §9.2 |
| ⭐ **存在替换必须"对外表现为一次替换"**：广播**一条 `Replaced`**（不是 `Removed`＋`Added`） | `03` §9.3 |
| ⭐ **升级不进本层**（位置／占格／归属都不变 ⇒ **本层零操作**）—— 归**对象自己** | `03` §9.4 |
| ⭐ **"改"少，契约就稳** ⇒ 增／删两条链覆盖其余全部 | `03` §9.5 |

### 3.7 资源池与重生参数（`03` §6.7）

| 项 | 定论 |
|---|---|
| **池子上限** | **64 / 大区块**（上限，非必须填满） |
| **上限按温度带缩放** | 64 × 丰度 ⇒ **热 58 ／ 亚热 83 ／ 温 70 ／ 寒 45** |
| **单类上限** | ＝ 总上限 × 该类占比 × 松弛系数 |
| **开局** | **不铺满**（⏳ 初始铺量待定） |
| **重生条件** | ① 总数 < 总上限 ② 该类 < 单类上限 |
| **节奏曲线** | **线性平方** `间隔 ＝ base × (1+3x)²`，`x ＝ 现有 ÷ 上限` |
| **填满目标** | ≈ **7 天**（游戏天）；base ≈ **0.02 天** |
| **时间基准** | ⭐ **游戏天**（直问 `TimeManager.CurrentDay`）⇒ **删 `RespawnConfig.daySeconds` 与 `_elapsed`** |
| **调度粒度** | **区块统一调度**（到点按权重抽一类补） |
| **落点** | 落点器**随机落新位置**（不原地复活）；户口＝**锚点归属法**；兜底原位 |
| **实感参考** | 区块级：起始约**每天 8 个**，接近满约**每天 3 个** |
| ❌ **旧数值作废** | `树7/木4/石10/矿12 天` |
