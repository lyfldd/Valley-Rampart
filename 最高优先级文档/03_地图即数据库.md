## 〇、一句话

**地图不是"一堆对象"，是"一张表"**：每一格一行，每个东西按位置登记；**所有读写都走一个门**。

## 一、判据：什么该由地图承载

> **「位置」是不是这个东西的身份？** 是 → 地图承载；不是 → 地图不管。

| 数据 | 进地图 | 挂哪一级 |
|---|---|---|
| **气候**（温度带） | ✅ | **地块级**（小格子继承） |
| **地表**（草/林/山/水） | ✅ | 小格子级 |
| **资源点** | ✅ | **坑位级**（2×2 小格子） |
| **建筑占格** | ✅ | 小格子级 |
| **单位存在** | ✅ | 小格子级 |
| **可走** | ✅ **存下来**（14 处高频读，不能现算） | 小格子级 |
| **领土归属** | ✅ | **地块级** |
| 建筑属性（HP/等级/生产/工人） | ❌ | 实体自己装 |
| 单位属性（HP/AI/背包） | ❌ | 实体自己装 |
| 国库／时间／季节 | ❌ | 全局，无位置 |
| 热度・LOD | ❌ | 中区块级（聚合统计，非格数据） |

**删**：`TerrainType` 整层（11 项）／ `PlainSubState`（零读者）。

## 二、地图的两张表

```
格表（一行 = 一个小格子）
  ├ 气候 ｜ 地表 ｜ 资源点 ｜ 建筑 id ｜ 单位 id ｜ 可走 ｜ 归属

建筑表（一行 = 一座建筑）
  └ id ｜ 类型 ｜ 左上角 ｜ 宽×高 ｜ HP ｜ 等级 ｜ 生产…
```

- 格表存 **id**，指向建筑表 ⇒ **存在在地图，属性在自己**
- **跨格建筑**：它覆盖到的**每个小格子都写同一个 id** ⇒ 查任何一格都是 O(1)
- **删建筑**：读建筑表的"左上＋宽高"，一次算出范围 ⇒ **两向都是 O(1)，不扫全图**

## 三、接入协议：一个宽箱子

**任何要接入"增删"链的东西，都提供同一个箱子**；链**只取自己那几栏**，用不到的不管。

```
箱子（每个类型一个）
  类型ID ｜ 显示名 ｜ 占几格 ｜ 可重生 ｜ 重生权重 ｜ 单类上限
  提供锚点 ｜ 需要锚点 ｜ 允许底面 ｜ 允许面 ｜ 登记到 ｜ …
```

| 链 | 只取这几栏 | 不看 |
|---|---|---|
| 生成链 | 重生权重／单类上限／允许底面 | 锚点、登记 |
| 重生链 | 可重生／重生权重 | 占几格 |
| 锚点链 | 提供锚点／需要锚点 | 权重 |
| 放置链 | 占几格／允许底面／允许面 | 重生 |
| 登记链 | 登记到 | 其余全部 |

**三条性质**：
1. **加新东西 ＝ 造一个新箱子填栏** ⇒ **链一个字不改**
2. **加新链 ＝ 声明它取哪几栏** ⇒ **箱子不改**（没值当空）
3. **链不读"这是什么类型"，只读字段** ⇒ 不存在"忘了接某一类"

**代价**：宽箱子有空栏（配置数据量小，可接受）。

**防呆**：启动时**全表自检** —— 必填栏非空／类型 ID 不重复／`需要锚点`的前缀有对应提供方／引用的底面存在。有错**直接报**，不静默。

**副产品**：自检还能比对「**箱子里的栏**」vs「**有链来取的栏**」 ⇒ **没人取的栏 = 死字段，自动报警**（`L-01` 的自动探测器）。

## 四、ID 制度

| | 形式 | 说明 |
|---|---|---|
| **类型 ID**（这是什么） | **命名式** `building_mine` / `resource_tree` / `unit_worker` | 加类型＝加名字，**永不动老编号**；细分用 `_` 交替（`building_mine_lv2_attach_a`） |
| **实例 ID**（这是哪个） | **不动 ⇒ 坐标即 id**；**会动 ⇒ 分配号** | 建筑/资源点用坐标（免费、唯一、不冲突）；单位用号 |
| **地表** | ❌ 不给 id | 没人会引用"第 3 号平原" |

⇒ **"给一切东西贴 id"要打折**：给**会被引用的**贴。统一的是"有唯一标识"这件事，**不是标识的形式**。

**不做数字号段**（1~100 建筑类那种）：段会满、要迁移、引用会断——这正是要避免的。

## 五、锚点机制（附着关系）

```
提供方字段：anchorProvide = "resource_mine"
需求方字段：anchorRequire = "resource_"        ← 前缀匹配，大类/小类都行
```

- **锚点不是独立对象，是"某个东西身上的一个字段"**
- **一个锚点可被任意多个东西引用**（引用存在需求方，锚点自己不记录清单）
- **生命周期①（建造时）**：**① 锚点消亡（走删）② 新东西诞生（走增，类型 ID ＝ 新命名）**——**锚点被"消费"掉**
- ⭐ **生命周期②（删除时·对偶）**：**任何"通过消费某个锚点"建起来的建筑，被删除时返还那个锚点**（**不只矿山**）
  ⇒ 建筑需记住"我消费了哪个锚点（类型 ＋ 位置）"——这属"属性自己装"
- 用途不限于矿洞：**"在已有建筑上加装"** 走同一条

## 六、「增」完整规格

### 6.1 边界

| | 算不算「增」 | 理由 |
|---|---|---|
| 造地形／气候／山脉 | ❌ | **0→1，建立**合法性 |
| 铺资源点／预置建筑 | ✅ | **1→N，遵守**合法性 |
| 地形变化（挖山/填河） | ⏳ 将来 | 现在没有 |

**判据**：规则是用来**建立**合法性的（造世界），还是用来**遵守**合法性的（增）？

⇒ **造世界规则（连通/地块大小/山脉）不污染增的规则表**；两者**共用一个零件：落点器 ＝ 合法性检查 ＋ 按权重抽样**。

## 七、「删」完整规格（**本层**）

### 7.1 与「增」的关系：**不是镜像，是逆序**

```
增（自下而上）                       删（自上而下）
1 本层：占位                          1 高级层：释放功能 / 实体
2 本层：写表                          2 本层：清表
3 本层：广播 Added                    3 本层：释放占位
4 高级层：建实体 / 赋功能              4 本层：广播 Removed ⇒ 高级层收尾
```

⇒ **栈式：谁后加的、谁先拆。** 删**不能**照增的顺序走。

### 7.2 ⭐ 本层"删"删的不是"那个东西"

> 用户原话：**"删除的是本层赋予的东西。"**

| 本层赋予它的 | **增** | **删** |
|---|---|---|
| **位置**（格表标记） | 写 | 抹 |
| **占格**（footprint） | 标 | 释放 |
| **登记**（本层索引） | 登记 | 注销 |
| **锚点** | 消费 | **返还** |
| **重生资格** | 进池 | 出池 ／ 记入重生队列 |
| （广播） | `Added` | `Removed` |

⇒ 本层**不关心删的是什么**（NPC 还是矿洞），只负责**把当初给出去的收回来**。

### 7.3 入口与步骤

```
Remove(什么, 在哪 / 哪个 id)        ← 唯一入口，不区分死因
  1 存在性校验（不存在 ⇒ 直接返回，幂等）
  2 锚点返还（当初消费掉的锚点还回来）
  3 清表（格表 / 建筑表）
  4 释放占格
  5 注销（本层索引）
  6 出重生池 / 记入重生队列        ← 仅"可重生"者（即资源点）
  7 广播 Removed ⇒ 高级层收尾
```

⭐ **第 6 步只服务资源点** —— **只有资源点的完整生命周期在本层**（生／死／重生）。本层**不越界干涉其他层级**。

### 7.4 校验（与增对偶）

| | **增** | **删** |
|---|---|---|
| 校验什么 | 位置**空闲**（不重叠・底面允许・在界内） | ⭐ **它确实在**（存在性） |
| 不通过时 | 拒绝 | **跳过（幂等）** —— 删两次等于删一次 |

### 7.5 本层**不判**"能不能删"

- `BuildingPanel.cs:169` 的 `isPlayerBuilt && isDestructible && !isResourceNode` 是**业务规则** ⇒ 归**高级层／数据栏**，本层不管
- 本层只有一个 `Remove`；**"为什么删"是调用者的语义**（拆／打烂／采走，本层一视同仁）

### 7.6 高级层要接的事（**自己订广播，本层不管**）

回对象池 · 摘编队 · 清任务 · 清仓库登记 · 解除 AI 引用 · 掉落与结算 · 死因统计 · **拆除产物（返不返材料）**

### 7.7 特例的落法（**不破坏主干**）

| 方式 | 怎么做 | 适合 |
|---|---|---|
| **加栏** | 主干读的那几栏，特例多填（`拆除后返还什么`／`可否被拆`／`拆除产物`） | **静态差异** |
| **钩子** | 主干广播 Removed，**各系统自己订** | **动态联动** |

⇒ **主干永远只跑那 7 步；特例挂在主干上，不绕开主干。**

### 7.8 锚点返还（**通用，非特例**）

> 用户原话：**"不只是矿山，应该说是锚点这个东西……拆除了带有锚点的建筑，返还的应该是锚点。"**

⇒ 规则：**建筑只要 "通过消费某个锚点" 建起来 ⇒ 被删时返还那个锚点**（类型 ＋ 原位置）。
⇒ 与 §五「消费」构成**完整对偶**。

## 八、「查」完整规格（**本层对外读接口**）

### 8.1 三条原则

| # | 原则 |
|---|---|
| 1 | ⭐ **造基础件，不按需求接接口** —— 下层**不因"某系统要 XXX"而加方法** |
| 2 | **条件只用下层知道的事实** —— "敌人／威胁／值钱"这类**上层概念由上层翻译**成事实组合 |
| 3 | **不返回可写引用** —— 单格返回值（复合结构）、区域用 buffer |

> ⭐ **这是一个解耦的工具箱**（用户 `D754`）：设计上支持**随时增补缺失的底层工具**，增补**不破坏已有用法**。

### 8.2 五个基础件

| # | 件 | 形态 |
|---|---|---|
| ① | **格子属性**（地表／气候／可走／归属／坑位） | 按格取 · 返回**复合结构** |
| ② | **格子上的存在**（建筑／单位／资源点） | 按格取 · 返回**复合结构** |
| ③ | ⭐ **区域枚举** | 范围 ＋ 条件 ＋ 数量；输出 buffer（**禁分配**） |
| ④ | **换算**（世界 ↔ 格 ↔ 小格子） | 纯函数 |
| ⑤ | **变更订阅** | 事件（＝`Added`／`Removed` 广播 ＋ 状态变化） |

### 8.3 ⭐ 条件 ＝ 选择器（"选择哪些返回"）

```
查询 ＝ { 范围 ＋ 条件 }
条件 ＝ { 勾选事实 ｜ 限定参数 ｜ 数量（全部／一个／N） }
```

**条件能勾的「事实全集」＝ 下层能看见的一切**（这就是"菜单"）：

| 类 | 事实 | 限定参数 |
|---|---|---|
| **地表** | 平地／树／山／雪山／河／海／海岸／矿 | 具体类型 |
| **气候** | 温度带 | 热／亚热／温／寒 |
| **可走** | 能／不能 | — |
| **建筑** | 有／无 | 类型 · 阵营 · 归属 |
| **单位** | 有／无 | **阵营** · 分类 |
| **资源点** | 有／无 | **类型** · **等级** · 可否重生 |
| **归属** | 属于谁 | 王国 id（无主 ＝ -1） |
| **坑位** | 还剩几个空坑 | 数值比较 |
| **界内** | 是／否 | — |
| ⭐ **邻接** | 周围有没有 X（水／建筑／路…） | 目标事实 |
| ⭐ **距离** | 离某点多远 ／ **最近的是谁** | 参照点 |
| ⭐ **计数** | 这片里有几个 X（**只要数、不要列表**） | 目标事实 |

⚠️ **最后三类是"算出来的"（派生量），不是存下来的** —— 实现时**不许把它们塞进格表**。

### 8.4 范围形状

**矩形**（窗口／扫描片）＋ **半径**（视野／爆炸）两种。

### 8.5 两个数据组

| 口 | 返回 | 适用 |
|---|---|---|
| **按格** | 一串**格子信息**（位置 ＋ 地表 ＋ 可走 ＋ 归属 ＋ 有没有东西） | 扫地形 · 找可建点 |
| **按实体** | 一串**实体引用**（单位／建筑） | 窗口内敌人 · 范围伤害 |

### 8.6 玩家侧：`PickAt`

**屏幕矩形 ＋ y 序** ⇒ **"看到的"与"点到的"必须同源**（渲染怎么排 y，拾取就怎么排）。
⛔ **不走物理引擎**（`Collider2D` 铺满会崩：极限 147,456 座）。

⭐ **已落地（`HH.305`·`D776`·`MapGate.PickAt`）**：
- 实现落在**门内**（`MapGate.PickAt`／`PickWorld`／`FillUnitsInWorldRect`），上层只调门；内部换算全走 `GridSystem` 口。
- **排序键两段**：① 层带 `sortingOrder` 大者在前 ② 同层带按**深度键**。深度键**已有**（`MapRenderService.IsoDepth`），**按各自实际排序点**取：`spriteSortPoint = Pivot`（单位）⇒ `transform.position.y`；未设者（建筑/宝箱·默认 `Center`）⇒ `SpriteRenderer.bounds.center.y`。
- ⭐ **符号（谁在前）＝「世界 y 越小越靠前」**（`MapGate.DepthMajorYInFront = false`）—— 由 **G0 构造用例真实渲染像素实测**得出（`ProjectSettings/GraphicsSettings.asset:42-43` ＝ `TransparencySortMode: CustomAxis` ＋ 轴 `(0,1,0)`）；**与直觉相反**。
- **候选有界**：建筑 `PickCellRadius=1`（3×3 格 `BuildingRegistry.GetAt`）／单位 `GridSystem.FillUnitsInRect`（单位索引）／宝箱 `ChestManager.FillChestsInCellRect`；**稳态零 GC**。
- ⚠️ **已知边界（`R1`·待修）**：窗口半径 1 格（3.84×1.92 世界单位）**小于建筑 sprite 溢出**（实测折算 `castle` 3.1×6.8 格）⇒ 点其可见上半部**落不进候选集**（"看到的点不到"）。**非回归**（改前 `Collider2D` 仅 `size=1×1`，可点区更小）；修法＝按实际 sprite 半高推窗口半径。

### 8.7 判据（链路闭合句）

1. **无裸读**：全库 grep ⇒ 除本层自身，**无任何代码直接读**格表／建筑表底层数组
2. ⭐ **不涨接口**：任取一条**上层新需求** ⇒ **能用现有五件拼出来**（若必须新开方法 ⇒ 说明件不够，补"件"而不是补"需求接口"）
3. **条件无上层词**：所有查询条件**只用事实表里的事实**，不得出现"敌人／威胁／价值"
4. **零分配**：区域查询在**稳态下不产生 GC 分配**（buffer 复用）
5. **只读**：上层**拿不到可写引用**
6. **拾取同源**：点一屏里最靠前的建筑 ⇒ 命中的是**渲染上最靠前的那个**（与 y 序一致）
   - ⭐ **证据要求（`D776` 立）**：本条的验证**必须含"来自被测实现之外"的观测**（真实渲染像素读数／引擎 API／独立算法）。⛔ **禁以"同源重算"自证** —— 用**同一个常量／同一个键函数**算出来的对照列，只能证"实现与常量一致"，**符号若相反它照样通过**（片 6-1 判据 2 即此形态 ⇒ 自证无效）。凡"对照类"判据须指明**哪一列来自外部观测**。
7. ⭐ **代价已记档·禁每帧调用**（`D772` 立）：区域查询（`QueryCells`／`QueryCellsRadius`／`TryGetCell`）的**成本特征必须写在接口旁**；⛔ **禁在 `Update`／每帧路径调用**；若将来出现真实调用需求 ⇒ **先治本再启用**。

> ⭐ **像素隐藏法证据规范（`D780` 立·片 6-2 收尾批实证）**：以真实像素作**外部观测列**时，判据须齐四条 ——
> ① **身份可区分**：两对象须**改名或按实例比对**（⛔ 禁按 `name` 比同类同精灵 —— 同名时 A/B 互换**照样判 ✅**）；
> ② **四点采样**：`both`／`hideA`／`hideB`／**`hideBoth`**；判据＝「`chA ∧ hideA≠hideBoth` ⇒ A 遮挡 B」——
>    `hideBoth` 即**背景对照**，无它则「X 遮挡 Y」与「Y 在该像素无贡献」**签名相同**（不可区分）；
> ③ **有效点 ≥3 且同类须异 sprite**：两 sprite **同图同色**时 `hideA==hideB==both` ⇒ **有效点恒 0** ⇒ 同类用例**必须取不同 sprite**；
> ④ ⭐ **鉴别力自证（必做·2 次跑）**：临时取反 `MapGate.DepthMajorYInFront` ⇒ 本判据**必须变 ❌**；复原后**必须复现 ✅**

## 九、「改」完整规格（**本层**）

### 9.1 本层的「改」只有两条腿

| 改什么 | 做法 | 为什么 |
|---|---|---|
| **存在替换**（这格 A → B） | ⭐ **封装的「先删后增」** | "存在"是**引用**，不能就地改 |
| **字段变更**（归属／地表） | **直接覆写一个值** | 它就是一个值，**不需要删增** |

> 用户判断（`D755`）：「**改更像先删后增**」—— 成立，**但仅对"存在替换"这一支**。

### 9.2 ⚠️ 单值字段清单（**只有两个**）

| # | 字段 | 场景 | 现状 |
|---|---|---|---|
| 1 | **归属** | 领土扩张／易主 | `TerritorySystem.Claim*`（**形态基本对**） |
| 2 | **地表** | 挖山／填河／采完翻平地 | 现在靠**裸写 `features[]`**（要收进「改」门） |

❌ **不是「改」的对象**：**可走** —— 它是**派生缓存**（由 **地表 ＋ 占格 ＋ 桥** 算出）。
⇒ 改它的**来源**，它**自己重算**。**禁开"改可走"入口**（否则又回到"同一件事两个源"）。

### 9.3 ⭐ 存在替换必须"对外表现为一次替换"

```
Replace(旧, 新)
  1 位置与占格：复用（都不变）
  2 清旧的存在标记 → 写新的
  3 注销旧 / 登记新（本层索引）
  4 广播【一条】：Replaced      ← 不是 Removed + Added 两条
```

**为什么必须一条**：
- 否则**中间态**会被别处读到（"这里什么都没有"）
- 否则**统计会记成"拆一座 ＋ 建一座"**，任务／编队／仓库被无谓打断
- 让高级层**自己决定**：**换皮（保留实体、只换数据）** 还是 **重建**

### 9.4 ⭐ 升级**不进本层**

升级时：**位置没变、占格没变、归属没变** —— 变的只是**属性（等级／HP／产出）** ⇒ **属性归对象自己** ⇒ **本层零操作**。

⇒ 用户判断「升级更好的安排是设计成**对象本身的东西**」**成立**。
⇒ 若把升级做成"删＋增"：**丢状态 ＋ 两条广播 ＋ 打断周边系统**，成本高得多。

### 9.5 「改」为什么这么少 —— 这是**收益**

| 传统「改」 | 我们的处理 |
|---|---|
| 改属性（HP／等级／进度） | ⇒ **对象自己的事**，本层不碰 |
| 改类型（升级／换皮） | ⇒ **对象自己换**（本层零操作，或走 §9.3 替换） |
| 改位置 | ⇒ 不动的用坐标（**改位置 ＝ 删＋增**）；**会动的（单位）归高级层** |
| 改归属 ／ 改地表 | ⇒ ⭐ **本层仅剩的两个字段** |

⇒ ⭐ **"改"少，契约就稳**："改"是最容易膨胀的操作（什么都想改一点）；只剩两个字段 ⇒ **增／删两条链覆盖其余全部**。

### 9.6 判据（链路闭合句）

1. **无「改可走」**：全库 grep ⇒ 除派生重算外，**无任何地方直接写可走**
2. **替换是一次**：做一次替换 ⇒ 高级层**只收到一条** `Replaced`（不是两条）
3. **无中间态**：替换过程中任一观察点读到 ⇒ **要么旧、要么新**，读不到"空"
4. **升级不动本层**：升一级 ⇒ 本层数据（位置／占格／归属）**逐字段不变**
5. **字段变更唯一入口**：归属／地表的写入**只走「改」门**

## 十、判据（**链路闭合句**，禁用落点句）

1. **不走裸写**：全库 grep ⇒ 除门自身，**无任何代码直接写**格表/建筑表
2. **七步完整**：任取一次"增"，能观察到 校验→锚点→写表→占格→登记→实体→重生池 全链落地
3. **开局不满**：生成一张图 ⇒ 实测每区块资源点**显著低于上限 64**
4. **能填满**：连续推进 **7 游戏天** ⇒ 每区块数量**接近上限**；再推进不超上限
5. **不原地复活**：采掉 X ⇒ 等它回来时，位置**与 X 不同**（允许兜底原位）
6. **上限守得住**：任取区块 ⇒ 总数 ≤ 上限、单类 ≤ 单类上限
7. **日历唯一**：重生读的是 `TimeManager.CurrentDay`；**全库不再存在第二个日历**
8. **锚点可查**：建矿洞 ⇒ 原矿山锚点消亡、新建筑诞生；且**一个锚点可被多个东西引用**
9. **无死字段**：启动自检 ⇒ **没有任何"有栏无链"的字段**（或全部被显式标为保留）
10. **同 seed 一致**：同 seed 两次生成**逐格一致**
