## 一、定位与目标【定案】

**像素工坊**＝一个服务于本项目美术资产生产的**本地工具链**：网页像素编辑器 ＋ agent，让 AI 以**"文本网格"**为媒介对像素图做**像素级精确修改**。

**核心洞察**：项目单位图为 32×32、13~16 色小调色板（实测 `Assets/_Game/Art/Units/` 13 张），整图转文本仅 1~2k token —— AI 能在单次上下文里"看全"并精确编辑每个像素。这是文生图模型做不到的（重画整张、风格漂移、无法保证未改区域 bit 级不变）。

**服务对象**：

- 单位图：`Assets/_Game/Art/Units/`（13 张，32×32，≤16 色）
- 地块图：`Assets/_Game/Art/Ground/`（8 张，4000~6000 色，软边缘手绘风）—— 走降级管线（§三.3）

**四个核心场景**：① 打磨现有图（描边/轮廓/细节/风格统一）② 阵营变体工厂（四王国换色变体批产）③ 从零生成（建筑/UI/物件初稿）④ 分析质检（风格一致性）。

**四项用户决策（2026-09-01）**：

| 决策点 | 结论 |
|---|---|
| 资产安全 | 暂存区 ＋ 发布：AI **只碰 `workspace/`**，人工点"发布"才拷入 Assets |
| 编辑能力 | AI ＋ 人工手绘都要 |
| 技术栈 | 单文件 HTML 编辑器 ＋ pwsh 启动脚本，**零构建零依赖** |
| 工具范围 | 像素图 ＋ 地块图都管（地块走量化降色 ＋ 分块降级） |

## 二、核心设计（架构）【定案 · P0 已落地】

### 2.1 组件总览

```text
pixel-forge/                          ← 工具根目录（仓库根级，git 跟踪）
├── index.html                        ← 单文件编辑器（零构建零依赖）
├── start.ps1                         ← pwsh7 启动脚本（-Init 导入/起服务/开浏览器）
├── server/                           ← node 侧代码（零依赖）
│   ├── gridtext.mjs                  ← 网格协议（浏览器/node 共用，纯 ESM）
│   ├── pngcodec.mjs                  ← PNG 编解码（纯 node zlib 手写）
│   ├── forge.mjs                     ← workspace 业务（台账/导入/成对保存/发布）
│   ├── occlient.mjs                  ← agent 适配（session+message+schema）
│   ├── serve.mjs                     ← HTTP 入口（静态白名单+API+AI 代理）
│   ├── init.mjs                      ← 首次初始化导入
│   ├── png2grid.mjs / grid2png.mjs   ← CLI（agent 批量回路工具面）
│   └── test-roundtrip / test-publish / test-ai-e2e.mjs ← 门禁测试
└── workspace/                        ← 暂存区（AI 唯一可写范围）
    ├── AGENTS.md  config.json  manifest.json
    ├── units/  ground/  misc/  variants/
```

### 2.2 运行时架构

```text
浏览器编辑器 (index.html, 127.0.0.1:5173)
   │ 同源 /api/*（serve.mjs）
   ↓
serve.mjs（静态白名单 + workspace API + AI 代理）
   │ 服务端 fetch（零 CORS）
   ↓
agent serve (127.0.0.1:4096)
   │ 工具执行（批量回路，P1）
   ↓
workspace/ 暂存区  ──发布（人工确认，仅拷 PNG，保 .meta）──→  Assets/_Game/Art
```

- **AI 永远碰不到 Assets**：`serve.mjs` 仅 `/api/publish` 白名单写入。

### 2.3 两条工作回路

**单图回路（编辑器内 AI 面板，日常打磨）**：载入 `.grid.txt` → 用户输自然语言指令 → 编辑器把**当前网格全文内联**进 prompt ＋ `json_schema` 约束 → POST 到 agent → 返回新网格（schema 校验失败自动重试，默认 2 次）→ diff 预览（改前/改后/差异三视图）→ 接受写回 ／ 拒绝丢弃。**AI 在此回路中不接触任何文件**（网格全程内联）。

**批量回路（agent 自主，成批任务）**：用户在"任务"框输批量指令 → agent 在 workspace 按 `AGENTS.md` 协议干活（读 `.grid.txt` → 改 → 回写 → 跑 `grid2png`）→ 编辑器轮询 `/session/:id/diff` 展示文件级改动清单 → 不满意可 `/session/:id/revert` 整批回滚 → 全部确认后才进发布。

### 2.4 编辑器界面分区（单文件 HTML）

| 区 | 内容 |
|---|---|
| 顶栏 | 文件列表刷新／保存／撤销·重做／改名（别名）／健康状态 |
| 左栏 | 手绘工具：铅笔/橡皮/吸色/油漆桶/直线/矩形 ＋ 网格线开关 ＋ 缩放（4x~32x） |
| 中央 | 像素画布（Canvas，格子吸附）＋ diff 高亮层 |
| 右栏上 | 调色板（点击选色，十六进制值，支持锁定语义色槽） |
| 右栏下 | AI 面板：单图指令／diff 三视图／接受·拒绝；批量任务框 ＋ 进度日志 |

### 2.5 Agent 接入配置【取证 · ⚠️ 见 §九】

- 启动：`agent serve --port 4096 --hostname 127.0.0.1`（`start.ps1` 探活失败时自动拉起；AI 调用经 `serve.mjs` 服务端代理，浏览器零 CORS）。
- 静态服务：`node server/serve.mjs --port 5173`（静态白名单 ＋ workspace API ＋ AI 代理，仅监听 127.0.0.1）。
- 会话：单图回路每次任务新建 session（源实测 v1.18.19，结果落 `info.structured`）；批量回路一个长期 session。
- 结构化输出：请求体带 `format: { type: "json_schema", schema: <网格协议 schema>, retryCount: 2 }`。
- **模型选择（2026-09-01 增补）**：编辑器 AI 面板带模型下拉（`GET /api/models`），默认＝当前模型；可选免费池 30 个模型（多模态标 👁／废弃标 ⚠旧）；选择存 localStorage；`message` 请求体透传 `model:{providerID,modelID}`。
  - **模型能力实测**：big-pickle 指令遵循外科级（恰改 1 像素）；nemotron-3.5-lightning-free 格式合法但过度修改（154 像素）—— 网格编辑是纯文本"摆字符"任务，任何强文本模型可用，指令精度差异靠 diff 预览人工把关；deprecated 模型可能已下线。
- 不设服务端密码（仅本机 127.0.0.1 监听）。

## 三、数据定义【定案】

### 3.1 网格文本协议 v1（`.grid.txt`）

```text
# forge v1 | name=<文件名> | size=32x32 | colors=15
# palette
. = transparent
0 = #2a1a3a
1 = #4a3a5a
...
# grid
...(32 行，每行恰好 32 字符)...
```

**硬性规则**：

- 字符集：`.`（透明）＋ `0-9` `a-z` `A-Z` `#` `$` `%` `&`（**66 个色字符**；调色板上限 ≤64，留 2 冗余）。
- 调色板色值：`#rrggbb`（不透明）或 `#rrggbbaa`（半透明）；全透明像素一律 `.`，其 RGB 归一化为 0。
- 调色板按**频率降序**分配字符（最高频用 `0`）。
- 网格行数＝图高，每行字符数＝图宽，**禁止行尾空白**。
- 解析时任何一行宽度不符或字符越界 → **整文件拒绝**（见 §六.1）。

### 3.2 结构化输出 schema（单图回路）

```json
{
  "type": "object",
  "required": ["palette", "grid"],
  "properties": {
    "palette": { "type": "array", "maxItems": 64,
      "items": { "type": "string", "pattern": "^#[0-9a-fA-F]{6}([0-9a-fA-F]{2})?$" } },
    "grid": { "type": "array", "minItems": 32, "maxItems": 32,
      "items": { "type": "string", "pattern": "^[.0-9a-zA-Z#$%&]{32}$" } }
  }
}
```

### 3.3 地块图降级管线（Ground 专属）【未决 · P2】

地块图 170×200 ≈ 34,000 像素、数千色，超出单次上下文编辑能力 ⇒ 三级降级：① **量化降色**（中位数切割 ≤48 色，预览确认）② **分块**（32×32 块，块间共享调色板）③ **降采样概览**（仅质检用）。

| 场景 | 单位图 | 地块图 |
|---|---|---|
| 打磨 | 全图网格编辑 | 分块编辑（一次 1~4 块） |
| 变体工厂 | 调色板重映射（纯代码） | 同左（可叠加原 alpha 通道） |
| 从零生成 | 直接生成 | **不支持全图生成**；改"生成小物件 → 合成叠加" |
| 分析质检 | 全图直读 | 降采样概览 ＋ 抽块深查 |

### 3.4 workspace 资产台账（`manifest.json`）

```json
{
  "units/<文件名>.png": { "alias": "剑士", "source": "Assets/_Game/Art/Units/<文件名>.png",
    "size": "32x32", "paletteCount": 14, "importedAt": "2026-09-01" }
}
```

- **文件名保持与 Assets 原名一致**（发布时零映射、Unity 引用不断）。
- `alias` 语义别名供 AI 指令引用，初始可空。

### 3.5 变体工厂数据（palette 变体表）

`workspace/variants/kingdoms.json`：每王国一套映射表（键=源色，值=目标色），**保持明度关系不变**（HSL 的 L 值偏差 ≤5%）。映射表由 AI 一次性设计；`remap.mjs` 纯代码遍历执行（13 图 × 4 王国 ＝ 52 张，秒级，**不消耗 AI 调用**）。

## 六、错误处理与边界情况【定案】

1. **网格校验失败**：行数/行宽/非法字符/调色板缺色任一不符 → 拒绝加载，报错定位到行号；AI 返回不合规 → 自动重试 2 次，仍失败则丢弃并提示。
2. **agent 不可达**：启动脚本先探活，失败则报"服务未启动"；编辑器 AI 请求超时（30s）→ 面板红字 ＋ 重试按钮；**手绘功能完全不受影响（离线可用是底线）**。
3. **双文件一致性**：真源是 `.grid.txt`，PNG 是渲染产物；写入**成对执行**，`grid2png` 失败则回滚 grid 写入，保证不出现"grid 新 PNG 旧"；载入时校验成对时间戳。
4. **地块量化色损**：量化前生成并排对比预览；用户否决 → 该图标记 `manual_only`；软边缘图量化后叠加**原始 alpha 通道**（仅压 RGB）。
5. **发布覆盖冲突**：目标 Assets 文件被外部修改 → 发布前字节级比对，不一致弹窗警告；`.meta` 存在性检查（防御性阻断）。
6. **浏览器兼容**：改用 `serve.mjs` 本地 API 后不依赖浏览器文件系统 API，任意现代浏览器全功能可用。
