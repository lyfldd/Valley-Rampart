## 〇、一句话

> ⭐ **交互不是"一种行为"，是"一次数据操作"** —— 两个数据携带者之间，**读对方 / 改自己 / 改对方**。
> ⇒ **所以不需要交互类型清单**（清单会漏、会膨胀）。

---

## 一、参与双方与它们的数据

```
交互者（NPC）  ←──── 数据 ────→  被交互对象（资源点 / 建筑 / 单位 / 地面）
      │                                    │
   自己带数据                            自己也带数据
```

**数据只有三类**（`D757` 用户修正）：

| 类 | 是什么 | 例 | 谁有权改 |
|---|---|---|---|
| **① 自身数据** | 描述"我是什么、我怎么样" | 类型 · HP／耐久 · 等级 · 状态 · **进度**（生产/建造） · **容量** | **自己** |
| **② 资源数据** | 可转移、可增减的东西 | 木／石／矿／粮／金／水晶／火油 · 弹药 · 水 | **交换时两边都变** |
| **③ 引用数据** | "我依赖谁 / 谁挂在我身上" | 锚点 · 工位 · 归属（王国） | **建立者** |

⚠️ **两处归位**：
- **位置（坐标/占格）** 也在数据里，但**归地图层** ⇒ **交互双方谁都不改对方的坐标**（要改位置 ⇒ 走地图层的门）
- ⭐ **「时间」不是第四类数据** —— 交互涉及的时间**只有"这次交互本身的耗时"** ⇒ 它是**交互自身的属性**，不是携带的数据

---

## 二、⭐ 交互只有三种数据操作

```
读对方   （看条件：你有没有我要的、你还行不行）
改自己   （花掉我的资源 / 推进我的进度）
改对方   （你的资源给我 / 你的 HP 降 / 你的类型变）
```

**用六种交互验一遍**：

| 交互 | 读对方 | 改自己 | 改对方 |
|---|---|---|---|
| **采集** | 有木头 ∧ 未采完 | 背包 **+5** | 资源 **−5**／消失 |
| **搬运** | 你有仓位 | 背包 **−n** | 目标仓 **+n** |
| **建造** | 这里能建 | 资源 **−n** | 进度 **+?**；满 ⇒ **类型变**（走 `Replace`） |
| **生产** | 我在岗 | 进度 **+?** | 产物进建筑仓 |
| **攻击** | 对方可打 | — | 对方 **HP −d** |
| **装填** | 弹仓没满 | 弹药 **−n** | 弹仓 **+n** |

⇒ **没有一种需要"新的交互类型"。**

## 三、两端声明（各自一个箱子）

**对象侧**（一个对象**可声明多项**能力）：

```
仓库.能力 = [
  { 被修:   条件(耐久 < 满),      耗时, 改我(耐久 ↑) },
  { 被升级: 条件(等级 < 上限 ∧ 资源够), 耗时, 改我(等级 ↑) },
  { 被填入: 条件(库存 < 容量),    耗时, 改我(库存 ↑) },
]
```

**NPC 侧**：

```
工人.能力 = [ 采集, 搬运, 建造, 修复, 升级, 填仓 ]
```

⇒ **加一种新交互 ＝ 两边各多填一栏**，中间的"交互层"**一个字不用改**。

## 四、⭐ 三层分工（谁决定做什么）

| 谁 | 做什么 | 类比 |
|---|---|---|
| **下层（地图层）** | 提供**能力声明** ＋ **算交集**（"这里能做什么"） | **出菜单** |
| **任务管理器** | 从交集里**选一项（或多项）下发** | **点菜** |
| **下层** | **执行**被派的那一项（走完耗时、改数据） | **做菜** |

⚠️ **为什么必须有"任务管理器"这一层**：

一个建筑**常有多个能力**（仓库：被修／被升级／被填入）⇒ **能力交集会有多项** ⇒ **"这次到底做哪一项"不能由下层决定**（那是玩法策略），**必须由任务管理器派**。

⇒ 这正是"查"的同构：**下层提供件（能力匹配），上层各取所需（选哪一项）**。

```
1 下层：我能做什么（对象能力 ∩ NPC 能力）→ 一组可选项
2 任务管理器：派任务（指定 one / many）
3 下层：执行（耗时 → 读/改 → 结果）
```

---

## 五、执行（一次交互）

```
1 条件复核（读对方）—— 不满足 ⇒ 取消
2 耗时推进（交互自身属性）
3 改自己 / 改对方（三类数据）
4 若目标"类型变了" ⇒ 走地图层 `Replace`（对外一次替换）
5 汇报结果给任务管理器（成功 / 失败 / 干到一半）
```

## 六、与现有代码的对齐

| 现有 | 应变成 |
|---|---|
| `ITaskSource`（**7 个各自为政**） | ⇒ **对象的能力声明**（每个对象填一个箱子） |
| `KingdomTaskType`（**12 项枚举**） | ⇒ **不再需要**（能力名替代；枚举会漏会膨胀） |
| `BehaviorModule.WorkAt`（注释"位移即目的·首版") | ⇒ **执行一次交互**的通用动作 |
| `WorkerTask`（只有 `Gather`/`Transport`） | ⇒ **一个交互实例**（含耗时、进度、目标） |
| `TaskScheduler` | ⇒ **任务管理器**（出题 → 选一项 → 派工） |

⚠️ **现状提醒**：现在**真跑通的交互只有一种** —— `WorkAt → ExecuteWorkAt → HarvestCarry()`（**走过去 + 搬走**）。建造/修复/生产/装填**都没落地**。

## 七、判据（链路闭合句）

1. **无交互枚举**：全库 grep ⇒ **不存在**"交互类型枚举"（能力名替代）
2. **两端各声明**：任取一种交互 ⇒ **两边各有一份声明**，**下层无第三份**
3. **交集可算**：任取（NPC × 对象）⇒ 能算出**可选交互集合**（多项时**不擅自选一**）
4. **选择归任务管理器**：一次派发 ⇒ **由任务管理器指定**执行哪一项
5. **加交互不改中间层**：新增一种交互（两边各填一栏）⇒ **交互层零改动**
6. **时间只有耗时**：交互涉及的时间 ⇒ **只有这次交互的耗时**（不与世界日历混）
7. **位置不参与交换**：任取一次交互 ⇒ **双方坐标不变**（要变 ⇒ 走地图层的门）
