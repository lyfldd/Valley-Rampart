## 〇、一句话

> ⭐ **交互不是"一种行为"，是"一次数据操作"** —— 两个数据携带者之间：**读对方 / 改自己 / 改对方**。
> ⇒ **不需要交互类型清单**（清单会漏、会膨胀）。
> ⚠️ 但**"什么叫完成"必须写死在每条交互自己的定义里**（用户 `D758`：**「硬编码就硬编码到底」**）。

---

## 一、参与双方与它们的数据

```
交互者（NPC）  ←── 数据 ──→  被交互对象（资源点 / 建筑 / 单位 / 地面）
```

**数据只有三类**：

| 类 | 是什么 | 例 | 谁改 |
|---|---|---|---|
| **① 自身数据** | "我是什么、我怎么样" | 类型 · HP／耐久 · 等级 · 状态 · **进度** · **容量** | **自己** |
| **② 资源数据** | 可转移、可增减 | 木／石／矿／粮／金／弹药／水 | **交换时两边都变** |
| **③ 引用数据** | "我依赖谁" | 锚点 · 工位 · 归属 | **建立者** |

**三处归位（`D757`／`D758` 修正）**：
- **位置**（坐标/占格）也在数据里，但**归地图层** ⇒ **交互双方谁都不改对方的坐标**
- ⭐ **「时间」不是数据** —— 交互涉及的时间**只有"本次动作的耗时"**
- ⚠️ **「预定/配对」不是双方的数据** —— 它是**管理器里的记录**（见 §六），**双方零字段**

---

## 二、⭐ 交互只有三种数据操作

```
读对方   （看条件：你有没有我要的、你还行不行）
改自己   （花掉我的资源 / 推进我的进度）
改对方   （你的资源给我 / 你的 HP 降 / 你的类型变）
```

| 交互 | 读对方 | 改自己 | 改对方 |
|---|---|---|---|
| **采集** | 有木头 ∧ 未空 | 背包 **+5** | 数量 **−5**／空了消失 |
| **搬运** | 你有仓位 | 背包 **−n** | 目标仓 **+n** |
| **建造** | 这里能建 | 资源 **−n** | 建造度 **+?**；满 ⇒ **类型变**（走 `Replace`） |
| **生产** | 我在岗 | — | 产物进建筑仓 |
| **攻击** | 对方可打 | — | 对方 **HP −d** |
| **装填** | 弹仓没满 | 弹药 **−n** | 弹仓 **+n** |

## 三、两端各声明一个箱子

**对象侧**（一个对象**可声明多项**能力）：

```
仓库.能力 = [
  { 被修:   条件(耐久 < 满),          进度(耐久 → 满) },
  { 被升级: 条件(等级 < 上限 ∧ 资源够), 进度(等级 → +1) },
  { 被填入: 条件(库存 < 容量),         进度(库存 → 容量) },
]
```

**NPC 侧**：`worker.能力 = [ 采集, 搬运, 建造, 修复, 升级, 填仓 ]`

⇒ **加一种新交互 ＝ 两边各多填一栏**（若为**全新动作** ⇒ 见 §九 的诚实修正）。

## 四、⭐ 交互表（唯一权威）

**命名**（用户 `D758`）：`对象名字_能力名字`（如 `worker_gather` · `warehouse_repair`）。
**配对**：⭐ **查表**（用户定）—— 能力名**集中一张能力表**，两侧都引用表里的条目，**配对只比能力段**。

| 栏 | 装什么 |
|---|---|
| **交互ID** | `对象名_能力名` |
| **谁可以做** | 引用能力表 |
| **目标须提供** | 引用能力表 |
| **条件** | 读对方（**不满足 ⇒ 不能做**） |
| ⭐ **进度** | **"看哪个字段、到什么值算完"** —— ⭐ **每条交互自己写死**（见 §五） |
| **产物去哪** | 改自己（背包／无） |
| **目标怎么变** | 改对方（哪个字段、改多少） |
| **耗时** | **单次动作**的时长（≠ 进度） |

## 五、⭐「进度」栏 —— 硬编码到底

> 用户原话：「这个进度我们要**硬编码就硬编码到底**，把**全部的任务对应的完成进度都硬编码**，而不是单独的一个分类，而应该是**对应的分类下面的数值的完成情况**」

⇒ **不做通用的"进度条"抽象** —— 每条交互**自己写死**：看哪个字段、到什么值：

| 交互 | 进度栏写什么 |
|---|---|
| **采集** | 目标 `数量` → **0** |
| **修复** | 目标 `HP` → **HP 上限** |
| **建造** | 目标 `建造度` → **100**（多段则写"阶段全完"） |
| **填仓** | 目标 `库存` → **容量** |
| **搬运** | 目标 `仓存量` → 背包清空 |

⚠️ **为什么这里"硬编码"是对的**（`D758` 确认）：
- **"什么叫完成"本来就是每种交互定义的一部分**，不是通用机制
- 且它硬编码在**交互表**（**数据**）里，**不是散在代码里** ⇒ **集中、可查、好改** ⇒ **不违背"不涨接口"**

## 六、⭐ 三层分工

| 谁 | 做什么 | 类比 |
|---|---|---|
| **下层（地图层）** | 出**能力交集**（"这里能做什么"） | **出菜单** |
| **任务管理器**（`06`） | **派一项或多项** | **点菜** |
| **下层** | **执行**（耗时 → 读/改 → 回调） | **做菜** |

**为什么必须有任务管理器**：一个对象**常有多个能力**（仓库：被修/被升级/被填入）⇒ 交集多项 ⇒ **"做哪项"是玩法策略**，下层不能定。

### ⭐ 配对只在管理器（双方零引用）

> 用户 `D758`：「预定**一定不能要双方知道**……**使用引用这个东西，很容易出现生命周期问题**……**会占用 npc 状态以及被交互者状态**」

```
任务管理器（唯一知道配对的一方）
  配对表：{ 交互者 A ↔ 被交互者 T · 能力 · 状态 }
     ├─ 给 A 一条："去 T 做 X"
     └─ 给 T 一条："A 要来做 X"

A 与 T 【都不持有对方引用】⇒ 谁也悬空不了
目标没了 ⇒ 下层广播 ⇒ 管理器收到 ⇒ 配对表与两侧条目一起清掉
```

⇒ ⚠️ **预定/配对不是"对象身上的字段"** ⇒ **对象侧零字段**。

## 七、执行与完成回调

```
1 条件复核（读对方）—— 不满足 ⇒ 取消
2 耗时推进（动作时长）
3 改自己 / 改对方（三类数据）
4 按「进度」栏判定是否完成（判定标准**由该交互写死**）
5 完成 ⇒ 广播【完成(交互者, 被交互者, 能力)】
       ├ 交互者侧：收产物 / 标记
       ├ 被交互者侧：处理自身变化（数量减／HP 变／类型变）
       └ 其他系统：自己订
```

⭐ **完成回调就是"执行"的出口**（用户 `D758`）：
- **资源交换**是默认动作
- **"交换完还要做的事"写在这层**（如"砍完树，树消失""修完房，房子升级"）
- ⇒ **交互层不需要知道具体做什么** ⇒ 正是"各取所需"

## 八、多人协作

**不做特例**：`可多人` 是**字段**（对象侧声明）。

| 字段 | 效果 |
|---|---|
| `可多人 = false` | 只允许**一个实例**（管理器独占） |
| `可多人 = true` | 允许多个实例 ⇒ **进度自然合流** |

**为什么"自然合流"**：**进度就是对象自己的数据**（HP／数量／建造度）⇒ 多个实例改同一个字段 ⇒ 累加成立。

⇒ **不需要在交互层造"进度条"。**

⚠️ 两件事仍需解决（**都不在交互层**）：
1. **原子性**：**加进度与"判完成/跨阶段"必须是同一个原子操作** —— 否则两个 NPC 同时判定成立 ⇒ 阶段被跳两次
2. **顺序**：阶段依赖（先地基后墙）⇒ **是对象自己的规则**（建筑自己的建造规则），**不在交互层**

**例子**：搬战利品箱子 ＝ `可多人=true`、无阶段 ⇒ 多 NPC 各搬一部分 ⇒ 剩余量到 0 ⇒ 完成。

## 九、⚠️ 一处诚实修正（本端 `D758` 自纠）

我早前说过「**加一种新交互 ＝ 两边各填一栏，中间层一个字不改**」——**只对一半**：

| 加什么 | 要动什么 |
|---|---|
| 加一种**已有动作**的交互（给新建筑加"被修"） | ✅ **只填栏**（"修"的执行逻辑已存在） |
| 加一种**全新动作**（如"灌水""读碑文"） | ⚠️ **必须写一段执行代码** |

⇒ **声明可以数据化，执行必然是代码。** "纯零代码扩展"**不成立**。

## 十一、判据（链路闭合句）

1. **无交互枚举**：全库 grep ⇒ **不存在**"交互类型枚举"
2. **两端各声明**：任取一种交互 ⇒ 两边**各有一份声明**，下层**无第三份**
3. **进度写死**：任取一条交互 ⇒ 其"看哪个字段、到什么值"**写在交互表里**
4. **配对零引用**：任取一次进行中的交互 ⇒ **双方都不持有对方引用**（一方消失不悬空）
5. **选择归任务管理器**：一次派发 ⇒ **由任务管理器指定**执行哪一项
6. **时间只有耗时**：交互涉及的时间 ⇒ **只有本次动作的耗时**
7. **位置不参与交换**：任取一次交互 ⇒ **双方坐标不变**
8. **回调节口**：任取一次完成 ⇒ 双方**各自处理自己的事**（交互层不代劳）
