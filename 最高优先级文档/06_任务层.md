## 〇、一句话

> **任务管理器 ＝ 调度层**：**受上层委托出题 → 从能力交集点菜 → 管住过程 → 收尾释放**。
> 它**不碰地图数据**（走下层门）、**不懂玩法策略**（受上层委托）、**不管交互内部**（交互层的事）。

## 一、边界

| 管 | 不管 |
|---|---|
| 任务的**生成**（受委托）· **选择**（从交集点菜）· **派发** · **过程状态** · **意外处置** · **收尾释放** | **改地图数据**（走 `03` 的门）／**判定"什么叫完成"**（`05` 的进度栏）／**玩法策略**（上层给的）／**交互的执行细节**（`05`） |

## 二、层级与对话方

**L2 任务层**（`D759` 用户拍：**同级层**）。它只跟三方说话：

```
        ┌── 上层（L3/L4）：委托任务、撤回任务、给优先级
        │
   L2 任务管理器
        │
        ├── L1 交互层：要"能力交集"（这里能做什么）、派交互、收结果
        └── L0 地图层：解析目标（坐标→存在吗）、订阅广播（Removed / Replaced）
```

⇒ ⚠️ **它不直接读地图数据** —— 目标是否还在，问地图层的门。

## 三、任务卡片（**五组**）

| 组 | 栏 | 说明 |
|---|---|---|
| **身份** | `taskId` ｜ `issuer`（谁派的）｜ `priority` | 调度与去重 |
| ⭐ **归属方** | **属于哪个王国／玩家** | 谁能看到、谁能派（多国必须分清） |
| **做什么** | `ability` ｜ **`targetRef`（坐标 ＋ 类型）** ｜ `count`（1 次／N 次／直到满足） | ⚠️ **targetRef 不是引用** |
| **条件与进度** | `precondition` ｜ ⭐ **`progressSpec`**（看哪个字段 → 到什么值）｜ `duration` | ⭐ `progressSpec` **与 `05` 的「进度」栏同源** |
| **结果** | `rewardTo`（产物进谁）｜ `targetEffect`（目标怎么变） | 回调照着做 |
| **执行中** | `state` ｜ `workerId` ｜ `workProgress` ｜ `deadline` | 派出后才有值 |
| **意外** | `retry` ｜ `onFail`（换人／放弃／降级） | 防卡死 |

## 四、⭐ 全生命周期（八阶段）

```
[0] 生（Created）
      │ 卡片不合法（能力名不存在／目标无效）⇒ ✂ 丢弃 + 日志
      ▼
[1] 待派（Pending）—— 等匹配（能力 ∩ 优先级）
      │ ✂ 目标没了（Removed）      ⇒ 作废
      │ ✂ 目标变了（Replaced）     ⇒ 重验条件，不匹配 ⇒ 作废
      │ ✂ 目标用尽（条件不满足）    ⇒ 作废
      │ ✂ 过期（taskExpiry）       ⇒ 作废
      │ ✂ 归属方灭亡                ⇒ 整批作废
      ▼ 匹配到工人
[2] 已派（Assigned）—— 已绑定工人
      │ ✂ 工人死（OnNpcDied）      ⇒ 解绑，回 [1]（重派）
      │ ⏸ 工人被抢（OnThreatSusp） ⇒ 挂起（保留绑定）
      │ ✂ 到不了（路径失败）        ⇒ 解绑 + 标记不可达（防死循环），回 [1]
      ▼ 工人到达
[3] 执行中（Working）—— 耗时推进
      │ ✂ 目标没了                  ⇒ 取消
      │ ✂ 目标变了                  ⇒ 重验，不匹配 ⇒ 取消
      │ ⏸ 工人被抢／死亡            ⇒ 挂起或解绑（**本次贡献已在目标数据上**）
      │ ✂ 超时（taskTimeout）       ⇒ 强制放弃，回 [1]
      ▼ 完成一次交互
[4] 判定（Check）—— 按 progressSpec
      ├ 未完成 ∧ 还要继续 ⇒ 回 [3]（或回 [1] 重新派）
      ├ 未完成 ∧ 条件已不满足 ⇒ [6] 终止
      ▼ 完成
[5] 完成（Done） ⇒ 回调 · 结算 · **释放配对** · 归档
[6] 终止（Aborted）—— 失败／取消／作废 ⇒ **释放配对** · 清理
[7] 读档（Restore）
      │ 恢复进行中的任务 ⇒ **一律重验**（目标在吗？工人在吗？条件成立吗？）
      └ 不成立 ⇒ 直接作废（**不恢复**）
```

## 五、⭐ 异常 → 处理 对齐表

| 异常 | 触发源 | 处理 | 现状 |
|---|---|---|---|
| **NPC 死亡** | `OnNpcDied` | 解绑，回待派 | ✅ 已有 |
| **建筑死亡** | `OnBuildingDied` | 相关任务作废 | ✅ 已有 |
| **威胁抢占** | `OnThreatSuspended/Resumed` | 挂起／恢复 | ✅ 已有 |
| **外部撤回** | `AbandonTask` | 直接终止 | ✅ 已有 |
| ⭐ **目标变了**（`Replace`／升级） | 地图层 `Replaced` 广播 | **重验条件** ⇒ 不匹配作废 | ❌ **本设计新增** |
| ⭐ **目标用尽**（采空／仓满） | 条件复核失败 | 作废 | ❌ 新增 |
| ⭐ **工人到不了** | 路径失败 | 解绑＋**标记不可达**，回待派；`retry` 用尽 ⇒ 终止 | ❌ 新增 |
| ⭐ **读档一致性** | 读档流程 | **全部重验**，不成立即作废 | ❌ 新增 |

## 六、配对与预定（**同生共死**）

```
任务管理器持有配对表（唯一真源）：{ 交互者 A ↔ 目标 T · 能力 · 状态 }
  ⚠️ A 与 T 都不持有对方引用（05 定的）⇒ 谁也悬空不了

纪律：任务在 ⇒ 预留在；任务亡（完成/取消/作废）⇒ 预定【立刻释放】
     + 兜底：预定带超时（防任务管理器自己出漏）
```

## 七、扩展（**单管理器 ＋ 分域**，`D759` 用户拍）

| 手段 | 做法 |
|---|---|
| **分域** | 内部按**大区块**（或**王国**）分桶 ⇒ 派发只扫相关桶 |
| **节流** | 沿用现有 `tickInterval = 1s`（**已是轮询节流**，不是每帧） |
| ⛔ **不要** | **不要多个管理器** —— 会引入"工人属 A、活属 B"的跨管理器仲裁，复杂度反涨 |

| 现有 | 目标 |

## 九、判据（链路闭合句）

1. **零引用**：任取一个进行中的任务 ⇒ **双方都不持有对方引用**
2. **目标可判**：目标消失/变化 ⇒ 任务**在下一 tick 内**收到并处置（不卡死）
3. **配对不悬空**：任取一个终止的任务 ⇒ **配对表与预定都已释放**
4. **不居中态**：任取一次异常 ⇒ 结果是"回到待派"或"作废"，**不存在中间悬挂态**
5. **读档重验**：存档→读档 ⇒ 进行中的任务**逐条重验**，不成立的**已作废**
6. **单管理器**：全库只有**一个**任务管理器实例（分域是内部结构）
7. **不碰地图数据**：任务管理器**不直接读写**地图底层数组（走门）
