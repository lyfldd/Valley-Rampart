### B2 · **`GridTypes.cs:100` 注释勘正**（`D737` 术语红线落地）

- **问题**：该行注释写「**矿洞**（石，需争夺；可走，Locked 由 2_2/2_7 置）」——**与文档术语冲突**（实为**矿山锚点**＝地形）。`D737` 已定：**同名不同物**（`FeatureType.Mine`＝锚点／`mine.asset`＝建筑）是本次误判的**根因**。
- **做法**：改为**矿山锚点（地形）**语义，并显式并列**「≠ `mine.asset`（矿洞·建筑」**；保留 `Locked` 语义与 `Locked 由 2_2/2_7 置` 的技术说明（**只改术语，不改行为**）。
- **对比样例**（供参考，不强制逐字）：`Mine,  // 矿山锚点（地形；其上可建 mine（矿洞·建筑）／quarry）——≠ mine.asset（建筑，2×2，allowedTerrain=[Quarry]）`

### B3 · **矿洞密度下限拆除**（`:841` 地板 ＋ `B_i` 保底退出）

- **问题（实读）**：`MapGenRules.cs:840-841`
  ```csharp
  int mineClusters = Mathf.RoundToInt(e[ResMine] / 4);
  if (mineClusters <= 0 && b[ResMine] > 0) mineClusters = 1;   // ⛔ 每大区块恒 ≥1 簇
  ```
  ⇒ **矿山锚点密度下限被锁死在「1 簇/大区块」＝ 4 格/256 格** ⇒ 4× 视域（≈20.25 大区块）**恒 ≥20 簇**，与用户权重怎么调**无关**。
- **做法**：①**删除**该行地板；②**矿洞退出 `B_i` 保底**（`ComputeQuota` 内对 `ResMine` 置 `b = 0`，否则 `b[ResMine] > 0` 会把地板顶回来）。
- ⚠️ **本项效果的诚实界定（策划端已实算·写进判据）**：以用户新权重（`mine w = 0.95` ⇒ `p ≈ 2.1%`）计，四带 `E_mine` ≈ **1.8 ~ 2.9** ⇒ `round(E/4)` ∈ **{0, 1}** ⇒ 拆地板后**平均仍约 1 簇/区块**（一屏 ≈10~15 簇），**只比现状（恒 20）略降**。**要达成「4× 视域 2~3 个」必须靠 `R-03` 方案 A′**（格口径归一 ＋ 概率密度采样 ＋ **跨区块累加**）—— **本项只拆"下限"，不承诺"最少"**。
