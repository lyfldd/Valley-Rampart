## 五、HH/D 循环利用与固定上限

### 5.1 推荐规则

1. **HH 热区：120 个文件**。开放、阻塞、待裁、仍被当前任务引用的文件永不因数量自动归档；已关闭且最近没有引用的旧文件进入月度归档目录。**同一 HH 编号的全部文件是一个归档单元，不得部分归档。**
2. **主仓 D 热区：60 个 D 条目**。单位改为去重后的 D 号条目；来源是 `_编号登记.md` 当前有效 D 行与 `测试基线台账.md` 当前有效条目。训练仓卡内 D 号和 TD 号不并入主仓 D 上限；`0.6_审查决策记录.md` 只作 D739 及以前的历史存档。
3. **编号登记活跃窗口：80 行**，其中 HH 不超过 50 行、D 不超过 30 行；D≤30 是 60 个 D 条目总热区内的账本展示窗口，不是第二个 D 上限；完成项压缩进 `_编号登记_历史存档.md`，索引仍可追溯。
4. **同号链预警**：120 个 HH 热区的 25% = 30 个文件；任一编号达到 30 个文件即标记 `CHAIN_REVIEW_REQUIRED`，由主策划复核，不把 30 当作硬性每编号上限。单一编号若超过 120 个文件，标记 `ROTATE_BLOCKED`，只能扩大热区或另立裁决，仍不得部分归档。
5. **队列最近完成：10 项**。更早完成项只保留指针和归档位置，不重排历史行。

### 5.2 轮换六步（到达任一上限即触发）

1. 分类：`开放／阻塞／待裁／当前引用／已关闭`，记录完整数量与分母。
2. 回收：逐份旧 HH/D 提取可复用教训、反例、判据或工具规则，写入 `_策划教训库.md`、对应 skill 或训练手册；只写增量，不改原证据。
3. 固化：生成 `多Agent交接/_archive/轮换清单_YYYY-MM.md`，列出源文件、提取条目、目标位置、引用检查结果。
4. 移动：HH 文件仍只移动已关闭且无活动引用者到 `_archive/HH/YYYY-MM/`；D 条目只更新 `_编号登记_历史存档.md`、测试基线台账与引用指针，不因 D 条目超限搬动 HH 裁决书正文；不使用删除命令。
5. 更新：更新 `_交接索引.md`、`_编号登记_历史存档.md`、测试基线台账和引用指针；主账本仍保留编号、状态和归档路径。
6. 校验：重新计数、抽查 3 个开放项和 3 个已归档项、运行 `git diff --check`；事务端提交轮换清单，主策划只裁分类与边界。

**选项**：A 80 HH / 40 D 条目（更省空间但归档频繁）；B **120 HH / 60 D 条目（推荐）**；C 200 HH / 100 D 条目（保留更多上下文但热区仍会膨胀）。推荐 B，影响是首轮需完成 D 条目去重分类，之后按条目回收教训和历史指针，不再按 D 字符串批量搬动文件。

## 六、五工具端拓扑与加载

| 工具 | 默认角色 | 主加载入口 | 失败时的可复核路径 |
|---|---|---|---|
| Codex | 主策划（决策端） | `AGENTS.md` + 用户点名主策划卡；skill 主本 `.codely-cli/skills` | 直接读主策划卡和 `.codely-cli/skills/<name>/SKILL.md` |
| WorkBuddy | 事务端 | 用户级 `~/.workbuddy/skills`；项目 `.workbuddy/skills` 只作镜像/审计 | 按事务端入场卡给出主本路径；不得假设项目镜像自动加载 |
| Trae | 执行端 | `.trae/skills` 与执行端入场卡 | 直接读主本路径并提交执行端回执 |
| Trae 内 CodeBuddy | 执行端继承 | 用户级 `~/.codebuddy/skills`；内置 skill 不替代项目 skill | 以主本哈希和扩展日志 `Loaded N skills` 双证核对 |
| Cursor | 执行端继承 | 项目 `.cursor/skills` 中文镜像 | 直接读主本路径；不建立第五角色或英文分叉 |

加载顺序固定为：**工具入口 → 四端角色卡 → `vr-tool-topology` → 任务类型 skill → 必看文档 → 回执/审计**。五个工具不改变写权：主策划不碰代码资产，执行端不改策划账本，训练端不替训练师判根因，事务端不改决策内容。
