## 四、⭐ 件 1 裁定（形态定案 · 单点改）

### 4.1 门体幂等判据 ⇒ **采纳执行端候选 1（本层存在性）**

```csharp
public void RemoveBuilding(Building b, DeathCause cause)
{
    if (b == null) return;
    // `03` §7.4 存在性校验：本层已不持有它 ⇒ 幂等跳过（删两次等于删一次）
    var reg = BuildingRegistry.Instance;
    if (reg != null && reg.GetAt(b.coord) == null
        && GridSystem.Instance != null && GridSystem.Instance.GetOccupant(b.coord) == null)
        return;
    b.ReleaseLayerOwnedState(unregisterFromRegistry: true);
}
```

**本端实读依据**（判据三直读 ②）：
- `BuildingRegistry.cs:44-48 GetAt(GridCoord)` ✓（按 `_byCoord` 查 · **footprint 覆盖格均命中同一 Building**）
- `BuildingRegistry.cs:30-41 Unregister(Building)` ✓（回收时清 `_byCoord` 中指向 `b` 的格 ⇒ 回收后 `GetAt` 返 `null`）
- `GridSystem.cs:361-376 GetOccupant(GridCoord)` ✓（地块级 · `_occupants`）；`GridSystem.cs:445-450 FreeFootprint` ✓（**整块 `div²` 子格同写** ⇒ 回收后返 `null`）

⇒ 判据与 `03` §7.4 **同义** ✓；⛔ **不新增字段/机制** ✓。

**⚠️ 已知边界（本端声明 · ⛔ 本批不处理）**：
`BuildingRegistry._byCoord` 与 `GridSystem._occupants` **均单槽存储**（`BuildingRegistry.cs:75` 注释自陈；`F-15` 实盘 **9 座** footprint 重叠）⇒ **重叠场景下"按格查"不可靠**。
⇒ 判据用 **`&&`（两者皆空才跳过）** ＝ **方向安全**：宁可**多执行一次回收**（各步骤对同对象近似幂等），**绝不漏回收** ✓
⇒ 登记为 `F-15` 重叠面下的**已知边界**，⛔ 不在本批处理。

### 4.2 ⭐ 新增裁定：`Die()` 入口加幂等守卫

```csharp
public void Die(DeathCause cause = DeathCause.Killed)
{
    if (state == BuildingState.Dead) return;   // 生命周期只结束一次
    state = BuildingState.Dead;
    ...
}
```

**理由**：
1. 门化后「数据回收」成为**唯一入口**，但**入口无守卫** —— 实读 `Building.cs:1369-1371`：`Die()` **首行即置 `Dead`、无任何守卫** ⇒ 若被重复调用 ⇒ **重复掉箱（三路）＋ 重复回收 ＋ 重复广播**。
2. ⚠️ 「`Die()` 被重复调」**不是假想**：`U-8`／`E1` 已知场景「**拆除中被打毁**」（`FinishDemolish` 与 `TakeDamage→Die` 竞态）。
3. 成本 1 行；且把「**生命周期只结束一次**」落到实处 —— ⛔ 不改任何现有路径语义。

**⚠️ 安全性（本端复核）**：守卫只挡「**已 `Dead`**」，⛔ **不挡** `Ruined`／`Abandoned`／`Constructing` ⇒ 现有调用面（`Building.cs:921 FinishDemolish → Die(Demolished)`、`:1289 工事被破 → Die(Killed)`）**行为不变** ✓

**判据**：`Die()` 二次调用 ⇒ **零副作用**（三路掉箱不重复 ／ 回收不重复 ／ `UnitDiedEvent` 不重复 ／ 无异常）。
