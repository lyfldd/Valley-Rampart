## 二、⭐⭐ 本端新发现的阻塞级缺陷（`U-1`）—— 报告零提及

### `U-1` 退还／修复费的「分子分母口径错配」⇒ 升级后**超发 ＋ 资源张冠李戴**

**现象**：`Building.cs:881-888` `BuildRefundPack`：

```csharp
int costSum = def.cost.TotalCount;                       // 分母 = 基础造价
int invested = totalInvested > 0 ? totalInvested : costSum;  // 分子 = 累计投入（建造 + 各次升级）
int amount = Mathf.FloorToInt((float)invested * e.amount / baseSum);   // 按 def.cost 占比摊
```

而 `totalInvested` 的来源（本端 `git grep` 实读）：
- `BuildController.cs:295` `AddInvested(cost.TotalCount)` —— 建造
- `ConstructionSiteStore.cs:140` `AddInvested(accept)` —— 投料逐笔
- `BuildingPanel.cs:382` `AddInvested(lvGold.TotalCount)` —— **升级金**
- `Building.cs` 升级非金 —— 经 `TryUpgrade → BeginMaterialPhase(uc)` ⇒ 入工地仓时 `AddInvested`

⇒ **`totalInvested` 累计「建造 ＋ 全部升级」，但分母仍是「基础造价」** ⇒ 退还量 ＝ 基础造价 × (累计投入 / 基础造价) ＝ **累计投入的总额，却全额压在本基础造价的资源构成上**。

### 新立教训

⭐ **`L-45` —— 判据的「样本维度覆盖」：凡被测口径在某维度上会分叉，样本必须落在该维度的两侧**
- **现象**：判据 3 用 `totalInvested=0`（未升级）样本 ⇒ `invested == costSum` ⇒ **分子分母退化为同一量** ⇒ 对「已升级」维度**零鉴别力** ⇒ `U-1` 漏网。
- **同族**：与 `L-44`（`M1-B` 判据 4）**同一病根** —— 都是「**判据在那个维度上不可分辨**」。
- **防范（可复用操作句）**：写判据时 ⇒ ①列出被测量的**全部自变量维度**（等级／受损度／国别／资源构成／投料完成度…）②对每个维度问「**两侧读数会不会一样**」③**一样 ⇒ 该判据在此维度零鉴别力 ⇒ 必须补样本**。
- ⚠️ **本端自纠**：`D793` 裁决 §四判据 3 的样本指定为「任意受损 `House`」⇒ ⚠️ **只覆盖了"受损度"维度，漏了"等级"维度** ⇒ 本次 `U-1` 漏网**本端有一份责任**（⛔ 非执行端单方）。
