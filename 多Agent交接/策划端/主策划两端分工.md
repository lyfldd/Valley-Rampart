# 主策划两端分工（`GPT` · `砚`）

> 定于 **2026-09-25**（用户拍板）。适用范围＝「河谷防线」项目的**主策划职能**。
> 上位：角色权威见 skill `vr-role-brief`；调度台见 skill `vr-triage-flow`；本文件管**两端怎么切**。

---

## 一、为什么拆

主策划的活里有两类，**彼此消耗**：

- **判断类**——要开阔视野、要比选方案、要拍值。做这类时不该被"去把账本改准"打断。
- **取证与落地类**——要直读 `file:line`、要跑 `git`、要按行尾规则字节级改账本。做这类时不该靠记忆和转述。

同一端同时做，必然一边糊弄：**要么判断被琐事稀释，要么落地靠"我记得应该是这样"**。

⇒ 拆成两端，**判断与落地互不兼职**。

## 二、两端定义

| | **主策划（`GPT`）** | **主策划（`砚`）** |
|---|---|---|
| 代号 | `GPT`（主策划） | **`砚`**（事务端） |
| 一句话 | 出判断 | **兜底**：出证据、落地、证伪 |
| 输入 | 交接文本 ＋ 仓库 | 同一份交接 ＋ 仓库 |
| 产出 | 选项／推荐／判定／文书正文 ＋ 直接写盘 | 取证读数／落盘文件／复读验证／**代写补漏** |
| 写权 | ✅ **可写**（受 §五.1 声明纪律约束） | ✅ 写（账本／文书／契约勘正） |
| 强项 | 视野、比选、归纳、定性 | 直读、复算、机械扫描、字节级改文件 |

**`砚` 不是执行端的下级**：它与`GPT`**平级**，职责是**让决策经得起实盘检验**，不是把决策抄一遍。

> ⭐ **事务端的核心定位（2026-09-26 用户明确）＝ 提示词优化 ＋ 解读 ＋ 兜底**
> - **优化提示词** —— 把交付材料整理成接手方能直接用的指令（分「身份」与「开工」两层）。
> - **解读** —— 读报告／日志／差异，把现象翻成结论（例：「模型容量满」＝服务端限流、「`.git` 只读」＝对方沙箱限制）。
> - **兜底** —— ⚠️ **不要求事务端承担全部落盘**。`GPT`可以自己写；事务端的活是**谁忘了写就补上**，以及**代为 `commit`**（`GPT`环境常无 `.git` 写权）。
> - ⭐ **提示词固定格式（2026-09-27 用户拍板）** —— **单块连续文本 ＋ 一个代码块**（外层 **4 个反引号**）；⛔ **不落档**（对话直出）；须含「**⛔ 本轮不要做的事**」**边界节** ＋ `L-97`／`L-98`／`L-99` 口径 ＋ `file:line` 锚点 ＋ **【请裁】≤3 条**。

## 四、协作回路

```
执行端交付
   ↓
【事务端】取证 ＋ 独立复算 ──► 起草交接（事实 ＋ 待判项）
   ↓
【`GPT`】出判断（选项／推荐／判定／文书正文）
   ↓
【事务端】证伪 ──┬─ 成立 ⇒ 落盘 ＋ 进账 ＋ 派工
                └─ 不成立 ⇒ 打回，附实读证据
   ↓
【用户】拍板（仅 A1）
```

### 4.1 派工前回路（2026-09-27 用户拍板）

```
用户／别处出「执行端的提示词」草稿
   ↓
【事务端】优化（格式 ＋ 边界节 ＋ 口径 ＋ 锚点）──► 转交 `GPT`
   ↓
【`GPT`】出决策（做不做 ／ 做到什么边界）
   ↓
【事务端】据决策出**正式**「给执行端的提示词」──► 发执行端
```

⚠️ **例外（⛔ 不重复回炉）**：若执行端任务的**内容已由既有裁定指定**（如 `D900 Q1`／`Q6`／`Q8`）⇒ 视为**已过决策**，事务端**可直接出正式提示词**。
⚠️ **本轮不要做的事**是必填节 —— 反例：2026-09-27 执行端（`Grok` 实例）因缺边界节而**自行扩张**（含 `git checkout --` 打在挂账文件上 ⇒ **违纪**，见 `L-99`）。

**关键**：事务端的证伪**不是可选步骤**。回路里"取证 → 证伪"缺一环，`GPT`的判断就直接进了账本。

## 五、红线

### `GPT`
1. ⚠️ **可写仓库文件**（2026-09-26 起 · 见 §六），但 ⛔ **每写必声明**：改动面须列**逐文件 ＋ `file:line` 级锚点**，交事务端核实后方可入提交。⛔ 不得"写完不说"；⛔ 不得绕过核实直接要求提交。
2. ⛔ 引用必须带 `file:line`；引原文须**整行**（已发生：引 `hh339_binding.log:87` 前半句、漏同句后半"断言执行 = 43"）。
3. ⛔ 说"缺失／未知"前须自证扫过那里（给扫描范围 ＋ 命中数）。
4. ⛔ 不替用户拍板（A1 归用户）。

### 事务端
1. ⛔ **不改变决策内容** —— 只执行 ＋ 证伪；有异议走回路打回，不私自改值。
2. ⛔ 不凭记忆／转述下结论；未直读不得回答"为什么"。
3. ⛔ 不碰**代码与资产**（`Assets/`／`.cs`／`.asset`／`.prefab`／`.unity`）；只读取证可以。
4. ⚠️ 改共享文件前必重读磁盘；单一写者。
5. ⛔ 强断言（"只有 N 处"／"清零"）须查别名后门 ＋ 机械扫描 ＋ 限定作用域 ＋ 附复现输出。

2026-09-25 首次全流程运转，事务端对`GPT`**证伪成立 3 次**：

⇒ 结论：**"出判断"与"证伪"分开之后，两端各自的质量都被逼上来了。** 这套分工保留。
