## 一、背景（用户三痛点+三担心）

1. **痛点①时间加速不够**：考跑 3x→10x 仍慢，用户要求「现实 1 秒=1 游戏小时」并评估保真上限
2. **痛点②测试被噪声截断/干扰**：P1 五考被玩家灭绝提前收口（D111）；实测多次出现地图生成的工人捣乱环节——测试需要「没有别的东西打扰」
3. **痛点③从零发展浪费**：想测王国补给/兵力就得等王国慢慢发展
4. **担心①** 测试环境搭不好；**担心②** API 没接全导致 AI 用不上对应能力；**担心③** 模块生命周期没接入测试环境（建-拆-建断链）

## 二、timeScale 评估结论（D549 裁决）

1. **换算**：D547 统一度量衡后 360s/天@1x；「1 现实秒=1 游戏小时」=24s/天=**timeScale 15——采纳为考跑档**（100 天≈40 分钟挂钟；对比 10x=60 分钟）
2. **保真性**：P1 判定口径全为**日级事件**（经济结算/生育/招工/建造/阶段推进，OnNewDay 链），timeScale 只压缩挂钟映射不改变日序——五考 10x 快进段（D109~111）已实证数据正常。风险层=帧驱动系统（位移步长/物理推挤/帧计数逻辑），15x 每帧游戏跨度≈0.25s（60fps），与 10x 同量级，可控
3. **上限=15，不再向上**：①`Time.maximumDeltaTime` 默认 0.33s 钳制——渲染掉帧时 deltaTime 被钳，**加速静默失效**（跑得越快越要保帧率）；②每帧游戏跨度 >0.3s 后位移穿透/物理失真陡增；③无先例数据。**更快的正解不是无限加速，而是 fixture 预设成熟王国跳过 40 天发展期（省 27%+ 时长）+无渲染减负**
4. **保真护栏（硬性）**：考跑模式联动设置 `Time.maximumDeltaTime`（≥1.0）+无渲染减负（关阴影/VSync/降分辨率——考跑不看表现）；**15x 首跑必须对照 10x 基线**跑行为探针（2_20B 六轮容器同 seed），假红即回退 10x 并列报，判定数据以探针全绿档位为准
