## 八、两处自查事故（如实列报）

### 事故① LF/CRLF 回滚事故

- **现象**：按铁律 6 执行 `git checkout --` 回滚后，`git status` 显示干净，**但 MD5 变为 `76908748130F0D7DD2A8BAA3B347FB79` ≠ 基准 `A5C0921…`**，训练仓与 Unity 侧**一度失配**。
- **根因**：本仓 `core.autocrlf=true` ⇒ `git checkout` 把无 BOM 的 LF 文件检出为 **CRLF**（499 处），Unity 侧仍为 LF。
- **处置**：手工将两文件转回 LF（`b.replace(b'\r\n', b'\n')`），随后**逐字节复核**：工作区 `== git show HEAD:<path>`（`identical=True`）、MD5 双端均 `A5C092119D7B108AACD184DD14493764`。
- **教训**：**本仓回滚/检出后必须复核行尾/哈希，不得只看 `git status` 干净**（`git status` 空不代表字节一致）。
- **定性**（依 TD-023）：＝**训练仓操作纪律**（`core.autocrlf` 工具链行为），**不入策划教训库**；单次自曝自纠。

### 事故② `@30` / `@100` 跨局数混比

- **现象**：核验初期用 `probe-k --card F26 @30` 读数与锚 **`@100`** 基准直接对比，**误报「churn↓」**（初判方向与最终相反）。
- **真相**：同局数 `@30` 对照实为**全升**（`KF26_2_0` 888→1175／`_1` 805→1179／`_2` 1019→1827）；**同口径 `benchmark @100`** 才验伪（`focusSwitches` 5217→5808 升）。
- **教训**：**待验收指标必须同口径（同局数/同 seed 集）对照，禁跨局数混比**；口径变更须并列新旧实测。
- **定性**（依 TD-023）：＝**`L-35` 同族实例**（读数口径与语义不匹配 ⇒ 漏报被掩盖），**已加注记、不新立条**（`_策划教训库.md` L-35 行末已含 STR-01 注记）。
