## 一、件1 移速现值实测（改前基线）

### 1.1 实测读数

| 项 | 实测 | 来源 |
|---|---|---|
| **实际净位移速** | **2.508 ~ 3.358 格/秒，中位 2.591 格/秒** | 正门 `EnterTestRun`（seed 21107／Medium／diff2／**1x**）· `timeScale=1` · 34 单位中 **28 个在移动** · 窗口 **3.21 s** · 世界位移经 iso 逆变换折算格数 |
| 运行时 `UnitController.WalkSpeed` | **3.000** | 28/28 单位一致 |
| 实盘 `UnitData.walkSpeed / runSpeed` | **3.000 / 6.000** | 同上（`Data.walk=3.000/run=6.000`） |
| 设计基准 | `MovementConfig.npcSpeed = 0.716` **世界单位/秒** | Tooltip：「按 iso 步长 0.716/格 重标＝**1 格/秒基准**」 |
| **偏差** | **≈ 2.5 ~ 4.2 倍**（净位移速 2.59；理论上限 4.19） | 见 1.2 |

**⚠️ 勘正 1（对任务书 §一③）**：任务书写「`UnitData.cs:79` **`walkSpeed = 5f`**／`:82` `runSpeed = 10f` ⇒ 5÷0.716≈**7 格/秒**」——
- `UnitData.cs:79/82` 的 5f／10f **确为代码默认值**（实读无误）；
- **但实盘资产覆盖为 `3.000 / 6.000`**（28 单位实测一致）⇒ 任务书以代码默认推算的「≈7 格/秒」**与实机不符**；实机为 **≈2.6 格/秒**。

### 1.2 换算式（实读，供策划端核口径）

- `UnitController.cs:1224`：`movement = GridDistClampDir(direction) * speed * Time.deltaTime`
- `UnitController.cs:1244`：`step = speed * Time.deltaTime` → `Vector2.MoveTowards`
- `GridDistClampDir`（`:1302-1308`）：把方向**除以 cellSize 后在格空间归一** ⇒ 沿单一格轴时世界步长 = 0.7155（√(0.64²+0.32²)）
- ⇒ `WalkSpeed 3.0` 的**理论上限 = 3.0 / 0.7155 ≈ 4.19 格/秒**；实测净位移 2.59 ⇒ 约 **62%**（差额＝路径拐弯 / 到达停顿 / 起步停止，属正常）

### 1.3 怪物是否同单位制（M2 答）

- `MonsterController.cs:192/213`：`npc.walkSpeed = def.speedCellsPerSec * cell`（`:193/214` `runSpeed = walkSpeed × 2`）
- `MonsterDef.cs:18`：`speedCellsPerSec` 注释逐字＝**「移速（格/秒）」**
- ⇒ **怪物源＝格/秒（显式 × cell 换算）**；**NPC 源＝世界单位/秒（无换算）** ⇒ **二者不同单位制**。
- 附带：`MonsterController.cs:183/204` 用 `ScriptableObject.CreateInstance<>` 建**运行时实例**写入，**不污染资产** ⇒ 改 NPC 侧**不会连带改坏怪物**。
- ⚠️ 唯一交叉点：`MovementConfig.npcSpeed` 现被 `PathFollower.cs:99/178`（**到达半径/重寻超时**）＋`UnitController.cs:1286`（到达半径）消费 ⇒ 若改 `npcSpeed` 的**数值语义**，会连带改**到达半径**（非速度）；采用 (b) 时须同核这三处。

### 1.4 两种修法（**报裁**）

| | (a) 数据侧重标 | (b) 代码侧接管（任务书推荐） |
|---|---|---|
| 落点 | `Resources/UnitData/` 下的 `walkSpeed`／`runSpeed` | `UnitController.cs:376` ＋`:510`（`WalkSpeed = data.walkSpeed;`）改为 `MovementConfig.npcSpeed × 倍率` |
| 改动量 | 实测 `Resources/UnitData/` **共 35 个 `.asset`**（18 `Human_Player_*` ＋ 3 Elf ＋ 3 Dwarf ＋ 3 Orc ＋ 8 塔/墙/门/机器）；**须逐个核对**，易漏 | **2 行**（倍率源＝`RaceDef.moveSpeedMul`，已被 `EffectiveSpeed` 单点消费） |
| 副作用 | 资产面多点漂移风险 | **全局手感一次性变更**（所有 NPC） |
| 死字段 | `npcSpeed` **仍为死字段**（须列报） | **激活 `npcSpeed`**（消费点由 3 → 4） |
| 与既有设计意图 | 与 `RaceDef.moveSpeedMul` 的「全局基准×种族倍率」Tooltip 不符 | **一致**（`RaceDef.cs:83-84`） |

**执行端建议＝(b)**，但**必须先由策划端定「目标格/秒」**：
> 现状实测 **≈2.6 格/秒**；若一步回到**1 格/秒基准**，将是**全局节奏 2.6 倍的降速**（影响所有 NPC 的赶路/换班/逃亡/追击手感），属**玩法级变更**，非纯缺陷修复 ⇒ **本批停手待裁**（红线：「件1 修法先报裁」）。
> 备选档位供参考：**目标 1.0 格/秒（严格按基准）** ／ **2.0 格/秒（折半，`npcSpeed ≈ 1.43`）** ／ **保持现状仅消「异常快」个案**。
