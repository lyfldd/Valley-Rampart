## M1 大脑提取双编译（照 03 施工）

任务：03 §六 迁移 6 步。
验收（三项全过）：
1. Unity 同剧本 60s 行为快照与迁移前一致（焦点/谱系序列）
2. `grep -r "UnityEngine" AI.Core/` 零命中
3. 控制台 smoke test：手喂 FactorContext → L1/L2/L3 输出与 Unity 同输入一致
风险：步 4（接口注入）是最容易引入行为偏差的——**先快照对比再合并**。

## M2 模拟器 v0（照 04 施工）

任务：SimWorld/SimGrid/SimDamage/SimClock + 适配器 + S1/S2 两剧本 + JSONL。
验收：S1 平原镜像战跑 100 局，胜率落在 45%-55%（不对称=有 bug）；S2 能产出弓手被贴身指标。
风险：伤害时间轮的 CD 取整与首次立即攻击最易漏——对照 DamageSystem.cs:121-137 逐行抄。

## M3 基准套件 + 确定性

任务：S1-S6 六剧本 JSON + 报告聚合器（report.json 生成）。
验收：
1. **确定性**：同 config 同 seed 跑两次，JSONL 逐字节 diff = 空
2. **区分度**：把 rfDistWeight 从 0.35 改成 0.20，总分必须有可感知变化（没变化=指标瞎了）
3. S2 弓手被贴身率指标与 Unity 手测同场景趋势一致（量级对即可，不求精确）

## M4 手动调参闭环（MVP 达成点）

任务：champion/candidate 目录机制 + 深合并 patch 应用 + 目标函数 v0。
验收：人手动改 1 个参数 → patch JSON → 跑分 → 看报告 → 决定留/弃，**全流程 <10 分钟**。
到这一步，"几天迭代一版"正式死亡。

### 已实现（2026-08-02）

- `SimChampion.cs`：champion 全量快照（tuning 全字段 + 职业库）导出/加载，全量替换语义（场景 Load 之前应用，patch 部分覆盖在之后）
- `SimVerdict.cs`：冠军裁决——总分 Δ（round 3 对齐 report 精度）+ 场景退化 >5% 红线 + 双条件 candidate/rejected
- `benchmark` 子命令（对齐 05 §四）：`dotnet run -- benchmark [--config champion/...] [--patch xxx.patch.json] [--battles N] [--out dir]` → report.json + verdict.json；无 baseline 时自动建档 `results/baseline/`
- `champion` 子命令：`champion export`（首次建档）/ `champion baseline`（重新建档）
- 验收实测：champion 加载 = 默认配置逐分一致（0.545）；rfdist20 patch Δ+0.001 无退化 → **candidate**；undeadfast patch S1 退化 -10% → **rejected + 退化标记**。单轮（6 剧本 × 100 局）秒级完成，远 <10 分钟

### M4 遗留（移交 M5/M6）

- M3 已知限制：S2 被贴身负面场景（需强 patch，如 attackRange）、S4 无撤退触发（场景调参）、S6 依赖 v1——均为"场景/指标完善"项，不阻塞调参闭环本身
- holdout（H1/H2）按 05 §七 在 verdict 阶段跑，M6 落地

## M5 DeepSeek 训练师（照 05 协议）

任务：factor_registry 全量化（01 §六 A 类全字段+边界）+ opencode 配置 + history.log 机制。
验收：
1. 训练师独立完成 3 轮提案（提案格式合法率 100%，harness 拒收率 <50%）
2. 至少 1 个提案进入 candidate
3. history.log 有复盘内容（不是空话，引用了 verdict 数据）

### 已实现（2026-08-02）

- `schemas/factor_registry.example.json` 全量化 v1.0：A 类 tuning 全字段（~70 项，按族分组）+ B 类职业字段（7 职业关键属性），每项带 min/max/语义/consumer；harness=false 标记模拟器不消费字段；deadParams/frozenParams 完整
- `SimProposalValidator.cs`：提案校验（≤3 改动 / path 注册 / 边界 / 死参数 / 冻结参数 / harness=false 拒收 / 滞回类 risk 声明 / rawFactor Σ 软提示），拒收率可测
- `propose` 子命令：`validate <p_x.json>` / `run <p_x.json>`（校验→patch 装配→benchmark 闭环）/ `list`（提案+history.log）
- `opencode.json`（DeepSeek 配置模板）+ `proposals/history.log`（复盘纪律已落盘）
- 验收实测：p_0001（l2FormationResistScale）rejected Δ=0（敏感性不足——真实教训）；p_0002（死参数）/p_0004（越界）拒收路径正确；p_0005（rfDistWeight 0.35→0.30）**candidate** Δ=+0.001 无退化（首个 candidate）。3 轮提案闭环 + history.log 复盘引用 verdict 数据全达成

### M5 遗留（移交运营/后续）
