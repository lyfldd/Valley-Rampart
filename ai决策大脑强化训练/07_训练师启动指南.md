## 一、环境就绪检查（30 秒）

```bash
# 1. opencode 已安装
opencode --version          # 需 ≥1.18（1.18.6 实测）

# 2. DeepSeek provider 可用（读全局配置 ~/.config/opencode/opencode.json）
cd "D:\Valley Rampart\ai决策大脑强化训练"
opencode models | findstr deepseek
# 应看到：deepseek/deepseek-chat、deepseek/deepseek-reasoner、deepseek/deepseek-v4-flash

# 3. 跑通一次最小对话（验证 key + 网络 + 配置）
opencode run "用一句话说你是谁"
```

**如果第 2 步看不到 deepseek/ 开头的模型**：
- 检查 `~/.config/opencode/opencode.json` 里是否有 `"deepseek"` provider（含 baseURL + apiKey）
- 项目 `ai决策大脑强化训练/opencode.json` **不要**写 provider / key——它只留 `model` 和 `instructions`，
  复用全局 provider（写 `{env:...}` 会覆盖全局导致起不来）
- `instructions` 必须是数组：`"instructions": ["AGENTS.md"]`（1.18.x 起字符串会报错）

**常见报错**：
| 现象 | 原因 | 修法 |
|------|------|------|
| `Configuration is invalid ... instructions` | instructions 写成了字符串 | 改 `["AGENTS.md"]` |
| `model ... not found` | 项目配置覆盖了全局 provider | 删掉项目里的 provider 块 |
| 401 / Unauthorized | key 失效或不在全局配置 | 更新 `~/.config/opencode/opencode.json` 的 apiKey |

## 三、和训练师说什么（话术模板）

> 它读 AGENTS.md 后按铁律干活：≤3 参数改动 / 必须引用证据 / 禁死参数 / 边界内 / 被拒要复盘。

### 1. 开局唤醒（第一次或换了环境）

```
读 AGENTS.md 了解你的职责，再读 harness/results/baseline/report.json 和 proposals/history.log。
列出你认为最差的 2 个场景及分数，说明各自的病根（因果链）。
```

### 2. 让它写提案

```
针对 S3 破阵频繁（subScore 0.384，winRate 0.000）写一份提案 proposals/p_0007.json：
≤3 个参数改动，每个改动引用 report.json 或 *.jsonl 里的真实数据作为证据，
参数必须在 factor_registry 边界内，risk 字段写预期副作用。
写完后用 dotnet run --project harness -- propose validate proposals/p_0007.json 自检，
如果被拒，读拒收原因修正后重试，直到通过。
```

### 3. 让它跑分验证（出 verdict）

```
用 propose run 跑你刚写的提案（dotnet run --project harness -- propose run proposals/p_0007.json --battles 100），
读 results/p_0007/verdict.json，告诉我：总分 Δ、三条件（总分升/无退化/holdout 不退）、最终裁决。
```

### 4. 让它复盘（被拒后 / 每轮结束）

```
你的提案 verdict 是什么结果？读 verdict.json 和 report.json，引用具体数字说明为什么成/败，
并把复盘写进 proposals/history.log（引用 verdict 数据，不许写"可能""也许"开头的空话）。
```

### 5. 方向引导（防止它瞎逛）

```
先别动 S1/S2（已达标），聚焦 S3 和 S5 这两个最低分场景。
探索职业参数（如弓手射程/移速）之前，先确认它们在套件上"推得动"（参考 history.log 里 p_0001 的教训）。
```

## 四、完整工作循环（人 + 训练师 + harness 三方）

```
[harness] champion baseline 建档（含 holdout）       dotnet run --project harness -- champion baseline
    ↓
[训练师] 读战报 → 写提案 p_xxxx.json                  opencode（对话，见 §三）
    ↓
[harness] 校验 + 跑分 + 裁决                        dotnet run --project harness -- propose run proposals/p_xxxx.json
    ↓
[训练师] 读 verdict → 复盘写 history.log              opencode（对话，见 §三）
    ↓
[人] candidate 累积 3-5 个 → 挑一个替换 champion     复制 champion 配置 or 手动调 champion/tuning.champion.json
    ↓（每 1-2 周）
[人] 回灌 Unity 手玩 10 分钟抽检                    最终裁判永远是手感
```

**权限边界**（AGENTS.md 铁律 6）：
- 训练师**能**：读 `harness/results/**`、写 `proposals/p_*.json`、写 `proposals/history.log`、跑 harness 命令
- 训练师**禁**：改任何 .cs、改 `Scenarios/`、改 `Holdout/`、改 `AGENTS.md`、改 `champion/`
- 替换 champion 永远归人

## 五、日常节奏建议

| 频率 | 动作 |
|------|------|
| 每天 | 让训练师跑 3-5 轮提案（读报告→提案→跑分→复盘），扫一眼 verdict 列表，批准/驳回 candidate |
| 每周 | 换一批基准 seed（防背题，改场景 JSON 的 seed）；回灌 champion 到 Unity 手玩抽检 |
| 平台期 | 提案连续 5 轮被拒 → 让训练师用 deepseek-reasoner 归因，或考虑改目标函数权重 |

## 六、成本参考（DeepSeek 官方价）

- 一轮提案 ≈ 输入 30K tokens + 输出 1K：deepseek-chat 约 ¥0.03/轮 → 一天 50 轮 ≈ ¥1.5
- 跑局算力全在本地，零 API 成本。瓶颈从来不是钱，是提案质量。
- 嫌贵可切 `deepseek-v4-flash`（更便宜更快，适合大量探索轮次），疑难归因再用 reasoner。
