# 02 可迭代性分级与 AI 修改边界

> 核心问题：因子、函数、结构分别怎么迭代？AI 训练师在每一级能做什么？
> 原则：**改动越大，验证越重**。T1 秒级验证 AI 全权；T2 编译+基准门禁人审；T3 人主导。

---

## 一、三级定义

| 级 | 对象 | 例子 | 修改方式 | 验证 | AI 权限 |
|----|------|------|---------|------|--------|
| **T1 数值参数** | config 字段 / 职业数值 / 硬编码常数 | rfDistWeight 0.35→0.3；编队抵抗 0.4→0.5；Undead courage 85→90 | 改 JSON 镜像，harness 注入 | 基准套件跑分（秒级） | ✅ 全权（边界内） |
| **T2 公式变体** | 计算函数的实现 | rawFactor 加权 → 加权+非线性惩罚项；撤退距离公式换型 | 写新 C# 变体，注册表切换 | 编译通过 + 基准门禁 + 人审 diff | ⚠️ 可提案，需人合并 |
| **T3 结构重构** | 管线本身 | L2 仲裁改三因子投票；新增第六综合因子 | 结对改代码 | 基准 + Unity 抽检双门禁 | ❌ 只出分析，不动手 |

## 二、T1：数值参数迭代（MVP 主力，覆盖 80% 手感问题）

### 2.1 机制：参数 JSON 镜像

```
Unity: AttentionTuningConfig.asset ──ToSnapshot()──┐
                                                    ├─→ 决策核只吃 TuningSnapshot（POCO）
harness: tuning.base.json ──反序列化───────────────┘
         + proposal.patch.json（提案只写差异字段，深合并覆盖）
```

- 决策核不直接依赖 SO（见 03 §三配置快照方案），Unity 与 harness 用**同一份快照结构**
- 训练师/黑盒只改 patch JSON，不动 C# → 编译零风险
- 职业数值同理：`professions/{name}.json` 镜像 NpcProfessionDef 字段

### 2.2 参数边界表（AI 必须遵守）

写在 `schemas/factor_registry.example.json`，每个参数带 `min/max`：
- 权重类：0~1（rawFactor 六权重另约束 Σ=1，提案必须归一化）
- 阈值类：语义区间（如 abandonThreshold 0.2~0.8；safetyRetreatGate 0.1~0.6）
- 时间类：0.1s~10s
- 勇气/服从：0~100；血量/攻击/防御：现值 ±50%
- **滞回类参数（breakThreshold/breakRelease/量化器阈值）改动 → 基准局数 ×2**（滞回参数影响路径依赖，方差大）

### 2.3 禁区

1. **死参数**（01 §八）：retreatBonusS/A/B/C、cautiousMinDwell、retreatMinDwell、safetyConfirmTime、threatUpgrade/DowngradeThreshold（单值版）、alertSpeedScale、lodCommandUpgradeLevel——调了无效果，纯浪费轮次
2. **结构性常数**：cellSize 2.26、think 分片 5、tick 0.1s——改了等于换游戏
3. **armorK**：伤害公式常数，影响全游戏数值平衡，首轮冻结不动

## 三、T2：公式变体（M6+，先把接口留好）

### 3.1 候选公式（按收益/风险排序）

| 优先级 | 公式 | 现实现 | 变体空间 |
|--------|------|--------|---------|
| 1 | CalculateRawFactor | 6 因子线性加权 | 非线性（距离平方衰减/贴脸指数）、因子交互项（数量×距离） |
| 2 | persistFactor（坚持任务） | 5 项线性加权 | 门限改软 sigmoid、收益侧加"敌方阵型完整度" |
| 3 | 破阵分 ComputeBreakScore | threatPressure/formationHold | 比值改差值、加 SafetyFactor 第三项 |
| 4 | RetreatFormulas 族 | 线性 courage 系数 | 分段函数（勇敢/懦弱两态） |
| 5 | EvaluateTaskValue | 硬编码 0.5/0.8/0.2+修正 | 连续函数、读更多上下文 |

### 3.2 变体机制（设计预留，M6 实施）

```csharp
public interface IThreatFormula { float Compute(in ThreatInputs i, TuningSnapshot cfg); }
// 注册表：harness 启动按 config 里 "formula.threat": "LinearV1" 选择实现
```

- 每个可换公式一个接口 + 默认实现（现公式原样搬入，作为 baseline 变体）
- 训练师写新变体 → 放 `harness/Formulas/` → 编译门禁 → 基准门禁（必须不劣于 baseline 才可人审）
- **T2 的守门原则：新变体必须带"为什么"**——提案里写明现公式在哪个场景失效（引用战报证据）

## 四、T3：结构重构（人主导）

- 例：新增综合因子、L2 仲裁改型、FormationBrain 意图枚举扩充
- 流程：人写设计 → 训练师可读代码出分析/风险清单 → 人实施 → 基准+Unity 双门禁
- **基准套件是结构重构的保险丝**：T3 前后同卷对比，行为退化立现

## 五、迭代节奏建议

| 阶段 | 手段 | 预期 |
|------|------|------|
| M4 手动期 | T1 人调 | 熟悉参数敏感度，标出"手感最差 Top3" |
| M5 AI 期 | T1 训练师提案 + 本地黑盒 | 分钟级收敛到局部优 |
| M6+ | T2 公式变体 | 突破 T1 天花板（公式形态限制） |
| 赛后 | T3 + RL 思想（3.0.1_7 修订版） | 研究性探索 |

## 六、回滚与存档（防 AI 改崩）

1. 每次提案运行独立存档：`results/{时间戳}_{提案id}/`（含 patch+报告+裁决）
2. 冠军配置单独维护：`champion/tuning.champion.json`——只有打败现任冠军才替换
3. Unity 回灌只从 champion 出——训练师的中间产物永远不进 Unity
4. git 管理 harness 与 configs，patch JSON 小文件天然可 diff
