## 二、职业全集（规范化集合表达）

> 用"集合 + 子集"消除歧义。**职业 = 装备**（装备已并入，不再单独存在"装备改变职业"）。

### 2.1 我方 NPC 职业全集

**上层身份**
- **君主（Ruler）**：玩家控制单位，出生城堡旁，修复后入主；阵亡 = GameOver。

**生活/生产类（可被招募 / 转职 / 指派）**
| 职业 | 定位 | 来源 | 攻击能力 | 日耗粮 |
|------|------|------|:--:|:--:|
| **流浪汉（Vagrant）** | 王国外的无业者 | 流浪汉营地 | 无 | 1（营地不耗国会粮） |
| **小孩（Child）** | 未成年的王国成员 | 繁殖 | 无 | 1 |
| **居民（Resident）** | 王国内无职业成人（原 `Unemployed`） | 流浪汉成年 / 小孩长大 | 无 | 1 |
| **工人（Worker）** | 通用生产（训练所训练） | 居民转职 | 无 | 1 |

> 居民/工人/小孩/流浪汉 **均无攻击能力**（普通居民不平攻）。只有军事职业有攻击。

**军事类（训练获得，装备已并入训练）**

- 卫戍营：**骑兵**

| 职业 | 属主建筑 | 日耗粮 |
|------|---------|:--:|
| 战士 / 弓手 / 弩手 / 重装战士 | 练兵场 | 2 |
| 法师 / 治疗师 | 练兵场 Lv2 | 2 |
| 盾卫 / 大法师 / 主教 | 练兵场 Lv2 | 3 |

| 将军 | 卫戍营 | 3 |

**非 NPC（机器 / 工事，不参与饱食/幸福/点击交互）**
- 投掷机 / 弩炮 / 箭塔 / 弩塔 / 魔法塔 / 城墙 / 城门 / 拒马。

### 2.2 职业集合层级与关系

```
人口全集
├─ 王国领域内（NPC 实体）
│   ├─ 君主（Ruler）
│   ├─ 生活/生产：流浪汉* / 小孩 / 居民 / 工人
│   └─ 军事：将军 / 战士/弓手/法师/治疗师 / 重装/盾卫/弩手/大法师/主教 / 骑兵
└─ 王国领域外（等待招募）
    └─ 流浪汉（营地）
        * 流浪汉被招募后进入王国领域变居民
```

- **流浪汉** 是"王国领域外"的算子集，招募后并入"王国领域内" → 变 `居民`。
- **居民** 是"王国无职业成人"的原子集，是转职的**公共源**（工人/士兵都从居民来）。
- **小孩** 是"未成年居民"，是繁殖的直接产物，非转职源。
- **军事职业** 是"战斗能力子集"，生活职业无攻击能力。

## 三、人口实体化（核心改造）

### 3.1 本质
人口从 `PopulationSystem.PopulationCount`（一个 int 计数）改为**维护 NPC 实体列表**。每个实体 = 一个地图上的 `UnitController` 实例，拥有独立的位置 / 饱食 / 幸福 / 职业 / 任务，可被点击交互。

> 现状：`PopulationSystem` 只存 `PopulationCount`、`BirthCooldownDays`、`AvgSatiety`、`AvgHappiness`（[PopulationSystem.cs](file:///d:/Valley%20Rampart/Valley%20Rampart/Assets/_Game/Systems/Kingdom/PopulationSystem.cs)）。饱食/幸福已挂在每个 `UnitController` 个体（游 `UnitRegistry`，见 [SatietySystem.cs](file:///d:/Valley%20Rampart/Valley%20Rampart/Assets/_Game/Systems/Kingdom/SatietySystem.cs) / [HappinessSystem.cs](file:///d:/Valley%20Rampart/Valley%20Rampart/Assets/_Game/Systems/Kingdom/HappinessSystem.cs)）。**缺的是"人口 = 实体"这一层**。

### 3.2 改造点
- `PopulationSystem` 增加/维护**实体注册表**（引用王国领域内 NPC 实体，含居民/小孩/工人/军事，不含机器工事）。
  - `PopulationCount` 改为 `实体注册表.Count`（派生值，不再独立维护）。
  - 生育 / 出生 / 长大 / 招募 / 转职 / 死亡 都通过注册表增删实体，保持计数与实体一致。
- 存档：`PopulationSaveData` 从"计数 + 冷却"升级为 **实体快照列表**（复用 `UnitSaveData v2`，含职业/饱食/幸福/坐标/成长倒计时/流浪汉招募来源标记）。
- 单位存档字段（`UnitSaveData v2`）需补：`satiety / happiness / childGrowthDays / isVagrantRecruit`，见 3.5 实施计划 §2.3（原字段已预留，本次落地）。

## 四、NPC 生命周期

### 4.1 外部入口：流浪汉 → 居民（招募）

**子场景清单**
1. 地图生成：开局随机生成流浪汉营地（4 格占位）2-3 个。
2. 营地位置规则：近王国区块**必须至少 1 个**；其余在更远区块；**禁落王国核心区块**。
3. 营地刷新：单营地上限 3 流浪汉，初始 2，不满时**每日补 2**，刷满停。
4. 玩家点击流浪汉 → 触发**招募交互**（花 1 粮）→ 流浪汉**立即变 `居民`**（职业翻转）→ **AI 大脑自动走回王国** → 抵达王国正式纳入人口。
5. 走回途中已是居民身份（职业已变），但仍在王国领域外（未正式计入王国人口）；途中遇敌有风险。

**覆盖组合**
- 营地数量：2 / 3 个。
- 营地距离：近区块 / 远区块。
- 营地状态：初始（2）/ 不满（补员中）/ 满（3，停补）。
- 招募途中：安全到达 / 途中遇敌。

**关键因子（SO 配置）**：营地数量、营地占位格数、单营地上限、初始流浪汉数、每日补员数、招募粮耗、走回速度。

**验收（目标参考）**：开局 2-3 营地在合法区块；营地刷满停补、不满逐日补员；点击招募扣 1 粮、流浪汉立即变居民、AI 自动走回王国、抵达纳入人口（王国人口 +1）。

### 4.2 内部入口：繁殖 → 小孩 → 居民

**子场景清单**
1. 生育条件（沿用 3.5）：整体幸福 > 60 且 平均饱食 > 50，每 2 人每 5 天。
2. **生小孩表演**：两居民（一男一女概念，无性别仅配对）进入一栋房屋 → 表演 → 出来两人 + 一小孩。
3. 小孩实体：只吃粮（1/日）不干活，无攻击。
4. **成长**：**天数事件累积 2 次后**自动长成 `居民`（非精确时刻）。
5. 房屋容量：小孩占用房屋容量（纳入"有房住"判定）。

**覆盖组合**
- 生育条件：满足 / 不满足（幸福不足 / 饱食不足）。
- 房屋：有房 / 无房（无房可否生育？→ 默认需有房，见 §5 幸福）。
- 成长到点：2 次天数事件后。
- 人口惩罚（幸福低 → 增长因子 < 100% → 概率折算）。

**关键因子（SO）**：生育条件阈值、生育间隔、小孩成长天数事件数、小孩日耗粮、房屋容量。

**验收**：满足条件 → 进房表演 → 人口 +1 小孩；2 次天数事件后小孩变居民；不满足条件不生育。

### 4.3 转职：居民 → 职业（训练，装备已并入）

**子场景清单**
1. 居民 → **工人**：训练所训练（耗金+时间），表演 = 居民走过去几秒变工人。
2. 居民 → **士兵**：练兵场训练（战士/弓手；Lv2 法师/治疗师 + 重装/盾卫/弩手/大法师/主教）；卫戍营（将军/骑兵）。
3. **装备已并入训练**：训练完成即完整职业能力，**无需再单独装备**；训练成本内已含原装备成本（适当降低，不直接相加）。
4. 训练建筑：训练所（工人）/ 练兵场（士兵）/ 卫戍营（将军、骑兵）。

**覆盖组合**
- 转职源：居民 / 工人在职转职（士兵）。
- 训练建筑等级：Lv1 / Lv2。
- 训练成本：金 / 水晶（魔法职业）/ 时间。
- 训练中：排队 / 训练中 / 完成变职业。

**关键因子（SO）**：各职业训练消耗与时长、训练建筑等级门槛、训练上限（如将军 2）。

**验收**：居民在对应训练建筑训练 → 完成即获职业能力（弓箭手可直接射箭）；训练成本含装备成本且降低；非生活职业有攻击能力，生活职业无。

## 六、统一点击交互系统（含优先级子系统）

### 6.1 本质
**一个通用的 NPC 点击交互系统**，预留接口，所有可交互 NPC 复用。点击任意 NPC 弹出**交互语言**（头顶语句），并按**优先级**决定当前最先响应的交互事件。

### 6.2 接口设计（预留，可扩展）
```csharp
public interface IClickInteractable
{
    // 注册的交互行为列表（对话/招募/训练...）
    InteractAction[] GetInteractActions();
}

public class InteractAction
{
    public string actionId;      // 交互标识（如 "recruit" / "talk"）
    public int priority;         // 优先级（数字越大越先响应）
    public bool oneShot;         // 是否一次性（执行后失效/降级）
    public bool CanTrigger();    // 当前是否可触发（如招募=有粮且未招募）
    public void Execute();       // 触发表现（头顶语句 + 实际效果）
}
```

### 6.3 优先级子系统（关键）
- 点击一个 NPC 时，系统收集它所有**可触发**（`CanTrigger=true`）的交互，按 `priority` 从高到低，取第一个执行。
- **示例（流浪汉）**：可触发 `招募（priority 100，oneShot）` 与 `对话（priority 10）`。点击 → 优先执行**招募**（一次性）；招募完成后该交互失效/降级，下次点击回落为**对话**。
- 其他 NPC 复用同一优先级系统：想让某 NPC 最先响应哪个交互，就给它配对应 `priority`。

### 6.4 各 NPC 交互清单（默认）
| NPC | 可触发交互 | 说明 |
|-----|-----------|------|
| 流浪汉 | 招募（高，一次性）、对话 | 招募 = 花 1 粮，**立即变居民**，AI 自动走回王国 |
| 小孩 | 对话（成长状态） | 无操作 |
| 居民 | 训练（打开训练菜单）、对话 | 转职入口 |
| 工人 | 对话（当前任务） | 无操作 |
| 士兵（战士/弓手/等） | 对话 | 编队操作走 E 键军令面板，不塞进点击 |
| 将军 | 对话 | 编队指挥走 E 键面板（点击不塞指挥逻辑） |
| 君主 | 对话（特殊） | 玩家控制单位 |

> 原则：**点击交互只做"轻量表现 + 高频一次性操作"**（招募/训练/对话），复杂操作（编队指挥/贸易/研究）走已有面板（E 键 / 建筑面板），避免点击交互过重。装备已并入职业，点击无装备操作。

### 6.5 覆盖组合
- 交互数量：单交互 / 多交互并存。
- 一次性：是一次性 / 永久。
- 可触发：满足条件 / 不满足（如无粮不能招募）。
- 优先级：冲突时按 priority 裁决。

### 6.6 验收
点击流浪汉 → 优先出招募（有粮）；无粮 → 出对话；招募后 → 对话。点击居民 → 训练菜单。点击士兵 → 对话（不弹编队）。接口可被新 NPC 复用。

## 七、君主出生与入主（解决历史遗留）

### 7.1 现状
君主出生在废弃城堡左侧 1 格（`RulerController.ResolveSpawnPosition`，已实现）。历史遗留：君主与废弃城堡的关系一直没定死。

### 7.2 定案（两阶段）
1. **出生阶段**：君主出生在废弃城堡旁（左侧，现状保留）。
2. **入主阶段**：玩家移动君主到废弃城堡 → 触发**修复**（耗 木10/石6/粮6/金2，复用 3.3 建筑状态机）→ 修复完成主城 Lv1 → 君主**入主城堡驻留** = 王国核心。
3. 君主死亡 = 主城被破 = 单一失败条件（沿用 3.5 §13.1 决策 3）。

### 7.3 关键因子（SO）
出生偏移、修复消耗、入主判定（君主到达 + 城堡可修复）。

### 7.4 验收
开局君主在城堡旁 → 移君主到城堡 → 点修复 → 完成 → 君主入主，主城 Lv1 生效。

## 八、接入 3.5 王国体系（系统间联系）

### 8.1 依赖（地基）
- 3.5 模块/建筑解锁（训练所/练兵场/卫戍营）→ 本档职业转职链。
- 3.5 饱食/幸福/税收/贸易 → 消费每个 NPC 实体的饱食/幸福。
- 3.0.1 AI（工人/士兵/将军/编队）→ 驱动 NPC 行为。
- 3.3.5 资源流转搬运 → 工人搬运（并入通用工人，见 3.5.2）。
- 3.2 地图生成 → 流浪汉营地生成（位置/数量）。

### 8.2 共享能力
- **日耗粮**：`KingdomConfig.GetDailyFoodByOccupation`（饱食 + 人口 + 幸福共用）。
- **生育/成长判定**：`PopulationSystem`（幸福/饱食输入 + 成长计数）。
- **NPC 实体注册**：`UnitRegistry`（饱食/幸福/人口/交互共用同一实体集合）。

### 8.3 能力叠加
- 招募流浪汉 → 王国人口 +1 → 税收/幸福/生育条件联动。
- 生小孩 → 人口 +1 → 房屋容量/粮食压力。
- 转职工人 → 生产产能 → 更多粮 → 支撑更多人口。
