# 🎯 地图生成约束规则与玩法保障

> 2026-07-28 主理人游承峰汇编
> 是 `3.2_区块与地图生成系统设计.md` 的**玩法约束补丁**——解决"生成出来的地图能不能玩"的问题。
> 参考思路：`程序化城市生成算法文档.md`（三层约束 + 邻接矩阵 + 中心辐射布局 + 数量下限）。

---

## 📝 设计动机：3.2 文档缺了什么

`3.2` 把区块的**数据结构**（Region/Cell/Layer）和**生成 pipeline**（seed → 三层约束 → MapData）写好了，但有一个空白：

> **生成出来的地图，怎么保证"能玩"？**

具体表现为阿铁提的几个痛点：

| 痛点 | 后果 |
|------|------|
| 没有玩法约束 → 四资源可能缺一种 | 玩家开局没有矿洞 = 没石头 = 防线建不起来 |
| 废弃城堡位置随机 → 可能落在雪山/荒地 | 废弃城堡建在极端地形 = 出门即死 |
| 出门可能是极端地形 | 一出门就踩雪山/荒地 = 体验割裂 |
| 资源点地形可能离废弃城堡太远 | 走半张图才到林地 = 经营节奏崩 |
| 地形过渡无约束 → 雪山紧贴平原 | 视觉突兀 + 不合理 |

**本补丁的定位**：在 `3.2` 的三层约束（大地形→小地形→资源点）之上，加一层**玩法约束层**，用一套确定性规则保证每张生成的地图都"能玩、好玩、过渡自然"。

---

## 一、核心原则：玩法约束优先于地形随机

```
随机性负责"每局不一样"
约束性负责"每局都能玩"

约束 > 随机 —— 当两者冲突时，约束赢。
```

地图生成的**第一目标**不是"多样/好看"，而是"能玩"：
1. 四资源都有来源（硬约束，不可违反）
2. 废弃城堡有开阔平原（硬约束）
3. 出门不踩极端地形（硬约束）
4. 资源点在合理距离内（软约束，尽量满足）
5. 地形过渡自然（软约束，邻接矩阵约束）

## 二、5 区结构（中心辐射型布局）

### 2.1 借鉴与适配

参考城市生成文档的「中心辐射型」城市风格——商业区在中心，住宅环抱，工业郊区在外圈。河谷防线是 **1D 横向卷轴**，适配为 **5 段式横向布局**：

```
[左极端区] [左资源区] [中心区] [右资源区] [右极端区]
   出怪口     资源点   废弃城堡    资源点     出怪口
```

这是整个约束规则的**骨架**——所有地形分配、资源放置、出怪口位置都围绕这个骨架展开。

### 2.2 分区数量公式

大区块总数 M 由 `worldSize` 决定（Small=10 / Medium=15 / Large=24，见 3.2 的 MapSizeConfig）。5 区分配公式：

```
中心区 center = round_to_even(M × 0.3), 至少 2
剩余 remaining = M - center
极端区 extreme_sym = round(remaining / 4), 至少 1
资源区 resource = (remaining - 2×extreme_sym) / 2
  若 resource 非整数 → 左右极端不对称 (自动取整分配)
```

> **中心区 30%**（四舍五入取偶数）。限制中心区内容：只放平原 + 最多 1 个肥沃，**不放林地/矿山**。城墙围住中心区只能保护废弃城堡+1 农田，林地和矿山在资源区城墙外。

**验证表**：

| M | 左极端 | 左资源 | 中心 | 右资源 | 右极端 | 合计 |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| 10 (Small) | 1 | 2 | 4 | 2 | 1 | 10 |
| 15 (Medium) | 2 | 4 | 4 | 4 | 1 | 15 |
| 24 (Large) | 4 | 4 | 8 | 4 | 4 | 24 |

> M=15 时中心=round_even(4.5)=4，极端左 2 右 1（剩余奇数时自动不对称，确保资源区整数）。中心区强制为偶数，保证废弃城堡左右对称。极端区至少 1（必须有出怪口）。

### 2.3 区索引映射

给定 M 和 5 区分配，大区块索引到区的映射：

```csharp
// 输入：regionIndex (0..M-1)，输出：该大区块属于哪个区
MapZone GetZone(int idx, int M, int center, int extreme, int resource)
{
    int leftExtremeEnd = extreme;                    // [0, extreme)
    int leftResourceEnd = extreme + resource;        // [extreme, extreme+resource)
    int centerEnd = extreme + resource + center;     // [..., +center)

    if (idx < leftExtremeEnd) return MapZone.LeftExtreme;
    if (idx < leftResourceEnd) return MapZone.LeftResource;
    if (idx < centerEnd) return MapZone.Center;
    if (idx < centerEnd + resource) return MapZone.RightResource;
    return MapZone.RightExtreme;
}

public enum MapZone { LeftExtreme, LeftResource, Center, RightResource, RightExtreme }
```

### 2.4 废弃城堡位置（硬约束）

废弃城堡固定在**中心区的正中间 1 个大区块**（占 2 个小区格）：

```csharp
// 废弃城堡所在的大区块索引（1 个，正中心）
(int, int) GetCastleRegionIndices(int M, int center, int extreme, int resource)
{
    int centerStart = extreme + resource;
    int midOffset = center / 2;  // 中心区中点
    return (centerStart + midOffset - 1, centerStart + midOffset);
}
// 取 castleB 作为废弃城堡位置
// M=10 → castleB=5；M=15 → castleB=8；M=24 → castleB=13
```

废弃城堡所在大区块**强制为平原**（普通子状态），且为建造开阔地（不放资源点）。城堡占该大区块中间的 2 个小区格（`cellWidth = 2`）。

## 三、各区地形规则

### 3.1 区 → 允许地形映射

| 区 | 允许地形 | 禁止地形 | 用途 |
|----|---------|---------|------|
| **中心区** | 平原(普通/肥沃) | 矿山/雪山/荒地/林地/海岸 | 废弃城堡 + 建造开阔地（城墙核心区） |
| **资源区** | 林地/矿山/丘陵/平原(普通/肥沃) | 雪山/荒地/海岸 | 四资源产出（风险分层区） |
| **极端区** | **岛屿**：海岸/丘陵(仅内侧缓冲) | 平原/林地/矿山 | 出怪口(敌军登陆) + 造船厂位 |
| | **内陆**：雪山/荒地/丘陵(仅内侧缓冲) | 平原/林地/矿山 | 出怪口 + 大山屏障 |

> **平原拆两态**：平原是一级地形，子状态分「普通」(建造位) 和「肥沃」(农田位)。肥沃不再独立，降为平原子状态。荒地保持独立（它是荒芜战场，不是可建造平地）。
>
> **海岸（Coast）**——岛屿两端水陆交界，出怪口+造船厂位。**雪山仅内陆**（大山屏障）。丘陵仍是「万能缓冲」。

### 3.2 中心区地形分配（平原不能太大）

中心区全部为平原，但**平原不能太大**——否则玩家城墙能围住所有资源点，失去风险博弈（见第六点五节「资源点风险分层」）。

**约束**：
1. 中心区占比 **30%**（公式见 2.2）
2. 中心区内**最多 1 个肥沃**（粮来源，可被城墙保护 = 低风险资源）
3. 林地/矿山**不在中心区**——它们必须留在资源区（城墙外 = 有风险）

中心区地形分配：

```
中心区（M=10，4 个大区块 #3#4#5#6）：
  #3 = 平原（建造开阔地）
  #4 = 平原（建造开阔地）
  #5 = 平原（废弃城堡）       ← 强制平原，城堡占中间 2 格
  #6 = 平原 或 肥沃（靠资源区侧，最多1个肥沃）  ← seed 随机
```

> **为什么平原不能太大**：城墙是玩家建造的建筑，围起来形成保护圈。如果中心区占 35%+，城墙轻松围住废弃城堡+农田+林地甚至矿山 → 所有资源零风险 → 失去防御博弈乐趣。降到 30% 且矿山不在中心区，保证城墙默认只能围住废弃城堡+1 个农田，林地和矿山在城墙外有被袭击风险。

### 3.3 资源区地形分配（核心随机区 + 风险分层）

资源区是地形随机性的**主要承载区**，也是**资源风险分层的落地区**。分配规则：

1. **左右资源区各自独立**，用 `seed` 确定性随机
2. 每个资源区大区块从 `[林地, 矿山, 丘陵, 肥沃, 平原]` 中随机选
3. **资源保障校验**（见第四节）：全地图必须满足 林地≥1 + 矿山或丘陵≥1 + 肥沃≥1
4. 与中心区接壤的资源区大区块，地形必须能和平原/肥沃邻接（见邻接矩阵）
5. **风险分层约束**（关键）：
   - **内侧**（靠近中心区）：倾向林地/肥沃 → 中低风险资源（相对安全，城墙边缘可达）
   - **外侧**（靠近极端区）：倾向矿山/丘陵 → 高风险资源（城墙外，靠近出怪口）
   - 矿山**优先放外侧**，距废弃城堡 2~3 个大区块（有防御纵深但城墙围不到）

```
资源区（M=10，每侧 2 个大区块）：
  左资源区: #2(内侧→林地/肥沃)  #1(外侧→矿山/丘陵)
  右资源区: #7(内侧→林地/肥沃)  #8(外侧→矿山/丘陵)

  内侧 = 靠中心区 = 相对安全    外侧 = 靠极端区 = 高风险
```

### 3.4 极端区地形分配（按大地形区分）

极端区地形**由大地形决定**，不随机：

| 大地形 | 极端区地形 | 出怪口 | 说明 |
|--------|----------|:---:|------|
| **岛屿** | **海岸**（两端） | 两端海岸滩头 | 敌军从海上登陆；海岸也是造船厂建造位（跨岛远征） |
| **内陆** | **雪山**（大山屏障侧）+ **荒地**（出怪侧） | 荒地侧单端 | 一侧是大山屏障（无怪），一侧是荒地出怪 |
| **无限岛屿** | **海岸**（两端） | 两端海岸滩头 | 通关后固定岛屿，难度递增 |

**岛屿极端区**：
```
[海岸#0] [资源区...] [平原废弃城堡] [资源区...] [海岸#9]
  ↑出怪口                                        ↑出怪口
  敌军登陆                                  敌军登陆/造船厂
```
- 两端大区块**强制海岸**（不随机）
- 海岸不放资源点（纯战场 + 造船厂位）
- 裂隙（出怪点）放在海岸大区块的最外端小区块

**内陆极端区**：
```
[雪山#0] [资源区...] [平原废弃城堡] [资源区...] [荒地#9]
  ↑大山屏障                                      ↑出怪口
  无裂隙(不出怪)                            敌军从荒地方向来
```
- 左端（大山屏障侧）**强制雪山**，无裂隙（不出怪）
- 右端（出怪侧）**强制荒地**，有裂隙（出怪）
- 雪山不放资源点（纯屏障），荒地不放资源点（纯战场）
- 难度更低（单向防御），适合新手

## 四、四资源保障（硬约束）

### 4.1 保障规则

每张**玩家初始地图**必须满足以下资源完整性：

| 资源 | 依赖地形/建筑 | 最低保障 | 来源区 |
|------|-------------|:---:|------|
| **木** | 林地大区块 ≥ 1（伐木场依赖树资源点） | 1 个林地 | 左/右资源区 |
| **石** | 矿山大区块 ≥ 1（矿洞开口） | 1 个矿山 | 左/右资源区 |
| **粮** | 平原 always 有农田（基础产出），肥沃 = 高级产出 buff | 中心区平原自动满足 | 中心区（平原自带） |
| **金** | 无地形依赖（市场/码头/税收建筑产出） | — | 任意建造位 |

> 金币不依赖地形——通过建筑（市场/码头贸易/税收）产出，建在平原或肥沃即可。这样避免给地图生成加第五种地形约束。

### 4.2 资源完整性校验与修复

生成完大区块地形后，做一次校验。不满足则**强制替换**（确定性，用 seed 决定替换哪个）：

```csharp
// 校验 + 修复（在 GenerateMap 内，地形分配后调用）
void EnsureResourceCoverage(System.Random rng, List<Region> regions, int M, int castleA, int castleB)
{
    bool hasForest = regions.Any(r => r.terrain == TerrainType.Forest);
    bool hasQuarry = regions.Any(r => r.terrain == TerrainType.Quarry);  // 石来源仅靠矿山
    // 粮 auto-satisfied：中心区 always 平原，平原 always 有农田
    // 肥沃 = 高级产出 buff，尽量保障但不强制
    bool hasFertile = regions.Any(r => r.terrain == TerrainType.Plain && r.plainSubState == PlainSubState.Fertile);

    // 缺木 → 在资源区随机选一个大区块替换为林地
    if (!hasForest) ForceReplace(rng, regions, M, castleA, castleB,
        new[] { MapZone.LeftResource, MapZone.RightResource }, TerrainType.Forest);
    // 缺石 → 替换为矿山（丘陵不再提供持续性石来源）
    if (!hasQuarry) ForceReplace(rng, regions, M, castleA, castleB,
        new[] { MapZone.LeftResource, MapZone.RightResource }, TerrainType.Quarry);
    // 缺肥沃 buff → 在中心区边缘替换一个平原为肥沃（非强制，仅优化）
    if (!hasFertile) ForceReplace(rng, regions, M, castleA, castleB,
        new[] { MapZone.Center }, TerrainType.Plain,
        forceSubState: PlainSubState.Fertile);
}

// ForceReplace：在指定区内，用 rng 随机选一个大区块，替换地形（不破坏废弃城堡）
void ForceReplace(System.Random rng, List<Region> regions, int M,
                 int castleA, int castleB, MapZone[] zoneMask, TerrainType target,
                 PlainSubState forceSubState = PlainSubState.Normal)
{
    var candidates = regions.Where(r =>
        zoneMask.Contains(r.zone) &&
        r.regionIndex != castleA && r.regionIndex != castleB  // 不动废弃城堡
    ).ToList();
    if (candidates.Count == 0) return;
    int pick = rng.Next(candidates.Count);
    candidates[pick].terrain = target;
    if (target == TerrainType.Plain)
        candidates[pick].plainSubState = forceSubState;
}
```

## 五、地形邻接约束矩阵

### 5.1 借鉴与设计

参考城市生成文档的邻接约束（商↔商✅ 商↔工❌），为 7 种小地形设计**左右邻接规则**（平原拆两态后肥沃不再独立，合并为平原）。

核心逻辑：
- **平原**是「宜居地形」——不能直接接极端地形（雪山/荒地/矿山），子状态（普通/肥沃）不影响邻接
- **海岸**是「水陆过渡」——可接所有宜居地形 + 荒地，是岛屿极端区的固定地形
- **丘陵**是「万能缓冲」——能接所有地形，是极端与宜居之间的过渡带
- **林地**半宜居——可接平原/丘陵，勉强接矿山（资源区内部允许）
- **矿山/荒地/雪山**是「极端地形」——互相可邻接，但不能直接接宜居地形
- **雪山↔海岸** = ❌（雪山只在内陆，海岸只在岛屿，不会共存）

### 5.2 邻接矩阵

| 左\右 | 海岸 | 平原 | 林地 | 丘陵 | 矿山 | 荒地 | 雪山 |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| **海岸** | ❌ | ✅ | ✅ | ✅ | △ | ✅ | ❌ |
| **平原** | ✅ | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ |
| **林地** | ✅ | ✅ | ✅ | ✅ | △ | ❌ | ❌ |
| **丘陵** | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| **矿山** | △ | ❌ | △ | ✅ | ✅ | ✅ | ✅ |
| **荒地** | ✅ | ❌ | ❌ | ✅ | ✅ | ✅ | ✅ |
| **雪山** | ❌ | ❌ | ❌ | ✅ | ✅ | ✅ | ✅ |

- ✅ = 可直接邻接
- ❌ = 禁止（需缓冲地形隔开）
- △ = 勉强（仅资源区内部允许，不作为区与区的交界）
- 海岸↔海岸 = ❌（海岸只出现在地图两端，不会自邻接）
- 平原的子状态（普通/肥沃）不影响邻接规则——邻接在一级地形层面约束

### 5.3 5 区结构天然满足邻接约束

**岛屿地图**（两端海岸）：
```
极端区      资源区        中心区       资源区      极端区
[海岸] → [丘陵缓冲] → [林地/肥沃] → [平原] → [平原] → [肥沃/林地] → [丘陵缓冲] → [海岸]
  ✅海岸接丘陵  ✅丘陵接林地  ✅林地接平原  ✅平原接平原  ✅平原接肥沃  ✅肥沃接丘陵  ✅丘陵接海岸
```

**内陆地图**（一端雪山一端荒地）：
```
极端区      资源区        中心区       资源区      极端区
[雪山] → [丘陵缓冲] → [林地/肥沃] → [平原] → [平原] → [肥沃/林地] → [丘陵缓冲] → [荒地]
  ✅雪山接丘陵  ✅丘陵接林地  ✅林地接平原  ✅平原接平原  ✅平原接肥沃  ✅肥沃接丘陵  ✅丘陵接荒地
```

5 区结构中，**极端区与资源区交界处**强制放丘陵做缓冲（海岸/雪山/荒地 都能接丘陵），**资源区与中心区交界处**用能和平原邻接的地形（林地/肥沃/平原）。这样邻接约束在区层面就天然满足，只需在**区内**做局部校验。

### 5.4 邻接校验与缓冲插入

生成完地形后，做一次邻接校验。相邻大区块地形若违反邻接规则，**在违规交界处强制插入丘陵**（替换其中一个）：

```csharp
// 邻接校验：扫描相邻大区块对，违规则修复
void EnforceAdjacency(List<Region> regions, int M, int castleA, int castleB)
{
    for (int i = 0; i < regions.Count - 1; i++)
    {
        var a = regions[i].terrain;
        var b = regions[i + 1].terrain;
        if (!_rulesConfig.CanAdjacency(a, b))
        {
            // 违规：把非废弃城堡、非出怪口端的那一侧改成丘陵做缓冲
            // 优先改 i+1（靠中心侧），除非 i+1 是废弃城堡
            int fixIdx = (i + 1 == castleA || i + 1 == castleB) ? i : i + 1;
            // 出怪口端(0 或 M-1)不改
            if (fixIdx == 0 || fixIdx == M - 1)
                fixIdx = (fixIdx == i) ? i + 1 : i;
            regions[fixIdx].terrain = TerrainType.Hills;
        }
    }
}

bool CanAdjacency(TerrainType a, TerrainType b)
{
    // 查 AdjacencyMatrix（5.2 矩阵），△ 在区交界算违规，区内算合法
    // 简化：这里用严格模式（△ 算违规），区交界处靠 5 区结构天然避免
    return AdjacencyMatrix[(int)a, (int)b] == AdjacencyRule.Allowed;
}
```

## 六、二级约束：区块内部资源点生成

### 6.1 两级约束体系

地图生成分两级约束，**一级定骨架，二级填内容**：

```
一级约束（大区块级）← 第二~五节
  ├─ 决定大区块地形（平原/林地/丘陵/矿山/荒地/雪山/海岸）
  ├─ 平原子状态（普通/肥沃）
  ├─ 5区结构 + 废弃城堡位置 + 资源保障 + 邻接约束
  └─ 输出：每个大区块的 TerrainType + PlainSubState

二级约束（小区块级）← 本节
  ├─ 资源点类型 ← 一级地形决定
  ├─ 资源点数量/密度 ← 难度因子 × 位置 × seed
  ├─ 资源点等级（贫瘠/普通/富有）← 难度 + 位置(风险分层) + seed
  └─ 资源点位置 ← 避开两端 + 确定性随机
```

### 6.2 资源点类型映射（Building 体系统一）

**统一为 Building 体系**：所有资源点（持续性/一次性）、特殊点、裂隙、废弃城堡、玩家建造——全部是 Building 子类。`ResourceNode` 类废弃，资源点生成即创建 Building 占位。

Building 分类：

| 类别 | Building 子类 | 占格 | 产出/行为 | 说明 |
|------|-------------|:---:|------|------|
| **持续性资源** | `ResourceProducer` | 1 | 持续产出 | 树(伐木场)/矿洞/农田 |
| **一次性资源** | `ResourcePickup` | 1 | 一次获得后消失 | 石头堆/木头堆/矿脉 |
| **特殊点** | `SpecialPoint` | 1 | 交互触发 | 宝箱/遗迹/交互建筑(未来) |
| **裂隙** | `Rift` | 1 | 出怪 | 可被消灭 |
| **废弃城堡** | `CastleCore` | 2 格 | 核心 | 不可拆 |
| **玩家建造** | `PlayerBuilding` | 1~N | 依赖类型 | 城墙/箭塔等(建造系统) |

一级地形 → 持续性资源 + 一次性资源的生成规则：

| 一级地形 | 子状态 | 持续性 | 一次性 | 特殊点(概率) |
|---------|:---:|--------|--------|:---:|
| 平原 | 普通 | 农田（基础产出） | 石头堆(少量木+石)、木头堆(少量木)，无矿石 | 极低 |
| 平原 | 肥沃 | 农田（高级产出 buff） | 石头堆(少量)、木头堆(少量) | 极低 |
| 林地 | — | 树（木来源） | 木头堆（中等量） | 低 |
| 丘陵 | — | 无 | 石头堆(中等)、木头堆(中等)、矿脉(少量) | 低 |
| 矿山 | — | 矿洞（石来源） | 矿脉（少量但高等级） | 低 |
| 荒地 | — | 无 | 无 | 无 |
| 雪山 | — | 无 | 无 | 无 |
| 海岸 | — | 无 | 无 | 无（出海口/造船厂位，未来放特殊点） |

> **平原 always 有农田**：普通平原 = 基础农田（标准产出），肥沃平原 = 高级农田（多产出 buff）。肥沃不是独立地形，是平原上农业生产点的等级增强。
>
> **丘陵无持续性资源**：丘陵只提供一次性石头堆/木头堆/矿脉，是"一次性复合资源区"。石来源靠矿山（持续性矿洞）。
>
> **中心区原则**：大量一次性低等级资源（石头堆/木头堆），无矿石，平原自带基础农田。**资源区**：林地(树) + 矿山(矿洞) 提供持续性资源 + 一次性高等级资源（富矿脉在外侧）。

#### BuildingPlaceholder 数据结构

地图生成产出的 Building 占位数据（不是运行时 Building 实例，是"生成结果"）：

```csharp
/// <summary>地图生成产出的 Building 占位。运行时由 BuildingFactory 转为 Building 实例。</summary>
public class BuildingPlaceholder
{
    public BuildingCategory category;   // ResourceProducer/ResourcePickup/SpecialPoint/Rift/CastleCore
    public BuildingType type;            // 具体类型（Tree/Mine/Farmland/StonePile/WoodPile/OreVein/TreasureBox/Ruins/Rift/CastleCore）
    public int localCellX;               // 在大区块内的小区块局部坐标
    public int cellWidth = 1;            // 占几个小区格（默认 1，废弃城堡=2）
    public ResourceGrade grade;          // 等级（Barren/Normal/Rich），仅资源点有效
    public bool isConsumable;            // 是否一次性（true=用完消失，false=持续产出）
}

public enum BuildingCategory
{
    ResourceProducer,  // 持续性资源（树/矿洞/农田）
    ResourcePickup,    // 一次性资源（石头堆/木头堆/矿脉）
    SpecialPoint,      // 特殊点（宝箱/遗迹/交互建筑）
    Rift,              // 裂隙（出怪口）
    CastleCore          // 废弃城堡
}

public enum BuildingType
{
    None,
    // 持续性
    Tree, Mine, Farmland,
    // 一次性
    StonePile, WoodPile, OreVein,
    // 特殊点
    TreasureBox, Ruins, Interactable,
    // 功能
    Rift, CastleCore
}
```

### 6.3 Building 等级三档

每个 Building（ResourceProducer / ResourcePickup）有等级，影响产出：

| 等级 | 枚举 | 持续性产出倍率 | 一次性获得量 |
|------|------|:---:|:---:|
| 贫瘠 | `Barren` | ×0.5 | 少量 |
| 普通 | `Normal` | ×1.0 | 标准 |
| 富有 | `Rich` | ×2.0 | 大量（高风险区倾向，高风险高回报）|

### 6.4 难度因子

难度直接决定**持续性 + 一次性资源**的密度和等级（高难度=资源少=纯压力）：

| 难度 | 密度因子 | 贫瘠% | 普通% | 富有% | 一次性资源密度 |
|------|:---:|:---:|:---:|:---:|:---:|
| Easy(1) | ×1.0 | 20% | 60% | 20% | ×1.0（基准） |
| Normal(2) | ×0.8 | 35% | 55% | 10% | ×0.8 |
| Hard(3) | ×0.6 | 50% | 45% | 5% | ×0.6 |

- **密度因子**：资源点基础数量 × densityFactor
- **等级概率**：高难度→贫瘠更多、富有更少
- **一次性资源**：高难度下额外减少（受同一密度因子调节）
- 补偿由其他系统负责（科技树/外交等），不在地图生成层

### 6.5 位置因子（风险分层联动）

资源点所在大区块的位置（内侧/外侧）影响等级概率偏移：

| 位置 | 贫瘠偏移 | 普通偏移 | 富有偏移 | 逻辑 |
|------|:---:|:---:|:---:|------|
| 内侧（低风险） | +10% | 0% | -10% | 安全区保底供给 |
| 外侧（高风险） | -10% | 0% | +10% | 高风险高回报 |

**最终等级概率 = 难度基础概率 + 位置偏移**

示例（Normal 难度 + 外侧）：贫瘠 25% / 普通 55% / 富有 20%

> 高风险区（外侧/靠近极端）的矿洞更可能是富矿——玩家有动力冒险保护城墙外的矿洞。

### 6.6 资源点基础数量

每大区块 **16** 小区块内的资源点基础数量（密度因子调节前，上限为原来的 2 倍）：

| 地形 | 持续性 | 一次性 min | 一次性 max | Normal 一次性 |
|------|:---:|:---:|:---:|:---:|
| 林地 | 树(1~2) | 4 | 6 | 3~5 |
| 矿山 | 矿洞(1~2) | 2 | 4 | 2~3 |
| 丘陵 | 无 | 4 | 6 | 3~5 |
| 平原(肥沃) | 农田(1, 高级buff) | 2 | 4 | 2~3 |
| 平原(普通) | 农田(1, 基础) | 1 | 3 | 1~2 |

> **为什么要翻倍**：小区块从 8→16，大区块容量翻倍，资源点上限定为原来的 2 倍。中心区的一次性低等级资源也按此表取最大值。

### 6.7 资源点生成算法（Building 体系，确定性）

```csharp
// 为一个大区块生成所有 Building 占位（持续性 + 一次性 + 特殊点）
List<BuildingPlaceholder> GenerateBuildings(System.Random rng, Region region,
                                             int difficulty, bool isInner)
{
    var buildings = new List<BuildingPlaceholder>();
    var config = ResourceGenConfig.Instance;

    // 1. 持续性资源
    var producerType = GetProducerType(region);
    if (producerType != BuildingType.None)
    {
        int count = RollCount(rng, region.terrain, difficulty);
        PlaceBuildings(buildings, rng, producerType, count, region.cellCount,
                       difficulty, isInner, BuildingCategory.ResourceProducer);
    }

    // 2. 一次性资源（石头堆/木头堆/矿脉，根据地形+难度）
    var pickupTypes = GetPickupTypes(region);
    foreach (var pt in pickupTypes)
    {
        int count = RollCount(rng, region.terrain, difficulty);
        float pickupDensity = config.GetDensity(difficulty); // 一次性资源额外密度因子
        int finalCount = Mathf.RoundToInt(count * pickupDensity);
        PlaceBuildings(buildings, rng, pt, finalCount, region.cellCount,
                       difficulty, isInner, BuildingCategory.ResourcePickup);
    }

    // 3. 特殊点（宝箱/遗迹/交互建筑，低概率）
    if (rng.NextDouble() < config.specialPointChance)
    {
        var spType = RollSpecialPointType(rng);
        PlaceBuildings(buildings, rng, spType, 1, region.cellCount,
                       difficulty, isInner, BuildingCategory.SpecialPoint);
    }

    return buildings;
}

void PlaceBuildings(List<BuildingPlaceholder> list, System.Random rng,
                    BuildingType type, int count, int cellCount,
                    int difficulty, bool isInner, BuildingCategory category)
{
    var candidates = Enumerable.Range(1, cellCount - 2)
        .Where(x => !list.Any(b => b.localCellX == x))  // 每个小区块最多一个 Building
        .ToList();
    var gradeProb = ResourceGenConfig.GetGradeProb(difficulty, isInner);

    for (int i = 0; i < count && candidates.Count > 0; i++)
    {
        int pickIdx = rng.Next(candidates.Count);
        list.Add(new BuildingPlaceholder
        {
            type = type,
            category = category,
            localCellX = candidates[pickIdx],
            grade = RollGrade(rng, gradeProb)
        });
        candidates.RemoveAt(pickIdx);
    }
}
```

### 6.8 小区块内容规则（简化）

每个大区块含 `regionCellCount`（默认 16）个小区块。**判断能否建造 = 当前小区块是否有 Building 占位**。所有 Building（资源点/裂隙/废弃城堡/玩家建筑）共享同一套占位判定逻辑。

#### 中心区（平原，废弃城堡所在）（16 格/大区块）

```
小区块:  [建造] [...] [...] [...] [...] [废弃城堡×2] [...] [...] [...] [...] [...] [...] [...] [...] [...] [...]
资源点:   一次性低等级（石头堆/木头堆），无矿石，少量农业生产点
```

- 废弃城堡占中心 2 格（`cellWidth = 2`），**不可在其他 Building 占位上建造**
- 其余格为建造开阔地 + 散布一次性低等级资源
- 平原子状态=普通（城堡附近）或肥沃（中心区边缘，粮来源）

#### 资源区

- 持续性资源 + 一次性资源 + 特殊点按 6.7 算法生成，占位即不可建造
- 资源点避开大区块两端小区块（留战场缓冲）
- 丘陵特有：一次性石头堆 + 木头堆 + 矿脉（复合，无持续性资源）

#### 极端区

```
小区块:  [裂隙(Building)] [战场] [战场] ... [战场×15]
```
- 最外端小区块放裂隙（Rift Building），可被玩家消灭
- 其余 15 格纯战场，不放资源点

> **废弃城堡 = 大建筑**：废弃城堡是 CastleCore（Building 子类），占 2 格（`cellWidth = 2`），不可拆。不和资源点混在同一小区块。

### 6.9 资源点风险分层与保护机制

### 设计问题

资源点（特别是矿山这种高级资源）在玩家城墙控制范围之外，晚上怪物或敌方王国进攻时会经过、破坏这些资源点。需要平衡两个矛盾：

- **保护感**：玩家能通过城墙/驻军保护资源 → 有经营博弈乐趣
- **风险感**：高级资源不该零风险 → 有防御压力和决策取舍

### 三档风险分层

| 风险档 | 资源 | 位置 | 城墙保护 | 被破坏后果 | 修复成本 |
|:---:|------|------|:---:|------|------|
| **低** | 农田(粮) | 中心区 / 资源区内侧 | ✅ 可被城墙围住 | 停产 | 低（少量粮+时间） |
| **中** | 树(木) | 资源区内侧 | △ 城墙边缘，部分保护 | 树被砍倒 | 中（时间自恢复） |
| **高** | 矿洞(石) | 资源区外侧（靠近极端区） | ❌ 城墙外 | 停产 | 高（木+石+时间） |

### 设计原则

1. **农田可被城墙包括** → 放中心区/资源区内侧（低风险，保障基础经济）
2. **矿石是高级资源，必须有风险** → 放资源区外侧（高风险，高回报）
3. **矿山离废弃城堡不能太远** → 距废弃城堡 2~3 个大区块（有防御纵深，但城墙默认围不到）
4. **中心区平原不能太大** → 否则城墙能围住所有资源，失去风险博弈（见 3.2 平原占比 30%）

### 城墙保护范围（与建造系统衔接）

```
                城墙保护圈
         ┌─────────────────────┐
[海岸] → [矿山] → [林地] → [城墙] → [农田] → [废弃城堡] → [农田] → [城墙] → [林地] → [矿山] → [海岸]
         ↑城外      ↑城边缘    │      ↑城内      ↑城内      ↑城内      │   ↑城边缘    ↑城外
         高风险     中风险      │      低风险                          │   中风险     高风险
                    └───────────────────────────────────────────────────┘
```

- 城墙是建造系统的建筑，围成区域形成保护圈
- 圈内资源点受保护（怪物/敌军须先破城墙）
- 圈外资源点暴露，被经过时会被破坏
- **玩家可扩张城墙**保护更多资源点，但城墙越长 → 建造成本越高 + 防线越薄弱（兵力分散）
- 这是**核心防御博弈**：围多少资源 = 承担多少防线压力

**动态风险变化**：
- **前期**：城墙围不住高级资源点（矿山在外侧，距废弃城堡 2~3 大区块）→ 玩家必须冒险派兵或接受停产风险
- **后期**：王国可以扩张到全地图 → 消灭裂隙（Rift Building）→ 只剩出海口入口（别国攻打）→ 所有资源点都在保护圈内
- 这是建造/波次系统的事，地图生成只需保证初始资源分布合理

### 资源点损坏与修复（平衡失落感）

资源点被破坏**不是永久消失**，而是进入「损坏」状态：

| 状态 | 产出 | 修复方式 | 修复成本 |
|------|:---:|---------|---------|
| 正常 | ✅ 正常产出 | — | — |
| 损坏 | ❌ 停产 | 玩家点击 → 消耗资源修复 | 农田低 / 树自恢复 / 矿洞高 |
| 修复中 | ❌ 停产 | 倒计时 | — |

**修复成本设计**（平衡失落感）：
- **农田**：少量粮 + 短时间 → 被破坏不心疼，快速恢复
- **树**：无需资源，时间自恢复 → 被砍倒等几天重新长，中等奖励损失
- **矿洞**：木 + 石 + 较长时间 → 高级资源被破坏有痛感，但可修复不是永久失去

> **核心平衡**：损坏 = 停产打击（有风险感）+ 可修复（不永久失去 → 不挫败）。玩家面对的选择是"花钱修矿山" vs "先修防线防止再被破"——这是博弈。

### 地图生成层的保证

以上风险分层的**位置约束**在地图生成时就保证好（不需要建造系统配合）：

| 约束 | 落地位置 | 保证方式 |
|------|---------|---------|
| 农田在城墙内 | 中心区/资源区内侧 | 3.2 中心区允许 1 个肥沃 + 3.3 资源区内侧倾向肥沃 |
| 矿山在城墙外 | 资源区外侧 | 3.3 资源区外侧倾向矿山/丘陵 |
| 矿山距废弃城堡 2~3 大区块 | 资源区位置 | 5 区结构公式保证（资源区在中心区两侧） |
| 平原不太大 | 中心区占比 30% | 2.2 公式 + 3.2 约束 |

> 建造系统的城墙保护范围、资源点损坏/修复逻辑是**建造系统 GDD** 的范畴，本节只定义**地图生成如何保证资源点位置合理**。

### 6.10 出怪口（裂隙）放置规则

```csharp
// 在极端区的最外端大区块的小区块 0 放裂隙（Rift Building）
void PlaceRifts(MapData map, int M, BigTerrain bigTerrain)
{
    bool isInland = bigTerrain == BigTerrain.Inland;
    int leftRiftRegion = 0;                    // 最左大区块
    int rightRiftRegion = M - 1;               // 最右大区块

    // 内陆：左端=雪山屏障(无怪)，右端=荒地出怪
    // 岛屿：两端海岸都出怪
    int riftRegion = isInland ? rightRiftRegion : leftRiftRegion;
    PlaceRiftInRegion(map.regions[riftRegion]);

    if (!isInland)
    {
        // 岛屿：右端也有裂隙
        PlaceRiftInRegion(map.regions[rightRiftRegion]);
    }
}

void PlaceRiftInRegion(Region region)
{
    // 裂隙放在该大区块的小区块 0（最外端），作为 Rift Building 占位
    region.riftCellX = 0;  // -1=无裂隙
}
```

> 裂隙是 Rift Building（Building 体系子类），可被玩家消灭。消灭后该点不再出怪。

## 七、完整生成 Pipeline（确定性）

### 7.1 Pipeline 总览

```
Step 0: 输入 (worldSeed, worldSize, difficulty, isPlayerHome)
  │
Step 1: 确定大区块数 M (worldSize → MapSizeConfig)
  │
Step 2: 5 区分配 (公式：中心/资源/极端)
  │
Step 3: 中心区地形 = 平原 (废弃城堡强制平原, 占比30%, 16格/大区块, 最多1个肥沃)
  │
Step 4: 资源区地形 = 受约束随机 (System.Random(seed))
  │       ├─ 候选集 [林地/矿山/丘陵/肥沃/平原]
  │       └─ 与中心区接壤的须能和平原邻接
  │
Step 5: 极端区地形 = 按大地形区分 (不随机)
  │       ├─ 岛屿: 海岸 (两端, 出海口+敌军登陆滩头)
  │       └─ 内陆: 雪山(大山屏障侧,无怪) + 荒地(出怪侧)
  │
Step 6: 资源完整性校验 + 修复 (四资源保障)
  │       └─ 缺什么补什么 (ForceReplace, 不动废弃城堡)
  │
Step 7: 邻接校验 + 缓冲插入 (违规则插丘陵)
  │
Step 8: 二级约束 - Building 生成 (持续性+一次性+特殊点)
  │       ├─ 类型 ← 一级地形决定 (树/矿洞/农田/石头堆/木头堆/矿脉)
  │       ├─ 数量 = 基础随机 × 难度密度因子 (高难度→更少)
  │       ├─ 等级 = 难度概率 + 位置偏移 (贫瘠/普通/富有)
  │       └─ 位置 = 避开两端小区块, 确定性随机
  │
Step 8.5: 废弃城堡占位 (中心区正中间大区块, 2 格)
  │       └─ PlaceAbandonedCastle(regions, abandonedCastleRegionIdx, cellCount)
  │
Step 9: 出怪口/裂隙放置 (极端区端点)
  │       ├─ 岛屿: 两端
  │       └─ 内陆: 单端
  │
Step 10: 输出 MapData (regions + buildings + rifts)
```

### 7.2 落地代码（GenerateMap 完整版）

替换 3.2 文档 5.2 节的 `GenerateMap`，加入约束层：

```csharp
// WorldManager.GenerateMap：生成一张地图（M 个大区块，含玩法约束）
MapData GenerateMap(System.Random rng, int seed, int mapId, WorldSize size,
                    bool isPlayerHome, BigTerrain? forcedBigTerrain = null)
{
    int cellCount = _gridConfig != null ? _gridConfig.regionCellCount : 16;

    // === Step 1: 确定大地形 ===
    BigTerrain bigTerrain = forcedBigTerrain ?? (
        isPlayerHome
            ? (rng.NextDouble() < 0.5 ? BigTerrain.Island : BigTerrain.Inland)
            : BigTerrain.Island  // 敌方王国固定岛屿（攻城）
    );

    int M = _mapSizeConfig != null ? _mapSizeConfig.GetRegionCount(size) : 15;

    var map = new MapData
    {
        mapId = mapId,
        seed = seed,
        bigTerrain = bigTerrain,
        regions = new List<Region>(M),
        isPlayerHome = isPlayerHome
    };

    // === Step 2: 5 区分配 ===
    var (center, extreme, resource) = CalcZoneCounts(M);
    var (castleA, castleB) = GetCastleRegionIndices(M, center, extreme, resource);

    // 废弃城堡所在的大区块索引（正中心，只占 1 个大区块）
    int abandonedCastleRegionIdx = castleB;

    // === Step 3-5: 按区分配地形 ===
    for (int i = 0; i < M; i++)
    {
        MapZone zone = GetZone(i, M, center, extreme, resource);
        TerrainType terrain = PickTerrainByZone(rng, zone, i, M, bigTerrain);

        // 废弃城堡所在区块强制平原
        if (i == abandonedCastleRegionIdx) terrain = TerrainType.Plain;

        var region = new Region
        {
            regionIndex = i,
            terrain = terrain,
            cellStartX = i * cellCount,
            cellCount = cellCount,
            resources = new List<BuildingPlaceholder>(),
            riftCellX = -1,
            isEnemyTerritory = !isPlayerHome,
            zone = zone,
            isInner = (zone == MapZone.LeftResource || zone == MapZone.RightResource)
                      ? IsResourceInner(i, M, zone) : false
        };

        // 平原子状态判定
        if (terrain == TerrainType.Plain)
        {
            region.plainSubState = IsCenterEdge(i, M, center, extreme, resource)
                && rng.NextDouble() < _rulesConfig.centerFertileChance
                ? PlainSubState.Fertile
                : PlainSubState.Normal;
            // 废弃城堡区块强制普通平原
            if (i == abandonedCastleRegionIdx) region.plainSubState = PlainSubState.Normal;
        }

        map.regions.Add(region);
    }

    // === Step 6-7: 资源保障 + 邻接校验（循环 2 轮）===
    for (int round = 0; round < 2; round++)
    {
        if (isPlayerHome) EnsureResourceCoverage(rng, map.regions, M, abandonedCastleRegionIdx, abandonedCastleRegionIdx);
        EnforceAdjacency(map.regions, M, abandonedCastleRegionIdx, abandonedCastleRegionIdx);
    }

    // === Step 8: 二级约束 - Building 生成 ===
    foreach (var region in map.regions)
    {
        region.resources = GenerateBuildings(rng, region, _world.difficulty, region.isInner);
    }

    // === Step 8.5: 废弃城堡占位（2 格，中心区块）===
    PlaceAbandonedCastle(map.regions, abandonedCastleRegionIdx, cellCount);

    // === Step 9: 出怪口/裂隙放置 ===
    PlaceRifts(map, M, bigTerrain);

    return map;
}

// 按区选地形（极端区按大地形固定，资源区分内/外侧风险分层）
TerrainType PickTerrainByZone(System.Random rng, MapZone zone, int idx, int M, BigTerrain bigTerrain)
{
    switch (zone)
    {
        case MapZone.Center:
            // 中心区边缘肥沃概率由调用方处理（plainSubState），这里返回平原
            return TerrainType.Plain;

        case MapZone.LeftResource:
        case MapZone.RightResource:
            return IsResourceInner(idx, M, zone)
                ? PickWeighted(rng, _rulesConfig.resourceInnerWeights)
                : PickWeighted(rng, _rulesConfig.resourceOuterWeights);

        case MapZone.LeftExtreme:
        case MapZone.RightExtreme:
            if (bigTerrain == BigTerrain.Island)
                return TerrainType.Coast;
            else // 内陆
                return zone == MapZone.LeftExtreme
                    ? TerrainType.Snow      // 内陆左端=雪山（大山屏障）
                    : TerrainType.Wasteland; // 内陆右端=荒地（出怪侧）

        default:
            return TerrainType.Plain;
    }
}
```

### 7.3 确定性保证

- **全程用 `System.Random(seed)`**，禁用 `UnityEngine.Random`
- `seed` 来源：玩家地图用 `worldSeed`，敌方地图用 `worldSeed` 派生（`rng.Next()`）
- 同 seed 同结果——存档只存 seed，读档复现完全一致
- 修复操作（ForceReplace / EnforceAdjacency）也走 rng，保证确定性

## 九、边界情况与处理

### 9.1 小地图（M=10）资源保障

M=10 时每侧资源区有 2 个大区块，资源保障基本不会缺。但极端情况下可能全随机出平原，需校验。

**处理**：
- 中心区允许 1 个肥沃（粮来源）
- 左资源区 2 个 → 内侧倾向林地，外侧倾向矿山
- 右资源区 2 个 → 内侧倾向林地/肥沃，外侧倾向丘陵
- 若随机没出林地/矿山/肥沃，靠 `EnsureResourceCoverage` 强制替换

**M=10 典型布局**：
```
[#0 海岸] [#1 矿山] [#2 林地] [#3 平原] [#4 平原] [#5 废弃城堡] [#6 肥沃] [#7 林地] [#8 丘陵] [#9 海岸]
  出怪口    外侧石     内侧木     建造      建造    废弃城堡     粮         内侧木     外侧石      出怪口
```

### 9.2 内陆地图单边出怪

内陆地图只有一端有裂隙（另一端大山屏障）。5 区结构调整为：

```
[大山屏障] [左资源区] [中心区] [右资源区] [出怪口(极端区)]
   无裂隙     资源点   废弃城堡    资源点      裂隙
```

- 左极端区替换为「大山屏障区」——地形固定雪山（视觉屏障），无裂隙，不出怪
- 右极端区正常出怪
- 难度更低（单向防御），适合新手

### 9.3 敌方王国地图

敌方王国是**另一套生成逻辑**——"已建成高度王国"，和玩家"初始化空地"完全不同。待以后单独设计 GDD。当前地图生成规则只适用于玩家初始地图。

### 9.4 邻接修复破坏资源保障

`EnforceAdjacency` 可能把一个林地改成丘陵（做缓冲），导致缺木。

**处理**：邻接修复后**再跑一次** `EnsureResourceCoverage`。两步循环最多 2 次（实测 1 次足够，5 区结构天然避免大部分冲突）。

```csharp
// GenerateMap 内，Step 6-7 循环
for (int round = 0; round < 2; round++)
{
    if (isPlayerHome) EnsureResourceCoverage(rng, map.regions, M, abandonedCastleRegionIdx, abandonedCastleRegionIdx);
    EnforceAdjacency(map.regions, M, abandonedCastleRegionIdx, abandonedCastleRegionIdx);
}
```
