## 〇、背景与现状（讨论起点）

### 0.1 现有 sim 是什么

- sim = `ai决策大脑强化训练/` 下的 headless 控制台，**1D 战斗模拟器**。
- 三条铁律：决策核只有一份源码（Unity 与 sim 双编译同源）；同卷考试（固定剧本+固定种子）；LLM 不进 tick 循环。
- 已具备：SimWorld 8 步 tick 循环 / SimDamage 时间轮 / SimBrain Think 管线 / SimFormation 编队 / SimGrid / SimMetrics / SimLogger / champion 快照 / factor_registry / 提案机制 / 规模谱系（24-996 单位）。
- **决策核**（AttentionSystem + L1/L2/L3 + 五综合因子）是纯 C#，Unity 与 sim 共用。

### 0.2 生产链现状在哪

- 生产/经济/王国经营**只在 Unity**（3.5 系列，P0/P1/P2 已实施）：资源采集→加工→运输→仓储→人口→训练→税收→贸易→科技→防御→军事。
- 系统规则唯一出处：3.5（顶层）/ 3.5.1（NPC 实体循环）/ 3.5.2（通用工人）/ 3.5.3（建筑功能+搬运链）/ 3.5.4（建筑数据卡）/ 3.3.5（中心任务调度）。
- 关键事实：**人口无"士兵成长"链，只有"小孩成长"**；可生产职业全集尚未定义（用户点名待考虑）。

### 0.3 本次要讨论的核心命题

把"生产链"与"战斗链"在 sim 里打通成**全链路**。但用户强调：**生产-战斗联动在正式游戏里是玩家的决策层 / 乐趣来源**——所以 sim 既要能训练"AI 生产/战斗决策"，又要能作为一个可回放、可验证的沙盘被玩家/训练师理解。

## 一、时间尺度与昼夜循环（点 1）

### 现状
- Unity：1 天 = 180s（白天 120 / 黄昏 30 / 夜晚 30），白天经营、夜晚防守，时间加速仅 2x，感知到敌降速 1x。
- sim：纯 tick 战斗（10Hz think），没有"天"的概念，只有"对局"。

### 待讨论
生产是**天级**（人口/税收/建筑日结算），战斗是**tick 级**。sim 如何统一两种时间尺度？

**方案 A：天-夜双环（白天经济环 / 夜晚战斗环，同一次 sim 对局内交替）**
- 一个对局 = 若干"天"；每天内：白天跑经济 tick（采集/加工/运输/人口/税收），夜晚跑战斗 tick（波次/敌军来袭）。
- 与 Unity 昼夜节奏天然对齐，玩家/训练师可分段回放。
- 代价：单局变长，经济环与战斗环的耦合边界要设计清楚。

**方案 B：episode 式（每个"夜晚"= 一个战斗 episode，经济在 episode 间结算）**
- 模拟器一次只跑一个夜晚战斗；白天经济作为"上一局结算 + 下一局初始条件"在 episode 之间推进。
- 战斗 sim 复用度最高、改动最小；但"生产-战斗联动"被切到 episode 间隙，连续性弱。
- 适合：先验证生产对战斗胜率的宏观影响，不做微观联动。

**方案 C：单环全 tick（经济战斗同一 tick 流）**
- 全部按 tick 推进，经济也有自己的 tick 频率（如每 180 tick = 1 天）。
- 最贴近"全链路本身"，但 sim 复杂度、确定性、性能风险最高。

### 待决
- 你倾向 A / B / C？还是先 B 后 A 的两阶段？
- 若选 A：一个对局默认几天？白天经济 tick 频率/npc 粒度定到多细（见点 2 保真度）？

## 二、sim 保真度分层：哪些生产环节进 sim、哪些抽象（点 2）

### 现状
- sim 铁律：sim 战斗结果必须与 Unity 一致（sim-to-real gap 是头号风险）。
- 经济系统（3.5）数值极度细（产量 rate 每秒、携带量、饱食、幸福、税率、贸易额度周期……）。
- **2026-08-10 审计新发现（实体化）**：Unity 侧已完成「人口实体化」重构（E-S1~E-S11）——疑点：
  - 开局/繁殖/小孩长大/流浪汉招募都生成**真正的 UnitController 实体**（不再是 PopulationSystem 计数）。
  - 人口系统从「计数制」改为「实体注册表」（_entities List<UnitController>）。
  - 建筑数据卡（footprint/HP/产量/训练槽位/并发）、新职业资产（Porter 等）已就位。
  - **结论：Unity 真身已是「逐个体」模型，与 sim 的 SimUnit 个体模型天生对齐** → golden replay 有真实逐个体参考；但 sim 白天经济环仍按已定决策走**队列式人口池**（性能/迭代取舍，见点 5），两者不冲突。

### 待讨论
生产链全量照搬 vs 分层抽象？我初步分三层：

**L1 全量复刻（进 sim，逐条对齐 Unity）**
- 资源采集（木/石/矿/粮：伐木场/采石场/矿洞/农田产量）
- 存储与搬运（仓库/粮仓携带量、就近搬运、溢出）
- 人口基础（**实体化后**：小孩成长 Child→Resident、房屋容量、饱食、幸福、生育三层前置、繁殖实体化、死亡扣幸福 K=0.5）
- 训练链（无职业→工人/士兵；练兵场/卫戍营）——**可生产职业定义见点 4**
- 这些是"生产→兵力"的骨干，必须进 sim 才有意义。
- **实体化使 L1 更实**：Unity 的逐个体实体给了转换层（夜间实例化）一个真实参考模型；但白天经济环仍用队列式人口池（§12.2 已定案）。

**L2 吞吐近似（进 sim，用简单模型近似，不逐点对齐）**
- 加工/制造（面包/肉/弹药/战争机器）——用"消耗 A 产出 B"的吞吐方程近似，不模拟工人路径。
- 税收/贸易/科技——用宏观结算曲线近似（影响金流与增益，不模拟商人 NPC 行为）。
- 人口/饱食/幸福在 L1 已逐个体，此处不再重复近似。

**L3 暂不进 sim（先留 Unity，靠假设/场景参数给定）**
- 君主/指挥面板、UI、美术、昼夜动画、**点击交互系统本体**（IClickInteractable+优先级子系统）。
- 这些是"玩家决策点/表现层"。**点击交互系统本身不进 sim**，但它背后的**决策点**（招募/买幼崽/点宰杀/排训练队列/点建筑）要映射为 sim 的 auto-player 策略脚本或场景预设（见点 6）。

### 待决
- 认可 L1/L2/L3 三层划分吗？实体化后边界要不要再调整？
- L2 里哪些"吞吐近似"会导致生产-战斗联动失真，需特别注意？
- 玩家决策点（L3）在 sim 里是否要用**策略脚本**模拟（auto-player），还是先固定预设？

## 五、人口与招募链条在 sim 的建模（点 5）

### 现状（3.5 / 3.5.1 / 实体化审计）
- 人口增长 = 生育（幸福>60 & 饱食>50 & 房屋容量>0 & 单对 10 天冷却，随机配对）。
- 开局 10 人（1 君主 + 4 工人 + 5 无职业）。
- 新生儿 = 无职业废人，吃粮 1/日，需训练转职。
- 死亡扣幸福公式（K=0.5）。
- **2026-08-10 审计新发现（实体化）**：
  - 人口已从「计数制」改为**实体注册表**（`_entities List<UnitController>`），每个居民/小孩/工人都是真实实体。
  - 开局实体化（SpawnInitialEntities 生成 4 工人 + 5 居民实体）、繁殖实体化（生成 Child 实体）、小孩长大机制（ChildGrowthDays 累积 → SetOccupation(Resident)）、流浪汉招募（生成无职业居民实体）。

### 待讨论 & 已定决策（2026-08-10 六轮收敛）
人口模型进 sim 的颗粒度，**已定案：白天队列式人口池 + 夜间实例化士兵 SimUnit**（§12.2.2 / §12.2.3）：
- **白天经济环**：队列式（PopulationPool 各职业人数 + 平均饱食/幸福 + 房屋容量），轻量、快跑数值。
- **夜晚战斗环**：转换层把"已训练士兵"从队列实例化为逐个体 SimUnit（HP 满、位置城墙后），复用现有战斗管线。
- **实体化审计与本决策的一致性**：Unity 实体化（逐个体）**不推翻**队列式设计——sim 白天用队列抽象是性能/迭代速度取舍；实体化反而给了转换层一个**真实的逐个体参考模型**，golden replay 时 sim 的"夜间实例化"应对齐 Unity"生成实体士兵"的语义（§12.6 洞察 2 / §12.3 生育冷却差异标注）。

### 待决
- 转换层细节口径（§12.2.3）：训练中士兵不参战、工人/居民不实例化、主城 HP 跨夜保持——已定案。
- 夜间实例化位置规则（城墙后具体格）→ T1.7 待 P1 设计。
- **流浪汉招募（2026-08-10 已定案：纳入人口池）**：作为"地图边缘流浪汉营地实体 + 招募转为无职业居民"的**第二个生育外人口来源**。落地到 T0.1（Vagrant 定位外部流入）/ T0.3（人口池两源）/ T0.5（日结算招募判定）/ T0.7（场景流浪汉来源池配置）。

### 12.2 新增架构需求

#### 12.2.1 SimClock 扩展"天"概念

- 新增 `dayPhase = Day / Night`
- 1 天 = 180s（白天 120s + 夜晚 60s），tick 10Hz → 1 天 = 1800 tick
- 白天 120s 内每 18s 结算 1 次经济（每天 10 次）
- 夜晚 60s 跑战斗 tick（复用现有 8 步循环）
- **日结算钩子**：每天白天结束时统一结算（人口增长 / 税收 / 训练完成 / 饱食消耗 / 死亡扣幸福）

#### 12.2.2 SimEconomy 独立模块

```
SimEconomy（新模块，纯 C# 数据结构）
├── 资源存量（木/石/矿/粮/金/水晶/火油）
├── 建筑列表（BuildingState: type/level/hp/concurrentWorkers/trainingSlots/productionRate）
├── 人口池（PopulationPool: 各职业人数/平均饱食/平均幸福/房屋容量）
├── 训练队列（TrainingSlot: profession/sourceBuilding/remainingTime/cost）
├── EconomyTick() — 每 18s 调用，推进采集/加工/搬运/饱食消耗
└── DailySettle() — 每天 1 次，推进人口增长/税收/训练完成/死亡扣幸福
```

- **复用 SimTask**：SimEconomy 通过 SimTask 派发工人任务（采集/搬运），SimTask 继续管工人移动状态机
- **SimEconomy → SimTask 接口**：`DispatchTask(workerId, type, sourceX, destX, duration)`
- **与现有 SimWorld 的关系**：SimWorld.Tick() 新增"经济 tick"子步骤（白天环），夜晚环复用现有 8 步循环

#### 12.2.3 队列→个体转换层

```
DayNightTransition（天→夜 / 夜→天 转换层）
├── ToNight(PopulationPool, wallX)
│   └── 从队列读取已训练士兵 → 实例化为 SimUnit（HP 满、位置城墙后）
│   └── 训练中士兵不参战（留在队列）
│   └── 工人/居民不实例化（白天经济环专属）
└── ToDay(PopulationPool, List<SimUnit>)
    └── 存活者回写队列（HP/位置丢弃）
    └── 阵亡者从队列删除
    └── 主城 HP 跨夜保持（主城是 BuildingState，不是 SimUnit）
```

- 转换点固定在天→夜边界
- 白天无战斗（与 Unity 夜晚防守一致）

#### 12.2.4 建筑建模

- **纯数据结构**（BuildingState），不进 SimGrid 不占位置
- P0 阶段建筑不可被攻击（纯经济沙盘无战斗）
- P1 阶段建筑是否需转为 static SimUnit（夜晚可被攻击）→ 留 P1 设计时决定

#### 12.2.5 训练系统

- **队列式训练**：训练是 SimEconomy 的数据结构（TrainingSlot），日结算时推进剩余时长
- 训练完成 → 人口池对应职业 +1
- 不模拟工人走到练兵场的过程
- 训练中断 → 居民存活（变回无职业居民），不退款（与 Unity 一致）

#### 12.2.6 P0 决策模式

- **战略固定**：建筑布局 / 升级顺序 / 训练队列 / 工人分配比例 → 场景 JSON 预设
- **运营自动**：哪个工人去哪个任务 → 规则自动处理（类似 ScheduleCenter）
- P0 只跑数值不练决策，**预留 AI 决策接口**（P2 可插入）

### 12.6 架构洞察

1. **统一架构**：SimEconomy 独立模块 + 复用 SimTask 工人移动 + 转换层连接战斗环。SimClock 扩展"天"概念，日结算钩子统一处理人口/税收/训练。三层各司其职：SimEconomy（经济数据）→ SimTask（工人移动）→ SimWorld（战斗 tick）。

2. **四阶段转换模型**：队列人口 → 夜间实例化 → 战斗单位 → 战后回写。白天轻量（队列），夜晚复用 SimUnit，转换层负责数据映射。转换点固定在天→夜边界，白天无战斗。

3. **时序矛盾已解决**：生育冷却 sim 专调 3 天（7 天/局可触发 2 轮），golden replay 标注与 Unity 10 天的差异。所有 sim 专调参数需在 golden replay 协议中显式标注。

4. **P0→P2 加速**：P0 全速 21 分钟/局（人看报告），P2 经济抽象加速到 ≤5 分钟/局（减少结算频率），两档速度。训练时用加速档，验证时用全速档。

5. **SimTask 复用而非重写**：现有 SimTask 已有完整状态机（Assigned→MovingToSource→Working→MovingToDest→Completed）+ 威胁挂起/恢复。SimEconomy 复用它派发工人任务，避免重写。T-K/T-R 场景无需迁移。
