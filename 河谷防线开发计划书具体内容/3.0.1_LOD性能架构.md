## 一、核心架构：区块持有 + 事件覆盖

### 1.1 LOD 区块 = 3.2 的 region

- LOD 思考区块直接复用 3.2 地图生成系统的 **region（大区块，16×16 cell）**，思考区块与地图区块一致，零新增空间结构。
- 每个 region 持有三样东西（新增 `RegionLodState`）：
  - `LodLevel level`：活跃 / 半活跃 / 休眠
  - `float threatHeat`：威胁热度（见第三节）
  - `float idleTimer`：无事件计时器（降级防抖用）
- NPC 侧：NPCBrain 从所在 region 读 Think 频率；跨 region 移动时继承新状态（移动本就要维护格子归属，挂载点现成）。
- 判定成本 O(region 数) 而非 O(NPC 数)。

### 1.2 活跃带判定（一维带状）

地图是左右向的，活跃判定就是一条带：

```
活跃中心：君主所在 region + 每支军队（FollowAnchor 锚点/将军）所在 region
每个中心点亮：[中心-1, 中心, 中心+1] = 活跃（3 格）
              [中心-2, 中心+2]       = 半活跃（2 格）
其余 region = 休眠
多个活跃中心取并集（君主在城里 + 军队在野外 = 两段活跃带）
活跃中心位置变化时即时重算（升级即时，降级仍走 1.4 防抖）
```

### 1.3 事件覆盖（升级不走路径 tick）

| 事件类型 | 升级粒度 | 原因 |
|---------|---------|------|
| 威胁类（受击 / 敌人进格广播 / ThreatHeat 过阈） | **整 region 即时升活跃** | 敌人会移动，只唤醒单个 NPC 会出"瞎子 NPC" |
| 军令 / 任务下发 | **只升目标 region**（至半活跃） | 任务目标固定，不该点亮全区 |
| 受击事件（个体层） | 被打 NPC **off-tick 即时进 Caution** | 不等区块 tick，沿用 3.0.1_2 受击冷却状态机 |

### 1.4 升降级防抖（与全文档"升快降慢"同构）

- **升级即时**：战斗唤醒不能等。
- **降级滞后**：热度归零 **且** 30s 无事件 → 降一级；**逐级降**（活跃→半活跃→休眠，不跳级）。
- NPC 跨 region 移动继承新区块状态，个体不做滞回（区块级滞回已覆盖）。

### 1.5 三区行为语义

| 区 | Think 频率 | 谱系 | 输入收集 |
|----|-----------|------|---------|
| 活跃 | 10Hz（现状） | 0/2/4 全谱系 | 全量（威胁评定 + 保护因子 + 全因子） |
| 半活跃 | 2Hz | 0/2/4 | 全量 |
| 休眠 | 0.5Hz | 0/4（砍谨慎态，母文档 §6.3） | 跳过保护因子计算；威胁输入只剩事件 + ThreatHeat |

Execute 每帧照跑（`_lastCmd` 复用），搬运/走路/工作循环不中断。

## 三、ThreatHeat 区块威胁热度（危险如何传递到一个区块）

**问题**：区块最外层的工人被射，危险怎么传给同区块没见到敌人的 NPC、以及相邻区块？

**方案**：不写"工人A告诉工人B"的通信代码，延续涌现哲学，分三层：

```
第一层·个体即时（已有）：受击事件 off-tick 唤醒被打 NPC → 撤退/警戒
第二层·区块热度（新增）：region 累积 ThreatHeat，作为环境型威胁推高同区块所有 NPC
第三层·区块间扩散（新增）：热度 > 扩散阈值 → 相邻 region 获比例热度并升半活跃
```

### 3.1 热度累积与衰减

| 来源 | 累积量（占位） |
|------|--------------|
| 区块内任何 NPC 受击 | +0.4 |
| 敌人进入本 region（感知广播） | +0.2 |
| 友军撤退经过本 region | +0.05 |

衰减：-0.05/s；clamp [0, 1]。

### 3.2 热度进威胁评定（heatFactor 入统一因子表）

ThreatHeat 作为**环境型威胁因子**进 FactorContext（与夜晚 timeFactor 同构——无 ThreatStimulus 对象也能推高威胁）：

> ⚠️ **2026-08-01 代码核查勘误**：代码现状 rawFactor 只有 5 项（dist 0.35 / count 0.15 / hp 0.2 / ally 0.2 / time 0.1）且**权重硬编码**在 ThreatAssessor 方法体内（3.0.1_1 的 enemyPowerFactor/selfPowerFactor 未落地）。heatFactor 落地前置：①权重全部迁入 AttentionTuningConfig；②**删除 `enemyCount==0 早退返回 0`**（ThreatAssessment.cs:70）——否则"没见到敌人也要警觉"的 heat 语义是死路。下方公式为含 heatFactor 的目标态：

```
rawFactor = distFactor*0.23 + countFactor*0.09 + enemyPowerFactor*0.14
          + hpFear*0.14 + allyFactor*0.18 + selfPowerFactor*0.09
          + timeFactor*0.05 + heatFactor*0.08   // heatFactor = 本 region ThreatHeat
// 原七权重等比压缩，总和保持 1.0；heatFactor 权重 0.08（占位，入 SO）
```

效果：同区块 NPC 没见到敌人也开始警觉（威胁 1）甚至谨慎（威胁 2）——"危险传开了"是算出来的。FactorDef 化（3.0.1_2 附录 B，P1）时 heatFactor 作为数组一项自然迁移。⚠️ 因子编号统一（2026-08-01 审计 E4）：与 3.0.1_3 §14.6 enemyTypeFactor 合并改造，目标态 **9 项统一因子表**（见《AI编队等前置工作》§3.4），"第八项"表述废止。

### 3.3 区块间扩散

- 本 region 热度 > 0.6（扩散阈值）→ 左右相邻 region 各获得 ×0.4 比例热度，并升至**半活跃**（预激活：敌人真来时零延迟）。
- 敌人实际进入某 region → 该 region 直接升活跃（事件覆盖，§1.3）。
- 扩散只走一级（邻区的邻区不再被点燃），防止单点战斗点亮全图。

### 3.4 热度与 LOD 的双向关系

热度既驱动 LOD 升降（过阈升、归零超时降），又被 LOD 影响（休眠区热度照常累积——受击事件 off-tick 即时入账，不等 Think tick）。

### 3.5 衔接 3.0.1_3（留接口）

ThreatHeat 是 AI 协作层的事件源：将军/调度中心订阅 region 热度变化 → 调兵支援。协作层不自己发明感知。接口：`EventBus.Publish(new RegionHeatChangedEvent(regionId, heat, level))`。

## 四、好奇层漫游（CuriosityStimulus 实装）

### 4.1 定位

母文档第 5 层好奇层留壳，本文实装为**无任务时的兜底漫游**——兜底中的兜底，强度低于 SafetyStimulus（D 级）。漫游是"看起来有生活感"，永不干扰任务/威胁层。

### 4.2 触发与行为

```
触发：任务层无活跃项 且 处于 HomePoint Idle 满 wanderDelay（5s 占位）
行为：漫游域内随机选点 → MoveTowards(walkSpeed) → 到达 → Idle(2-4s 随机) → 再选点
退出：任何更高层刺激出现（任务下发/威胁）→ 好奇层被压制，自然中断
```

### 4.3 漫游域（与城墙/防区绑定）

| 职业 | 漫游域 |
|------|--------|
| 生产职业 / 无职业（平民） | 城墙 region + 城墙以内 region |
| 士兵 | 城墙 region 的**本驻守半区**（左防区 / 右防区，不越中线） |

- "城墙以内"：首版由地图/建造数据提供城墙 region 区间配置（占位：WorldConfig 加城墙区间字段，接建造系统后自动取）。
- **驻守边由军令系统下发**（部署是任务不是性格）：首版 ScheduleCenterStub 配置左/右防区字段；P1 升级为君主玩家划防区玩法（3.0.1_3 联动）。
- 休眠区 0.5Hz 思考 + 好奇层漫游 = 远处村庄最便宜的生动性。

## 六、实施优先级

### P0（思考分区跑通）

1. RegionLodState：region 持有 level/threatHeat/idleTimer + LODSystem 管理器（含 region→单位索引，GridSystem 无现成）
2. 活跃带判定：君主（RulerController.Instance.MonarchUnit 现成）+ **军队锚点注册表（新增）** 双中心，一维带状并集。⚠️ 鸡生蛋规避（2026-08-01 审计 D1）：注册方 FormationController 在 3.0.1_3 P0 才出生——LOD P0 降级为**仅君主中心**先行，注册表建好但无注册方时单中心运行（军队中心留接口）；编队 P0 落地时 FormationController 注册进表
3. NPCBrain 三区 Think 降频接入：ThinkInterval 常量 → per-brain 变量读 region 频率；**Think 的 dt 改传真实墙钟差值**（结构性障碍②）；感知计时器 `_perceptionTimer` 同步接 LOD，否则休眠区感知照跑 5Hz
4. **感知广播事件源（新增，结构性障碍③）**：GridSystem.TryEnter 挂"敌人进格"发布点 → 威胁类事件升整 region 即时 / 军令升目标 region / 受击 off-tick 唤醒个体
5. ThreatHeat 累积衰减 + heatFactor 进 rawFactor：**前置 = rawFactor 权重迁 SO + 删 enemyCount==0 早退**（结构性障碍①）；受击事件节流（0.5s）致热度入账偏少，接收端自行累计
6. 升降级防抖（升级即时 / 降级 30s 逐级）+ 量化器墙钟秒语义钉死（随第 3 项 dt 修复落地）
7. RegionHeatChangedEvent：Publish 前 HasSubscribers 守卫（EventBus 无订阅者刷警告）
8. 验证场景：远处村庄工人 0.5Hz 搬运不中断；村口被射 → 全区升活跃、同区 NPC 提前警觉；玩家走近 → 活跃带覆盖
