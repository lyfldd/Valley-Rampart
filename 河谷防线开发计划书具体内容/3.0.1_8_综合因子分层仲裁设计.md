# 3.0.1_8 综合因子分层仲裁设计（因子体系完备化）

> 日期：2026-08-02
> 状态：设计定稿（用户决策，待实施）
> 前置：3.0.1_4 多因子决策（§5 因子通道纪律）/ 3.0.1_LOD（统一因子表目标态）/ 3.0.1_3（破阵博弈 = 两因子仲裁的验证样本）
> 本文解决：**"一直在修威胁因子，改来改去，系统不完备"**——rawFactor 单通道过度承载 + 量化器过早压档的架构缺陷。

---

## 一、问题诊断：为什么"一直在修威胁因子"是系统不完备的信号

### 1.1 现状决策链

```
小因子(距离/数量/血量/友军/昼夜/热度)
   → rawFactor 加权和（一个袋子）
   → 量化器压 4 档（0.25/0.5/0.75 升阈）
   → L2 谱系只认 ThreatLevel 4 档
```

### 1.2 四个结构性缺陷

| # | 缺陷 | 表现 |
|---|------|------|
| 1 | **单通道过度承载** | 所有语义全揉进一个 rawFactor——"贴脸一个敌人"和"远处三个敌人"可能都是威胁 2，档内差异全丢 |
| 2 | **调参耦合** | 改距离权重牵连血量语义；修"白嫖"调了距离因子又导致"深入腹地"——调的其实不是"距离"而是"整个威胁概念" |
| 3 | **语义不可解释** | 威胁 2 说不清是"敌人近"/"被集火"/"战友死了"，没法针对性调 |
| 4 | **决策被量化器卡死** | L2 只认 4 档，精调因子也没用，精度天花板在那 |

## 二、定案方案：B 分层仲裁 + 两个修正（用户决策 2026-08-02）

### 2.1 方案选型

| 方案 | 做法 | 结论 |
|------|------|------|
| A 加权合成 | 四个综合因子再加权成一个分数 | ❌ 换汤不换药——"威胁0.6+归巢0.4"和"威胁1.0+归巢0"总分相同但决策应相反，语义在合成点丢失 |
| B 分层仲裁 | 保持五层注意力+层间压制，每层各吃综合因子，L2 变因子仲裁器 | ✅ **选定** |
| C 多目标分解 | 不合成分数，逐因子 if-else 仲裁 | ❌ 退回行为树，违背 3.0.1_2 铁律"永不写场景专属 if-else，行为从因子计算涌现" |

### 2.2 修正一：B 不是革命，是推广

现有架构里已有两个 B 的活样本：

1. **L1 本身就是多因子仲裁器**：`ThreatStimulus.Intensity / safetyUrge / FollowStimulus.Intensity` 就是各语义综合因子的雏形——各走各的层，靠层间压制仲裁，不合成总分。
2. **破阵博弈（3.0.1_4 §4.3）是"两因子不合成总分、靠仲裁定胜负"的已验证实现**：`threatPressure / formationHold` 连续比较 + 双阈值滞回（升1.0/降0.7）。

真正要改的只有一条链：

```
rawFactor → 量化器 4 档 → L2 谱系查表
```

### 2.3 修正二：耦合止于语义同类 + 量化器再定位

**铁律**：
- ✅ 小因子 → 综合因子：**耦合**（距离/数量/战力语义同类，加权和没毛病）
- ❌ 综合因子 → 单一总分：**不做**（威胁和归巢语义不同类，合成即丢失）
- ✅ 最终决策靠**仲裁（比较）**，不靠**合成（加权）**

**量化器再定位**：
- 量化器不是敌人，**量化位置才是**
- 缺陷 1/4 的病根不是"有量化器"，而是量化发生在决策链太上游（rawFactor 第一步就压 4 档，后面全链路消费档位）
- 正确形态：

```
连续综合因子 → 连续仲裁（如 breakScore）→ 双阈值滞回 → 最后一步才离散成谱系
```

- 谱系是仲裁的**结果**而非输入；滞回防抖保留（防焦点横跳）

## 三、综合因子设计（范围克制：先拆 2 个）

### 3.1 目标形态（长期）

```
FactorContext 平行放多个综合因子（各自 0-1，各由小因子构成）：
├─ 威胁因子 ThreatFactor    ← 距离/数量/敌方战力/受击溯源/集火/夜间
├─ 协作因子 FormationFactor ← 编队完整度/槽位偏差/友军密度（我在编队）
├─ 工作因子 WorkFactor      ← 任务投入/军令执行/工作进度
└─ 归巢因子 SafetyFactor    ← 离家距离/夜晚/受伤（现在散在 Safety 刺激里）
```

每个因子**独立可调、语义清晰、可解释**——调距离只影响威胁因子，不再牵连全局。

### 3.2 本期范围（克制，先拆 2 个）

| 综合因子 | 小因子构成 | 现住 | 迁移目标 |
|---------|-----------|------|---------|
| **威胁因子 ThreatFactor** | distFactor / countFactor / enemyPowerFactor / 溯源强度 / 集火计数 / timeFactor | rawFactor 加权和 | 独立计算，输出连续值 0-1 |
| **协作因子 FormationFactor** | 编队存活率 / 槽位偏差 / 友军密度 | 散在 FollowStimulus + 阵型完整因子候选 | 独立计算，输出连续值 0-1 |
| 其余（工作/归巢） | — | 保持现状 | 留待后续拆 |

> 其余因子先留在 rawFactor 不动（风险 5.4：因子越多越难调，分批拆）。

## 四、仲裁机制：破阵博弈推广为多因子竞争

### 4.1 核心思想

不再"威胁 4 档一刀切"，而是**多因子连续竞争 + 滞回防抖**：

```
每 tick：
  威胁因子 T（连续 0-1） vs 协作因子 F（连续 0-1） vs 归巢驱力 S
  竞争分数 = 仲裁函数(T, F, S)   ← 连续比较，不合成总分
  双阈值滞回：升阈/降阈之间保持当前状态（防横跳）
  最后一步：按仲裁结果离散成谱系（FullPower/Cautious/Retreat）
```

### 4.2 现有破阵博弈的推广

3.0.1_4 §4.3 已是"两因子仲裁"样板：

```
breakScore = threatPressure / formationHold
升阈 1.0 持续 → 破阵（威胁胜出）
降阈 0.7 持续 → 归队（编队胜出）
带内保持当前状态
```

推广方式：
- 破阵博弈的两端各换成一个综合因子（威胁因子 vs 协作因子）
- 归巢驱力作为第三方参与（三因子仲裁，或两两仲裁后取优）
- 所有仲裁函数**连续输入、滞回输出**，谱系是最后一步的离散化

### 4.3 顺带解决"阵型切换执行力低"

用户痛点：有敌人时优先打敌人，切阵型没执行力，弓手被白嫖。

- 现状病根：威胁 4 档一刀切——战斗中威胁层永远压过任务层，士兵不响应新槽位
- 新设计：切阵型 = **协作因子提高**（将军 S 级军令注入），能否压过威胁因子取决于**连续仲裁**而非档位
  - 威胁 0/1 级（低威胁）：S 级军令强制归位（协作胜出，保护弓手）
  - 威胁 2/3 级（高威胁）：允许打完再归（威胁胜出，不丢贴脸敌人）
  - 这是"指挥优先级 vs 战斗本能"的连续权衡，而非"4 档"的粗暴二选一

## 五、归巢因子定案（SafetyFactor 独立化，P1）

### 5.1 与放弃任务的语义分工（先厘清，防混淆）

| 驱力 | 触发 | 目的地 | 层级 |
|------|------|--------|------|
| **放弃任务**（§六） | 追击/执行成本 > 收益 | **回阵型**（回协作状态） | 任务层 |
| **归巢**（SafetyFactor） | 重伤 / 夜晚 / 离家远 | **回家**（HomePoint） | 生存层 |

**级联关系**：先弃任务 → 回阵型；仍重伤 → 再归巢回家。放弃 ≠ 归巢，二者目的地不同、触发不同。

### 5.2 B 重构：0-1 连续因子

```
SafetyFactor = clamp01( 离家距离×w1 + 夜晚×w2 + 受伤×w3 )
  w1 离家：离家格数 / 感知半径（归一化，越远越想家）
  w2 夜晚：nightFactor × nightWeight（复用 3.0.1_2 夜间权重）
  w3 受伤：(1 - hpRatio) × woundWeight
```

现状：Safety 刺激（RetreatFormulas.SafetyUrge）是连续强度但散在 L1，不参与 L2 仲裁。
目标：SafetyFactor 抽象为 FactorContext 的独立综合因子（0-1），进 L2 仲裁。

### 5.3 A 串行仲裁 + AND 联合语义

```
L1（刺激层）：safetyUrge 保留（保底归巢，D 级归巢行为不变）
L2（仲裁层）：撤退 = 威胁压过协作（破阵升阈） AND SafetyFactor 强（> 阈值）
```

AND 语义防"白嫖逃跑"：单有威胁不撤（编队协作压住），必须"被打狠 AND 想回家"才真撤。

### 5.4 实施要点

- P1：FactorContext 加 `SafetyFactor` 字段；L2 撤退谱系判定加 AND 条件
- 归巢原路径（L1 safetyUrge）保留，L2 只做撤退谱系的联合判定

## 六、放弃任务因子定案（防风筝无谓追击，P1）

### 6.1 用户痛点（3.0.1_4 场景实测）

聪明 AI 弓手边打边退，我方士兵追不上还一直追——单靠威胁+协作两因子表达不了"这个任务不划算"。

### 6.2 定义

> **放弃任务** = 追击/执行中**成本超过收益** → 主动放弃当前任务，**回到编队状态**（不是回家）。
> 与归巢区分：放弃 = 回阵型，归巢 = 回家。

### 6.3 加权仲裁 + 滞回（效仿强化学习奖励函数）

```
收益 Benefit（正分）：
  + 可击杀     （目标残血 / 距离内可近身）
  + 战果预期   （我方 dps vs 目标剩余血）
  + 军令要求   （协作因子支持追击）
  + 君主令     （S 级军令 / 不顾一切指令 → 收益封顶，永不弃）

成本 Cost（负分）：
  - 追击损失   （追击中无输出还挨打：掉血速率）
  - 队友减损   （周围友军数量下降）
  - 距离拉大   （目标远离速度 > 我方追击速度）
  - 时长       （追击超时）

abandonScore = ΣBenefit − ΣCost
双阈值滞回：升阈（继续追）/ 降阈（放弃），带内保持当前状态（防横跳）
```

### 6.4 与破阵博弈 / 归巢的级联三档

```
1. 放弃任务（abandonScore 降阈）→ 回阵型，FollowStimulus 重新拉回
2. 仍重伤（SafetyFactor 高）→ 撤退回家（AND 联合，§五）
3. 军令/君主令压过 → 不弃（军队任务价值高，见 3.0.1_5 §FormationBrain）
```

### 6.5 实施要点

- P1：`AbandonTaskFactor` 独立因子（FactorContext 字段 + 计算）
- 消费点：L2 谱系新增"放弃追击 → 回归编队"判定（FullPower ↔ Cautious 之间）
- 多编队应用：军队级 FormationBrain 读同类信号，决定**编队整体**放弃进攻（3.0.1_5）

### 6.6 坚持任务因子（PersistFactor，收益侧扩充，用户决策 2026-08-02）

**动机**：放弃任务因子当前收益侧只有"可击杀 + 军令"两项，太薄——坚持的理由（君主令/装备/敌情/移速差）全缺失。放弃与坚持是天平两侧，扩收益侧 = 扩坚持。

**定案**：`abandon = clamp01(成本 − persistFactor)`，persistFactor 是收益侧加权和：

```
persistFactor（坚持理由，0-1）：
  ├─ 君主令     （S 级军令/不顾一切 → 直接封顶 1.0，永不弃）——载体留作战面板批（FollowStimulus.IsRoyalCommand）
  ├─ 编队军令   （FormationFactor × abandonBenefitOrder，已有）          w2
  ├─ 装备战力   （我方 attack ≥ persistPowerAttackGate → 打得动）        w3
  ├─ 敌情可击败 （目标残血 / 我方 attack − 目标 defense ≥ persistDamageMargin）  w4
  └─ 移速追得上 （我方 walkSpeed > 敌方 × 1.1 → 真追得上）              w5
```

**对称关系**（同一事实的正反两面）：
- 移速追得上 ↔ 距离拉大（追得上则坚持，追不上则成本叠加）
- 敌情可击败 ↔ 追击受伤（我能杀它 vs 它能耗我）
- 君主令是最高权——收益封顶，永不弃（覆盖一切成本）

**数据源**（全都有，不等新系统）：
- 我方：NpcProfessionDef.attack / defense / walkSpeed
- 敌方：目标 `as UnitController` 读 Data（NpcProfessionDef，含攻击/防御/移速/种类）
- 装备系统首版空（equipmentSlotCount=0）——装备战力先用基础攻击/防御间接表达，因子位留好，装备系统落地后挂真实属性
- ⚠️ 当前全部职业 walkSpeed 相同（=3）——移速因子位就绪但暂不触发，待职业移速差异化后生效（因子位不删）

**实施**：P1 扩 ComputeAbandonTaskFactor 收益侧 5 项（君主令载体后置）。

## 七、阵型切换定案（A 瞬时提强度 + 自然归位，P1）

### 7.1 痛点

战斗中切阵型没执行力（威胁层永远压过任务层），弓手被白嫖。

### 7.2 定案：切阵型瞬时提军令强度

```
正常军令：orderIntensity = 4.5（S 级）
切阵型瞬间：orderIntensity = 6.0（瞬时提强度，保底 1s）
  → FormationFactor = 6.0 / 4.5 = 1.33 → clamp 1.0（协作因子满值）
  → 破阵博弈中编队抵抗更强 → 低威胁士兵强制归位
```

- **低威胁**（ThreatFactor < 0.3）：瞬时军令强制归位（保护弓手）
- **高威胁**（ThreatFactor ≥ 0.3）：允许打完再归（威胁胜出，不丢贴脸敌人）
- 效果：切阵型 1s 内士兵优先响应新槽位，1s 后自然回落到正常军令强度

### 7.3 与 §4.3 的关系

§4.3 是机制描述（协作因子提高），本节是**具体参数定案**（4.5 → 6.0 瞬时提强度 + 保底时长）。

### 7.4 实施要点

- P1：FormationController.SetIntent 内瞬时提强度（`_boostUntil` 时间戳，提升期 orderIntensity=6.0）
- NPCBrain 组装 FormationFactor 时读提升后强度（FormationController 暴露 `EffectiveOrderIntensity`）
