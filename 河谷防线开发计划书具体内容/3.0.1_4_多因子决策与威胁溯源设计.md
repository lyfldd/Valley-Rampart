## 一、背景与问题（用户场景复现）

### 1.1 现象：近战士兵被远程白嫖

敌方弓箭手（射程 5 格）站在我方近战士兵（射程 1 格）感知范围内射击，我方士兵站在原地挨打不还手。

### 1.2 根因链路（已核实代码）

```
敌方弓箭手进入感知范围
  └─ UpdatePerception 产生 ThreatStimulus（威胁等级来自量化器，敌人远 → rawFactor 低 → 0/1 级）
  └─ 3.0.1_3「编队优先」：威胁 ≤1 级 + 有编队军令 → FollowStimulus(槽位) 压过威胁层
        （AttentionSystem.SelectTopFocus，固定等级阈值硬开关）
  └─ 被射中 → Caution 态，stateThreatBias 最多抬到 Alert=1 级 → 仍 ≤1 → 编队继续压制
  └─ 攻击注册（NPCBrain.UpdateCombatRegistration）：
        路径1（威胁焦点）被压制不成立
        路径2（射程内最近敌）弓箭手在近战射程(2.26 世界单位)外 → 不成立
  └─ 结果：焦点=槽位 → 已到槽位 → Idle，傻站挨打
```

### 1.3 暴露的设计缺口

| # | 缺口 | 说明 |
|---|------|------|
| ① | **受击无溯源** | 威胁感知只靠空间查询（感知半径内找敌人），未订阅受击事件。攻击者在感知范围外射击 → 完全不知道谁射的 → 无威胁刺激 |
| ② | **编队压制是硬开关** | 威胁 ≤1 级一刀切压制，不区分威胁来源（贴脸近战 vs 远处弓箭手 vs 被持续集火） |
| ③ | **因子单一** | rawFactor 7 因子距离主导，无受击/仇恨/集火/阵型/伤亡因子 |
| ④ | **无漫游** | SafetyStimulus 兜底直接回城，无事时原地待命，不会左右小幅移动 |

## 二、受击溯源（攻击者信息回传）

### 2.1 现状核实

- `UnitDamagedEvent { Unit, Source(IDamageable), ActualDamage, Position }` —— **Source 已带攻击者引用**，由 `DamageSystem.ApplyDamage` 发布（近战/投射物到达共用）
- 投射物命中时 `ProjectileManager` 以发射者为 source 调用 `ApplyDamage`
- 受击事件已节流（同一 victim 每 0.5s 最多一次，住 DamageConfig.EventThrottle）
- **NPCBrain 未订阅** `UnitDamagedEvent` —— 当前威胁感知 100% 依赖空间查询

### 2.2 结论：被射中的人能拿到发射人信息，且当前就能拿

只需要 NPCBrain 订阅 `UnitDamagedEvent`，把 `Source` 转为"指向攻击者的 ThreatStimulus"。

### 2.3 方案：受击溯源威胁注入（聚合式，O(1)）

> ⚠️ **性能约束（讨论确认 2026-08-02）**：几百 AI 逐个追踪攻击者列表绝对行不通。
> 溯源**不追踪"所有攻击者"，只聚合为 O(1) 状态**——无论被 1 个还是 10 个弓箭手射，
> 每 tick 都只处理一条聚合信息。

**每个 NPC 只维护一份聚合溯源状态**：

```
private IDamageable _lastAggressor;  // 最近攻击者（1 个，谁打最狠/最近）
private int _recentHitCount;         // 受击次数（聚合计数）
private float _lastHitTime;          // 最近受击时间
```

**订阅 UnitDamagedEvent 时的更新（每 0.5s 节流后触发，O(1)）**：

```
OnDamaged(UnitDamagedEvent evt)
  ├─ evt.Unit != 自己 → 忽略
  ├─ evt.Source == null（环境伤害）→ 只 HitCount++，不更新攻击者
  ├─ evt.Source 阵营 == 自己阵营（误伤）→ 忽略（或降权）
  └─ 敌对攻击者 → _lastAggressor = evt.Source；_recentHitCount++；_lastHitTime = now
```

**每 tick 只生成一个溯源 ThreatStimulus（聚合）**：

```
溯源 ThreatStimulus
  Position = _lastAggressor.GetPosition()
  Enemy    = _lastAggressor
  Intensity = min(溯源上限, 40 + (_recentHitCount - 1) × 10) × Decay(Δt)
             Δt = now - _lastHitTime
             Decay(Δt) = exp(-Δt / 3s)      // 指数衰减，与 threatDecayTime=3s 对齐
             Expiry = now + 5s              // 无受击 5s 后刺激移除（3s 衰减的保险）
  ThreatLevel = max(空间威胁等级, 受击保底 1)   // 被射至少警戒
```

> 📌 **溯源强度细节已定（2026-08-02）**：基础强度 40 + 每次追加 10（达上限 60），指数衰减 3s。
> 验算（士兵 courage70/obedience80）：一次受击=40（破阵 0.55 不破，白嫖一次不脱队）；
> 二次=50（0.69 不破）；三次=60 达上限且 threatLevel 抬到 2 → 破阵 1.11（集火 1.5s 后反应）。

**关键收益**：
- 攻击者在感知范围外也能被"溯源"到 → 被射了知道谁射的 → 突破①
- O(1) 聚合：几百 AI 无压力，被多个弓箭手射也只是一条聚合刺激
- 受击越密集 → 强度越高 → 集火识别自然涌现（被重点照顾的人先反应）

**与空间感知的关系（决策4 已定：合入威胁层）**：

> ✅ **讨论定稿（2026-08-02）**：溯源威胁与空间威胁**合入同一个威胁层**竞争，不设独立溯源层。
> 理由：两者本质都是威胁，分家无语义收益；威胁分层（近战 100 > 远程溯源 ≤60）已保证"近战贴脸时不会弃近战追远程"，无需独立层兜底。

- 感知内敌人 → 空间威胁（现有，距离主导）
- 感知外攻击者 → 聚合溯源威胁（新增，受击驱动）
- 两者合入 `_threatStimuli` 按 Intensity 竞争，取最高者（`GetTopThreat` 现成逻辑）

### 2.4 注意点

- 事件节流 0.5s 天然限频，不会刷爆 AttentionSystem
- 溯源威胁需有 Expiry（如 2-3s 无受击衰减），避免"被打过一次永远记得"
- 对象池回池时清空溯源状态（防新 NPC 继承上辈子仇恨）
- `_lastAggressor` 死亡/离开 → 该溯源刺激失效（`RemoveThreatStimuli` 现成逻辑）

## 三、多威胁并存裁决

### 3.1 现状（用户问题："前面近战贴身 + 又被射"）

- `ThreatStimulus.Intensity = 100 × (1 - dist/perceptionWorld)` → **距离越近强度越高**
- 近战贴身敌人 → Intensity 接近 100 → 威胁焦点=近战 ✓（用户的直觉正确）
- 近战被消除（死亡/离开）→ 该 ThreatStimulus 失效（`RemoveThreatStimuli`/Expiry）→ 下一个威胁浮出

### 3.2 近战消除后，"被箭射"场景

| 情形 | 攻击者位置 | 能否溯源 | 结果 |
|------|-----------|---------|------|
| A | 在感知范围内 | 空间威胁已有 | 弓箭手威胁浮出，正常 |
| B | 在感知范围外 | **靠 §2 溯源注入** | 无溯源 → 完全无感知 → 被白嫖 |

**§2 溯源方案落地后，情形 B 被覆盖**：被射 → 溯源 ThreatStimulus → 威胁层有内容 → 破编队压制（见 §4）→ 主动转向攻击者。

### 3.3 集火识别（多攻击者）

- 被多个远程同时射击 → 多次受击 → 聚合溯源强度累加（§2.3 `_recentHitCount`）
- 设计：`溯源强度 = min(溯源上限, 单次增量 × _recentHitCount) × 时间衰减`，受击越密集威胁越高
- 集火目标会比其他成员更早破阵脱队 → "被重点照顾的人先反应"的自然涌现

### 3.4 威胁分层（近战 > 远程）——防脱队深入敌腹

> ⚠️ **讨论确认（2026-08-02）**：不能靠"调高远程因子权重"解决白嫖——那样士兵会弃近战追远程、
> 冲出阵型深入敌方腹地。正确方向是**威胁分层**：近战贴脸威胁 > 远程威胁，分档而非同一把尺子。

**近战优先天然成立，无需调权重**：

```
近战贴脸（1 格内）：Intensity ≈ 100   ← 距离主导，天然第一
远程 5 格外：       Intensity ≈ 30-50  ← 天生低
```

**关键约束：溯源远程强度设上限，保证永远低于贴脸近战下限**：

```
溯源强度上限 = 60（占位）< 贴脸近战强度 ≈ 100

焦点选择（GetTopThreat 按强度）：
  近战贴脸(100) > 远程溯源(≤60) → 永远先打近战 ✓
  近战被清除 → 远程(60) 浮出 → 才转向远程 ✓ 「近战没了，远程占大头」
```

这实现用户直觉的「受击近战最大，近战没有则远程占大头」——不是按距离线性排，
而是**威胁源类别分档（近战档 > 远程档），档内再按距离/受击强度排序**。

### 3.5 防深入腹地的三层钳制（已有一半，③ 需新增）

```
① chaseRange clamp（已有，L3CommandComputer §4.1）：MoveTowards 目标钳在槽位 ±2 cell
② 远程停射程外（已有）：isRanged 时目标进射程就停原地，攻击系统 In-Range 自动开火
③ 近战追远程钳制（新增）：只允许追到 chaseRange 边缘；
   够不到（超出钳制范围）→ 威胁减弱 → 回归守槽位，不无限追出阵型
```

| 场景 | ① 钳制 | ② 远程停射 | ③ 近战追远程 | 结果 |
|------|--------|-----------|------------|------|
| 近战贴脸 | 追击被钳 | — | — | 槽位附近应战 ✓ |
| 远程 5 格外射击 | 追击被钳 | — | 追到钳制边缘够不到 → 回归 | 不脱队 ✓ |
| 远程进入射程 | 追击被钳 | 停原地开火 | — | 站桩对射 ✓ |

## 四、威胁因子 vs 编队压制（动态博弈）

### 4.1 现状：固定等级阈值硬开关

```csharp
// AttentionSystem.SelectTopFocus
if (hasFormationSlot && threatLvl <= 1)
    return SelectTopTaskLayer();   // 编队压过威胁
// 威胁 2+ 才破阵
```

问题：等级是量化器对 rawFactor 的分档（0.25/0.5/0.75 升阈），**把连续的威胁强度压成 4 档**，档内差异丢失；且"1 级警戒"与"2 级危险"之间是断崖，弓箭手持续射击可能永远卡在 1 级以下。

### 4.2 用户诉求

> "想要威胁因子自己大于我们的编队压制，怎么设计呢"

### 4.3 方案：强度化博弈（替代等级硬开关，公式已定稿）

破阵判定从"等级阈值"改为"威胁压力 vs 编队约束"的连续博弈。

**公式（已归一化，量纲统一）**：

```
// 威胁压力（分子，0-1+）
threatPressure = (Intensity / 100)                    // 威胁强度归一化：0-1
               × (1 + threatLevel × levelWeight)      // 等级加成：levelWeight 住 SO，默认 0.5
                                                      //   （0级=1.0，1级=1.5，2级=2.0，3级=2.5）
               × (0.5 + courage / 100)                // 勇气系数：courage50=1.0，100=1.5，0=0.5

// 编队约束（分母，0-1+）
formationHold  = max(0.1, formationIntensity / 4.5)   // 军令强度归一化（4.5=S级基准），除零保护
               × (0.5 + obedience / 100)              // 服从系数：obedience50=1.0，100=1.5，0=0.5

breakScore = threatPressure / formationHold
破阵条件：breakScore > breakThreshold（默认 1.0，住 AttentionTuningConfig）
```

> 📌 **细节 1 已定（2026-08-02）：levelWeight 显式化**——等级加成系数从硬编码 0.5 提为 SO 参数
> `levelWeight`（默认 0.5）。threatLevel 承载"整体危险度"（血量/数量/友军/昼夜综合），保留加成有价值；
> 显式化后调参可单独控制"整体危险度"对破阵的影响力，不必动公式结构。

> 📌 **细节 2 已定（2026-08-02）：破阵双阈值滞回**——`breakScore` 每 tick 裸算会在阈值附近抖动，
> 导致破阵/归队焦点横跳、阵型撕裂。给破阵判定配双阈值滞回（与 HysteresisQuantizer 同构）：
>
> ```
> 升阈：breakScore > 1.0（默认，住 SO）    → 破阵
> 降阈：breakScore < 0.7（默认，住 SO）    → 归队
> 带内（0.7 ~ 1.0）：保持当前状态（破阵中保持破阵，守位中保持守位）
> 升级确认 0.3s / 降级确认 0.5s（沿用现有量化器确认节奏，可选）
> ```
>
> 效果：敌人轻微进退（0.7~1.0 带内）不触发切换；真正远离/受击停止才归队。
> 参数（升阈/降阈/确认时长）全部住 AttentionTuningConfig。

> 📌 **细节 3 已定（2026-08-02）：保留军令强度参与**——分母 `formationIntensity / 4.5` 保留，
> 军令越强越难破阵（将军调 orderIntensity → 破阵难度随之变化）。此通道同时服务后续意图系数
> （§14 防守意图对分母加成 = 更难脱队，进攻意图对分子加成 = 更敢脱队）。

**场景验算（士兵 courage70 / obedience80 / S 级军令 4.5）**：

| 场景 | Intensity | threatLevel | 分子 | 分母 | breakScore | 行为 |
|------|-----------|----|------|------|-----------|------|
| 近战贴脸 | 100 | 2 | 1.0×2.0×1.2=2.4 | 1.0×1.3=1.3 | 1.85 | 破阵应战 ✓ |
| 远程受击一次 | 40 | 1 | 0.4×1.5×1.2=0.72 | 1.3 | 0.55 | 守位 ✓ |
| 远程持续集火（溯源达上限） | 60 | 2 | 0.6×2.0×1.2=1.44 | 1.3 | 1.11 | 破阵 ✓ |
| 无威胁 | 0 | 0 | 0 | 1.3 | 0 | 守位 ✓ |
| 懦夫 courage30 被集火 | 60 | 2 | 0.6×2.0×0.8=0.96 | 1.3 | 0.74 | 不破阵 → 走 L2 谱系撤退 ✓ |
| 高纪律 obedience90 被集火 | 60 | 2 | 1.44 | 1.0×1.4=1.4 | 1.03 | 临界（勉强破） |

**关键行为解读**：
- **近战贴脸必破阵**（无论纪律多高，敌在脸上不能不打）✓
- **远程一次射击不够破阵**（守位，白嫖一次不脱队）✓
- **持续集火才破阵**（受击溯源强度累积 + 等级抬高 → 被重点照顾的先反应）✓
- **懦夫不破阵去撤退**：courage 低 → breakScore 低 → 不脱队 → 走 L2 谱系（威胁高 → 撤退逃跑）。**脱队反击=勇者行为，逃跑=懦者行为，两套机制自然分工** ✓
- **纪律兵更难脱队**：obedience 高 → 分母大 → 破阵阈值更高 ✓

**兼容旧逻辑**：旧"威胁 2+ 硬破阵"被新公式覆盖——贴脸威胁 threatLevel≥2 时 Intensity≈100，breakScore 必然 >1，等价旧行为但更平滑（不再有档位断崖）。

**编队强度的含义**：
- `formationIntensity` = FollowStimulus.Intensity（S 级军令下发值，FormationController.orderIntensity）
- `obedience` = NpcProfessionDef.obedience（0-100，士兵高、工人低）
- 意图（§14 防守/进攻）后续可通过系数参与：防守意图对分子打折（守位加成），进攻意图对分子加成（脱队鼓励）

**与 §3.5 钳制的联动（重要）**：破阵 = 焦点切到威胁层 → L3 MoveTowards 目标仍被 `chaseRange clamp`（槽位±2 cell）钳制 → **破阵 ≠ 无限追击**：
- 近战追远程：走到钳制边缘（朝远程方向前压 2 cell），够不到 → 若威胁持续则停在边缘警戒，若威胁消失则回归守槽
- 近战贴脸：敌在钳制范围内，直接应战
- 破阵的真正收益：允许**离开槽位**（解除 FollowAnchor 压制），远程单位（弓手）前压后若敌进射程则 In-Range 自动开火

**好处**：
- 连续而非断崖，威胁强度/血线/受击次数都能细粒度参与
- 参数全部住 SO（AttentionTuningConfig + NpcProfessionDef），Play 模式可调
- 编队不再"铁板一块"——个体差异（courage/obedience）自然涌现，呼应 3.0.1_3 §1.1"溃散/死战/续战由 courage × obedience 涌现"

### 4.4 受击后行为（决策1 已定：混合方案）

> ✅ **讨论定稿（2026-08-02）**：混合方案——受击行为按威胁源类别分流，与威胁分层（§3.4 近战>远程）天然一致：

```
受击发生
  ├─ 近战威胁贴脸（强度≈100）→ 原地应战，Caution 语义自然成立（敌在脸上，无需跑）
  └─ 远程受击（溯源）
       ├─ 近战威胁仍在 → 守位（近战优先，不弃近战追远程）
       └─ 近战威胁已清除 → 直接破阵应对远程（不再等警戒结束）
```

> 📌 **细节 5 已定（2026-08-02）：混合方案靠公式自然涌现，不写显式分流逻辑**——
> 近战贴脸(100) + 远程受击(60) 同时存在时，`GetTopThreat` 取强度最高者 → 焦点=近战（守位语义自然成立）；
> 近战死后只剩远程溯源 → breakScore 过线才破阵。实现最简，优先级靠"溯源上限 60 < 贴脸近战下限"参数纪律保证（§3.4）。
> ⚠️ 调参纪律：调整溯源上限或近战强度时，必须保持 上限 < 贴脸近战下限 的数值差，否则近战优先会被反转。

> 📌 **细节 4 认知校准（2026-08-02）**：近战贴脸强度实际是 90-100（`100×(1-dist/感知半径)`，dist≈0.5cell → 90），
> 非恒 100。验算表按 100 估算，真实输入 breakScore 略低但仍 >1.0 破阵。调参时 breakThreshold 有效区间
> 按输入真实范围（贴脸 90-100 / 溯源上限 60）校准。

**好处**：
- "受击→破阵"只发生在"没有更紧迫的近战威胁"时 → 纪律和反应速度兼得
- 与威胁分层同一套判据（近战 100 > 远程溯源 ≤60），无新增裁决分支

### 5.1 现有因子（`ThreatAssessor.CalculateRawFactor`，7 个）

| 因子 | 权重 | 输入 | 缺陷 |
|------|------|------|------|
| distFactor 距离 | 0.35 | nearestEnemyDist | 感知内最近敌人距离，感知外攻击者=0 |
| countFactor 数量 | 0.15 | enemyCount | 不区分近战/远程构成 |
| hpFactor 血量 | 0.2 | hpRatio | 无 |
| allyFactor 友军 | 0.2 | allyCount | 只算数量不算构成 |
| timeFactor 昼夜 | 0.1 | isNight | 只有 0/0.1 两态 |
| （隐含）敏感度 | × | threatSensitivity | 职业差异 |
| （隐含）保底 | max 0.5 | 敌人进攻击距离 | 贴脸强制威胁2 |

### 5.2 新增因子候选（按价值排序）

> ⚠️ **通道归属纪律（讨论确认 2026-08-02）**：威胁分层 / 受击 / 集火 / 仇恨
> **全部走刺激源强度通道（ThreatStimulus.Intensity）**，不进 rawFactor 加权和——
> 否则 distFactor(0.35) 再加新权重会失衡，且 rawFactor 压 4 档丢失连续信息。
> rawFactor 保持 5-7 个主因子不动。

| # | 因子 | 输入 | 作用 | 通道 | 住哪 |
|---|------|------|------|------|------|
| ① | **受击因子** | 聚合溯源状态：`_lastAggressor` / `_recentHitCount` / `_lastHitTime`（§2.3） | 被持续射击 → 溯源强度推高，识别"正在被打"而非"旁边有敌人" | B 刺激源强度 | 代码 + AttentionTuningConfig |
| ② | **仇恨因子** | 受击累计次数（对攻击者定向，激活 Hate 层） | 被打得越多越恨特定攻击者，优先还击 | B 刺激源强度 | NpcProfessionDef（记仇程度） |
| ③ | **攻击者战力因子** | 攻击者 attack / 自身 defense | "能打死我的人"威胁更高（3.0.1_1 §4.1 enemyPowerFactor 有雏形未入 rawFactor） | B 刺激源强度 | 代码 |
| ④ | **集火因子** | `_recentHitCount`（聚合计数，非逐个攻击者） | 被多人瞄准 → 溯源强度累加 → 提前破阵/撤退（O(1) 聚合实现） | B 刺激源强度 | 代码 |
| ⑤ | **威胁分层因子** | 威胁源类别（近战/远程）+ 溯源强度上限（§3.4） | 近战档 > 远程档，防脱队深入敌腹 | B 刺激源强度 | AttentionTuningConfig（上限） |
| ⑥ | **阵型完整因子** | 编队存活成员数 / 满编数（FormationController 已有数据） | 阵亡越多越容易脱队（呼应 3.0.1_3 减员防抖） | A rawFactor | FormationController 接口 |
| ⑦ | **队友伤亡因子** | 附近友军死亡事件（UnitDiedEvent） | 战友死了 → 恐惧推高，个体化反应 | A rawFactor | EventBus 订阅 |
| ⑧ | **任务投入因子** | 当前焦点是否任务/军令，任务进度 | 军令执行中难脱队，闲逛中易脱队 | 编队压制强度（§4.3） | 代码 |
| ⑨ | **漫游扰动因子** | 无威胁时的随机扰动 | 配合 §6 漫游，无事左右小幅动 | C 行为命令 | 代码 |

### 5.3 因子组织纪律（沿用三分法）

- 代码枚举/标定：不进 SO（改即改架构）
- cellSize：住 GridConfig
- 可调参值：AttentionTuningConfig（全局节奏）+ NpcProfessionDef（职业差异）
- **rawFactor 权重表考虑整体搬入 AttentionTuningConfig**（当前硬编码在 CalculateRawFactor），Play 模式拖滑块调手感，不用重编译

### 5.4 风险

- 因子越多越难调出好手感（7+8=15 因子），需要分层：rawFactor 保持 5-7 个主因子，其余走刺激源强度（溯源/仇恨注入 ThreatStimulus.Intensity），避免全部塞进加权和
- ⚠️ 设计原则建议：**主因子（加权和）瘦身，次因子（刺激源强度）增肥**——受击/仇恨/集火都注入 ThreatStimulus.Intensity 而非 rawFactor 权重

## 六、漫游行为（WanderStimulus）

### 6.1 现状

- SafetyStimulus 兜底：无更高活跃项 → 回 HomePoint（回城待着），到点后 Idle
- 无"闲逛"行为，士兵/工人无事时站在原地

### 6.2 用户诉求

> "没有威胁的时候，会不自觉的左右动"

### 6.3 设计

新增 `WanderStimulus`（class 池化，任务层最低优先级，强度低于 Safety）：

```
WanderStimulus
  ├─ 触发：无威胁 + 无任务 + 无军令（最高优先级刺激源全部为空）
  ├─ 行为：在 HomePoint 周围安全半径内随机取点，MoveTowards 走过去
  ├─ 到点：停留 1-2s 再取新点（走走停停，见下方细节2）
  └─ 被打断：任何威胁/任务/军令出现 → Wander 让位（低优先级自然让位）
```

**与 SafetyStimulus 的关系（决策2 已定：回城优先）**：

> ✅ **讨论定稿（2026-08-02）**：Safety（回城）优先级高于 Wander——先回城，回城后在城内漫游（城门口/安全区内晃悠）。
> ⚠️ **机制缺口与解法（细节1 已定）**：Safety 到达 HomePoint 后强度不降，Wander 永远浮不出来（焦点恒是 Safety → 已到达 → Idle）。
> 解法：**SafetyStimulusProvider 加到达判定**——已到 HomePoint 则强度压 0（归巢驱力消失），Wander 作为低优先刺激源自然浮出。

```
无威胁时任务层竞争（强度排序）：
  Safety（回城，较高）> Wander（城内漫游，0.05 占位）
  未回城 → Safety 胜出（士兵白天 0.10 / 工人 0.50）→ MoveTowards(HomePoint)
  已回城 → Safety 到达 → Provider 压强度为 0 → Wander(0.05) 浮出 → 城内漫游 ✓
```

**强度量级**：Safety 未到达时最低是白天满血士兵 0.10（`0.5×1.0×1.0×0.2`），Wander 定 0.05 保证恒低于 Safety；已回城后 Safety=0，Wander 浮出。

**执行**：BehaviorExecutor 加 Wander 命令——HomePoint 周围安全半径随机取点，MoveTowards 过去，固定 Y 轴 1D 横版 → 左右小幅移动。到点停留后由 Executor 自行取新点循环（不依赖刺激源刷新）。

> 📌 **细节 2 已定（2026-08-02）：漫游节奏 = 到点停一下再走**——到随机点后停留 1-2s
> （停留时长住 NpcProfessionDef 或 AttentionTuningConfig）再取新点，走走停停更像真实闲逛，
> 且减少每 tick 换向的抖动。

### 6.4 注意点

- 1D 横版"左右动"= 在 x 轴上取随机点移动，y 固定
- 漫游不脱离安全区：随机点范围限制在 HomePoint 周围（安全半径，住 NpcProfessionDef，如士兵 2 cell / 工人 3 cell）
- 性能：漫游不产生新刺激源扫描，复用 Safety/Follow 的 tick 节奏
- Safety 强度压 0 只发生在"已到达 HomePoint"时，不影响夜晚/受伤时的回城驱力（未到达时强度照常算）
- 战略撤退目标也是 HomePoint：撤退到达后 Safety 压 0 → 若仍无威胁，士兵同样进入漫游（从"逃回城"自然过渡到"城内晃悠"，语义正确）
