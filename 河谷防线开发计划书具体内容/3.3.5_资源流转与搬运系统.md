# 3.3.5 资源流转与搬运系统（建筑产能 → 国库闭环）

> 日期：2026-08-02
> 状态：设计定稿（用户决策，待实施）
> 前置：3.3.4 产能闭环（ProducerComponent/StorageComponent/IHarvestable）/ 3.0.1 AI（工人三层管线 + AddTaskStimulus + WorkAt）
> 本文解决：**产能建筑产出后玩家手动收取的卡点**——资源流转到国库的最后一段（搬运）没有自动化。

---

## 一、现状与缺口

```
资源点 → 采集建筑(BuildingFactory 前置校验)
  → ProducerComponent 每秒产出 → StorageComponent 本地存储(满载停)
  → Harvest() 转国库(RulerController.ModifyResource)  ← ⚠️ 玩家手动点"收取"
  → 建造消耗(BuildingDef.cost → RulerController.Spend) ✅ 已有
```

- IHarvestable 注释预留："3.10 后由 NPC 工人轮询调用同一接口搬运到国库"——未实现
- ScheduleCenterStub 是空壳（占位注释，P1 待补全）——用户确认用它做中心调度
- BuildingPanel 已显示产能/收取按钮（手动路径可保留作补收）

## 二、定案：中心任务调度 + 工人搬运（用户决策 2026-08-02）

### 2.1 搬运语义

> **搬运 = 工人走到产能建筑 → Harvest() → 资源直接入国库**。
> Harvest() 本身已 ModifyResource 进国库，无需"工人携带资源走回"的携带量机制（P0 简化，
> 与 IHarvestable 注释一致。真实搬运动画/携带量留 P1 表现层）。

### 2.2 调度中心（ScheduleCenterStub 补全 → 正式调度中心）

```
每秒 tick：
  1. 遍历产能建筑（StorageComponent.IsReadyToHarvest && storedAmount>0）
  2. 跳过已有进行中搬运任务的建筑（防重复派发，_transporting 标记）
  3. 找空闲工人（IsIdleForTask：无活跃任务焦点）
  4. 派发：npc.AddTaskStimulus(new TaskStimulus(B级, 建筑位置, intensity, expiry, issuer: StorageComponent))
  5. 标记该建筑为"搬运中"
  6. 建筑 storedAmount==0（被 Harvest 清空）→ 清除标记（任务完成）
```

- 任务生命周期：刺激带 expiry（5s）——工人被战斗打断没去，刺激过期任务自然消失，下 tick 重新派发
- 防重复：_transporting 标记（建筑 → 状态），Harvest 清空后释放
- 昼夜节律：沿用 Stub 的"夜间停发户外任务"（TimePhase 判定）

### 2.3 搬运链路（AI 侧透传）

```
TaskStimulus(issuer: StorageComponent) —— Source 携带搬运目标
  → 工人 L1 焦点 = 该任务（WorkPosition）
  → L2 → WorkAt 模块
  → L3CommandComputer：focus.Source is StorageComponent → cmd.HarvestTarget = storage
  → BehaviorExecutor.ExecuteWorkAt 到达 → cmd.HarvestTarget?.Harvest() → 国库
  → 任务完成（建筑存储清空）
```

- BehaviorCommand 新增 `IHarvestable HarvestTarget` 字段（搬运目标透传）
- WorkAt 到达时调 Harvest（原占位"原地待机"扩展为"到达即收取"）

### 2.4 空闲工人判定

- NPCBrain 暴露 `IsIdleForTask`：当前焦点无效 或 焦点是 Wander/Follow（无进行中工作任务）
- 非空闲（焦点是 TaskStimulus/ThreatStimulus）不派新任务（防任务堆叠）

### 2.5 UI（闭环可视）

- BuildingPanel 产能行扩展：显示 本地库存（storedAmount/capacity）+ 收取状态（自动搬运中/可手动补收）
- 手动"收取"按钮保留（Harvest 幂等：存储 0 时收取 0，无副作用）
