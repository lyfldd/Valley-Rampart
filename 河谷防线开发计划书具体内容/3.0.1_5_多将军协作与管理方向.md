# 3.0.1_5 多将军协作与管理（方向备忘）

> 状态：方向备忘（提一嘴，未设计未实现）

## 一、现状（单将军）

- **FormationController 挂在将军 GameObject 上**：将军死 → 组件销毁 → 编队解散（3.0.1_3 §15.1）
- 热键调试绑"将军编队"，将军死失效（已改为动态检测，见 §三）
- AIDebugSpawnController 可生成将军并 `BindGeneralFormation` 组编队（复用同一条编组逻辑）

## 二、多将军方向（明天再干，先记方向）

| 方向 | 说明 | 涉及 |
|------|------|------|
| **多编队实例化** | 多个将军各自挂 FormationController，天然多编队（架构已支持，只需验证不互抢空闲士兵） | FormationController 招募来源（空闲池） |
| **将军间协作** | 分兵（各带一队）、会师（多队合并）、援护（一队支援另一队受威胁区） | ThreatHeat 事件 / 指挥链扩展 |
| **编队归属管理** | 士兵归属哪个将军、切换指挥（士兵改绑锚点）、多队编制（军团/师） | FormationMember 归属字段 |
| **将军死亡后的部队继承** | 将军死 → 编队解散 → 士兵是否自动归入其他将军/守城编队 | OnUnitDied 链扩展 |
| **多将军调度** | 君主对多将军的指挥界面 / 军令广播 | 君主指挥链（3.0.1_3 §6） |

## 三、已为多将军做的铺垫（2026-08-02）

- **热键动态检测将军**（CombatTestSpawner.FindActiveGeneralFormation）：每次按键按"存活将军 + 非守城 + 有成员"查找，
  不再依赖缓存引用。将军死 → 热键 1/2/3/5/6/7 失效（提示），只剩 4（守城）；新将军生成组编队 → 自动恢复。
  此设计天然支持多将军（多个活跃编队时返回第一个，多编队管理待 P1 扩展）。
