## 〇、问题：为什么会"直直冲锋"

病根不是缺队形模块，而是**当前威胁焦点 = 敌人位置本身**，NPC 拿到焦点就直奔敌人。解法不是禁止冲锋，而是给士兵一个**对冲焦点**：槽位军令（任务层）vs 威胁焦点（威胁层）持续博弈——服从度高的守槽位，服从度低的脱队迎战，courage × obedience 四象限直接变成四种战斗风格。

## 一、军队组织模型

### 1.1 将军实体 NPC 与锚点抽象

- 将军是特殊职业 NPC（NpcProfessionDef：courage 95 / 高 HP / 高 attack / 算近战）。
- **军队 = 成员 FollowAnchor 绑锚点**：锚点可将军 NPC 也可城墙预设点（静态）。将军移动全军跟随；将军阵亡 → 锚点丢失 → 编队解散 → 士兵回空闲池，按各自性格行动（溃散/死战/续战由 courage × obedience 涌现，不写溃逃逻辑）。
- **无将军编队 = 守城编队**（见 §14.7）：开局无将军或君主直接指挥未编队士兵时，编队只用于守城（夜晚/敌攻），锚点 = 城墙预设点，复用 FormationController（锚点抽象化，不绑死将军）。弓手上墙 / 近战堵口由守城阵型表 role + cellOffset 实现。无将军编队不进攻（进攻需将军带头，见 §14.2）。

### 1.2 编队招募（兵源通道）

- 调度中心维护**空闲士兵池**。⚠️ 核查勘误：母文档 §7.2 的空闲工人池**代码未实装**（已划归 3.5.0），"同构"对象是空气——士兵池/工人池同为绿地新增，统一池架构见母文档「对象池改造」节。
- 将军就位 → 读池内兵源构成 (m 近战, a 弓手) → 查阵型表选编制（见 §3.6）→ 向候选士兵发 FormationStimulus（军令）→ 接受即入队占槽。
- 标准满编：**6 人 = 1 将军 + 3 近战 + 2 弓手**。

### 1.3 军队与 LOD / 威胁热度的衔接

- 军队所在 region 是 LOD 活跃中心之一（LOD 文档 §1.2）。
- FormationController 订阅 `RegionHeatChangedEvent`：读威胁方向分布 → 判定单线/双线、哪边威胁大（将军归边与阵型切换的输入）。

## 二、槽位化队形

### 2.1 槽位 = FollowAnchor + slotOffset（零新增模块）

- 士兵的 L1 焦点 = 自己的槽位：目标位置 = **锚点（将军）位置 + 队形偏移**，每 tick 随锚点刷新。
- 复用 3.0.1_2 的 FollowAnchor 模块，只加 `slotOffset` 参数，**不新增行为模块**（守模块表纪律）。
- FormationStimulus：任务层军令（锚点型 + slotOffset），优先级由军令定。

### 2.2 槽位吸附 cell

- 槽位世界坐标吸附到 GridSystem cell 中心（cell=2.26，单人尺度），解决槽内重叠与队形漂移。
- 槽位人数上限 maxPerSlot=3（占位）；编队成员为 UnitCategory.Civilian（友方类别，GridConfig 资产 stackLimit=0 无上限），不受 stackLimit 约束（敌人 5/cell 的约束不影响编队）。
- 阵型前排/中军/后排天然跨 cell 展开。

## 三、阵型生成体系（本文核心）

**问题**：满编好配，残编怎么办——1 个士兵配 4 个弓手，士兵站哪？全排列枚举有多少种？怎么保证每种兵源下阵型都不蠢？

### 3.1 枚举空间（设计期）

编队 = 将军 G（算近战）+ ≤5 成员（近战 M / 弓手 A），一字横队 6 槽：

- 兵源构成 (m,a)，m+a≤5：**20 种**（+光杆将军=21）
- 原始排列空间 = 6 × 3⁵ = **1458 种**

### 3.2 压缩与硬约束（1458 → 321 → 讨论空间）

| 规则 | 内容 | 效果 |
|------|------|------|
| R2 残编紧凑 | 空槽一律压队尾，队中不留空洞 | 1458 → **321**（每种构成 (m+a+1)!/(m!·a!)，满编 60） |
| 最小安全策略 | 见 §3.3 | 321 → 约 200 进入评分 |

### 3.3 最小安全策略（硬约束，入 SO）

**定义**：近战 = 将军 + 近战士兵；保护对象 = 弓手（`protectedRole` 字段，未来可替换）。

| 近战数 | 单线约束 | 双线 |
|--------|---------|------|
| 1（光杆将军+弓） | 将军必须顶最前 | 一侧将军、另一侧 1 弓手（特例） |
| 2 | [兵，将，…]：将军不在极端，兵挡将 | 每侧至少 1 近战 |
| ≥3 | 将军不在极端 + **弓手不在第 2 位** | 递归模型（§3.4），无特例 |
| 6（全近战） | 无约束（无保护对象） | 同 |

阈值（2 / 3）与 protectedRole 全部入 SO。

### 3.4 双线 = 分兵 + 子队递归单线规则（架构统一）

- 编队按两侧威胁比分兵，**将军归威胁大边**。
- 每侧视为独立子队，**递归应用单线最小安全策略**（按子队近战数查约束）。
- 效果：原双线豁免条款（近战≥3 时弓手可站第 2 位）是递归的自然结果，不是特例——子队近战=2，本来就不触发"近战≥3"条款。

### 3.5 双评分函数（安全 + 进攻，约束之上选更好）

```
SafetyScore = Σ 每个弓手: w1·前方近战数 + w2·相邻近战数 − w3·位置暴露度
            + 将军存活分: w4·将军前方近战数
            + 意图加成: IntentWeights[当前意图] · 位置特征

AttackScore = 近战前出度(w5·近战越靠前越高) + 将军靠前度(w6)
            + 火力覆盖度(w7·弓手射程覆盖前排战场)
            − 脱队暴露度(w8·成员离槽越远越低，保"不脱队")
```

- **双评分对称**：SafetyScore 评"阵型稳不稳"，AttackScore 评"阵型攻不攻得动"。两者均设计期离线烘焙进候选表（§3.6）。
- **意图仍 = 评分权重集（IntentWeights SO）**，但不再单独决定阵型——见 §3.6 / §14.4 双评分加权。

| 意图 | 权重倾向 | 来源 |
|------|---------|------|
| 冲锋 | 将军靠前加分 | 君主军令 / 默认（夜晚守城=防御） |
| 防守 | 将军居中、弓手靠后加分 | 同上 |
| 撤退 | 近战殿后（面向敌人侧）、弓手先走加分 | 同上 |

### 3.6 候选表分级查表（运行时零实时评分）

- **阵型不打用途标签**（解决"一个标签对多个阵型"的纠缠）。选择器输入 = 三元组：
  `战术意图（冲锋/防守/撤退） × 战线形态（单线/双线，ThreatHeat 方向分布） × 兵源构成 (m,a)`
- 设计期：编辑器枚举工具对 321 排列 × 3 意图 × 2 战线离线跑"约束过滤 → 双评分（SafetyScore + AttackScore）排序"，每种三元组的 **Top-N 候选阵型**（标注安全向 / 进攻向）**人工复审后烘焙成查找表**（FormationTable SO）。
- 运行时：将军按三元组查得 Top-N 候选 → **按威胁因子分档权重在候选内挑一个**（见 §14.4 分档映射），零实时评分。保住"差异下沉为 SO 配置"哲学，只多一步候选内按权重挑选。
- "冲锋模式遇双线"不矛盾：意图定权重、双线定约束，两个正交输入。

### 3.7 生成工具

编辑器工具（P1）：枚举 321 种 → 应用安全策略 → 评分排序 → 导出候选清单供人工复审 → 写 FormationTable SO。阵型库可扩展（快速后撤等新阵型 = 加意图权重或加构成行）。

## 四、战斗行为规则（个体层，全部涌现）

### 4.1 守阵交战：能打就打不追击

守阵士兵可攻击**射程/感知内**的敌人（谱系 2 谨慎 = 原地打），但**不追击**——不离开槽位 chaseRange 限制（占位 2 cell）。解决"前面打架、后面看戏"：弓手射程覆盖全队战场，近战敌人贴脸时威胁层压制照常迎战。

### 4.2 破阵回援：分兵规模 = 威胁强度（涌现）

```
敌人突入中军/后排 → 受击 → 高强度威胁广播
├─ 前线近战·前方有敌：前方威胁焦点更强 → 不动（防线不空）
├─ 前线近战·前方无敌：威胁焦点被受袭区吸引 → 回身参战
│   受袭区敌人越多 → countFactor 越高 → 吸引的前线近战越多
│   → "按威胁程度分 1-2 兵回援"不写逻辑，调 countFactor 权重即调分兵比例
└─ 将军算近战，受袭即在第一响应位
```

> ⚠️ 核查勘误："高强度威胁广播"（友军受伤刺激源）**代码未实装**——PerceptionType.AllyDamaged 枚举在、生产方无。首版回援靠前排自身感知轮询看到突入敌人（感知半径内成立）；广播归 P1，且按母文档 §7 纪律需区域聚合器统一订阅过滤后注入，非 NPC 自订阅全图事件。

### 4.3 重整

威胁清除 → 威胁层空 → 槽位军令焦点浮出 → 各自走回槽位（槽位随将军锚点刷新），阵型自动恢复。与 3.0.1_2 场景 2"跟上部队"同构。

## 五、将军

### 5.1 定位

**buff 提供者 + 强力肉盾 + 有限的阵型切换决策权**——将军不是全自主指挥官，决策仅限"切阵型"。

### 5.2 buff 双通道

| 通道 | 内容 | 优先级 |
|------|------|--------|
| 因子光环（P0） | 光环半径 3 cell 内友军：rawFactor 负向抵消 + 算保护因子来源（与 allyFactor 同构——光环 = 友军保护计数加成来源；⚠️ 审计勘误 E1：原写"城墙地形因子"系虚构，rawFactor 无此项）→ 士兵在将军身边更难撤退、更敢打 | 纯因子哲学，零新系统 |
| 属性加成（P1） | 编队内成员 attack ×1.15 / defense ×1.2（占位，SO 配置），AuraBuff 组件实现。⚠️ 前置坑：NPCBrain.UpdateCombatRegistration 读 SO 静态 attack（NPCBrain.cs:410）而非运行时值——落地前必须先改读 `_controller.Attack`，否则 attack 侧 buff 不生效（defense 侧走 IDamageable 运行时值，无坑） | 数值直接，与因子光环正交 |

### 5.3 阵型切换决策（唯一决策）

- 输入：ThreatHeat 方向分布（单线/双线、哪边威胁大）+ 当前意图（军令）。
- 输出：按新三元组查表，换发 FormationStimulus（槽位重排）。
- 防抖：阵型切换确认 1s（占位），防边界抖动。

### 5.4 FormationController（军队级组件，挂将军 NPC）

- 有状态：当前三元组、槽位分配表、成员列表。
- 职责：编队招募/解散、查表选阵、阵型切换、下发 FormationStimulus。
- 将军阵亡 → 组件销毁 → 编队解散（指挥链断裂自然涌现）。
- **不住个体三层管线**（军队级决策）；输出物是刺激源，符合"两类东西"纪律。

## 六、指挥链

```
君主（玩家）── 大方向军令：集结点 / 进攻 / 撤退 / 驻守 + 意图选择（冲锋/防守/撤退）
   ↓ S 级 TaskStimulus（指令型，母文档 §2）
将军（FormationController）── 有限决策：按 ThreatHeat 切阵型（意图内）
   ↓ FormationStimulus（槽位军令）
士兵（个体管线）── 槽位焦点 vs 威胁焦点博弈 → 行为涌现
```

君主不微操单体；将军不自主开战/撤退（仍受君主军令约束）；个体保命反应（威胁层压制）永远优先。

## 七、场景走查

### 7.1 跳跳怪入中军（破阵-分兵-重整）

见 §4.2：前排有敌不动、无敌回援 1-2 人（分兵随威胁强度）、弓手原地射、将军迎战；敌灭后自动回槽。✓

### 7.2 两方向遇敌（双线）

ThreatHeat 显示左右双方向 → 意图（防守）× 双线 × 构成 (3,2) 查表 → 分兵两侧，将军归威胁大边，每侧递归单线安全策略布阵。✓

### 7.3 残编（1 近战 + 4 弓手）

构成 (1,4) → 近战总数=2（将军+1兵）→ 单线约束 [兵，将，弓×4]；弓手全在后排。若连近战兵都没有 (0,4)：将军顶最前（近战=1 条款），纯弓后缀"玻璃"特征，评分自然低——将军组队时优先补近战。✓

### 7.4 将军阵亡

锚点丢失 → FormationController 销毁 → 编队解散 → 士兵回空闲池；威胁层照常工作：courage 低的溃散（撤退链路）、高的死战——不写溃逃逻辑。✓

## 十、实施优先级

> ⚠️ 依赖链（2026-08-01 审计 D2 修订）：前置工作（将军占位 + 场景改造，见《AI编队等前置工作》）→ **编队 P0（场景可见）** → 对象池 P0 ∥ LOD P0（并行）→ 编队 P1。依据：P0 手配单阵型绕开 ThreatHeat；ClearFormationState 白嫖已实装 IMemoryComponent 契约，不阻塞于对象池；招募绕开 stub 自管；LOD 只阻塞 P1（阵型切换 / ThreatWeightTier 分档 / 补充热度判定 / enemyTypeFactor 合并改造）。

**架构洞察**：
1. **协作层只产输入不产行为**——"回援/分兵/重整"不写一行协作代码，全是个体管线对威胁焦点 vs 槽位焦点的博弈涌现；协作层的全部职责 = 发槽位军令 + 造光环因子。
2. **双线递归统一**——单线规则表递归应用于子队，双线豁免条款自动成立，规则表永不随近战数重写。
3. **意图即权重**——冲锋/防守/撤退不是阵型属性而是评分权重集，"冲锋遇双线"从矛盾变为两个正交输入的乘积。
4. **设计期评分、运行时查表**——评分函数的表达力与查表的零成本兼得，延续"差异下沉为 SO 配置"的项目哲学。
5. **性格因子是残编修正器**——弓手被迫顶前时低 courage 使其自行后缩，畸形编队向合理方向自演化。
6. **意图=双输出**——意图不再只摆阵型，同时驱动行为参数（谱系/chaseRange/推进目标）与双评分加权，"进攻推不动"从无解变为"基线+因子动态调节"。
7. **兵种差异靠因子涌现**——弓手是否冒险接近由威胁因子（含怪物种类）决定，不写兵种专属行为代码，守模块表纪律。
8. **锚点抽象统一**——将军 NPC 与城墙点同为锚点，进攻编队与守城编队同构，FormationController 不绑死将军。
9. **状态清理与对象池 Reset 同构**——编队离队清理是对象池 Reset 的编队子集，状态无残留，"将军减员了但不知道"漏洞堵死。

## 十四、兵种级行为与攻防决策（2026-08-01 需求讨论）

> 本节解决"阵型好但士兵会不会攻击 / 怎么攻防"与"无将军编队"两问。核心：意图从"只摆阵型"升级为"驱动行为参数 + 双评分加权"，兵种差异靠因子涌现而非专属行为代码。

### 14.1 意图驱动行为参数（双输出）

意图不只影响阵型权重（IntentWeights），还驱动**行为参数集 IntentBehaviorProfile SO**：

| 意图 | 谱系 | chaseRange 基线 | 推进目标 |
|------|------|----------------|---------|
| 防守 | 2 谨慎（原地打） | 2 cell（不追击） | 守槽位 |
| 进攻 | 0 全力（追击推进） | 8 cell（占位） | 将军带头向敌 |
| 撤退 | — | — | RetreatMove + 近战殿后 |

- 非将军减员不改变意图，意图由君主军令定（§6 指挥链）。
- ⚠️ 前置：IntentBehaviorProfile 是新增 SO；L3 参数计算从"查表给静态值"变为"意图给基线 + 威胁因子动态调节"（见 §14.3）。

### 14.2 推进机制：将军带头 + 士兵跟随

- 进攻意图下：将军焦点 = 敌人 / 集结点（MoveTowards 推进）；士兵主焦点 = 槽位（FollowAnchor 跟将军移动）；威胁压制时部分脱队打，obedience 高的保持阵型。
- 与现有"槽位 vs 威胁焦点博弈"同构——推进靠将军移动带动，不写"士兵主动压上"逻辑。
- 防守意图下：将军守位（不 MoveTowards），士兵守槽，遇敌守阵交战（§4.1）。
- ⚠️ 评估结论："阵型好但士兵不会攻击"在防守语义下不会发生（威胁压制切攻击 + 战斗系统 In-Range 自动开火）；真实风险在进攻——进攻若沿用守阵"不追击"会推不动，故进攻意图给 chaseRange 放大基线（§14.1）+ 将军带头推进（本节）双解。

### 14.3 chaseRange 动态调节（因子驱动）

- chaseRange 不再是 IntentBehaviorProfile 的固定值，而是 **基线 × 威胁因子调节**。
- 弓手：弱怪（enemyTypeFactor 低）→ chaseRange 放大可接近换快速击杀；强怪（enemyTypeFactor 高）→ 收紧保安全距离。
- 近战：基线固定贴脸（近战本就要贴近，不调节）。
- ⚠️ 依赖：怪物种类因子（§14.6）落地后此调节才生效；落地前 chaseRange 用 IntentBehaviorProfile 基线静态值兜底。

### 14.4 双评分加权选阵型（候选表分档）

- 设计期：每个三元组烘焙 Top-N 候选阵型（标安全向 / 进攻向），存入 FormationTable SO（§3.6）。
- 运行时：按**威胁因子分档**取 (安全权重, 进攻权重) 配比，在候选内加权挑一个。⚠️ 威胁因子归属（P0 占位）：**将军自身 rawFactor**——将军在阵中最具代表性，零新增计算；P1 可升级编队聚合（均值 / max）：

| 威胁档 | 阈值（占位） | (安全, 进攻) 权重 |
|--------|------------|------------------|
| 低 | <0.3 | (0.3, 0.7) |
| 中 | 0.3-0.7 | (0.5, 0.5) |
| 高 | >0.7 | (0.7, 0.3) |

- 配在 ThreatWeightTier SO。威胁因子高 → 偏安全向；低 → 偏进攻向。
- **"始终以队伍安全为核心"= 非 AllIn 时 §3.3 最小安全策略硬约束始终生效**（弓手不站第 1 位、将军不站极端），只有 AllIn override（§14.5）才放弃。

### 14.5 不顾一切模式（AllIn override）

- **override bool flag**，叠加任意意图：破 §3.3 安全硬约束（弓手可站第 1 位）+ chaseRange 无限 + 不脱队限制放松。
- 君主手动开启，不新增意图枚举（架构最轻）。
- 非 AllIn 时硬约束永远在——"不顾一切"语义即"放弃全部安全策略，不达目的不罢休"。

### 14.6 怪物种类因子（威胁评定扩展）

- rawFactor 新增 **enemyTypeFactor**：不同敌人对兵种的威胁权重（跳跳怪威胁高、弱怪低）。
- 新增 **EnemyTypeThreatWeight SO**（每种敌人 × 兵种 的威胁权重表）。
- ⚠️ 与 3.0.1_LOD 的 heatFactor 改造**合并一次做**——rawFactor 权重迁 SO + 删 enemyCount==0 早退同时进行，避免威胁评定模块改两轮。因子编号入**统一因子表**（9 项目标态，见《AI编队等前置工作》§3.4），原"第 6 项 / 第八项"各自表述废止（审计勘误 E4）。
- "不是受击就最高因子，而是按敌人类型判断"：威胁评定从通用变为按类型差异化。

### 14.7 无将军守城编队

- 无将军编队**只用于守城**（夜晚 / 敌攻），不进攻（进攻需将军带头，§14.2）。
- 锚点抽象化：FormationController 的 Anchor = 将军 NPC 或城墙预设点（静态），不绑死将军（§1.1）。
- 守城阵型表（role + cellOffset）：弓手上墙、近战堵口，由专门守城 FormationDef 配置。
- 与将军进攻编队**同构**：同一套槽位机制，锚点来源不同。

## 十五、减员与状态管理（2026-08-01 需求讨论）

### 15.1 减员主流程

- **将军阵亡**：锚点丢失 → FormationController 销毁 → 编队解散 → 成员回空闲池（现状，§1.1）。
- **非将军减员**：按当前构成查残编阵型（复用 §3.3 最小安全策略）重布槽位。
- **不自动补员**：需补充机制触发（§15.4）或君主 / 调度重新招募。

### 15.2 涌现式撤退（不破指挥链）

- 减员 → 成员减少 → 个体 allyCount 降 → allyFactor（友军保护）升 → rawFactor 升 → 个体威胁层更容易触发谱系撤退保命。⚠️ 审计勘误 E2：原写"SafetyScore 降 → 威胁放大"——SafetyScore 是设计期烘焙静态值（§3.6），运行时无"降"；真实传导链走 allyFactor，结论（涌现式撤退）不变。
- **将军不自主撤退**（守 §6 指挥链纪律）：将军仍只切阵型。集体撤退靠君主军令。
- 个体保命反应（威胁层压制）永远优先——减员时低 courage 士兵自行后撤，高 courage 死战。

### 15.3 决策动态刷新（即时 + 防抖）

- 成员死亡**即时触发** FormationController 重查三元组（构成变化）选候选阵型重排。
- 防抖 1s（占位）：防连续减员频繁重排。安全因子实时反映当前构成。
- 状态清理（§15.5）与重排同步进行，避免脏数据。

### 15.4 补充机制

- **触发条件**：编队所在 region 热度低于阈值 + 无成员受击持续 10s（占位）→ 允许补员。
- 补员走**与初始编队招募同一流程**（从空闲士兵池招募补满编制，§1.2）——"补充和一开始的编队是同一个东西，都是增加人员"。
- 防战斗中补员被秒杀。

### 15.5 状态防残留（离队清理钩子）

> 用户关切："将军明明减员了但不知道"——类似对象池清空状态记忆，状态 / 因子不能残留。

- 成员死亡 / 离队时，FormationController 主动对该成员 **ClearFormationState**：
  - 清除军令刺激源（FormationStimulus）
  - 清除光环因子标记（将军 buff 通道）
  - 清除槽位绑定
- **将军阵亡**：额外对**全体成员批量清理**（§八已勘误的 ClearFollowAnchor 补洞扩展为完整状态清理）。
- 复用 IMemoryComponent.Reset() 契约的**编队子集**——契约已实装（3 个实现），ClearFormationState **不阻塞于对象池**，随编队 P0 直接做（审计勘误 E3）；对象池（母文档 §7.4）落地后叠加：死人回池 1.5s 时 Reset 清全状态，编队内活成员离队走 ClearFormationState 子集。
- 不依赖 TTL 过期（避免残留窗口），主动即时清理。
