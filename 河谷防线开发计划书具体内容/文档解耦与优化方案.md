# 文档解耦与优化方案

> **本文件不做编号处理**（独立于计划书 1.x/2.x/3.x 编号体系），是文档体系的"运维篇"。
> 职责：评估已实施 / 未实施文档的解耦与优化——哪些该优化、哪些不该过度解耦。
> 建立：2026-08-03。

---

## 一、目的

1. **全面解耦（代码 + 文档）**：消除"文档硬编码"（模块等级写死、兵种分散、双份定义、改一处牵全身）
2. **优化已实施 / 未实施文档**：未实施的可重构；已实施的对齐代码，**不动**
3. **防再漂移**：单源真值（champion）→ Unity / sim / 文档统一出口

---

## 二、解耦三原则（与 3.6_军事统一管理 对齐）

| 原则 | 内容 |
|------|------|
| 等级 = 纯数据 int | 防御/穿透/模块等级不写死上限，加档 = 加配置项 |
| 引用 = id + 运行时规则 | 穿透 vs 防御是规则函数，不是查表 |
| 改动局部化 | 生产/装备/弹药/工事用 id 引用，改一处不级联 |

## 四、评估：该优化 vs 不该过度解耦

### 4.1 该优化（未实施 / 结构性问题，解耦收益高）

1. **模块等级硬编码** → 模块树（✅ 已做）：等级是树节点数，加档不牵连其他模块/文档
2. **兵种定义分散** → 统一数据契约：6 职业 + 装备 + 弹药，一处定义多处消费
3. **塔/墙双份** → FortificationDef：消灭 Buildings 与 UnitData 双份
4. **弹药体系缺失** → AmmoDef + impactChain：穿透/AOE/弹跳/debuff 通用化
5. **三方数值漂移** → 单源真值：champion 唯一真身，回灌流程固定（✅ 已做首次对齐）

### 4.2 不该过度解耦（已实施 / 无扩展需求 / 硬约束）

1. **已实施文档**（1.x / 2.x / 3.4 / 存档 / 流程）：已对齐代码，重构会制造文档与代码失配——**不动**
2. **场景 JSON / holdout / AGENTS.md**：训练师铁律禁改——**禁改**
3. **结构性常数**（cellSize / armorK / tick）：冻结参数——**不动**
4. **无独立扩展维度的等级**（伤害公式内参等）：int 足够，不建对象——**不过度设计**
5. **成长线接口不预先膨胀**：马资源/魔晶只做"消费点预留"，生产链路等经营层实施时再连

## 五、单源真值原则（防再次漂移）

```
champion/tuning.champion.json（训练/数值唯一真身）
   ├──→ Unity 资产（Resources/UnitData + Resources/Config）——回灌
   ├──→ sim 默认库（SimConfig.cs）——同步
   └──→ 文档（3.6 实施依据 / 3.5 模块树）——数据契约出口
```

- 数值改动：改 champion → 跑分验证 → 回灌 Unity + 同步 sim
- 文档改动：3.6 出数据契约，训练师底稿（3.6 训练师版）出机制/门禁，本文件管优化评估

---

## 六、维护规则

1. 新文档**内容不硬编码"前置：3.x"引用链**（编号仅用于索引定位）
2. 新概念优先进 3.6（军事）或本文档（跨模块优化），**不散落**
3. 文档优化清单集中在本文件维护，其他文档不各自维护重复清单
