## 一、改造背景与动机

### 1.1 现状

河谷防线当前是仿 Kingdom 的 **1D 横版卷轴**游戏：

- 世界是一条 X 轴线段，单位只有左/右两个移动方向
- 敌人从左右两端来袭，城墙是线上的两个点，防御没有纵深
- `GridSystem` 是一维格子数组；`LinearThreatFormula` 等 AI 公式建立在轴距离假设上
- 已实现系统：EventBus、时间/难度、存档（ISaveable）、UI 面板、Kingdom 经营全套（人口/饱食/幸福/税收/贸易/科技/职业）、建造与资源流转、AI 三层决策（L1 焦点→L2 姿态→L3 指令）、编队、伤害管线、训练模拟器（1D 战斗 + 经济）

### 1.2 动机

- **同质化风险**：仿 Kingdom 的 1D 玩法担心玩家不买账
- **玩法升级**：2D 开放地图带来真正防御纵深、围合建造、多方向威胁
- **资产复用**：已实现的经营/AI/数据系统大量与空间维度无关，应最大限度迁移而非推倒重来

### 1.3 本计划的唯一目标（本次重构核心）

> **一切为了 NPC AI。** 本次改造唯一的成功标准 = **让 NPC AI 在 2D 里可以被训练、训练完直接投入使用**。

这一目标派生三条硬约束，贯穿所有子文档：

1. **训练一次，直接可用**：模拟器训练出的 AI 回灌 Unity 后无需大幅重调（sim-to-real gap 最小化）
2. **Unity 端先落一个完整可用的简单模型**（占位美术），正式美术由美术同学并行推进，届时只换素材不换逻辑
3. **sim 与 Unity 全同源**：战斗 + 职业/经济全部在模拟器可训练，决策核共用一套，确定性对拍

## 三、地基优先的建造顺序（本次重构核心）

> 原则：**先打好地基，再上 AI**；地基顺序 = 地图生成 → 建筑 → 移动 → LOD → 伤害 → AI 栈。
> 原因：训练全场最贵最慢，**不想为它重训多次**，所以 Unity 端地基做到"AI 落地即可用"再一次性训练。
> 缓解：**每层地基自带冒烟验证**（如 LOD 做完验证区块热度可见、伤害做完验证一次击杀），避免长时间"无反馈期"做错方向而不自知。

### 3.1 前置地基（5 块，每块带冒烟验证）

> **地基 ⓪（前置）**：doc 1 网格与空间层（四级区块+微格 API）是所有坐标接缝的前提，先于 ①~⑤ 落地（对应 doc1_实施计划，阶段 0）。（2026-08-14 终审修订）

| 顺序 | 地基 | 冒烟验证 | 归属子文档 |
|------|------|---------|-----------|
| ① | 2D 地图生成（地形/出生点/刷点） | 空场景生成全向地图，出生点可见 | 2_1 |
| ② | 建筑与占格（footprint/摆放/围合） | 能放建筑、占格、围城墙 | 2_2 |
| ③ | 空间与移动（2D 网格/移动/PathFollower/可视化） | 一个单位在 2D 绕障碍从 A 到 B | 2_3 |
| ④ | LOD 区块划分（区块/热度/降频） | 区块热度随战斗扩散可见，远处单位降频 | 2_4 |

> **2026-08-13 审计调整（时序矛盾修复）**：2_6 的**最小微格 A\***（8 向 A\* + BinaryHeap，不含流场/成本场）**提前并入地基③**，使"一个单位绕障碍从 A 到 B"在阶段 0 即可验收；流场 + 成本场仍留在阶段 1（§3.2 ⑥）。

### 3.2 AI 栈（4 层）

| 顺序 | 层 | 内容 | 归属子文档 |
|------|----|------|-----------|
| ⑥ | 寻路工具层 | A*/流场/成本场/PathfindingService | 2_6 |
| ⑦ | AI 决策核心层 | L1/L2/L3 2D 化、成本场决策、撤退/槽位 | 2_7 |
| ⑧ | AI 应用层 | 任务/编队/战斗/行为整合调用 | 2_8 |
| ⑨ | 模拟器与训练 | sim 2D（战斗+职业全同源）、确定性、训练-once 回灌 | 2_9 |

### 3.3 分层架构（贯穿 2_6~2_8）

```
决策大脑（可训：目标选择 + 因子→成本权重，先 SO）
   └ BehaviorCommand = {目标, 成本偏好}          ← 核心层
成本场层 CostField（纯数据，Unity/sim 同源，确定性）
   └ 威胁带↑成本 / 安全区·编队位↓成本 / 撤退逃逸点低成本
共享寻路核 Pathing.Core（纯 C#，零 Unity 依赖）
   └ A*（个体/短距）+ 流场（群体/长距）在成本场上搜索  ← 工具层
PathFollower（执行层）
   └ 逐路径点 MoveTowards，碰撞/拒马/击飞原样     ← 应用层
移动端口 IMovable（不变）
```

## 五、迁移总原则

1. **空间抽象先行**：所有改造系统先定义"位置"抽象（格子坐标 `Vector2Int` + 世界坐标 `Vector2`）
2. **逻辑层不动口**：Kingdom 经营、AI 决策框架等直迁系统，只改坐标引用的"接缝"
3. **接口语义兼容**：GridSystem 等对上游接口保持语义，内部实现换 2D
4. **每层带冒烟验证**：地基每块落地即验证，禁止一次性全切后无反馈
5. **存档版本化**：schema 升版本号，写迁移器；不兼容时宁可清档也要显式提示
6. **SO 数据驱动不变**：所有新增可调参数（寻路权重/格子尺寸/成本权重/摄像机边界）一律走 SO；**美术资源挂接一律 SO 直接引用，禁止字符串命名匹配**（建筑已如此：`BuildingDef.prefab`；单位 prefab 现命名耦合 `"{faction}_{occupation}"`，2_3 步骤 0 消除）
7. **训练管线不断链**：模拟器与 Unity 共用 AI.Core 约定不变；寻路核/成本场纯 C#，sim 同源
8. **占位美术先行**：PlaceholderSprites 延续，正式素材由美术并行推进，阶段 4 才换

## 九、总验收标准（AI-first）

1. **训练一次直接可用**：sim 训练出的 NPC AI（含战斗+职业）回灌 Unity，无需大幅重调即可投入使用
2. **AI"看见"成立**：大脑经成本场感知威胁并绕路，决策与路径结合，非纯 A*
3. 新开局为全向 2D **等轴菱形**地图，上帝视角交互（点选/框选/指令/建造）流畅
4. 昼夜双环（白天经济/夜晚战斗）在 2D 完整闭环，与 1D 时代功能对齐
5. **点对点守卫成立**：高价值资源点（矿洞/仓库/营地）可派兵守卫；敌人被价值吸引多方向来袭；城墙/城门/桥为可选工事（D62~D64）
6. NPC 寻路无卡死、无明显绕远；**活跃带内 300~400 单位**帧率达标（2026-08-14 审查修订，原 200；起点 = doc 1 §3.4 密度占位表 Medium 档）
7. 存档可读旧档（迁移）或显式清档；所有新增参数 SO 化，无硬编码魔法数值
