## 一、老系统与新系统的衔接

### 1.1 现状（1D 建造）

| 老文件 | 现状 | 2D 处置 |
|--------|------|--------|
| `BuildController.cs` | 1D 放置流程（选建筑→落 X 轴） | 改造：悬停预览+点击放置（微格吸附） |
| `PlacementValidator.cs` | 已有 w×h footprint 雏形 + 5 项校验 | 改造：加微格吸附校验、2D 矩形边界、拆微格阻挡 |
| `GateController.cs` | 1D 城门开关 | 保留：门开关沿用；新增朝向（§3.4） |
| `BuildingFactory.cs` | 占位→实例化 | 改造：从 MapData naturalBuildings + 玩家建造双来源 |
| `BuildingRegistry.cs` | 建筑注册表 | 保留 + 2D 索引 |
| `Building.cs` / `BuildingDef` | 建筑/定义 | 改造：footprint 2D、高度纯视觉 |
| `ResourceNodeMapping` | 资源点锁格 | 保留，锁格粒度改坑位（0.5×0.5 小区块） |

### 1.2 衔接总图

```
老：PlacementValidator(1D X 轴校验) → 放置
新：微格吸附放置 → footprint(小区块 w×h) 校验 → 拆微格阻挡（围合判定已移除 D63，墙=可选工事）
    桥：跨水放置 → WalkFlags.Bridge 置位 → 水面可走
```

**关键**：1D 的"cellWidth"→ 2D 的"w×h 小区块 footprint"；放置吸附到微格（世界普朗克长度）。

### 1.3 接缝约定（与 doc 1 对齐）

- 坐标/距离一律按 doc 1 §1.6（格基准、世界=iso嵌入契约，2026-08-22 裁决 HH.3、代码待落；旧"正交逻辑层"废止、格单位分量归一化距离改"逆变换还原格差再求欧氏"）；本篇不出现投影计算（渲染归 2_10）
- `WalkFlags.Bridge` 由本篇桥建筑写入（doc 1 §5.1 规则：Bridge 豁免 Water 阻挡）
- 单位登记在微格主表（doc1 §5.2，D70/D71），本篇只改阻挡层，不碰单位层（2026-08-14 终审修订）

## 三、新系统的需求讨论（已收敛决策）

| # | 决策 | 结论 |
|---|------|------|
| 放置交互 | 悬停预览 + 点击放置（吸附微格） |
| footprint 单位 | 小区块 w×h（微格只做吸附/校验精度） |
| 围合判定 | ~~区域填充 flood-fill~~ **整体移除（D63）**：墙=可选工事，守卫判定归 2_8 |
| 城门语义 | 沿用门开关（白天开/夜晚关+手动）；**朝向随墙方向**（§3.4） |
| 资源锁格 | 沿用（禁重叠，需先采集）；粒度=坑位 0.5×0.5 |
| 高度层 | **纯视觉**，不参与逻辑（2.5D 功能性建筑） |
| 桥 | **新增**（2_1 §3.6 定稿"可造桥过河，归 2_2"）：跨水通行建筑（§3.5） |

### 3.1 ~~围合判定~~（2026-08-14 审查整体移除，D63/D65）

> **围合判定概念取消（D63）**：EnclosureDetector 整体移除，不再有"城内/城外"判定。原因：新玩法=点对点守卫 + 价值驱使（D52/D56），城墙=可选工事非王国必需；破城/安全区/游荡范围改由 2_3/2_7 按守卫区域（IsInGuardedArea）重定义（D66/D90）。
> 本节原"区域化 flood-fill 识别城内外"设计**作废**。保留的原语：
> - `IsFootprintClear(origin,w,h)`（doc 1）：建筑摆放校验（保留）
> - 墙/城门/桥 = 可阻挡可选工事（D62/D64）：墙阻挡、城门开关阻挡/通行、桥 Bridge 位通行
> - 守卫部署（派兵守高价值点）→ 归 **2_8**（D94/D116）

### 3.2 城门通行

- 城墙=阻挡；城门=可通行（开门时）
- 城门格在微格层特殊处理：开门=可走，关门=阻挡（`MarkOccupiedFootprint`/`FreeFootprint` 切换）
- 城门开关变化 → 发 `GateStateChangedEvent` → 2_6 寻路失效重寻（repath）（围合重算已移除 D63）

### 3.3 放置吸附流程

```
1. 玩家点击世界坐标 → WorldToSubCoord 吸附微格
2. footprint（小区块 w×h）→ 拆微格
3. 校验 IsSubWalkable 全覆盖 + 地形 + 资源 + 边界（桥走 canPlaceOnWater 特例）
4. 通过 → 放置，登记 footprint 拆微格阻挡（桥置 Bridge 位）
5. 若为墙/城门 → 发 BuildingPlacedEvent（围合重算已移除 D63，城门开关由 GateController 发事件）
```

### 3.4 城门朝向规则（2026-08-13 审计新增）

- 城门 footprint = 2×1，**必须与城墙走向一致**：横墙 → 城门占横向 2 格；竖墙 → 占纵向 2 格
- 放置时**自动推断**：检测落点两侧相邻格是否已有墙；有横墙则取横向，有竖墙则取纵向；两侧都有（拐角）→ 禁止放置（红显）
- 玩家可用 R 键**手动旋转**覆盖自动推断（仅限两侧无墙的自由段）
- 朝向决定：footprint 占格、sprite 变体（`bld_gate_h`/`bld_gate_v`，美术规范）、通行方向

### 3.5 桥（2026-08-13 审计新增，补 2_1 §3.6 缺口）

| 项 | 规则 |
|----|------|
| footprint | 1×1 桥段，可 1×N 拼接跨河（每段独立建筑，共享 `bridgeId`） |
| 放置条件 | `canPlaceOnWater=true`；目标格必须有 Water 位（只能造在水上）；两端必须接可走陆地（校验首尾段邻格） |
| 通行 | 放置后逐段置 `WalkFlags.Bridge`（doc 1 §5.1：Bridge 豁免 Water），单位可走 |
| 阻挡语义 | 桥不阻挡、不视为墙（桥面当普通可走地面，无城内/城外概念，围合判定已移除 D63） |
| 拆除 | 拆除任一段 → 全 bridgeId 链可拆提示；Bridge 位清除 → 水面恢复阻挡 |
| HP/破坏 | P2 预留：敌人可攻击桥（复用 Building HP），本期不做 |

> **bridgeId 共享机制（D271，2026-08-14 终审修订）**：bridgeId 由 `BuildingRegistry` 在首段放置时自增分配；后续段放置时检测邻格已有桥段并继承其 bridgeId；拆除时按 bridgeId 查全链段提示连锁拆（仅 UI 反馈，实际逐段拆除）。

## 四、新系统可能遇到的问题

| # | 风险 | 对策 |
|---|------|------|
| R1 | 大量建筑占格更新性能（微格批量拆分，分帧处理） | footprint 拆微格矩形批量置位/清位；大批建造/拆除分帧处理（每帧上限可配，围合判定已移除 D63） |
| R2 | 城门开关与寻路 repath 时序不一致（GateStateChangedEvent 先发后改 WalkFlags） | 统一顺序：先改 WalkFlags 再发 GateStateChangedEvent；2_6 收到事件后失效重寻 |
| R3 | 跨格建筑微格校验漏 | footprint 拆微格全覆盖校验（逐微格 IsSubWalkable） |
| R4 | 资源锁格与建造冲突 | 沿用 ResourceNodeMapping + footprint 冲突校验；锁格粒度=坑位 |
| R5 | 高度纯视觉但排序错 | 排序仍按 (x+y)+高度层（美术规范 §4.3，实现归 2_10），高度只影响 sprite 尺寸 |
| R6 | 桥悬空/断头（两端不接岸） | 放置校验首尾段邻格必须可走陆地；拼接段允许水上延伸 |

| R8 | 城门拐角误放 | 两侧墙走向冲突时禁止放置（§3.4） |

### 5.2 数据流


## 六、美术对接（§美术规范）

- 每个建筑按 `美术资源规范` 表做：`bld_house`(2×2)、`bld_wall`(1×1)、`bld_gate`(2×1，横/竖双变体)、`bld_tower`(1×1)、`bld_bridge`(1×1)...
- 锚点=底座中心（焦点），footprint 按小区块声明
- 高度层纯视觉，不参与逻辑

## 七、验收标准

1. 悬停预览吸附微格，绿/红高亮正确
2. footprint 校验 + 微格阻挡正确（跨格建筑不漏）
3. 墙/城门/桥=可选工事，占格阻挡与解除正确；城门开关实时改变可走性；多段桥连锁正确（D63/D271）
4. 城门开关：开可通行/关阻挡；朝向自动推断+手动旋转正确
5. 资源锁格沿用：被资源占格（坑位粒度）不能建
6. 建筑高度纯视觉，不参与可走/逻辑
7. 桥：水上放置、两端接岸校验、Bridge 位通行、拆除恢复阻挡
