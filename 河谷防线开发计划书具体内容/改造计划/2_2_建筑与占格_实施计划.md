### 步骤 2：PlacementValidator 微格吸附 + footprint 校验

**文件**：`Systems/Building/PlacementValidator.cs`（改造）

**旧定义迁移**（`PlacementValidator` 旧 5 项校验 → 新校验）：
| 旧项 | 旧实现 | 新处置 |
|------|--------|--------|
| 边界范围 | `grid.MapCellCount`（1D） | 2D 矩形边界 `IsInBounds`（越界 nullable，doc 1） |
| 区块占用 | `BuildingRegistry.GetAt` + 工具建筑特例 | 保留 + footprint 全覆盖逐格查 |
| 地形合法 | `grid.GetTerrainAt(coord)` 逐格 | 保留（按小区块地形逐格查） |
| 阻挡冲突 | `grid.IsObstacle(coord)` 单格 | footprint 全覆盖区逐格 `IsWalkable` + 拆微格判 `IsSubWalkable` |
| 资源足够 | `RulerController.CanAfford` | 保留（CanAfford） |
| 资源点锁格 | 沿用 ResourceNodeMapping | 粒度改坑位（Locked 位，0.5×0.5 小区块对齐，D36） |
| 水域特例 | 无 | **新增**：`def.canPlaceOnWater`（桥专属）→ 仅校验 Water 位，不校验 TerrainWalkable |

**新签名**（设计 §5.1）：
```csharp
public static class PlacementValidator
{
    // 微格吸附后校验（含桥的水域特例）
    public static PlacementResult Validate(BuildingDef def, GridCoord subOrigin, GateOrientation orient);
    // footprint 清空校验（doc 1 IsFootprintClear 的语义包装）
    public static bool ValidateFootprintClear(GridCoord cellOrigin, int w, int h);
}

public enum GateOrientation { Horizontal, Vertical }

public struct PlacementResult
{
    public bool ok;
    public PlacementFailReason reason;  // Blocked/Terrain/Resource/Bounds/GateCorner/WaterMismatch
    public GridCoord snappedOrigin;     // 吸附后的 origin（预览用）
}
```

**校验流程**（吸附 → footprint 小区块 w×h → 拆微格）：
```
1. origin 吸附到最近微格起点（WorldToSubCoord）
2. footprint（小区块 w×h）→ 拆微格（每个小区块 4×4）
3. 校验 IsSubWalkable 全覆盖 + 地形 + 资源 + 边界（桥走 canPlaceOnWater 特例）
4. 通过 → 放置，登记 footprint 拆微格阻挡（桥置 Bridge 位）
```

**验收**：跨格建筑（2×2）footprint 逐微格全覆盖校验不漏；桥在非水域格返回 `WaterMismatch`；半压水格 `IsSubWalkable` false 拒绝放置。

**文件**：`Systems/Building/GateController.cs`（改造）

**新规则（设计 §3.4）**：
- 城门 footprint = 2×1，**必须与城墙走向一致**：横墙 → 城门占横向 2 格；竖墙 → 占纵向 2 格
- 放置时**自动推断**：检测落点两侧相邻格是否已有墙；有横墙则取横向，有竖墙则取纵向；两侧都有（拐角）→ 禁止放置（红显，`GateCorner`）
- 玩家可用 R 键**手动旋转**覆盖自动推断（仅限两侧无墙的自由段）
- 朝向决定：footprint 占格、sprite 变体（`bld_gate_h`/`bld_gate_v`）、围合缺口方向
- 城门开关变化 → 发 `GateStateChangedEvent` → 2_6 寻路失效重寻（repath）

**验收**：关门 = `BuildingBlocked` 置位阻挡；开门 = 释放可通行；朝向自动推断 + 手动旋转正确；拐角误放被拒。

### 步骤 8：桥放置（WalkFlags.Bridge）

**文件**：`Systems/Building/Building.cs`（改动，桥语义）+ `BuildingDef`（canPlaceOnWater 已配）

**新规则（设计 §3.5）**：
- footprint = 1×1 桥段，可 1×N 拼接跨河（每段独立建筑，共享 `bridgeId`）
- 放置条件：`canPlaceOnWater=true`；目标格必须有 Water 位（只能造在水上）；两端必须接可走陆地（校验首尾段邻格）
- 通行：放置后逐段置 `WalkFlags.Bridge`（doc 1 §5.1：Bridge 豁免 Water），单位可走
- 阻挡语义：桥不阻挡、不视为墙（围合判定已移除，桥面当普通可走地面）
- 拆除：拆除任一段 → 全 bridgeId 链可拆提示；`Bridge` 位清除 → 水面恢复阻挡
- HP/破坏：P2 预留（敌人可攻击桥，复用 Building HP），本期不做

**验收**：跨河造桥 → `WalkFlags.Bridge` 置位 → `IsSubWalkable` 桥面 true；拆除恢复 Water 阻挡；断头桥（两端不接岸）被拒。

2. footprint 校验 + 微格阻挡正确（跨格建筑不漏）

4. 城门开关：开可通行/关阻挡；朝向自动推断+手动旋转正确
5. 资源锁格沿用：被资源占格（坑位粒度）不能建
6. 建筑高度纯视觉，不参与可走/逻辑
7. 桥：水上放置、两端接岸校验、Bridge 位通行、拆除恢复阻挡

## 六、风险与回滚

| 风险 | 对策 |
|------|------|
| R2 城门开关与可走不一致 | 门开关变化 → `GateStateChangedEvent` 驱动 footprint 切换（MarkOccupiedFootprint/FreeFootprint） |
| R3 跨格建筑微格校验漏 | footprint 拆微格全覆盖校验（逐微格 IsSubWalkable） |
| R4 资源锁格与建造冲突 | 沿用 ResourceNodeMapping + footprint 冲突校验；锁格粒度=坑位（Locked 位） |
| R6 桥悬空/断头（两端不接岸） | 放置校验首尾段邻格必须可走陆地；拼接段允许水上延伸 |

| 自然建筑数据源未就绪 | 卡此步：先完成 2_1 naturalBuildings 派生；本步可用占位 naturalBuildings 手填测试 |

| 回滚 | 建筑空间层改造集中于 Building 命名空间 + BuildingDef 字段，git revert 可回 1D；功能层组件（Producer/Storage/Combat）不受影响 |
