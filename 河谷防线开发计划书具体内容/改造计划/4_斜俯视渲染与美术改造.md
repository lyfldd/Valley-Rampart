## 一、老系统与新系统的衔接

### 1.1 现状（1D 侧滚渲染）

| 组件 | 现状 | 问题 |
|------|------|------|
| `CameraSetup` | 正交相机，**仅 X 跟随**，Y 锁背景中线；`orthographicSize` 由背景高度决定；`widthRatio=0.7` 限制 X | 完全 1D：无 Y 移动、无缩放、无边界矩形 |
| `MapVisualizer` | 程序化 Texture2D 底图，按大区块画区色+建筑标记 | 1D 条带；`R0_/R1_` 前缀归属大区块 |
| `PlaceholderSprites` | 占位 sprite 注册表（键→纯色方形/三角） | 无朝向/无高度/无 8 向 |
| `SpriteFactory` | 程序化生成纯色几何 | 无斜俯视素材 |
| `Art/` | Medieval Kingdom 侧绘素材 + TerrainTiles 地形参考图 | 侧绘不适用斜俯视；TerrainTiles 是参考图 |
| 渲染排序 | 无 Y-sort（1D 只要 X 排序） | 2D 必需 |

### 1.2 衔接总图

```
老 CameraSetup（X跟随）   → 重写 Camera2DController（俯视 Pan/Zoom + 边界矩形 + Y-sort 无关）
老 MapVisualizer（1D底图） → doc 4 重写为 Tilemap 渲染（或 SpriteRenderer 网格）
老 PlaceholderSprites       → 保留"占位键注册"框架，新增朝向/高度变体；美术到位后替换
老渲染排序（无）           → 新增 YSortManager（核心）
小地图                     → 新增 MiniMap（全新）
```

**衔接原则**：
1. **PlaceholderSprites 框架保留**：键→sprite 注册表是好的抽象，2D 只扩展键的维度（单位键加方向后缀、地物键保持）；美术到位后仍是"改 Get 为 Resources.Load"（代码注释已预留）
2. **SpriteFactory 保留**：占位生成器不变，2D 只调整生成尺寸/朝向
3. **渲染排序从无到有**：Y-sort 是纯新增，不依赖老代码
4. **摄像机重写**：老 X 跟随逻辑无迁移价值，直接重写

### 1.3 各老系统接缝表

| 老系统 | 接缝 | 归属 |
|--------|------|------|
| `CameraSetup.cs` | 重写为 `Camera2DController`；`backgroundSprite/widthRatio` 字段废弃 | 本文档 §2.1 |
| `MapVisualizer.cs` | 重写为地形 Tilemap；`showBuildingMarkers` 逻辑保留给 doc 6 | 本文档 §2.2 |
| `PlaceholderSprites.cs` | 键体系扩展（§2.4） | 本文档 §2.4 |
| `SpriteFactory.cs` | 保留 + 新增朝向变体 | 本文档 §2.4 |
| UI 面板 | 基础 UI 直迁（doc 0 已分类）；小地图为新增 | 本文档 §5.4 |
| LODSystem | 渲染 LOD（隐藏远距单位）归 doc 7 | 本文档只定义 YSort 排序，LOD 数据归 doc 7 |

## 三、新系统的需求讨论

### 3.1 功能需求

| # | 需求 | 场景 |
|---|------|------|
| F1 | 斜俯视相机：Pan（跟随君主+鼠标边缘/拖拽）+ Zoom（滚轮），边界矩形约束 | 大图浏览 |
| F2 | **Y-sort 渲染排序**：按世界 Y 排序，低 Y 先画（靠后），高 Y 后画（靠前），高度偏移 | 遮挡正确 |
| F3 | 地形 Tilemap 渲染（每格贴图，多类地形） | 底图 |
| F4 | 建筑/单位 8 向外观（朝向可视化） | 移动/战斗朝向 |
| F5 | 小地图（俯视缩略，显示地形/单位/视野/敌人） | 导航 |
| F6 | 占位体系扩展（朝向变体+美术替换钩子） | 开发期/美术期 |
| F7 | 运行时切换实际美术（占位→正式资源） | 美术到位 |
| F8 | 性能：Y-sort 同屏 200 单位不卡 | 阶段 2/3 |

### 3.2 非功能需求

| # | 指标 | 目标值 |
|---|------|--------|
| N1 | Y-sort 排序开销（200 对象） | ≤ 1ms/帧 |
| N2 | 相机 Pan/Zoom 无卡顿 | ≥ 60fps |
| N3 | 同屏可见地形格渲染 | 裁剪到视口（只画可见 Tilemap 块） |
| N4 | 小地图刷新 | ≤ 2 次/秒（不逐帧） |
| N5 | 占位→正式美术切换零代码改动 | 仅资源替换 |

### 3.3 待定项（附推荐值）

| # | 待定项 | 推荐 | 说明 |
|---|--------|------|------|
| D1 | 朝向档位 | **4 向**（下/右/上/左，镜像出 8 向感），不做 8 向 | 星露谷是 4 向；8 向素材量×2，性价比低；P2 可加 8 向 |
| D2 | 渲染方案 | **SpriteRenderer 分层 + Y-sort 排序**（不用 URP/2D Renderer Feature 复杂管线） | 项目当前是内置渲染管线；保持简单，Y-sort 用 sortingOrder 或自定义顺序 |
| D3 | Y-sort 实现 | **按 Y 的世界坐标排序 + 高度偏移量**，用 `ISortingSprite` 组件统一 | 简单可靠 |
| D4 | 小地图 | **独立 Camera 渲染到 RenderTexture**（只画地形+单位层 Marker） | 性能好，UI 叠放简单 |
| D5 | 地形渲染 | **Unity Tilemap**（官方 2D 组件） | 成熟；doc 3 产出 terrain[] 直接灌 Tilemap |
| D6 | 地图边界 | 相机 Clamp 到 MapData 宽高×cellSize 矩形 | 防看穿地图外 |

## 四、新系统可能遇到的问题

| # | 风险 | 触发 | 对策 |
|---|------|------|------|
| R1 | **Y-sort 与移动单位排序抖动**：移动中 may 遮挡闪烁 | 单位沿 Y 移动 | 排序用"世界 Y + 高度偏移"整体比较，不逐格；同 Y 用稳定次级键（实例 ID）防抖 |
| R2 | Y-sort 与建筑大 footprint 错位：大建筑跨多格，高度基准取哪 | 城堡/城墙 | 建筑用"底部中心"为排序基准 + `sortHeightOffset` 配置（SO 可调） |
| R3 | 大量 SpriteRenderer 每帧排序 GC/耗时 | 200 单位+建筑 | 缓存排序数组，仅 dirty 时重排；N1 预算 |
| R4 | 相机缩放过深看穿边界 | 玩家滚轮到底 | minZoom 限制 + 边界 Clamp（D6） |
| R5 | 小地图性能/尺寸 | 大图 | N4 低频刷新 + RenderTexture 低分辨率 |
| R6 | Tilemap 内存（256×256 格） | 大图 | 只建可见 chunk 的 Tilemap 块（N3 裁剪）；地格用就近 tile |
| R7 | 占位艺术与正式美术混排观感 | 开发期 | Y-sort 与占位无关，替换零冲突（N5） |
| R8 | CameraSetup 类名变更破坏场景引用 | 实施 | unity-mcp-first 同步改 GameScene 挂载 |

## 五、要开发的新系统（详细设计）

### 5.1 相机（Camera2DController）

```csharp
public class Camera2DController : MonoBehaviour
{
    [Header("跟随")]
    public float followSpeed = 5f;          // 平移平滑
    public float lookAhead = 0.15f;         // 君主朝向前瞻（可选）
    [Header("缩放")]
    public float zoomSpeed = 8f;
    public float minZoom = 0.5f;            // orthographicSize 下限
    public float maxZoom = 3f;              // 上限
    [Header("边界")]
    public Rect mapBounds;                  // 来自 doc 1 MapData：0..W*cellSize × 0..H*cellSize
    [Header("输入")]
    public bool edgeScroll = true;          // 鼠标边缘滚动
    public float edgeMargin = 24f;          // 像素
    public float edgeScrollSpeed = 20f;

    Vector3 _target;                         // 君主位置（或拖拽）

    void LateUpdate()
    {
        // 1) 目标 = 君主（有）+ 边缘滚动/拖拽偏移
        // 2) 平滑 Pan
        // 3) Zoom：累计滚轮 → orthographicSize clamp [minZoom,maxZoom]
        // 4) Clamp 到 mapBounds（D6）：保证视野不越界
    }
}
```

- `mapBounds` 来源：`WorldManager.ActiveMap` 宽高 × cellSize（doc 1 坐标系：地图中心=原点）
- 输入来源：`InputManager`（现有，doc 5 扩展）——鼠标滚轮/中键拖拽/边缘滚动

### 5.2 Y-sort 渲染排序（核心）

```csharp
/// <summary>挂在需要 Y-sort 的 SpriteRenderer 物体上（单位/建筑/落点特效）。</summary>
public class SortingSprite : MonoBehaviour
{
    public SpriteRenderer sr;
    public float sortHeightOffset = 0f;      // 高度偏移（建筑高/单位脚底）
    public bool dynamic = true;              // false=静态(建筑)，缓存排序值

    public float SortKey => transform.position.y + sortHeightOffset;
}

/// <summary>全局 Y-sort 管理器（每帧或 dirty 时重排）。</summary>
public class YSortManager : MonoBehaviour
{
    List<SortingSprite> _all;                // 注册表
    void Register(SortingSprite s);
    void Unregister(SortingSprite s);
    void Rebuild()                           // 按 SortKey 排序 → 写 sr.sortingOrder
    {
        // 排序稳定：SortKey 相同时按实例 ID（R1 防抖）
        // 排序开销：仅 dirty 时执行（N1）
    }
}
```

- **排序键**：`worldPos.y + sortHeightOffset`（D3）
- **建筑**：`sortHeightOffset` 配置在 BuildingDef（doc 6 字段），城堡/城墙大高度偏移
- **单位**：`dynamic=true`，移动后标记 dirty
- **次级稳定键**：防止同 Y 抖动（R1）

### 5.3 地形渲染（Tilemap）

- 用官方 Tilemap 组件（D5）
- TileAsset 映射：`TerrainType + PlainSubState → Tile`（SO 表 `TerrainTileTable`）
- 灌入：doc 3 MapData.terrain[] → 逐格 SetTile
- 裁剪：按视口只激活可见 chunk 块（R6，N3）
- 股息：地势起伏（可选，简单 Sprite 高度叠加，P2）

### 5.4 小地图（MiniMap）

- 独立正交 Camera 渲染到 `RenderTexture`（低分辨率，如 256×256，D4）
- 层：地形（底图）+ 单位 Marker（玩家金/AI 红/敌怪 dark）+ 视野灰边（可选）
- 刷新 ≤ 2 次/秒（N4）
- UI 叠放：`RawImage` 挂小地图 RenderTexture；点击小地图 → 相机跳转（可选）
- 数据源：doc 3 MapData + 单位注册表（doc 5 UnitRegistry）

### 5.5 占位体系扩展

- `PlaceholderSprites.Get(key)` 扩展：`Get(key, facing)` 单位键带朝向；内部 `Resources.Load("Art/"+key+"_"+facing)` → 没找到走占位
- `SpriteFactory.CreateIsoUnit(color, size, facing)`：三角/箭头指向朝向
- **正式美术替换**：美术到位只需放 `Resources/Art/<key>_<facing>.png`，零代码改动（N5）

### 5.6 SO 配置

**新增 `RenderConfig`（Resources/Render/RenderConfig.asset）**

| 字段 | 默认 | 说明 |
|------|------|------|
| facingCount | 4 | 朝向档位（D1） |
| isometricHeight | 0.35 | ×cellSize，建筑高度占位（Y-sort 偏移基准） |
| miniMapResolution | 256 | 小地图 RT 分辨率 |
| miniMapRefreshHz | 2 | 刷新频率 |
| terrainTileTable | TerrainTileEntry[] | TerrainType→Tile 映射 |
| sortDirtyThreshold | 0 | Y-sort dirty 判定 |

### 5.7 实施任务拆分

**P0（阶段 0 切片必须）**
1. Camera2DController（Pan/Zoom/边界）
2. SortingSprite + YSortManager（基础 Y-sort）
3. 地形 Tilemap 渲染（doc 3 数据灌入）
4. 占位体系朝向扩展（4 向占位）
5. 相机/渲染接入 GameScene（unity-mcp-first）

**P1（阶段 1~2）**

6. 小地图（独立 Camera + RT + UI）
7. 建筑高度偏移 Y-sort 优化（动态/静态分离）
8. 边缘滚动/拖拽输入
9. renderConfig SO + 资产

**P2（阶段 4）**

10. 正式美术替换管线验证（占位→资源）
11. 8 向升级评估（D1 P2）
12. 大图分块渲染优化（R6）
13. 地势起伏（可选）

### 5.8 验收标准

1. 相机跟随君主 Pan 平滑、滚轮 Zoom 顺滑、边界不越界
2. 单位沿 Y 移动时遮挡正确无闪烁（Y-sort 稳定）
3. 建筑（含高建筑）排序正确，底部中心+高度偏移生效
4. 地形 Tilemap 正确显示多种地形，仅渲染可见区
5. 小地图低频刷新显示地形+阵营 Marker
6. 占位→正式美术替换零代码改动（放 Resources 即生效）
