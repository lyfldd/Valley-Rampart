## 一、老系统与新系统的衔接

### 1.1 衔接总原则

新空间层**对外接口签名尽量不变、内部实现全换**。上游 28 个消费文件按改动量分三级：

| 级别 | 含义 | 文件数（估） | 处理方式 |
|------|------|-------------|----------|
| L0 零改动 | 只用 `TryEnter/GetUnitsInCell/GetUnitCoord` 等语义不变接口 | ~8 | 重新编译即用，行为回归验证 |
| L1 适配 | 用了会变语义的接口（坐标换算/footprint/地形查询），改调用不改逻辑 | ~12 | 按 §二清单逐处改 |
| L2 接管 | 强 1D 假设（IsInsideWall/区域事件/移动执行），由对应子文档重写 | ~7 | 本文档只提供新原语，改造归 2_2~2_9 |

### 1.2 坐标语义衔接（最大隐性风险点）

```
老 GridCoord(x, y)：x = 横轴格号，y = 层（0=地面, 1=空中）—— y 不是空间轴
新 GridCoord(x, y)：x/y = 平面两轴格号；层改独立字段 layer（int，预留，默认 0）
```

- 结构体名 `GridCoord` 保留（避免 27 文件改名风暴），但 **y 语义从"层"变"纵轴"**
- **全局核查清单**（改造执行时逐处人工确认）：
  - 模式 1：`coord.y == 0` / `coord.y == 1` / `coord.y > 0` —— 老层判断，全部作废
  - 模式 2：`new GridCoord(x, 0)` 字面量构造 —— 语义恰好兼容（地面层 y=0 ↔ 纵轴 0），但含义已变，抽查
  - 模式 3：`flyHeightThreshold` / `flyHeight` —— 删除
  - 模式 4：`GetHashCode() => x * 31 + y` —— 2D 坐标范围变大，改 `x * 73856093 ^ y * 19349663`（防 256×256 哈希冲突聚集）
- AI.Core 的 `Vector2IntX` 解耦层天然兼容：本就表达 2D 整数坐标，此前 y 恒 0/1，改造后自然承接纵轴

### 1.6 世界坐标约定（2026-08-13 审计定稿，全库强制）

> 本节是全库距离/坐标语义的**唯一真源**，所有子文档公式与此冲突时以本节为准。

1. **逻辑层正交**：`CoordToWorld` 输出**正交格空间坐标**；等轴投影只在渲染层做（归 **2_10**），逻辑/寻路/AI/sim 一律用正交坐标（审计决策：逻辑正交、渲染层投影）
2. **cellSize = (1.28, 0.64) 双分量**：x 轴格宽 1.28、y 轴格高 0.64 世界单位；**PPU=100（2026-08-14 审查修正，原 32）** → 1 小区块 = 128×64px（等轴 Tile 2:1）。**禁止任何公式把 cellSize 当标量用**
3. **距离约定（格单位分量归一化欧氏）**：

   ```
   dist(格单位) = √((Δx_world / 1.28)² + (Δy_world / 0.64)²)
   ```

   射程/感知/撤退/成本场/编队半径全部按此式，等价于"把世界坐标除以格尺寸回到方形格空间再求欧氏"。例：`InRange = dist(from, to) <= rangeCells`
4. **方向约定**：方向向量在**格空间**归一化（先除分量再 normalize），保证 360° 各向同性

### 3.4 规模密度目标（占位，2026-08-12 需求审查补充）

> 128²/256²/384² 面积是旧 1D 的平方级增长（约 100 倍），须显式定义单位/建筑/资源密度，否则做出来或空旷、或卡顿。下表为**占位基准**，2_6 按此定寻路性能预算，实机走通后回填真实值。

| 档位 | 尺寸 | on-map 单位 | 建筑 | 资源点 | 密度 |
|------|------|------------|------|--------|------|
| Small | 128² | ~100 | ~20 | ~15 | ~0.3% |
| Medium | 256² | ~400 | ~60 | ~40 | ~0.3% |
| Large | 384² | ~600 | ~120 | ~90 | ~0.3% |

> 注：on-map 为全图在册单位数上限（含 LOD 降频单位）；活跃带（玩家视野周边高 tick 区域）经 LOD 控制在 300~400（D6/D15/D268），为 on-map 子集（2026-08-14 终审修订，消除"子集>母集"矛盾）。

- **活跃带**经 LOD 控制在 **300~400 内**（2026-08-14 审查修订，D6/D15，原 200；起点 = Medium 档），剩余 on-map 单位靠流场/降频承担（2_6 预算基准）
- 密度 = on-map 单位数 / 总面积；0.3% 保证不空旷且不上压力
- 数值正反馈链：密度 → 2_6 寻路预算 → 2_8 战斗规模；三者联动调参归各子文档

## 五、要开发的新系统（详细设计）

### 5.1 核心类型

```csharp
/// <summary>2D 平面格坐标。x=横轴，y=纵轴（语义变更：老 y=层已废）。</summary>
public struct GridCoord
{
    public int x;
    public int y;          // 纵轴格号（0..H-1）
    public int layer;      // 预留：0=地面（空中层冻结，用户决策 2026-08-12）

    public GridCoord(int x, int y, int layer = 0) { this.x = x; this.y = y; this.layer = layer; }

    public static bool operator ==(GridCoord a, GridCoord b)
        => a.x == b.x && a.y == b.y && a.layer == b.layer;
    public static bool operator !=(GridCoord a, GridCoord b) => !(a == b);
    public override bool Equals(object obj) => obj is GridCoord c && this == c;
    public override int GetHashCode() => x * 73856093 ^ y * 19349663 ^ layer * 83492791;
}
```

```csharp
/// <summary>可行走位标记（byte，每格一份）。</summary>
[Flags]
public enum WalkFlags : byte
{
    None            = 0,
    TerrainWalkable = 1 << 0,  // 地形基础可走（地图生成写入）
    BuildingBlocked = 1 << 1,  // 建筑障碍（MarkOccupied 且 isObstacle 时置位）
    Locked          = 1 << 2,  // 资源点锁格（3.5 锁格机制延续，写入方 2_2/2_7）
    Water           = 1 << 3,  // 水域（2_1 河流/湖泊/海洋）
    Bridge          = 1 << 4,  // 桥面（2_2 桥建筑置位：桥可跨水，优先级高于 Water）
    // bit5~7 预留（空中层/特殊地形）
}
```

> 可走判定规则：`TerrainWalkable` 置位 **且** `BuildingBlocked/Locked/Water` 均未置位，**或** `Bridge` 置位（桥面豁免水域阻挡，由 2_2 桥建筑写入）。规则函数内联在 GridSystem，寻路经 §5.4 契约读取。
> 注：`Locked` 语义=资源点/矿洞采集占用临时置位，采集完释放，非永久阻挡（D270）（2026-08-14 终审修订）。

### 5.2 GridSystem（重写后 API 总表）

**坐标换算**

| API | 说明 |
|-----|------|
| `GridCoord? WorldToCoord(Vector2 worldPos)` | 地图中心原点，**分量换算**（cellW=1.28、cellH=0.64，§1.6）：`cx = Floor((pos.x + W*cellW/2) / cellW)`，`cy = Floor((pos.y + H*cellH/2) / cellH)`；越界返回 null（D2） |
| `Vector2 CoordToWorld(GridCoord coord)` | 格中心**正交**世界坐标（§1.6，等轴投影归 2_10 渲染层）：`wx = (x+0.5)*cellW - W*cellW/2`，`wy = (y+0.5)*cellH - H*cellH/2` |
| `bool IsInBounds(GridCoord coord)` | 矩形边界校验 |
| `int MapWidth / MapHeight` | 当前地图格数 |

**单位层（微格主表，2026-08-14 审查变更）**

> **登记粒度（2026-08-14 审查修订，D70/D71）**：单位登记改为**微格主表**（每单位 1 条 `Dictionary<微格坐标, 单位>`，不膨胀）；**登记/命中/寻路同粒度（微格）**。命中（2_5）/感知（2_7）/移动登记（2_3）一律按单位底座（1 微格）所在微格查询，O(1)。不再用"小区块主表+世界坐标精算"双轨（避免双表同步成本）。

| `bool TryEnter(UnitController, GridCoord subCoord)` | 微格登记 + 堆叠上限检查 → 换格登记 → 跨 Chunk 检测 → 发 `EnemyEnteredChunkEvent` |

**微格层（SubCell，2026-08-13 新增，2026-08-14 定义修正）**

> 微格 = **小区块边长 ÷ 4** → 每小区块 = **4×4 = 16 微格**（0.32×0.16 = 32×16px @PPU100，**非面积÷4**）。世界"普朗克长度"：所有建筑/地形放置**必须吸附到微格网格**（最小精度 1 微格），不能任意位置。可走性**按需推导**（不存全量数组，**热点缓存实现归 2_6**），footprint 用**矩形列表**查询覆盖。
> **NPC 底座 = 1 微格（0.32×0.16）**（D29）：所有 NPC 底座一致，寻路/命中/登记按此 1 微格。

| API | 说明 |
|-----|------|
| `GridCoord? WorldToSubCoord(Vector2 worldPos)` | 世界坐标 → 最近微格，含中心原点偏移：`sx = Floor((pos.x + W*cellW*subDiv/2) / subW)`（`subW = cellW/subDiv`，y 分量同理），越界 null |
| `Vector2 SubCoordToWorld(GridCoord sub)` | 微格 → 世界（格中心，分量式同上） |
| `bool IsSubWalkable(GridCoord sub)` | 微格可走 = `小区块可走 && 未被 footprint 覆盖`（按需推导；Bridge 豁免见 §5.1） |
| `GridCoord SubToCell(GridCoord sub)` | 微格 → 小区块（`sub/4`，返回 GridCoord，layer 透传） |
| `GridCoord CellToSub(GridCoord cell, int sx, int sy)` | 小区块 → 微格（`cell*4 + (sx,sy)`） |

**吸附规则**：放置建筑 → 世界坐标吸附到最近微格起点 → footprint 覆盖 N×N 微格 → 判 `IsSubWalkable` 全可走才放置。网格可不显示，但逻辑严格按微格吸附。

**微格查询逻辑**：
```
IsSubWalkable(sub):
  小区块 = SubToCell(sub)
  if 小区块不可走: return false
  for 该小区块 footprint 列表中的每个建筑(矩形):
    if 建筑矩形覆盖微格(sub): return false
  return true
```

### 5.4 寻路接口预留（2_6 的硬契约）

> **微格寻路（2026-08-13 升级，2026-08-14 定义修正）**：寻路在**微格 SubCell**（小区块边长÷4=4×4=16 微格/小区块、0.32×0.16）上计算。微格用于精确绕开跨格/任意形状地形与 NPC 精确避障。**NPC 底座=1 微格**（D29），寻路视为点/1 微格占位。`IPathGrid` 的 `GridCoord` 实为**微格坐标**，宽度高度为微格数。四级区块分工：大区块=温度带/生成、中区块=LOD/热度/成本场、小区块=建筑 footprint/单位落点、**微格=寻路/精确阻挡/单位登记（D70）**。

```csharp
/// <summary>寻路系统读取网格的最小契约（2_6 唯一依赖口）。坐标 = 微格坐标。</summary>
public interface IPathGrid
{
    int Width { get; }                 // 微格数宽（= 小区块宽 × 4）
    int Height { get; }                // 微格数高
    bool IsWalkable(GridCoord subCoord);          // 微格可走（§5.1 规则；跨格地形逐微格判定）
    float GetEnterCost(GridCoord subCoord);       // 地形移动代价（Plain=1.0，Hills=1.5 等，SO 可配；格单位，§1.6）
    bool IsDiagonalMoveAllowed(GridCoord from, GridCoord to);  // 防穿角：两正交邻微格均可走才允许斜走
}
```

- GridSystem 实现 `IPathGrid`；2_6 的寻路器只依赖接口不依赖 GridSystem 具体类（**sim 训练侧可另起纯 C# 实现**，落实总计划原则 7）
- 地形代价表走 SO（新增 `TerrainCostConfig`，字段归 2_6 细化）
- 8 向邻居顺序固定（E/NE/N/NW/W/SW/S/SE），2_6 直接可用；斜走代价 √2 按格单位计（§1.6）
- 微格坐标 ↔ 小区块坐标换算：`微格 = (小区块x*4+subx, 小区块y*4+suby)`；`小区块 = (微格x/4, 微格y/4)`
