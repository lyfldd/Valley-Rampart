## 一、老系统与新系统的衔接

### 1.1 衔接总原则

新空间层**对外接口签名尽量不变、内部实现全换**。上游 27 个消费文件按改动量分三级：

| 级别 | 含义 | 文件数（估） | 处理方式 |
|------|------|-------------|----------|
| L0 零改动 | 只用 `TryEnter/GetUnitsInCell/GetUnitCoord` 等语义不变接口 | ~8 | 重新编译即用，行为回归验证 |
| L1 适配 | 用了会变语义的接口（坐标换算/footprint/地形查询），改调用不改逻辑 | ~12 | 按 §二清单逐处改 |
| L2 接管 | 强 1D 假设（IsInsideWall/区域事件/移动执行），由对应子文档重写 | ~7 | 本文档只提供新原语，改造归 doc 2~9 |

### 1.2 坐标语义衔接（最大隐性风险点）

```
老 GridCoord(x, y)：x = 横轴格号，y = 层（0=地面, 1=空中）—— y 不是空间轴
新 GridCoord(x, y)：x/y = 平面两轴格号；层改独立字段 layer（int，预留，默认 0）
```

- 结构体名 `GridCoord` 保留（避免 27 文件改名风暴），但 **y 语义从"层"变"纵轴"**
- **全局核查清单**（改造执行时逐处人工确认）：
  - 模式 1：`coord.y == 0` / `coord.y == 1` / `coord.y > 0` —— 老层判断，全部作废
  - 模式 2：`new GridCoord(x, 0)` 字面量构造 —— 语义恰好兼容（地面层 y=0 ↔ 纵轴 0），但含义已变，抽查
  - 模式 3：`flyHeightThreshold` / `flyHeight` —— 删除
  - 模式 4：`GetHashCode() => x * 31 + y` —— 2D 坐标范围变大，改 `x * 73856093 ^ y * 19349663`（防 256×256 哈希冲突聚集）
- AI.Core 的 `Vector2IntX` 解耦层天然兼容：本就表达 2D 整数坐标，此前 y 恒 0/1，改造后自然承接纵轴

### 3.4 规模密度目标（占位，2026-08-12 需求审查补充）

> 128²/256²/384² 面积是旧 1D 的平方级增长（约 100 倍），须显式定义单位/建筑/资源密度，否则做出来或空旷、或卡顿。下表为**占位基准**，doc 2 按此定寻路性能预算，实机走通后回填真实值。

| 档位 | 尺寸 | on-map 单位 | 建筑 | 资源点 | 密度 |
|------|------|------------|------|--------|------|
| Small | 128² | ~50 | ~20 | ~15 | ~0.3% |
| Medium | 256² | ~200 | ~60 | ~40 | ~0.3% |
| Large | 384² | ~450 | ~120 | ~90 | ~0.3% |

- **同屏**经 LOD 控制在 ~200 内（沿用总计划验收 4），剩余 on-map 单位靠流场/降频承担（doc 2 预算基准）
- 密度 = on-map 单位数 / 总面积；0.3% 保证不空旷且不上压力
- 数值正反馈链：密度 → doc 2 寻路预算 → doc 8 战斗规模；三者联动调参归各子文档

## 五、要开发的新系统（详细设计）

### 5.1 核心类型

```csharp
/// <summary>2D 平面格坐标。x=横轴，y=纵轴（语义变更：老 y=层已废）。</summary>
public struct GridCoord
{
    public int x;
    public int y;          // 纵轴格号（0..H-1）
    public int layer;      // 预留：0=地面（空中层冻结，用户决策 2026-08-12）

    public GridCoord(int x, int y, int layer = 0) { this.x = x; this.y = y; this.layer = layer; }

    public static bool operator ==(GridCoord a, GridCoord b)
        => a.x == b.x && a.y == b.y && a.layer == b.layer;
    public static bool operator !=(GridCoord a, GridCoord b) => !(a == b);
    public override bool Equals(object obj) => obj is GridCoord c && this == c;
    public override int GetHashCode() => x * 73856093 ^ y * 19349663 ^ layer * 83492791;
}
```

```csharp
/// <summary>可行走位标记（byte，每格一份）。</summary>
[Flags]
public enum WalkFlags : byte
{
    None            = 0,
    TerrainWalkable = 1 << 0,  // 地形基础可走（地图生成写入）
    BuildingBlocked = 1 << 1,  // 建筑障碍（MarkOccupied 且 isObstacle 时置位）
    Locked          = 1 << 2,  // 资源点锁格（3.5 锁格机制延续，写入方 doc 6/7）
    Water           = 1 << 3,  // 水域（doc 3 决定是否有河流/湖泊）
    // bit4~7 预留（空中层/特殊地形）
}
```

> 可走判定规则：`TerrainWalkable` 置位 **且** `BuildingBlocked/Locked/Water` 均未置位。规则函数内联在 GridSystem，寻路经 §5.4 契约读取。

### 5.2 GridSystem（重写后 API 总表）

**坐标换算**

| API | 说明 |
|-----|------|
| `GridCoord? WorldToCoord(Vector2 worldPos)` | 地图中心原点：`cx = Floor((pos.x + W*cellSize/2) / cellSize)`，`cy = Floor((pos.y + H*cellSize/2) / cellSize)`（X/Y 对称，2026-08-12 补齐）；越界返回 null（D2） |
| `Vector2 CoordToWorld(GridCoord coord)` | 格中心世界坐标：`wx = (x+0.5)*cellSize - W*cellSize/2`，`wy = (y+0.5)*cellSize - H*cellSize/2`（对称式，2026-08-12 补齐） |
| `bool IsInBounds(GridCoord coord)` | 矩形边界校验 |
| `int MapWidth / MapHeight` | 当前地图格数 |

**单位层（零改动语义）**

| API | 说明 |
|-----|------|
| `bool TryEnter(UnitController, GridCoord)` | 堆叠上限检查 → 换格登记 → 跨 Chunk 检测 → 发 `EnemyEnteredChunkEvent` |

### 5.3 分层存储布局

```
GridSystem（单例，沿用 Singleton<GridSystem>）
├─ int _w, _h                          // 地图尺寸
├─ TerrainType[]   _terrain            // W×H，值类型（实际存 byte 压缩）
├─ PlainSubState[] _plainSub           // W×H byte
├─ WalkFlags[]     _walkFlags          // W×H byte（N2：65KB @256²）
├─ Building[]      _occupants          // W×H 引用（footprint 每格同引用，256² ≈ 512KB）
├─ GridCell[]      _cells              // W×H，懒分配 null 起步（R2）；仅承载 Units 列表
└─ Dictionary<UnitController, GridCoord> _unitCells   // 沿用
```

- 索引统一：`idx = y * _w + x`；私有 `ToIndex / FromIndex` 内联
- 老 `GridCell.occupant/isObstacle/terrain` 字段**下沉到数组**，GridCell 瘦身为 `Coord + Units`（兼容期保留旧字段读取的过渡属性，标 Obsolete，doc 6/7 适配完成后删除）

### 5.4 寻路接口预留（doc 2 的硬契约）

```csharp
/// <summary>寻路系统读取网格的最小契约（doc 2 唯一依赖口）。</summary>
public interface IPathGrid
{
    int Width { get; }
    int Height { get; }
    bool IsWalkable(GridCoord coord);          // §5.1 规则
    float GetEnterCost(GridCoord coord);       // 地形移动代价（Plain=1.0，Hills=1.5 等，SO 可配）
    bool IsDiagonalMoveAllowed(GridCoord from, GridCoord to);  // 防穿角：两正交邻格均可走才允许斜走
}
```

- GridSystem 实现 `IPathGrid`；doc 2 的寻路器只依赖接口不依赖 GridSystem 具体类（**sim 训练侧可另起纯 C# 实现**，落实总计划原则 7）
- 地形代价表走 SO（新增 `TerrainCostConfig`，字段归 doc 2 细化）
- 8 向邻居顺序固定（E/NE/N/NW/W/SW/S/SE），doc 2 直接可用
