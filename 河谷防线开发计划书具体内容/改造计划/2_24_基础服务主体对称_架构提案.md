## 一、原则陈述（一句话版）

**底层基础模块对王国主体的服务必须对称——`kingdomId` 是一等公民参数（0=玩家 / >0=AI / -1=无主），同一条 API 通道服务所有主体；基础模块层禁止「玩家硬编码路径 + AI 特殊通道」的双轨形态。**

- 「对称」≠「无差别」：阵营敌对/玩法规则差异（野怪敌意/玩家 UI 专属）仍在更上层（规则层/AI 决策核）处理——本原则约束的是**基础设施服务**（资源/人口/建筑/水网/税收/任务/存档/事件），不是游戏规则。
- 「全局可调用」的边界：模块间通信仍走 D520 裁定（EventBus+门面），本原则不改通信形态——改的是**模块对主体的服务签名与内部路由**（主体参数化，去特权路径）。

## 二、问题：双轨形态=断链温床（P1 三轮实证）

现状模式：基础模块为玩家设计（硬编码 kingdomId=0/Faction.PlayerCamp/桶 0 专属/玩家侧全局读数），AI 消费时逐个「开特殊通道」（AI 桶/AI 分支/守卫绕行/per-kingdom 补丁）——**每修一层暴露一层**（P1 大考逐层显形实况：粮→人口→招工/住房）。

| 双轨形态案例（已实锤） | 断链后果 |
|----------------------|---------|
| WaterNetwork 玩家单桶 → AI 补 AI 桶+AI 井分支（HH.73） | AI 农田断水停产（二轮熔断根因） |
| PopulationSystem 玩家专属繁殖（Faction.PlayerCamp 硬编码+桶 0 配对池+玩家侧全局读数）→ AI 补 OnNewDayPerKingdom（HH.78） | AI 人口零再生（二轮熔断） |
| VagrantCampSystem 流浪 kingdomId 硬编码 0（「未入籍=-1」设计从未实装）→ AI 招工恒拒（HH.81 修 -1） | 招工静默失败（三轮熔断） |
| HappinessSystem 玩家全局幸福/房容 → AI 补 per-kingdom 读口（HH.79） | AI 生育条件读错主体 |
| PlaceVagrantCamps 幽灵引用（HH.78） | 补员链永不触发 |

**结构性结论**：每条「玩家轨+AI 特殊通道」都是一次语义分叉，分叉点=断链候选点；特殊通道的开通依赖人工记忆（挂账），记忆失效=断链（P5 模式）。**双轨形态本身是缺陷生成器。**

## 三、目标态

1. **单轨参数化**：基础模块公开 API 一律携带 `kingdomId`（或 KingdomState/主体句柄）参数——调用方声明主体，模块内部按主体路由，无主体特判分支（除明确设计语义：如阵营敌对判定）。
2. **无主态一等公民**：`-1`（无主/未入籍）与 `0`（玩家）/`>0`（AI）同为合法主体态——生成端必须显式声明（禁止依赖默认 0）。
3. **条件数据 per-kingdom**：模块内部的状态桶（幸福/饱食/房容/水/冷却）一律 per-kingdom，读口带 kingdomId（批3a/HH.79 基建模式推广）。
4. **失败可见**：主体路由的每个拒绝分支必须日志（含主体 id+原因）——静默失败禁令。
5. **玩家=普通调用方**：玩家侧回归保障从「玩家轨不动」改为「冒烟全集兜底」（现网冒烟容器=玩家路径回归测试集）。

## 五、与既有决策的关系

- **D520（冒烟自动化与架构 API 化路线）不推翻**：D520 否决的是「模块间通信全面 web 式 API 化」（通信形态）；本提案约束「模块对主体的服务对称性」（主体参数化）——正交且互补（D520 接口纪律条款直接扩展复用）。
- **AI 北极星下沉**：北极星要求 AI 与 sim 全同源——sim 侧（harness）本就无玩家特权（纯 C# 对所有王国同构），Unity 侧玩家硬编码=15_账本 #7/#8 类差异的源头。主体对称=Unity/sim 同构度提升=**训练回灌保真提升**（本提案最硬的论据）。
- **2_23 资源第一性同构**：「资源第一性，模块派生」要求资源服务对主体对称——本提案是其基础设施层前置。

## 六、风险与回归策略

- 玩家回归：参数化改造=玩家路径也要动，回归风险真实存在——策略=每批参数化必须过现网冒烟全集（玩家路径回归测试集）+P1 式长局抽查；改造批次小步走（一模块一批）。
- 工程量：存量双轨点=审计耦合度清单计数（预计 10~20 处，量级小中为主——大件仅数据源类）；不设死线，随批携带。
- 命名预留：本提案若拍板，原则名=「基础服务主体对称」（文档版本历史记用户原话出处）。

## 七、轴B·操作侧对称（谁下令、怎么下令）｜**新增（D667，2026-09-12）**

> 定位：本轴是 2_24 的**第二条轴**。轴A（§一，D545）管「**服务谁**」（供给侧：`kingdomId` 一等公民，去玩家特权路径）；**轴B 管「谁下令、怎么下令」**（操作侧：两端各有等价的下令入口）。两轴**正交**：轴A 破"玩家特权路径"，轴B 破"AI 缺管道"。触发＝D665 实证（AI 无采集通道）＋用户架构指示。

### 7.1 原则陈述（一句话版）

**同一底层能力，两端须有等价的下令入口；决策核只出"粗意图"，微观目标选择归派工层——「两条表现，一条底层执行链」。**

- **玩家表现**：UI／点击／热键 → 底层 API（即时生效）**或** → TaskScheduler（派工执行）。
- **AI 表现**：**决策核（粗意图：识别缺口 → 下发"任务类型＋对象类"）→ TaskScheduler（选目标＋派工＋路径/距离）→ 工人执行**。
- **硬分界线**：决策核**只回答"要做什么"**（如"缺石 → 下发采集任务"）；**不回答"哪棵树／哪个工人／多远"**——后者一律归 TaskScheduler。
- **边界（与轴A 同源）**：本轴约束的是**基础设施的"下令入口"**，不是游戏规则（阵营敌对/玩法差异仍在规则层/决策核处理）。

### 7.2 操作侧断链三类（对账判定口径）

| 类 | 定义 | 实锤 / 例 |
|---|---|---|
| **O-1 单端缺入口** | 一端有下令入口、另一端**完全没有** | **D665**：世界资源采集——玩家有 UI（`BuildingPanel.cs:590` → `StartGather`），**AI 侧零入口** |
| **O-2 意图缺失** | 底层有能力、派工侧有源，但**决策核无"下发该类任务"的意图出口** | 采集通道补齐后，若决策核无"采集意图"出口 ⇒ 无人下单 |
| **O-3 越界直调** | 决策核**跳过派工层**直调底层执行 API（破坏"工人到场"语义） | 禁（与 §八 冲突） |

### 7.3 正例（已对称·可作范本）
- **建造/招兵**：决策核焦点（③建产能／⑦招兵）＝**粗意图**；派工与执行细节由既有链承担 ⇒ 属 O-1/O-2 均不犯的**合规形态**，本轴不改。

## 八、禁外源自增长｜**新增（D667，2026-09-12）**

> 用户裁定口径＝**最严档**（2026-09-12）：**产能建筑须工人到场才产**。

### 8.1 条律
**AI 与玩家的每个资源增量都必须回到同一条劳动链：意图 → 派工 → 工人到场 → 执行 → 搬运入账。**

1. **产能建筑须工人在岗 `Working` 才产**——无人在岗**即停产**（非"减产"，是停）。
2. **禁**：免劳动的免费/瞬时入账；视野外"资源自己涨"；任何**绕过工人执行链**的增量。
3. **允许的"表现层不同"**＝触发方式不同（UI vs 意图下发）＋目标选择主体不同（人 vs TaskScheduler）；**不允许**执行链不同。

### 8.2 性能策略（**不出让规则换性能**）

| 手段 | 做法 | 红线 |
|---|---|---|
| 结算粒度 | 事件级／日级低频结算（非逐帧） | 禁"低频=免费直给" |
| 视口外 | **降频采样结算**（每 N 分钟一次） | 禁"视野外不结算/直接给" |
| 在岗判定 | **复用 TaskScheduler 的 Working 态** | 禁新造高频轮询；禁"派工池认领即产" |

### 8.3 与 HH.221（AI 资源权力对等批）的接口

HH.221 主修 A 的**完整形态＝两件，缺一不可**：
1. **世界资源点作为 `ITaskSource` 向派工层广告**（供 TaskScheduler 选目标）；
2. **AI 决策核新增"下发采集意图"出口**（缺它＝O-2，无人下单）。

> **只有①没有② ⇒ 有源无单；只有②没有① ⇒ 有单无源。** 两句合起来才是 D665 的治本（对齐 §7.2 O-1/O-2）。

## 九、双端对称表（每模块一张·模板）

> 口径：**填表即审计**（同 HH.105 登记表"填表即排查"）。每模块一张，字段如下；**空格 = 隐患**。

| 字段 | 填什么 |
|---|---|
| **底层能力(API)** | 该模块对主体提供的底层入口（带 `file:line` 锚） |
| **玩家表现** | 玩家如何下令（UI/点击/热键 → 落点） |
| **AI 表现（下令入口）** | 决策核**意图出口** ＋ 派工落点 |
| **决策核/派工分界** | 谁定"做什么"／谁定"谁做、去哪、多远" |
| **生命周期（六阶段 × 双主体）** | 接 HH.105 登记表格子：生成→注册→运作→消费→死亡→存档；**必填"AI 侧下令入口"在场性** |
| **正负探针** | 命中 ＋ 反例断言（L-29 阳性对照） |
| **断链类** | O-1／O-2／O-3（§7.2） |

**示范·「招兵」玩法链**（用户给的例：招兵 → 需资源 → 需建造 → 用招兵建筑功能）：

| 环节 | 底层能力(API) | 玩家表现 | AI 表现（下令入口） | 分界 |
|---|---|---|---|---|
| ① 采资源 | 采集入账／产能入账 | 点树/矿 → `StartGather`（`Building.cs:860`） | **O-1 缺**（D665）⇒ 决策核下发"采集"意图 → 派工选点 | 核＝出意图／派工＝选点 |
| ② 建产能 | `BuildController.TryBuild` | 建造面板 | ③焦点（已合规） | 核＝选"建产能" |
| ③ 招兵 | `TrainingSystem.TryTrain` | 训练面板 | ⑦焦点（已合规） | 核＝选"招兵" |
| ④ 用建筑功能（军营训练） | 建筑功能 API | 面板操作 | 行动池（待核） | 核＝选行动 |
