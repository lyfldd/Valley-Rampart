## 一、全局规格（所有资源必须遵守）

| 项 | 值 | 说明 |
|----|----|------|
| 瓦片形态 | 等轴菱形（Isometric diamond） | 斜 45° 立体，非正方形 |
| 宽:高 | 2:1 | **128×64（@PPU100，2026-08-14 修正，原 64×32）** |
| Pixels Per Unit | **100**（2026-08-14 审查修正，原 32） | 1 世界单位 = 100 像素 |
| 锚点 Pivot | **地基菱形底面中心**（方块落脚点） | 唯一 |
| 高度基准 | **每层 = 半菱形高 = 32px**（128×64 瓦片菱形高 64px 的一半；@PPU100） | 沿屏幕 Y 轴堆叠 |
| 排序 | **按 (x+y) + 高度层，Unity Custom Axis (0,1,0) + Sprite Sort Point=Pivot**（D104，用户实测） | 高层晚画遮挡低处 |
| 网格到世界 | 等轴投影输出**锚点位置**，直接给 sprite pivot | 三者一致→无缝；**投影只在渲染层**（归 2_10；逻辑层正交坐标见 doc 1 §1.6） |

### 1.1 锚点铁律（严丝合缝的根源）

```
网格逻辑坐标 (gx, gy)
  → 等轴投影 → 世界坐标（锚点位置）
  → 直接赋给 sprite 的 pivot
```

**三者必须一致**：锚点 = 地基菱形底面中心；网格→世界输出该点；sprite pivot 设同一点。每个方块用同一规则 → 无缝隙、无错位、无重叠。

### 1.2 高度与锚点

| 对象 | 锚点 | 高度 |
|------|------|------|
| 地皮/平地（菱形地基） | 菱形中心 | 0 层 |
| 有高度物体（房/墙/山） | 地基底面中心（落脚点） | 按上标堆层 |

高度沿屏幕 Y 轴上涨：房子=2 层(64px)、围墙=1 层(32px)、山=3 层(96px)。

### 1.3 底座与焦点（2026-08-13 新增）

- **底座 footprint** = 物体逻辑占地，以小区块声明（如 树=1×1、雪山=2×2、民居=2×2），内部按微格细分
- **焦点 = 底座矩形中心**（网格→世界输出 = 焦点 = sprite pivot），三者一致
- 例：树底座 = 1×1 小区块（4×4 微格），**焦点 = 底座中心 = 树脚**（树根扎在底座中心）；寻路到树 = 到树的底座中心

| 物体 | 底座（小区块） | 微格 | 焦点 |
|------|:---:|:---:|------|
| 树 | 1×1 | 4×4=16 | 底座中心=树脚 |
| 雪山 | 2×2 | 8×8=64 | 底座中心 |
| 民居 | 2×2 | 64 | 底座中心 |

- **微格表现**：微格不建实体 GameObject，用 Gizmos 调试线画（可开关），运行时纯逻辑（`IsSubWalkable` 推导）。树预制体 = `SpriteRenderer(视觉) + BuildingFootprint 组件(声明 footprint)`，微格由程序推导。

### 1.4 Z As Y 说明（D275，2026-08-14 终审修订）

**Z As Y 说明（D275）**：Tilemap 'Isometric Z As Y' 仅用于 Tilemap 内部渲染排序辅助；建筑/单位堆叠遮挡实际靠 sprite 总高（地基高 32px+层数×32px）与 (x+y)+heightLayer 排序实现，不手动设置 Z 值；Cell Size Z=1 为 cell depth 默认值。

## 四、通用规则

### 4.1 命名
`artId` 前缀分类：`feat_`(自然) / `bld_`(人造) / `ground_`(地皮) / `mark_`(调试)

### 4.2 尺寸计算（2026-08-14 PPU100 修正）
```
sprite 总高 = 地基高(32) + 高度层数×32
sprite 总宽 = footprint宽 × 128（菱形地基每格 128px 宽 @PPU100）
pivot 位于：x = 总宽/2，y = 地基高（即地基底面中心）
```

### 4.3 排序
```csharp
// 等轴排序：先按 (x+y)，再按高度，高层后画
sortOrder = (cellX + cellY) + heightLayer
```

### 4.4 占位方针
- 占位 = 简单菱形/几何 + artId，先保证锚点/高度正确
- 正式美术替换只换贴图，锚点/高度/footprint 不变 → 逻辑零改动

## 五、验收标准

1. 任意两个相邻建筑/方块无缝、无错位、无重叠
2. 高层物体正确遮挡低层（排序生效）
3. 网格→世界输出锚点 = sprite pivot，一致
4. 所有资源符合 2:1 菱形 + **PPU=100** + 锚点铁律（D27，2026-08-14 终审同步）

## 八、单位序列帧动画规格（D259，2026-08-14 终审新增）

> 角色动画=序列帧 Sprite Sheet（非骨骼动画）；武器与坐骑直接烘焙进 Sprite Sheet（不拆独立 sprite）；工人搬运物除外（独立子 SpriteRenderer）。

### 8.1 朝向与帧数

- 8 向朝向：E / NE / N / NW / W / SW / S / SE（与 Facing8 枚举一致）
- 3 状态：idle（4 帧）/ walk（8 帧）/ attack（6 帧）
- 播放帧率 FPS=12（占位）
- **占位期 4 向降级**：只画 E / N / W / S 四向 + X 轴水平镜像补全 8 向（E↔W 互补、NE↔NW 镜像、SE↔SW 镜像、N/S 不镜像）

### 8.2 Sheet 切分规格

- 排列：单行横向帧序列，每朝向一张 Sheet（或大方阵按行切分，行=朝向）
- 帧画布：128×128px（含 1 层高度溢出：底面 128×64 + 高度层 32px + 头部余量）
- 锚点：与建筑一致=地基菱形底面中心（帧内位置固定，跨帧不抖动）
- 单位逻辑尺寸=1 微格（0.32×0.16 世界单位），美术可适当放大表现（建议不超过 0.5 小区块）

### 8.3 烘焙规则

- 武器：直接画进每帧（攻击帧含挥击/装填动作；远程单位弹道起点=帧内武器口）
- 坐骑：骑乘形态整体烘焙（人+坐骑一张 Sheet），不提供独立坐骑 sprite
- 搬运物**不烘焙**：8 种独立子 sprite——wood / stone / ore / grain / crystal / kerosene / bread / meat，挂载于子 SpriteRenderer（头部上方固定偏移），由代码切换

### 8.4 命名

- `unit_{职业}_{朝向}_{状态}.png`（如 `unit_archer_ne_walk.png`）；Sheet 版 `unit_{职业}_{朝向}_{状态}_strip{n}.png`
- artId 前缀沿用 §4.1 命名分类（`unit_` 为单位动画扩展前缀，与 `feat_`/`bld_`/`ground_`/`mark_` 并列）
