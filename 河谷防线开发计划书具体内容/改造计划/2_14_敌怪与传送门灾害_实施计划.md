### 步骤 4：灾害触发判定（PortalDisasterTrigger）

**文件**：新增 `Systems/Disaster/PortalDisasterTrigger.cs`

**实现**（设计 §2.1 触发条件，全部 SO 可配）：
```
输入：TimeDayChangedEvent（夜晚开始时）或 DayCycleSettlement 钩子（2_8 §5.4 昼夜双环）
逻辑：
  1. 天数 < minDaysBeforeFirst → 不触发
  2. 连续未触发天数 ≥ forceTriggerAfterDays → 保底触发（保底计数从 day≥minDaysBeforeFirst 起算，2026-08-14 终审澄清）
  3. 否则按 triggerProbability × 难度系数（D237 分档）概率触发
  4. 若已有活跃传送门（maxPortalPerNight 已满）→ 不触发
  5. 触发 → 调用 PortalDisasterManager.SpawnPortal() → 更新 DisasterState
```

**关键**：全程用注入的 `System.Random(seed)`，禁止 `UnityEngine.Random`（确定性 R4，sim 对拍）。
**触发事件**：发布 `PortalDisasterTriggeredEvent(day, portalWorldPos)`（UI 预警/2_10 渲染订阅）。

**验收**：
- [ ] 前 3 天不触发（minDaysBeforeFirst=3）
- [ ] day≥3 起连续 7 晚未触发 → 第 10 晚必触发（保底从 minDaysBeforeFirst 起算，2026-08-14 终审修正）
- [ ] Easy 概率低 / Hard 概率高（D237 分档正确）
- [ ] 已有活跃传送门 → 不再触发

### 步骤 5：传送门实体（Portal）

**文件**：新增 `Systems/Disaster/Portal.cs`

**实现**（设计 §2.3/§2.4 属性与规则）：
```csharp
public class Portal : MonoBehaviour, IDamageable
{
    public PortalDef def;
    public int hp;                    // 当前 HP（随难度+天数缩放，步骤 9）
    public int maxHp;
    public Vector2Int gridPos;        // 占格左上角（小区块坐标）
    public PortalState state;
    public int survivedNights;        // 已存活夜晚数（烈度递减计算）

    // IDamageable 实现：接 2_5 DamageSystem 管线
    // 白天（DayProtected）→ ApplyDamage 无效/不可交互
    // 被打 → 触发反向强化：召唤间隔缩短 + 广播 PortalAttackedEvent
    // HP=0 → Destroying → PortalDestroyedEvent → 清占格 → 恢复正常触发周期
}
```

**规则**（设计 §2.4）：
| 规则 | 实现 |
|------|------|
| 只晚上可攻击 | 白天 `state=DayProtected`，`IDamageable` 拒绝伤害 |
| 被打反向强化 | 收到攻击 → `summonInterval` 改用 `summonIntervalOnHit` + 广播增援（守门）——**P0 二档（30s→15s）；P1 升连续公式 30/(1+0.5×attackerCount) 封顶 5s（2026-08-14 终审）** |
| 不摧毁的持续袭击 | 天亮未摧毁 → 保留，白天无敌；每后一晚强度 ×aftermathDecayRate |
| 摧毁后 | 崩塌动画（2_10）→ 清除 → 恢复正常触发周期 |

**占格+阻挡**：注册进 `GridSystem`（占 2×2 小区块 + 阻挡，同建筑 D154）；摧毁后释放。

**验收**：
- [ ] 传送门生成后有 HP/占格/阻挡
- [ ] 白天不可攻击（ApplyDamage 无效）
- [ ] 被攻击时召唤间隔变短（15s）且广播增援事件
- [ ] HP=0 → 摧毁 → 占格释放

### 步骤 7：怪物行为——守门+出击双目标

**文件**：`Systems/Disaster/MonsterController.cs` + `Systems/Disaster/MonsterAI.cs`

> 2026-08-14 终审修订（D252）：**普通怪挂 MonsterAI（规则模式切换器，不进训练）；精英怪挂 NPCBrain + MonsterMode 注入**（MonsterDef.isElite，L1 FactorContext 注入，L2/L3 据模式调整姿态/指令）。

**设计 §4.1/§4.2**：

```
MonsterMode 切换：
  Raiding（出击，默认）：
    目标选择 = 价值×距离（D83，2_7 决策核同源）
      优先目标：高价值建筑（矿洞 D113/铁匠铺/仓库/主城）+ 资源点（箱子 D146 任意阵营可抢）
      建筑价值 = SO 配置价值表 × 高价值标志
      路径：走 2_6 成本场（威胁带/安全区），避开守卫区域
    掠夺行为：到达资源点 → 短暂停留（2~3s 掠夺动画）→ 携带资源回传送门
  Guarding（守门）：收到 PortalAttackedEvent → 按 guardRecallRatio 比例回援
      行为目标：保护传送门，攻击靠近传送门的玩家单位
  Retreating（撤退）：HP < retreatHpRatio → 尝试退回传送门；被攻击 → 继续战斗（无逃脱）
  Looting：掠夺动画期间不可攻击目标（短暂停留）
```

**关键规则**：
- **遇守卫**：不主动寻守卫，被攻击才反击；路过守卫/堵路被拦截则开战（§4.2）
- **击杀掉落**：怪物被击杀 → 所携资源掉落（箱子 D142/D213，内容=carryResource）
- **回传送门**：成功回传送门 → 资源消失（被传送门吸收）
- **守卫单位价值** = 战斗力权重（SO 可配），价值×距离自然决定优先级

**验收**：
- [ ] 怪物从传送门出生 → 走价值×距离选目标（矿洞/仓库/主城）
- [ ] 怪物到达资源点 → 停留掠夺 → 携带资源回传送门
- [ ] 传送门被打 → 部分怪物回援（50%）
- [ ] 怪物被击杀 → 掉落箱子（内容=所携资源）
- [ ] 怪物成功回传送门 → 资源消失

### 步骤 9：强度曲线（难度+天数缩放）

**文件**：`Systems/Disaster/PortalDisasterManager.cs`（或 `MonsterStatsScaler.cs`）

**设计 §3.3 + D235~D237**：
```
怪物属性基础强度（MonsterDef 值）：
  1. 难度缩放：× waveDifficultyCoefficient（D236：Easy 0.7 / Normal 1.0 / Hard 1.3）
  2. 天数增长：× (1 + day × growthRate)（growthRate SO 可配，占位 0.02/天）
  3. 强度上限：strengthCap = 60（D97），防止后期数值溢出
传送门自身：
  HP/召唤频率/dps 同天数增长（HP = hpByDifficulty[difficulty] × (1 + day × growthRate)）
烈度递减（未摧毁持续袭击）：
  strength × aftermathDecayRate^survivedNights（每晚 -20%）
```

**SO 配置（追加到 PortalDisasterConfig）**：
| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| growthRate | float | 0.02 | 天数增长系数（/天） |
| strengthCap | int | 60 | 单波强度上限（D97） |
| easyWaveCoefficient | float | 0.7 | Easy 波次强度系数（D236） |
| normalWaveCoefficient | float | 1.0 | Normal（基准） |
| hardWaveCoefficient | float | 1.3 | Hard 波次强度系数（D236） |

**验收**：
- [ ] 第 1 天 vs 第 30 天怪物属性差异符合曲线
- [ ] Easy=0.7x / Normal=1.0x / Hard=1.3x
- [ ] 强度不超过 strengthCap=60
- [ ] 未摧毁传送门每晚强度 -20%（烈度递减）

### 步骤 10：与 2_8 WaveDirector 联动修改

**文件**：`Systems/AI/Wave/WaveDirector.cs`（2_8 新增，本篇修改）

**设计 §6.1**：
```
2_8 §5.3 原"每夜流程" → 改为"灾害触发时流程"：
```

### 步骤 11：昼夜行为切换

**文件**：`Systems/Disaster/PortalDisasterManager.cs`

**设计 §4.4**：
| 时间 | 传送门 | 怪物 |
|------|--------|------|
| 夜晚 | 可攻击、可召唤 | 从传送门出生，可出击/守门 |
| 白天 | 无敌（不可交互） | 已在外怪物**继续存在**（不消失），传送门不召唤新怪物 |
| 下一个夜晚 | 仍可攻击（若未摧毁） | 继续召唤新怪物（烈度递减） |

**实现**：
- 订阅 `TimePhaseChangedEvent`：
  - 进入 Night → 若需要触发灾害（步骤 4）→ 生成传送门 → 开始召唤
  - 进入 Day → 传送门停止召唤（DayProtected）；已在外怪物不消失
- 夜晚结束时检查：若传送门未摧毁 → 继续保留（白天无敌）

**验收**：
- [ ] 夜晚传送门可攻击/召唤
- [ ] 白天传送门无敌（不召唤），怪物不消失
- [ ] 下一夜未摧毁 → 继续召唤（烈度递减）
