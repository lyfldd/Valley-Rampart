## 〇、背景与审计结论

### 0.1 立项触发（用户需求归纳）

1. **参照系**：《世界盒子》（WorldBox）的战斗场面，且**要比它更智能**；
2. **担忧**：老设计（单将军/多将军/阵型等）放 2.5D 是否要大改；
3. **核心诉求=解耦**：让 AI 在我们指定的规则下，通过内置的大脑**自行判断**——"遇到危险逃跑""前方有友军军队就不逃跑"等全部**涌现**，而非逐行为编程；
4. **文档要求**：完整设计文档 + 生命周期审查规范（八格检查表）+ 各模块关系影响面。

### 0.2 全景审计结论（2026-09-03 策划端代码实盘复核）

一句话：**大脑已同源受保护，眼睛是瞎的，三件套没接线（成本场/友军通讯/sim 2D），范式需要一次枢轴。**

WorldBox 单位=极简状态机（游荡/索敌/攻击/低血跑），战斗=两团 swarm 互撞；无撤退协同、无保护意识、无局部通讯、无宏观脑。**"更智能"的每一项抓手，本项目已有设计且大半已实现：**

| 抓手 | 机制 | 状态 |
|---|---|---|
| 性格分化（怂/勇/守纪/散漫） | courage/obedience 因子链 | ✅ |

### 0.4 对"老设计要大改"的澄清

维度适配层面，阵型/编队 2D 化完成度是全项目最高（§0.2）。真正要动的不是维度，是**驱动范式**：从"槽位钉死+查表"（RTS 指挥感）枢轴到"吸引场+权重"（涌现感）。本篇即该枢轴的分阶段落法。

## 一、目标范式：软涌现

### 1.1 范式公式

```
规则（SO 数据/可训练权重——人定，AI 不改）
   ↓
内置大脑（L1/L2/L3 个体管线 + L4 王国脑——自行判断）
   ↓
行为（涌现——代码不写"士兵A去掩护将军"这行）
```

### 1.2 范式三原则

1. **意图=权重，不是表行**：Charge/Defense/Retreat 不再驱动查表换阵，而是切换 CostBias 权重集（formation 偏好/追击基线/威胁容忍）——意图是"倾向调节器"；
2. **阵型=吸引场，不是钉子**：槽位从 FollowStimulus 硬钉改为成本场低代价吸引位——士兵"想"站好位置，但威胁/保命/保护可以随时打破，威胁解除自动归位（重整=涌现，3.0.1_3 §4.3 原样继承）；
3. **协作层只产输入不产行为**（3.0.1_3 哲学原文继承）：回援/分兵/重整/溃散全部是个体管线对刺激源的响应。

### 1.3 用户示例走查（范式兑现路径）

| 用户示例 | 因子链 | 阶段 |
|---|---|---|
| 遇到危险逃跑 | 威胁因子×courage > 撤退阈值 → L2 姿态 → 逃逸点背敌采样 | ✅ 已实现（阶段D 补 sim 对齐） |
| 前方有友军军队就不逃跑 | ProtectPowerSum ≥ protectThreshold → HasProtection → 撤退阈值抬升 | 机制✅；**阶段A 修眼即通** |
| 阵型跟随但战斗中可打破 | 交战态 formationWeight 软吸引 + 威胁/保护优先 | 阶段C |

## 三、阶段A：感知修复（详细设计）

### 3.1 病灶（代码级）

`PerceptionSystem.QueryNearby` 主路径按 cell 扫描：`for dx ∈ [-cellRange, cellRange] × for y ∈ {0, 1}`——y 双行=1D 横版"双层"残留。2.5D 256² 地图上单位遍布全图，仅最南两行（y=0/1）的单位可被发现。GameScene 实跑必中；纯逻辑冒烟走 FallbackQuery（全注册表扫描，2D 正确）故全绿。

### 3.2 修法：单遍过滤法（主路径=FallbackQuery 语义）

```
QueryNearby(position, radius, faction, findEnemies, results)：
  1. 遍历 UnitRegistry.Instance.GetAllUnits() 一遍（存活单位）
  2. 阵营过滤（findEnemies=true：f != my && f != None；false：f == my）
  3. 世界坐标欧氏距离 ≤ radius → 加入 results（复用调用方缓冲，签名/调用方零改动）
  4. UnitRegistry 缺失 → 返回空（FallbackQuery 分支合并删除）
```

- **为什么不是方格遍历**：`GetUnitsInCell` 每次调用都全量遍历 `_unitSubCells` 注册表（O(N)/格）；2D 方格数 (2n+1)² 平方级放大后 = (2n+1)²×O(N) 不可接受。单遍 O(N) 与既有 FallbackQuery/D468 野性扫描同构，是现役验证过的模式。
- **性能账**：活跃带 300~400 单位 × 感知节流（保底 0.5s + LOD 休眠降频）→ 单位时间全图数百次 O(N) 遍历，量级可接受；若 profiling 超预算，空间哈希分桶列为 P2 优化（非本批）。
- **连带恢复**：`_nearestDist`（最近敌距离）在同一循环内计算，随修复自动恢复；FactorContext.NearestEnemyDist/NearestEnemyDir 输入随之恢复真值。

## 四、阶段B：涌现奠基（详细设计）

### 4.1 AllyCommSystem——近距战斗通讯（"同伴被打我知道"）

**定位**：1D 遗留设计债 AllyDamaged 的 2.5D 落地。WorldBox 无此能力=核心差异化项。

**机制**：

```
订阅 UnitDamagedEvent（区域聚合器纪律：系统级统一订阅，非 NPC 自订阅全图——3.0.1_3 勘误先例）
  ↓ 每次受击事件
以 victim 为圆心 commRadius（SO，默认 1.5×感知半径，占位）内查同阵营存活单位
（复用阶段A 修复后的 QueryNearby findEnemies=false）
  ↓ 对每个目击者
注入 ThreatStimulus：
  Enemy   = attacker（IUnitHandle；已死则跳过）
  强度    = 受击溯源基础强度 × witnessScale（0.6 占位）× 距离衰减（victim→目击者）
  级别    ≥ 警戒（1）
  expiry  = threatDecayTime（同威胁衰减）
  ↓ 节流
每（目击者 × attacker）每 commCooldown（1s 占位）至多一次——防刺激洪泛
```

**语义边界**：目击刺激**只提警戒+指明威胁源**，不直接驱赶/改姿态——个体仍由三层管线自行判断（守 §1.2 原则③）。比 LOD 热点（区域级、无源信息）强一档：知道"谁在打我同伴"。

**八格检查表（生命周期审查，《设计方法论_生命周期工作流》§0.4）**：

| # | 环节 | 答案 |
|---|---|---|
| 1 诞生 | GameBootstrap/场景初始化显式 Init：订阅 UnitDamagedEvent（触发源唯一=伤害管线） |
| 2 归属 | 静态系统（对齐 VisionSystem/PerceptionSystem 先例），无 Manager 注册需求 |
| 3 更新 | 事件驱动（无 tick）；节流字典惰性过期清理 |
| 4 挂起/恢复 | Clear() 清节流表即无损复位；无持久状态 |
| 5 正常终结 | TeardownManager/场景卸载调 Shutdown：退订+清字典 |
| 6 异常终结 | attacker 已死→注入前校验 IsAlive 跳过；victim 死亡同帧→事件仍有效（"最后遗言"仍传播）；换图→Clear 幂等 |
| 7 清算 | 退订 UnitDamagedEvent；节流字典清空；不持有单位强引用（刺激只传 handle，expiry 自动过期） |
| 8 持久化 | 纯运行时行为，无状态入档 ✓ |

**SO**：`AllyCommConfig`（enabled/commRadiusCells/witnessScale/commCooldown），路径 Resources/Config/；可训参数 witnessScale/commRadiusCells 入 factor_registry 草案 + champion（TuningSnapshot 扩字段，禁第三源）。

### 4.2 意图=权重（FormationTable 简化）

**现状**：`Lookup(intent, line, melee, archer, formationWeights)`——意图×战线×构成三元组查表；BattleLine 无驱动方（死参数）；意图驱动表行=RTS 指挥感来源。

**简化**：

```
查表键简化：构成（近战族数 × 远程族数）→ 形状（线/圆/楔）——形状=构成的自然结果
意图脱离查表：IntentBiasConfig（按意图分档权重集，占位）
  Charge:   formationBias 0.4 / chaseRangeCells 基线 8 / 威胁容忍高
  Defense:  formationBias 0.8 / chaseRangeCells 2
  Retreat:  safetyBias 高 / 近战殿后=角色族填充顺序自然涌现（不写逻辑）
BattleLine（战线）退役：分兵由"多将军各带一队+热点支援"涌现（查表行删除）
守城（LookupGarrison）保留不动：守城=静态锚点+role 布局，不在软范式范围
```

**迁移路径**：阶段B 先落 IntentBiasConfig+简化 Lookup（硬槽位不变）；阶段C 成本场激活后 formationBias 直接进 CostBias.formationWeight（2_7 §5.2 已定义的钩子）。

**训练真源**：IntentBias 权重并入 TuningSnapshot（formationWeights 扩为按意图分档），champion 单源；IntentBiasConfig=Unity 壳（Resources/Config/），同步纪律按 sim-sync。

### 4.3 阵型残留清理（随阶段B 顺带，小项）

- 编队朝向回退值 `_formationDirection=±1`（仅左右）→ 回退改用 FormationBrain 最近有效前进向量（360° 正确）；
- 守城锚点占位（第一成员自跟随）维持现状，改 Transform 锚点挂既有 P1 账（不新增）。

## 五、阶段C：场化枢轴（接口级设计，主体归 2_6 P1）

### 5.1 成本场激活

2_6 §5.3 合成公式（D250 既有定稿）：`costField = clamp(1 + 2.0×threat − 0.5×safety − 0.8×formation, 0.1, 10)`；寻路代价=terrainCost×costField。本阶段=把既有设计落地激活，**不新设计**。

### 5.2 槽位软化（双模阵型）

```
集结态（硬槽位，保留现状行为）：
  触发：编队 heat < engageGate（FormationBrain 既有热度）且无成员受威胁
  行为：FollowStimulus 钉槽列队（行军/集结观感——Kingdom 直觉支柱需要）
交战态（软吸引，新）：
  触发：heat ≥ engageGate 或任一成员威胁等级 ≥ 警戒——1s 确认（防抖，对齐阵型切换防抖先例）
  行为：槽位钉释放 → 槽位坐标登记为成本场低代价吸引位
        （FormationController 注册，对齐 GuardRegion 注册模式）→ 士兵走 A* 消费成本场
  归位：威胁解除 + heat < disengageGate（低于 engageGate 的回滞带）持续 3s → 回集结态
回滚开关：FormationConfig.useSoftFormation=false → 恒硬槽位（对照/回滚，对齐 AIDistConfig.useGridUnits 先例）
```

### 5.3 将军降权（软范式下的将军定位）

将军=**高 protectPower 个体 + 军令源 + 锚点**。FormationController 保留（招募/军令/解散/锚点）；"阵型切换决策权"降级为"意图权重切换"（SetIntent 语义不变、防抖保留，效果从换表行变为调权重）。将军光环双通道退役见 §八。
