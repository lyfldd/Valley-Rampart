# 评分面「保全式赢收益路径」设计稿

> 出处：D572② 立项（HH.117 收兵结构批「行为变了分不动」）→ 五池实证（T06 r4 候选/T01 复开/F28/T03/T04/F27 参数死亡或弱活性共同结构根因）→ D581/D584/D586 三次交付承诺兑现。
> 作者：策划端 · 2026-09-09 · **状态=待用户拍板（方案 A 选择+权重分配确认）→ 训练师实施**
> 关联：D566① 参数快验制 / D519 双环演化 / D403 主要矛盾 / 17 手册罪1（指标先于参数）罪2（赢法单一化）罪5（代理指标漂移）

## 一、问题定义（五池实证的根因收束）

现评分公式（sim ScoreFormulas，五轮 baseline 口径）：

```
总分 = 胜率×0.40 + 战损比归一×0.30 − 弓手被贴身率×0.20 + 槽位保持×0.10
```

**收益路径缺陷**：D 档全胜局中，「全歼式赢」（残存 10%）与「保全式赢」（残存 90%）总分相同——
- 胜率项 0.40 二值化：赢的方式不影响该项；
- 战损比归一 0.30 是「我方损失/敌方损失」**比率**：保存有生力量的**绝对值**收益无处安放；
- 槽位保持/贴身率是过程约束项，非战果保全项。

**实证链**（五池参数死亡/弱活性的共同根因）：
- T06 收兵结构：仪式性收拢（敌残存<25% 才触发，承伤已定型）——收兵触发窗口在战斗已定局尾段，新公式下仍无分可加（D572 机理注记）；
- T01/F24 风筝：保全走位的行为收益无计分承载（D560 议题① 行为结构非评分结构，但结构落地后仍需评分通路兑现演化压力）；
- F28 夜间保全：safetyNightWeight 参数面死亡=「评分面无夜间保全收益通道（存活项饱和/承伤非评分输入）」（D-017 §5）；
- T03 站槽：break* 无因果=短板在指标/结构面（D578）；
- F27/T04/T05：带内弱活性与零触发死键——参数响应被评分圆整吞掉或路径未触发。

**结论**：评分面缺一条「赢且保全 > 赢且全歼」的收益通道，导致所有保全类行为结构（收兵/风筝/夜间收缩/撤退止损）落地后训练无法给它们演化压力。

## 二、方案比对

### 方案 A：新增「战后残存率」独立边际项（推荐）

```
总分 = 胜率×0.40 + 战损比归一×0.20 − 弓手被贴身率×0.20 + 槽位保持×0.10 + 战后残存率×0.10
```

- **战后残存率** = 战后我方存活数 / 开局我方总数（0~1，场景级统计新字段 `postBattleSurvivalRate`）；
- 权重重分配：战损比归一 0.30 → 0.20，让出 0.10 给残存率——**战损比与残存率是同一「兵力交换」语义的两面**（交换效率 = 比率；绝对保存 = 残存），拆分内部重分配不触碰胜率/贴身/槽位三个独立项，总权重 1.00 不变；
- 胜率 0.40 维持第一大项：**「赢」仍是第一收益**。

**防罪2 条款（赢法单一化防线）**：
- 残存率项**仅在 winRate > 0 局计分**——败局残存再高也不加（防「逃跑保命」伪赢法；败局的保全由既有撤退行为承载，不进公式）；
- 残存率权重 0.10 远小于胜率 0.40：「不赢只保全」的进化方向被胜率项压制；
- 「收兵赢」（winRate 1 + 残存高）与「全歼式赢」（winRate 1 + 残存低）分差 = 0.10×残存差（如 0.9 vs 0.2 → 差 0.07）——足以驱动收兵时机演化（disengageRatio 可训练标量的收益通路，D567③ 处方 (h) 兑现）。

**防罪5 条款（代理指标漂移防线）**：
- 公式改动**不改行为**（同 champion 同 seed 同场景，行为字段必须全等——纯计分面改动的验证判据）；
- 改动后回放抽查义务：determinism 子集跑批 + 抽 2 场景行为级对照（前后行为字段逐字段全等=改对；行为变了=改错）；
- 残存率语义直白（存活占比），无比率函数非线性化，回放归因简单。

**五池重估解锁**：公式落地后 T06 r4 候选/T01 复开/F28/T03/F27 五池统一在新公式口径下重估（D567③ (h)「评分面不足列报」的反向兑现：本稿即「评分面方案落地」事件本身）。

### 方案 B：战损比归一函数边际化（否决）

战损比归一改凹曲线（比率高位区边际递减/封顶加成），不动权重结构。**否决理由**：比率函数非线性化后回放归因困难（罪5 风险升高）；「保存兵力」的绝对值语义（少死 5 人）与比率语义（我损/敌损）混淆——比率已含相对信息，绝对保全信息比率不可分；改动面看似小实则语义最绕。

### 方案 C：评分不动+卡池自定义收益（否决）

每卡自定义收益函数。**否决理由**：碎片化=口径漂移（每卡一套收益定义，跨卡不可比）；不解决跨卡结构问题；与 D519「权重归训练、结构归策划」的分层相悖。

## 三、实施边界（训练师执行口径）

1. **仪器先于训练（罪1）**：场景级统计新字段 `postBattleSurvivalRate` 先落 report（回合末我方存活/开局数），随公式改动同批；
2. **公式改动=结构性改动**：走提案双门禁（超快验制范围）；权重为公式常量（注释声明策划域），**不入 champion tuning**（公式结构非可训练参数；D519 远期若权重入训另走受控重注册）；
3. **baseline 重建（一次成本，不可避免）**：新公式下旧 baseline 分数不可比——**建议与 T05 参数面开工合并时点**：公式落地→重建 baseline（12600 局）→参数面 7 键双探针在新公式口径下跑，一次到位（否则参数面旧公式跑完再改公式=参数面重估白跑，顺序敏感）；
4. **15_账本登记**：评分公式=训练专用评估器，Unity 侧无对应物（FormationBrain/战斗不消费此公式）=**无回灌义务**，登记事实注记即可（C-T3 口径）；
5. **行为级零变化验证**：公式落地轮（r6）@battles100 全套件——同 champion 下行为字段与 r5 全等（公式不改行为证明）+分数方向性抽查（D 档残存高场景 sub 上升/全歼式赢场景 sub 下降）。

## 四、验收判据

1. 公式落地轮行为级零变化（r6 vs r5 行为字段全等）；
2. 分数方向性符合设计（保全式赢局 sub↑ / 全歼式赢局 sub↓，抽查 ≥2 场景各一）；
3. 新 baseline 重建完成（分数快照入库，L-02 口径）；
4. 五池重估解锁声明（T06 r4/T01 复开/F28/T03/F27 在新公式口径下排队）。

## 五、用户拍板点

1. **方案 A 选择确认**（vs B/C）；
2. **权重分配确认**：胜率 0.40 + 战损比归一 0.20 − 贴身率 0.20 + 槽位保持 0.10 + 残存率 0.10（总权 1.00；战损 0.30→0.20 让位残存 0.10）；
3. **残存率计分门槛确认**：仅 winRate>0 局计分（防罪2 硬条款）；
4. **baseline 重建时点确认**：公式落地时一次重建（与 T05 参数面开工合并时点）。
