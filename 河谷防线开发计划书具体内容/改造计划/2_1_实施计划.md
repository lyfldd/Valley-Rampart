## 一、实施步骤（按依赖序，每步可独立验收）

### 步骤 1：枚举与数据结构

**文件**：`Systems/Grid/GridTypes.cs`（或新建 `Systems/World/ClimateTypes.cs`）

```csharp
public enum ClimateZone { Tropical, Subtropical, Temperate, Cold }

public enum FeatureType
{
    Plain, Tree, Mountain, SnowMountain, Mine,
    OreVein, StonePile, WoodPile,
    River, Lake, Ocean
}

public class NaturalBuilding
{
    public int cellX, cellY;     // 落点（左上）
    public int w = 1, h = 1;     // 默认 1×1；Mine/大型岩石可 2×2
    public FeatureType feature;
    public ClimateZone climate;
    public string artId;         // 占位 artId
}
```

**验收**：编译通过；`FeatureType` 含全部可走/阻挡特征物。

### 步骤 2：MapData 2D 装配

**文件**：`Systems/World/MapData.cs`（或契约所在文件）

按设计 §5.1：
```csharp
public class MapData
{
    public int mapId;                 // 恒 0
    public int seed;
    public int width, height;
    public ClimateZone[] climateZones; // 按大区块 16×16 存（宽度 = width/16）
    public FeatureType[] features;     // W×H，唯一功能源
    public List<Vector2Int> kingdomSpawns;
    public List<SpawnDef> threatSpawns;
    public List<NaturalBuilding> naturalBuildings;
}
```
- 删除遗留：`regions/bigTerrain/isPlayerHome/isConquered`
- `climateZones` 长度 = `(width/16) × (height/16)`

**验收**：`MapData` 可序列化（存档归 2_11，先保证字段存在）。

### 步骤 3：温度带权重铺

**文件**：`Systems/World/WorldManager.cs` 新增 / `MapGenRules.cs`

```
输入：seed, width, height
对每个大区块 (cx, cy)：climateZones[cx + cy*(width/16)] = 按 climateWeights 加权随机(seed RNG)
```

**关键**：全程用注入的 `System.Random(seed)`，禁止 `UnityEngine.Random`（确定性 R4）。

**验收**：Gizmos 临时按温度带画大区块色块，4 带散乱分布、无纬度排布。

### 步骤 4：特征物填充（本片核心）

**文件**：`MapGenRules.cs` 新增 `FillFeatures(rng, map)`

对每个小区块 (x, y)：
```
climate = map.climateZones[ (x/16) + (y/16)*(width/16) ]
density = climateFeatures[climate]   // 占位表，见设计 §3.3
feature = 按 density 加权随机（空格=Plain）
map.features[x + y*width] = feature
```
- **散点分布**：雪山/山地等阻挡按格随机，不整片封锁（设计 §3.2 语义）
- 河流/湖泊/海洋**暂不在此步**（步骤 9 覆盖），先留 Plain 占位

**验收**：抽样统计各特征物比例符合表；寒带内可走 ~45%，全图可走 ~72%（2026-08-13 审计按设计 §3.3 实算订正）。

### 步骤 5：FeatureType → 网格层派生映射 + PopulateFromMap

**文件**：`Systems/Grid/GridSystem.cs`（doc 1 基础上）

按设计 §5.1 映射表，`PopulateFromMap` 读 `features` 派生 `terrain / plainSub / walkFlags`：
- Plain → TerrainWalkable；Mountain/SnowMountain → IsObstacle
- Tree → Forest+可走（一次性木，采后延迟刷新，无伐木场）；Mine → Quarry+可走（Locked 由 2_2/2_7 置）
- River/Lake/Ocean → Water(阻挡)

**验收**：`GridSystem.GetTerrainAt/IsWalkable` 与特征物一致；映射表逐行核对。

### 步骤 6：王国出生点

**文件**：`WorldManager.cs`

```
aiCount = aiKingdomByDifficulty[difficulty]   // Easy=1/Normal=2/Hard=3
spawns = 随机放 (1+aiCount) 个点，间距 ≥ spawnMinDistanceCells
校验：必须落 Plain 可走格；否则就近找最近可走格（R6）
```

**验收**：`kingdomSpawns.Count == 1+aiCount`；全部落在可走格；两两间距达标。

### 步骤 7：后置校验① 资源就近补

**文件**：`MapGenRules.cs` 新增 `EnsureNearbyResources`

```
对每个出生点：半径 resourceGuaranteeRadius 大区块内
  缺木(Tree) 缺矿(Mine) 缺农田(Plain可建) 缺石(StonePile) → 就地改特征物
  一次性资源放宽：近出生点该类密度上调
```

**验收**：每个出生点 3 大区块内能找到木/石/矿/农田（冒烟 #2）。

### 步骤 8：后置校验② 连通性 flood-fill

**文件**：`MapValidator.cs` 新增 `ValidateConnectivity`

```
以第一个出生点为源做 flood-fill（只走可走格）
  若其他出生点/主要资源区不可达 → 打通走廊（把路径上的阻挡格改 Plain）
  死区检测：无出生点外的孤立可走口袋（允许水隔离的岛屿）
```

**验收**：所有出生点彼此可达；无可走死区；岛屿可隔断（水）保留。

### 步骤 9：海洋边缘 + 湖泊河流

**文件**：`MapGenRules.cs` 新增 `PlaceWater`

- 海洋：地图最外沿 1 圈设 `Ocean`
- 湖泊：随机若干 3×3~5×5 块设 `Lake`（避开出生点 1 大区块）
- 河流（**RuleTile 主干河，2026-08-13 审计定案，与设计 §3.6 对齐**）：
  1. 按地图大小生成主干河：128²=1 条 / 256²=2 条 / 384²=3 条，各不相交
  2. 源头 = 地图边缘（山/高地），注入 = 另一边缘海洋或大湖
  3. 走向：转弯之间隔 2~3 格直道；绕行雪地/湖泊（沿边界走），不穿特殊地形
  4. 地块变体按连接方向集写入 `River` 特征（straight_V/H、corner_NW/NE/SW/SE、end），渲染层 RuleTile 自动选块；**不做分支**（无 T 型/十字）
  5. 寒带湖泊写冰河视觉标记（占位 artId 区分，不改功能）
- **水域放置后复跑连通性校验**（审计补充）：河流阻挡切断出生点 → 打通走廊或改道

**验收**：地图边缘海洋环绕；湖泊/河流为阻挡；不切断出生点连通（复验通过）；河流地块变体集合正确。

### 步骤 10：威胁刷点（SpawnDef）

**文件**：`WorldManager.cs`

```
对每个王国出生点：在其大区块外、视野外（距离可配）随机放 1~N 个 SpawnDef
  方向朝向王国；强度与难度挂钩
```

**验收**：`threatSpawns` 生成；近王国且视野外；不与出生点重叠。

### 步骤 11：naturalBuildings 派生（视觉层）

**文件**：`WorldManager.cs` / `MapGenRules.cs` 新增 `DeriveNaturalBuildings`

```
遍历 features：
  feature ∈ {Tree/SnowMountain/OreVein/Mine} → 生成 NaturalBuilding（1×1）
  大型岩石/Mine 可升 2×2（w,h=2）；2×2 用主格+副格同值表示，**只从主格（左上）派生一条记录**（审计补充）
  artId = 设计 §六 对应 id；climate = 所属温度带
```

**验收**：`naturalBuildings` 全部由 features 派生，不反向改可走；未占用格不生成。

### 步骤 12：Gizmos 可视化

**文件**：`GridSystem.OnDrawGizmos`（doc 1 基础上追加）/ 独立 `MapGenDebugDrawer`

- 温度带色块（§5.4 配色）
- 特征物标记（阻挡红/树绿/矿暗紫）
- 出生点金块、威胁点红块

**验收**：空场景生成 256² 后可视化清晰。

### 步骤 13：简易渲染（让生成结果在 Unity 可见，非最终 2_10）

> 目的：地图生成后**立即能在 Unity 看见效果**，不等到 2_10。只做最简版，正式渲染（Y-sort/优化/正式美术）归 2_10。

**文件**：新增 `Systems/World/MapSimpleRenderer.cs` / 场景挂载

```
1. 建等轴 Tilemap：层① 地皮（温度带 4 Tile）+ 层② 自然建筑（山/水/树/矿 Tile）
2. 遍历 features → Tilemap.SetTile 铺到对应格（等轴 2:1）
3. 人造建筑：实例化预制体占位（临时占位图），pivot 对齐网格锚点
4. 出生点/威胁点：临时 marker
```

**关键约束**：
- 人造建筑**受 Tile 网格约束**——footprint 在逻辑格定义，位置 = `格子→世界` 锚点，尺寸按倍格，pivot 对齐网格（§美术规范）
- **逻辑层输出正交坐标（doc 1 §1.6），等轴投影只在渲染层**（归 2_10；本步骤占位实现用简化投影）：`isoX = (gx - gy) * halfTileW`，`isoY = (gx + gy) * halfTileH + 高度`（仅 Tilemap 摆放用，不进逻辑）
- 占位美术即可，正式替换归 2_10

**验收**：256² 生成后 Unity 场景可见——地皮温度带色块、自然建筑 Tile、人造建筑占位预制体，全部对齐网格无缝隙。

## 三、SO 配置（MapGenRulesConfig 2D 版）

| 字段 | 类型 | 默认 | 备注 |
|------|------|------|------|
| climateWeights | float[4] | 等概率 | 温度带分布 |
| climateFeatures | FeatureDensity[4] | 见设计 §3.3 | 每带特征物密度 |
| aiKingdomByDifficulty | int[3] | {1,2,3} | AI 数 |
| spawnMinDistanceCells | int | 可配 | 出生点间距 |
| resourceGuaranteeRadius | int | 3 | 大区块 |
| connectivityThreshold | float | 0.95 | 出生点彼此可达比例阈值，<95% 触发打通走廊（占位，D257，2026-08-14 终审修订） |
| resourcesPerChunkBase | int | 60 | 每大区块基准资源数；难度系数 Easy=0.7（42）/Normal=1.0（60）/Hard=1.3（78）（占位，D257） |
| treeRespawnDays | int | 7 | 树采后原坑位/附近 1 格内刷新天数（占位，D257） |
