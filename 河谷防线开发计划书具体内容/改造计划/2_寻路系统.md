## 一、老系统与新系统的衔接

### 1.1 现状：没有寻路的时代

老移动模型（`UnitController.cs` 实际代码）：

```
Move(direction) / MoveTowards(destination)
  → Vector2.MoveTowards 直线逼近
  → newPos.y = current.y 固定 Y 轴（1D 命脉，2D 后必删）
  → IsBlockedByFortification：撞墙即停（无绕行）
  → UpdateGridPosition()：每步登记 GridSystem.TryEnter
```

AI 侧（`BehaviorExecutor`/`NPCBrain`）只下发"目标点"，**如何到达**完全由 UnitController 直线走解决。2D 后这套模型彻底失效：直线走会被城墙/水域/建筑卡死。

### 1.2 衔接总图

```
老链路：NPCBrain/任务 → MoveTowards(目标点) → 直线走 → 撞墙停
新链路：NPCBrain/任务 → PathRequester（新）
                          ↓ 异步票据
                   PathfindingService（新：A*/流场）
                          ↓ PathResult（路径点列表）
                   PathFollower（新组件：逐路径点驱动 MoveTowards）
                          ↓ 遇动态阻挡/路径失效 → 重新请求
```

**关键衔接决策：移动原语保留。** `MoveTowards(Vector2)` 不删，语义从"走向终点"变"走向下一个路径点"——碰撞、拒马减速、击飞、冲锋让位等老逻辑（3.6/3.7 全部移动规则）原样生效。寻路只负责"算点"，跟随只负责"喂点"，移动规则零重写。

### 1.3 各老系统接缝表

| 老系统 | 接缝 | 归属 |
|--------|------|------|
| UnitController.MoveTowards/Move | 保留原语；调用方从"直接喂终点"变"PathFollower 喂路径点" | doc 5 改接线，本文档提供 PathFollower |
| BehaviorExecutor（AI 移动指令） | 移动类指令改发寻路请求 | doc 7 适配，本文档提供请求 API |
| WanderAnchorPool（游荡锚点） | 锚点需"可达性"校验（不可达锚点毒害游荡） | doc 7；本文档提供 `IsReachable(from,to)` |
| 建造占格/释格（MarkOccupied/Free） | 障碍变化需通知寻路失效缓存 | doc 1 GridSystem 发 `WalkabilityChangedEvent(rect)`；本文档订阅 |
| 城门/工事挡移动（IsBlockedByFortification） | 格级阻挡进 WalkFlags（doc 1）；位移级碰撞保留原样 | 双保险，不冲突 |
| LODSystem | 低档 LOD 单位不跑完整寻路（降频直走/沿缓存路径跳跃） | doc 7 定义降档策略；本文档接口按档分级 |
| 训练模拟器（harness） | **寻路核必须纯 C# 可独立引用**（总计划原则 7） | 本文档 §5.6 程序集隔离设计 |

## 三、新系统的需求讨论

### 3.1 功能需求

| # | 需求 | 场景 |
|---|------|------|
| F1 | 单单位点对点寻路（A*，8 向，禁穿角） | 工人去资源点、信使、追击 |
| F2 | 群体同目标寻路（流场 Flow Field） | 夜晚敌潮→主城；集体撤退→安全锚点 |
| F3 | 异步请求：票据制队列，分帧完成，不卡帧 | 200 单位同时需求 |
| F4 | 动态障碍响应：占格变化→受影响缓存失效→单位重寻路 | 建造/拆墙/城墙被破 |
| F5 | 不可达处理：目标不可达→返回"最近可达点"路径+明确标记 | 目标在水中央/被围死 |
| F6 | 可达性查询 `IsReachable(from,to)` | 游荡锚点校验、任务可行性预检 |
| F7 | 阵营感知可走性（可选覆盖层）：如城门对敌阵营不可走 | 围城玩法（默认行为对齐现状=全员可走，见 D3） |
| F8 | 路径跟随组件：逐点驱动 MoveTowards，支持中途取消/重寻 | 所有 NPC |
| F9 | LOD 分级消费：高档全跟随、低档降频跳格 | doc 7 联动 |
| F10 | 调试可视化：路径线/流场箭头/A* 展开热力 | 开发调参 |

### 3.2 非功能需求（性能预算，验收硬指标）

| # | 指标 | 目标值 | 依据 |
|---|------|--------|------|
| N1 | 单帧 A* 完成数 | ≤ 4 条（队列分帧） | 60fps 下寻路帧耗 ≤ 2ms |
| N2 | 单次 A* 展开上限 | 4096 节点（可配） | 覆盖 ~64×64 区域；更远分流场 |
| N3 | 流场全量重算 | ≤ 1 次/帧，256² 单次 ≤ 3ms | BFS 稠密数组实测量级 |
| N4 | 同时活跃流场目标数 | ≤ 8 个（可配） | 内存：每场 ~195KB，8 个 ~1.6MB |
| N5 | 同屏 200 单位路径跟随 | 帧耗 ≤ 1ms | 跟随是纯数组采样 |
| N6 | 寻路核确定性 | 同输入同输出，跨 Unity/sim 一致 | goldenReplay 硬需求 |
| N7 | 路径请求→完成延迟 | P50 ≤ 3 帧，P99 ≤ 15 帧（高优先级插队） | 体感无卡顿 |

### 3.3 待定项（附推荐值）

| # | 待定项 | 推荐 | 说明 |
|---|--------|------|------|
| D1 | 算法组合 | **A*（个体/短距）+ 流场（群体/长距/攻城）**，不做 HPA* | 256² 纯 A* 有上限风险但流场兜底；HPA* 复杂度不值，列 P2 备选 |
| D2 | 路径平滑 | P0 不做，P1 加"视线拉直"（Bresenham 超覆盖线检测跳点） | 纯格心路径观感锯齿可接受先行 |
| D3 | 阵营可走性 | 接口预留 `IFactionWalkOverlay`，**默认实现=全员一致**（对齐现 1D 行为：城门不挡敌） | 城门挡敌玩法是否启用归 doc 6/8 决策，寻路层只留口 |
| D4 | 单位间避让 | 不进网格（太动态）；跟随层叠加简单分离转向（separation steering） | 具体参数归 doc 5；本文档定"避让不改路径只改局部位移"原则 |
| D5 | 线程模型 | **单线程分帧**（不用 Job/Burst/多线程） | 确定性第一；性能预算 N1~N5 在单线程内可达 |

## 四、新系统可能遇到的问题

| # | 风险 | 触发 | 对策 |
|---|------|------|------|
| R1 | **破墙瞬间重寻路风暴**：夜晚敌潮+城墙被破→全场路径失效 | 阶段 3 战斗 | 失效不立即重算：单位跟随层检测下一路径点阻挡→冷却（repathCooldown，默认 1s）后重新请求；流场失效按 dirtyRect 局部重积 |
| R2 | 目标不可达的反复请求死循环 | 敌人锁定城内单位但围合完整 | F5 最近可达点+`Unreachable` 标记；AI 侧（doc 7/8）据标记换目标/转攻城 |
| R3 | 确定性漂移：float 代价累加顺序差异 | sim/Unity 对拍 | 固定邻居顺序（E/NE/N/NW/W/SW/S/SE，doc 1 已定）+ 开放列表平局按节点索引裁决 + 不用字典遍历序；代价用 float 但全程同序累加 |
| R4 | 斜穿角 exploit：两墙夹缝斜穿 | 建造密铺 | doc 1 `IsDiagonalMoveAllowed` 已禁穿角（两正交邻格均可走才允许） |
| R5 | 流场目标爆炸：每个敌将/每个撤退锚点都要流场 | 多将军+多锚点 | N4 上限 8 + 目标合并策略（同阵营同目标区共享场）；超限目标退化为 A* |
| R6 | 单位堵门/堵桥：动态软阻塞堆积 | 城门窄口 | D4 分离转向 + 跟随层"等待超时换邻格"微绕行；不做单位占格寻路（性价比低） |
| R7 | 大地图 A* 长尾：对角穿越 384² | Large 档 | N2 展开上限截断 → 返回"方向性部分路径"（朝目标最接近点），边走边续 |
| R8 | 路径点到达判定抖动：格心精确到达卡顿 | 跟随层 | 到达半径走 SO（默认 0.3×cellSize）；最后一点用精确到达 |
| R9 | sim 侧无 UnityEngine：`Vector2Int/Mathf` 依赖渗入 | 训练编译 | 寻路核放独立 asmdef，仅依赖 AI.Core 的 `Vector2IntX/MathfX` shim（已有）；禁止 using UnityEngine |

## 五、要开发的新系统（详细设计）

### 5.1 程序集与分层

```
Pathfinding.Core/（新 asmdef，纯 C#，零 UnityEngine 依赖——sim 共用）
├─ IPathGrid（引用 doc 1 契约，由 AI.Core shim 类型表达）
├─ AStarSolver        // 单请求展开器（无状态，可复入）
├─ FlowFieldBuilder   // 流场构建器（BFS 积分场 + 方向场）
├─ PathTypes          // PathResult/PathStatus/PathRequest 等 POCO
└─ BinaryHeap         // 开放列表（数组堆，确定性平局裁决）

Systems/Pathfinding/（Unity 侧，asmdef 依赖 Pathfinding.Core）
├─ PathfindingService : Singleton   // 请求队列/分帧调度/流场注册表/事件订阅
├─ PathFollower : MonoBehaviour     // 挂在单位上，驱动 MoveTowards
├─ PathfindingDebugDrawer           // Gizmos 可视化
└─ Data/PathfindingConfig (SO)      // 全部可调参数
```

### 5.2 核心类型

```csharp
public enum PathStatus { Pending, Ready, Partial, Unreachable, Cancelled }

public sealed class PathResult
{
    public PathStatus status;
    public GridCoord[] waypoints;   // 格心序列（起点剔除，末点=目标或最近可达点）
    public int version;             // 失效检测用
    public bool reachedExactGoal;   // false=Partial/最近可达
}

public struct PathRequest
{
    public int requesterId;         // 单位实例 ID（取消/去重用）
    public GridCoord from, to;
    public byte priority;           // 0=最高；君主相关/战斗追击高，游荡低
    public IFactionWalkOverlay overlay;  // D3 预留，默认 null=全员一致
}
```

### 5.3 PathfindingService API 总表

| API | 说明 |
|-----|------|
| `PathTicket RequestPath(PathRequest, Action<PathResult> onDone)` | 异步主入口；同 requester 重复请求自动取消旧票据 |
| `PathResult FindPathImmediate(GridCoord from, GridCoord to)` | 同步版（调试/sim/短距）；受 N2 展开上限约束 |
| `bool IsReachable(GridCoord from, GridCoord to)` | 连通性查询（流场/区域 id 缓存加速，F6） |
| `FlowFieldHandle RegisterFlowGoal(GridCoord goal, Faction faction)` | 注册流场目标（≤N4）；同目标复用 |
| `void UnregisterFlowGoal(FlowFieldHandle)` | 释放 |
| `Vector2 SampleFlowDirection(FlowFieldHandle, Vector2 worldPos)` | 单位采样移动方向（跟随层用） |
| `void CancelAll(int requesterId)` | 单位死亡/任务打断 |

**分帧调度**：每帧预算内依次处理队列（优先级排序）；A* 单请求耗时分片——展开达帧预算即挂起下帧继续（N1/N7 的落实机制）。

**失效订阅**：`WalkabilityChangedEvent(rect)` → ①流场：rect 与场相交则标记重积（帧预算内局部 BFS 修补，全量兜底）②路径缓存：本文档不做全局路径缓存（单位自持路径），由 PathFollower 检测下一路径点阻挡触发重请求（R1 冷却防抖）。

### 5.4 A* 设计要点

- 邻居：8 向，顺序固定 E/NE/N/NW/W/SW/S/SE（doc 1 契约）；斜走校验 `IsDiagonalMoveAllowed`（禁穿角，R4）
- 代价：`enterCost(to)`（地形代价表，SO）×（斜走 √2）；启发 =  Octile 距离 × 最小地形代价（可采纳，不超估）
- 开放列表：二叉堆；平局裁决 `f 相同 → 节点索引小者优先`（确定性 R3）
- 早停：弹目标即返；展开达 N2 上限 → 返回"最接近目标点"的部分路径（status=Partial，R7）
- 不可达：开放列表耗尽 → 沿闭合集取 h 最小节点为最近可达点（F5）

### 5.5 流场设计要点

- 积分场：`ushort[] integration`（W×H，目标=0，BFS 按 enterCost 累加，65535=不可达）
- 方向场：`byte[] direction`（W×H，指向积分最低邻居的方向编码 0~7）
- 构建：全量 BFS ≤ N3；增量修补：dirtyRect 扩 1 圈局部重积，污染超 1/3 场面积则全量
- 共享：`FlowGoalKey = (goalChunk, faction, overlayId)` 聚合——同区块同阵营同覆盖层共享一场（R5）
- 单位使用：PathFollower 持有 handle 时直接采样方向场，**不走 A***——敌潮 200 单位零寻路请求（N5 达成路径）

### 5.6 确定性保障（与 sim 对拍的纪律）

1. Pathfinding.Core 禁 `using UnityEngine`；坐标用 `Vector2IntX`，数学用 `MathfX`（AI.Core 已有 shim）
2. 禁字典遍历序参与结果（全数组+显式索引）；禁 `GetHashCode` 排序；禁 `System.Random`（随机源由调用方注入种子）
3. 浮点仅用于代价累加且顺序固定；不跨平台编译差异点（不用 `Math.Sqrt` 于热路径——√2 走常量）
4. sim 侧 goldenReplay 用例：固定种子地图 + 固定请求序列 → 路径哈希一致（验收 #5）

### 5.7 PathFollower 组件设计

| 成员 | 说明 |
|------|------|
| `SetDestination(Vector2 worldPos, byte priority)` | 内部转 GridCoord 发请求；持流场 handle 时改采样模式 |
| `SetFlowGoal(FlowFieldHandle)` / `ClearFlowGoal()` | 流场模式切换 |
| `Stop()` | 取消票据+清空路径 |
| 跟随循环 | 朝当前路径点 `MoveTowards` → 进到达半径（SO，默认 0.3×cellSize）→ 下一点；末点精确到达 |
| 失效检测 | 下一路径点 `IsWalkable==false` → R1 冷却后重请求；连续 3 次失败 → 上报 `PathFailedEvent`（AI 换目标） |
| 分离转向 | 采样 3×3 邻格同阵营单位，叠加分离向量（D4，参数归 doc 5） |
| LOD 接口 | `SetLodTier(int)`：低档降采样频率/跳格跟随（doc 7 调） |

### 5.8 SO 配置（PathfindingConfig）

| 字段 | 默认 | 说明 |
|------|------|------|
| maxExpansionsPerRequest | 4096 | N2 |
| maxAStarCompletionsPerFrame | 4 | N1 |
| maxActiveFlowFields | 8 | N4 |
| flowRebuildsPerFrame | 1 | N3 |

- 路径模式：选中单位画路径折线（绿=Ready，黄=Partial，红=Unreachable）
- 流场模式：每 Chunk 画方向箭头（编辑器 Gizmos，可关）
- A* 热力：闭合集染色（单次请求调试用）

### 5.10 实施任务拆分

**P0（阶段 0 切片必须）**
1. Pathfinding.Core 程序集 + BinaryHeap + AStarSolver（含禁穿角/部分路径/不可达）
2. PathfindingService 请求队列+分帧调度

4. GridSystem `IPathGrid` 对接 + `WalkabilityChangedEvent`（doc 1 追加项）

8. 路径平滑（视线拉直，D2）
9. 调试可视化三件套

**P2（阶段 4）**

11. sim 侧接入 + goldenReplay 路径哈希对拍

### 5.11 验收标准

1. 空图 256²：对角寻路 P50 完成延迟 ≤ 3 帧；200 并发请求不卡帧（帧耗 ≤ 2ms）
2. U 型围墙：单位正确绕行；封死围墙：返回 Unreachable + 最近可达点
3. 破墙测试：墙倒 → 受影响单位 ≤ 1s+1 帧内走上新路径，无风暴卡顿
4. 流场：200 敌人注册同一攻城目标，寻路请求数 = 0（纯采样），帧耗 ≤ 1ms
5. 确定性：sim 固定种子 1000 次混合请求，路径哈希与 Unity 侧一致
6. 禁穿角：两墙对角夹缝不可斜穿
