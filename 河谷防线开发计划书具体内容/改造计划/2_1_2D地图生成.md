## 一、老系统与新系统的衔接

### 1.1 1D → 2D 生成管线对比

| 维度   | 老（1D）                    | 新（2D）                     |
| ---- | ------------------------ | ------------------------- |
| 世界   | 1D 线段，多岛屿多地图             | 2D 单块大陆，四周海洋              |
| 地形单元 | 大区块=一种地形（Forest/Quarry…） | 大区块=**温度带**（热带/亚热带/温带/寒带） |
| 内部结构 | 大区块内 16 格同地形             | 大区块内**特征物**填充，空格=该带平原     |
| 出生   | 固定中心废弃城堡                 | 随机出生点（文明6式）+ AI 王国        |
| 出怪   | 裂隙在线段两端                  | 威胁刷点（SpawnDef）近王国视野外      |
| 资源   | 结构保证（5 区必有）              | 后置校验（就近补）+ 局部放宽           |

### 1.2 可复用 / 作废清单

**可复用**（与维度无关）：

- 种子确定性 + `System.Random` 注入（训练同源基础）
- `MapGenRules` 权重随机、`MapValidator` 校验概念、`RollGrade` 等级滚动
- 一次性资源点（石堆/木堆/矿脉）生成逻辑——放宽后复用

**作废**（1D 强假设）：

- `5 区 MapZone`（LeftExtreme→RightExtreme）、`BigTerrain`(Island/Inland)、`Region` 作为地形单元
- `originX` 居中（改地图中心原点，见 doc 1 §5.2）
- 裂隙放线段两端

### 1.3 MapData 契约（2D，doc 1 §5.5 扩展）

```csharp
public class MapData
{
    public int mapId;                 // 恒 0（单图）
    public int seed;                  // 确定性
    public int width, height;         // 格数（128/256/384）
    public ClimateZone[] climateZones; // 温度带，**按大区块 16×16 存**（256²=16×16=256 条）；每格由 chunk 坐标查所属带，不逐格冗余
    public FeatureType[] features;     // 小区块特征物（山/雪/水/树/矿/平原）——**唯一功能源**，可走/阻挡由此派生
    public List<Vector2Int> kingdomSpawns;  // 王国出生点（0=玩家，1..N=AI，与难度挂钩）
    public List<SpawnDef> threatSpawns;     // 威胁刷点（近王国视野外）
    public List<NaturalBuilding> naturalBuildings; // 自然建筑占位（**由 features 派生**的视觉层，供 2_2 实例化）
    // 冻结遗留：isPlayerHome / isConquered / bigTerrain（删）
}
```

> **与 doc 1 的对接（2026-08-12 钉死）**：`features` 为唯一功能源；`GridSystem.PopulateFromMap` 读 `features` 派生 `terrain / plainSub / walkFlags`（实体映射见 §5.1 映射表）。`naturalBuildings` 同样是 `features` 派生的视觉层，供 2\_2 实例化，**不反向影响可走性**。

## 三、新系统的需求讨论（已收敛决策）

### 3.1 四级区块（2026-08-13 升级：3 级 → 4 级，新增微格）

> **尺寸变更（2026-08-13）**：逻辑小区块 = **1.28×0.64 世界单位（= 1 个 Tile）**，推翻旧 cellSize 2.26。等轴渲染 Tile 参数：`Isometric Z As Y, Cell Size X=1.28 Y=0.64 Z=1, Sort Axis X=0 Y=1 Z=-0.25`。**逻辑格是方形，等轴换算只在渲染层**（寻路/AI 用方形格）。

| 层级 | 尺寸 | 用途 |
|------|:---:|------|
| 大区块 | 16×16 小区块 | **温度带**、地图生成单位、Chunk 级事件 |
| 中区块 | 4×4 小区块 | LOD 半活跃、成本场增量、热度聚合、编队槽位组 |
| 小区块 Cell | 1×1 = **1.28×0.64**（1 Tile） | 建筑 footprint、单位落点、视觉对齐 Tile |
| **微格 SubCell** | 小区块 ÷ 4 = **0.32×0.16** | **寻路节点、跨格地形精确阻挡、NPC 精确避障** |

> **区块索引锚定约定**：中/大区块由格子坐标整数除法推导，锚定 (0,0)：中区块 = `(x/4,y/4)`、大区块 = `(x/16,y/16)`；微格 = 小区块 ÷ 4，微格坐标 = `(gx*4+subx, gy*4+suby)`。每格唯一归属，无重复/重叠/残块（地图尺寸为 4 和 16 的倍数）。推导是纯函数，确定性。

> **跨格/自由建造终极解法（2026-08-13）**：任何建筑/地形（自然/人造、可跨格任意形状）——
> - **逻辑 footprint**：在小区块级声明整数格矩形（如雪山=2×2 小区块）
> - **拆微格**：footprint 内每小区块拆成 4×4=16 微格，**逐微格判定可走/阻挡**（按实际覆盖，超半格即阻挡）
> - **寻路在微格上算** → 精确绕开任意形状/跨格对象，无边界撕裂、无"半格"模糊
> - 视觉形状可自由伸出 footprint 之外，**不影响逻辑**（双层：逻辑 footprint + 视觉形状）
>
> **举例**：雪山占 2×2 小区块 → 拆 64 微格 → 逐微格阻挡 → 寻路微格级绕开。NPC 约 1 微格，微格级避障贴合。

### 3.2 温度带模型（本片核心）

- **大区块属性 = 温度带**（4 种：热带/亚热带/温带/寒带），用颜色区分，**散乱分布不按纬度**
- 大区块内部 = 该温度带的**特征物**按密度填充；**空格 = 该带平原**（可走）
- **功能由小区块特征物决定**，不再是"大区块地形类型"
- 相邻大区块温度带不同 → 边界特征物自然过渡（视觉，不改属性）

> **关键语义（2026-08-12 钉死，避免误读）**：温度带只是**大区块的配色/气候属性，不是可走层**。一个大区块内部仍由**小区块特征物逐个决定可走性**——"寒带大区块" ≠ 整块不可走，只是其中约 45% 的小区块是雪山/山地（阻挡）、其余 \~55% 仍为可走的平原/树/矿，且**散点分布、非整片封锁**。可走性只看小区块特征物（§3.3），与温度带身份无关。

### 3.3 特征物表（按温度带）

| 特征物         |  阻挡 | 功能     |  热带 | 亚热带 |  温带 |  寒带 |
| ----------- | :-: | ------ | :-: | :-: | :-: | :-: |
| 平原(空格)      |  否  | 可走/可建  | 60% | 55% | 45% | 35% |
| 树(阔叶/针叶/棕榈) |  否  | **一次性木（可刷新）** | 20% | 20% | 20% |  5% |
| 山地          |  是  | 阻挡     |  5% | 10% | 15% | 10% |
| 雪山          |  是  | 阻挡     |  0% |  2% |  5% | 35% |
| 矿洞 Mine     |  否  | 石(需争夺) |  5% |  8% | 10% |  5% |
| 矿脉/石堆/木堆    |  否  | 一次性资源（矿脉:石堆:木堆=4:3:3，占位 D257）  |  中  |  中  |  中  |  少  |
| 河流/湖泊       |  是  | 阻挡+水景  | 10% |  5% |  5% |  冰河（湖/河均视觉变体，D257） |
| 海洋          |  是  | 地图边缘环绕 |  —  |  —  |  —  |  —  |

> **木材来源唯一性（2026-08-13 变更）**：**木头 = 只有一次性树木**。树（Tree）= 采集后消失的一次性资源，采完**延迟刷新**（7 天（占位，D257）在原坑位/附近再长出新树，SO `treeRespawnDays=7` 可调），**没有可持续的伐木场**。全库木材口径：`Tree`（可刷新）+ `WoodPile`（纯一次性）两种来源，均为"砍了才给木"，木材存量随砍随减、无自动再增长。

> **可走性平衡（2026-08-13 审计按表实算订正）**：阻挡 = 山地+雪山+水，按小区块计、散点分布非整片。按 §3.3 表实算：热带 ~85%、亚热带 ~83%、温带 ~75%、**寒带 ~45%**（平原 35+树 5+矿洞 5），4 带等权全图约 **~72%**——以本实算为准（旧声明"寒带 ≥55%/全图 75~80%"与密度表不符，已订正）。可走性由 §5.1 映射决定，与温度带身份无关。

### 3.4 资源模型

- **一次性资源**（矿脉/石堆/木堆）：近出生点**放宽**——种类、数量更多，捡了就走
- **树（Tree）**：一次性采集，采完延迟刷新（**7 天（占位，D257）**后在原坑位或附近 1 格内再长新树，SO `treeRespawnDays=7`），**木头的唯一持续来源**。伐木场（lumbermill）**作废**，无可持续木材产能建筑
- **可持续矿洞**（Mine）：**需派兵争夺**，战术目标，温带最多。注：矿洞可走；`Locked` 仅在有单位采集时临时置位防抢采，采集完释放（D270）——未采集时可走可争夺（2026-08-14 终审修订）
- 资源不再是"大区块类型保证"，而是**特征物 + 后置校验**保证

> **资源摆放密度（2026-08-13 定稿，2026-08-14 审查修订）**：
> - **一格 4 资源**：每个逻辑 Cell（1×1）细分 **2×2 子坑位**，每坑位 = **0.5×0.5 小区块（2×2 微格）**，每个坑位放一个资源，一个 Cell 最多 4 个资源
> - **资源底座实测（2026-08-14，D36）**：**树 = 1 微格（0.32×0.16）**；**石头/矿石 = 2×2 微格（0.64×0.32）**（正好填满一坑位）；**矿洞 = 2×2 小区块（4 格）**；**地形地皮 = 1 小区块（16 微格）**。坑位 2×2 微格正好装下石头/矿石，树占 1 微格有余量
> - **防重复**：坑位是格内固定偏移（非独立随机坐标），**每坑位至多放一个** → 天然不重复、不重叠
> - **密度（D39 修订，2026-08-14 终审修订 D257）**：每大区块（256 Cell × 4 坑位 = 1024 坑位）放 **基准 60 个资源/大区块**，难度系数 **Easy=0.7（42 个）/ Normal=1.0（60 个）/ Hard=1.3（78 个）（占位，D257）**（SO `resourcesPerChunkBase` + difficulty 系数）；不挤占可走面积
> - **可走性**：有资源的坑位仍可走（资源可采不阻挡），同格 4 资源共享一个可走 Cell
> - **footprint 订正**：原稿"每资源 footprint 1×1"与一格 4 坑位矛盾，订正为 **0.5×0.5 小区块**；锁格（Locked）按坑位粒度写入

### 3.5 连通性

- 大区块不隔断；可走特征物**不允许被阻挡全包围**（无封闭口袋）
- **岛屿可隔断**（水隔离）；雪山可在单格/中区块级阻断
- 生成后 flood-fill 校验：所有出生点/主要资源区与彼此连通；孤立 → 打通走廊

### 3.6 水域

- **海洋环绕地图边缘**（单大陆）
- 内陆**湖泊 + 河流**（特征物，可走性阻挡）

> **河流地块系统（2026-08-13 定稿，耦合式 RuleTile 铺设）**——河流用**地块变体**（连接方向集）表示，用 **RuleTile** 根据相邻水格**自动选对地块/朝向**，根治"弯曲地块引用错误"：
>
> | 地块 | 连接方向 | 用途 |
> |------|---------|------|
> | `river_straight_V` | 上+下 | 垂直直道 |
> | `river_straight_H` | 左+右 | 水平直道 |
> | `river_corner_NW/NE/SW/SE` | 双向转弯 | L 型转弯 |
> | `river_end` | 单向 | 源头/出口 |
>
> **决策（2026-08-13）**：**不做分支** → 无 T 型/十字地块（工作量减半）；河流只有直道+转角+源头/出口。
>
> **生成规则**：按地图大小 **1~3 条主干河**（128²=1、256²=2、384²=3），各不相交；源头=地图边缘（山/高地）、注入=另一边缘海洋或大湖（有来有去）；转弯之间隔 2~3 格直道；绕行特殊地形（不穿雪地/湖泊，沿边界走）；**自然河流不做十字路口**。
>
> **可走性**：河流=**阻挡**（不可走/不可建/不可采），单位绕行；**可造桥过河**（桥=人造建筑，跨河格子，归 2_2 建筑系统）。
> - 寒带湖泊与河流均为**冰河**（视觉变体，D257）（2026-08-14 终审修订，原"仅湖泊为冰河"）

### 3.7 出生点 · 难度

- **难度定 AI 数**：Easy=玩家+1AI / Normal=+2 / Hard=+3
- 出生点**间距下限**保证公平（SO 可配）
- **随机出生，不保平原**（文明6式）

### 3.8 威胁刷点（SpawnDef）

- 近王国出生点、**玩家视野外**刷
- 有居民/设施的区域（对外）也可刷夜袭
- 写入 `MapData.threatSpawns`，夜晚怪袭用；**王国战推迟到阶段 4 后**，SpawnDef.faction 的 AI 王国值仅预留（总计划审计决策）

## 五、要开发的新系统（详细设计）

### 5.1 数据结构

```csharp
public enum ClimateZone { Tropical, Subtropical, Temperate, Cold }  // 温度带

public enum FeatureType  // 小区块特征物（功能层）
{
    Plain,             // 可走/可建
    Tree,              // 一次性木（可刷新，无伐木场）
    Mountain,          // 阻挡
    SnowMountain,      // 阻挡
    Mine,              // 矿洞（石，需争夺）
    OreVein, StonePile, WoodPile,  // 一次性资源
    River, Lake, Ocean,            // 水（阻挡）
}

public class NaturalBuilding  // 自然建筑占位（**features 派生的视觉层**，供 2_2 实例化）
{
    public int cellX, cellY;        // 落点（2×2 建筑取左上）
    public int w, h;                // 默认 1×1；仅 Mine/大型岩石等特殊特征物可升 2×2
    public FeatureType feature;     // 对应特征物
    public ClimateZone climate;     // 所属温度带（决定美术变体）
    public string artId;            // 美术资源 id（占位，见六）
}
```

> **2×2 特征物的 features 表示（2026-08-13 审计补充）**：`features` 是逐格数组，2×2 特征物（矿洞/大型岩石）用**主格+副格同值**表示——主格 = footprint 左上格，副格（其余 3 格）写同一 `FeatureType`；可走/阻挡派生逐格生效（2×2 阻挡即 4 格全阻挡）；`naturalBuildings` 只从主格派生一条记录（w=2,h=2），避免重复实例化。

**FeatureType → 网格层派生映射（`PopulateFromMap`** **用，features 为唯一源）**

| FeatureType                | TerrainType | WalkFlags                           | IsObstacle | 说明    |
| -------------------------- | ----------- | ----------------------------------- | :--------: | ----- |
| Plain                      | Plain       | TerrainWalkable                     |      否     | 可走/可建 |
| Tree                       | Forest      | TerrainWalkable                     |      否     | 一次性木（采完延迟刷新） |
| Mountain                   | Mountain    | —                                   |      是     | 阻挡    |
| SnowMountain               | Snow        | —                                   |      是     | 阻挡    |
| Mine                       | Quarry      | TerrainWalkable（Locked 由 2_2/2_7 置） |      否     | 需争夺   |
| OreVein/StonePile/WoodPile | 对应地皮        | TerrainWalkable（Locked）             |      否     | 一次性资源 |
| River                      | River       | Water                               |      是     | 阻挡+水景 |
| Lake                       | Lake        | Water                               |      是     | 阻挡+水景 |
| Ocean                      | Ocean       | Water                               |      是     | 边缘环绕  |

> TerrainType 取值随气候带地皮（美术资源规范/2_10 正式素材）最终订定；映射只保证"可走判定"（`TerrainWalkable` 置位且 Water/Locked/BuildingBlocked 均未置）与 doc 1 §5.1 规则一致。`naturalBuildings` 由 features 派生，默认 1×1，**不反向改可走**。

### 5.2 生成管线（六步）

```
1. 大区块温度带权重随机铺（16×16，4 带等概率占位，单大陆）
2. 特征物按密度填充（本片核心）：每温度带按 climateFeatures 密度灌小区块特征物，空格=该带平原；climateZones **按大区块存储**（每格归属由 chunk 坐标查带派生，不逐格冗余，§1.3）
3. 随机放置王国出生点（难度定 AI 数，间距下限，落可走格，否则就近找可走格）
4. 后置校验① 资源：近出生点缺木/石/矿/农田 → 就地补特征物 / 放宽一次性资源
5. 后置校验② 连通性：flood-fill，可走不得全包围，孤立 → 打通走廊
6. 放置威胁刷点（SpawnDef）+ 海洋边缘 + 湖泊河流 + 派生 naturalBuildings；**水域放置后必须复跑连通性校验**（河流阻挡可能切断出生点，发现切断 → 打通走廊或改道，2026-08-13 审计补充）
```

**确定性**：步骤 1\~6 全部用同一 `System.Random(seed)`，同 seed 同图（训练同源）。
