## 一、老系统与新系统的衔接

### 1.1 1D → 2D 生成管线对比

| 维度 | 老（1D） | 新（2D） |
|------|---------|---------|
| 世界 | 1D 线段，多岛屿多地图 | 2D 单块大陆，四周海洋 |
| 地形单元 | 大区块=一种地形（Forest/Quarry…） | 大区块=**温度带**（热带/亚热带/温带/寒带） |
| 内部结构 | 大区块内 16 格同地形 | 大区块内**特征物**填充，空格=该带平原 |
| 出生 | 固定中心废弃城堡 | 随机出生点（文明6式）+ AI 王国 |
| 出怪 | 裂隙在线段两端 | 威胁刷点（SpawnDef）近王国视野外 |
| 资源 | 结构保证（5 区必有） | 后置校验（就近补）+ 局部放宽 |

### 1.2 可复用 / 作废清单

**可复用**（与维度无关）：
- 种子确定性 + `System.Random` 注入（训练同源基础）
- `MapGenRules` 权重随机、`MapValidator` 校验概念、`RollGrade` 等级滚动
- 一次性资源点（石堆/木堆/矿脉）生成逻辑——放宽后复用

**作废**（1D 强假设）：
- `5 区 MapZone`（LeftExtreme→RightExtreme）、`BigTerrain`(Island/Inland)、`Region` 作为地形单元
- `originX` 居中（改地图中心原点，见 doc 1 §5.2）
- 裂隙放线段两端

### 1.3 MapData 契约（2D，doc 1 §5.5 扩展）

```csharp
public class MapData
{
    public int mapId;                 // 恒 0（单图）
    public int seed;                  // 确定性
    public int width, height;         // 格数（128/256/384）
    public ClimateZone[] climateZones; // 温度带，**按大区块 16×16 存**（256²=16×16=256 条）；每格由 chunk 坐标查所属带，不逐格冗余
    public FeatureType[] features;     // 小区块特征物（山/雪/水/树/矿/平原）——**唯一功能源**，可走/阻挡由此派生
    public List<Vector2Int> kingdomSpawns;  // 王国出生点（0=玩家，1..N=AI，与难度挂钩）
    public List<SpawnDef> threatSpawns;     // 威胁刷点（近王国视野外）
    public List<NaturalBuilding> naturalBuildings; // 自然建筑占位（**由 features 派生**的视觉层，供 2_2 实例化）
    // 冻结遗留：isPlayerHome / isConquered / bigTerrain（删）
}
```

> **与 doc 1 的对接（2026-08-12 钉死）**：`features` 为唯一功能源；`GridSystem.PopulateFromMap` 读 `features` 派生 `terrain / plainSub / walkFlags`（实体映射见 §5.1 映射表）。`naturalBuildings` 同样是 `features` 派生的视觉层，供 2_2 实例化，**不反向影响可走性**。

## 二、老系统的改造

| 文件 | 改造 |
|------|------|
| `WorldManager.GenerateMap` | 1D region 管线 → 2D 温度带管线（§五生成步骤） |
| `MapGenRules` | 5 区/邻接 → 2D 温度带权重铺 + 后置校验函数 |

| `GridSystem.PopulateFromMap` | 读 MapData 宽高 + 地形灌格（doc 1 已定） |
| `MapPreviewer` | 从"1D 条带预览"改"2D 温度带色块 + 特征物预览" |

本文档不实例化 Building（归 2_2），只产出 `MapData` + `naturalBuildings` 占位。

## 三、新系统的需求讨论（已收敛决策）

### 3.1 三级区块

| 区块 | 尺寸 | 用途 |
|------|------|------|
| 小区块 Cell | 1×1（2.26 单位） | 单位落点、寻路节点、建筑 footprint(1×1/2×2) |
| 中区块 MidChunk | 4×4=16 格 | 成本场增量、LOD 半活跃、热度聚合、编队槽位组 |
| 大区块 | 16×16=256 格（4×4 中区块） | **温度带单元**、地图生成单位、Chunk 级事件 |

> **区块索引锚定约定（2026-08-13 补充，消除歧义）**：中区块/大区块**不独立存储**，而是由格子坐标**整数除法推导**，锚定在格子原点 (0,0)：
> ```
> 中区块 = (x/4,  y/4)     // floor 整除
> 大区块 = (x/16, y/16)
> ```
> 每个格子**唯一**归属一个中区块/大区块 → 天然不重复、不重叠、无空洞。地图尺寸 128/256/384 均为 4 和 16 的倍数 → 整除无余数，无边界残块。推导是纯函数，与温度带/特征物无关，全程确定性。

### 3.2 温度带模型（本片核心）

- **大区块属性 = 温度带**（4 种：热带/亚热带/温带/寒带），用颜色区分，**散乱分布不按纬度**
- 大区块内部 = 该温度带的**特征物**按密度填充；**空格 = 该带平原**（可走）
- **功能由小区块特征物决定**，不再是"大区块地形类型"
- 相邻大区块温度带不同 → 边界特征物自然过渡（视觉，不改属性）

> **关键语义（2026-08-12 钉死，避免误读）**：温度带只是**大区块的配色/气候属性，不是可走层**。一个大区块内部仍由**小区块特征物逐个决定可走性**——"寒带大区块" ≠ 整块不可走，只是其中约 45% 的小区块是雪山/山地（阻挡）、其余 ~55% 仍为可走的平原/树/矿，且**散点分布、非整片封锁**。可走性只看小区块特征物（§3.3），与温度带身份无关。

### 3.3 特征物表（按温度带）

| 特征物 | 阻挡 | 功能 | 热带 | 亚热带 | 温带 | 寒带 |
|--------|:---:|------|:---:|:---:|:---:|:---:|
| 平原(空格) | 否 | 可走/可建 | 60% | 55% | 45% | 35% |
| 树(阔叶/针叶/棕榈) | 否 | 可采木 | 20% | 20% | 20% | 5% |
| 山地 | 是 | 阻挡 | 5% | 10% | 15% | 10% |
| 雪山 | 是 | 阻挡 | 0% | 2% | 5% | 35% |
| 矿洞 Mine | 否 | 石(需争夺) | 5% | 8% | 10% | 5% |
| 矿脉/石堆/木堆 | 否 | 一次性资源 | 中 | 中 | 中 | 少 |
| 河流/湖泊 | 是 | 阻挡+水景 | 10% | 5% | 5% | 冰河 |
| 海洋 | 是 | 地图边缘环绕 | — | — | — | — |

> **可走性平衡（2026-08-12 校订）**：阻挡 = 山地+雪山+水，按小区块计、散点分布非整片。4 带等权合并后全图可走约 **75~80%**（寒带内最低约 55%）——寒带雪山多但散置，靠其他带稀释可压低整体，但达不到"可走 90%"；以本修正为准。可走性由 §5.1 映射决定，与温度带身份无关。

### 3.4 资源模型

- **一次性资源**（矿脉/石堆/木堆）：近出生点**放宽**——种类、数量更多，捡了就走
- **可持续矿洞**（Mine）：**需派兵争夺**，战术目标，温带最多
- 资源不再是"大区块类型保证"，而是**特征物 + 后置校验**保证

### 3.5 连通性

- 大区块不隔断；可走特征物**不允许被阻挡全包围**（无封闭口袋）
- **岛屿可隔断**（水隔离）；雪山可在单格/中区块级阻断
- 生成后 flood-fill 校验：所有出生点/主要资源区与彼此连通；孤立 → 打通走廊

### 3.6 水域

- **海洋环绕地图边缘**（单大陆）
- 内陆**湖泊 + 河流**（特征物，可走性阻挡）
- 寒带湖泊为**冰河**（视觉）

### 3.7 出生点 · 难度

- **难度定 AI 数**：Easy=玩家+1AI / Normal=+2 / Hard=+3
- 出生点**间距下限**保证公平（SO 可配）
- **随机出生，不保平原**（文明6式）

### 3.8 威胁刷点（SpawnDef）

- 近王国出生点、**玩家视野外**刷
- 有居民/设施的区域（对外）也可刷夜袭
- 写入 `MapData.threatSpawns`，白昼王国战/夜晚怪场均用

### 3.9 待定项（不阻塞实施）

| # | 待定 | 说明 |
|---|------|------|
| D1 | 温度带精确权重 | 当前 4 带等概率，可调 |
| D2 | 出生点与地图大小关系 | 大图是否更多 AI/更远间距 |
| D3 | 河流生成算法 | 噪声带状 vs 手绕干流分支 |
| D4 | 雪山是否可走 | 当前阻挡，可作"可走高代价"备选 |

## 四、新系统可能遇到的问题

| # | 风险 | 对策 |
|---|------|------|
| R1 | 随机出生后资源不足 | 就近补资源后置校验（§5.2 步骤 3） |
| R2 | 可走地块被包围成死区 | flood-fill + 打通走廊（§5.2 步骤 4） |
| R3 | 温度带边界视觉突兀 | 边界特征物过渡 + Gizmos 调色 |

| R6 | 挡住出生点（Civ6 出生在雪山/水中） | 出生点校验：必须落在可走特征物上，否则就近找可走格 |

## 五、要开发的新系统（详细设计）

### 5.1 数据结构

```csharp
public enum ClimateZone { Tropical, Subtropical, Temperate, Cold }  // 温度带

public enum FeatureType  // 小区块特征物（功能层）
{
    Plain,             // 可走/可建
    Tree,              // 可采木（视觉取温度带对应树）
    Mountain,          // 阻挡
    SnowMountain,      // 阻挡
    Mine,              // 矿洞（石，需争夺）
    OreVein, StonePile, WoodPile,  // 一次性资源
    River, Lake, Ocean,            // 水（阻挡）
}

public class NaturalBuilding  // 自然建筑占位（**features 派生的视觉层**，供 2_2 实例化）
{
    public int cellX, cellY;        // 落点（2×2 建筑取左上）
    public int w, h;                // 默认 1×1；仅 Mine/大型岩石等特殊特征物可升 2×2
    public FeatureType feature;     // 对应特征物
    public ClimateZone climate;     // 所属温度带（决定美术变体）
    public string artId;            // 美术资源 id（占位，见六）
}
```

**FeatureType → 网格层派生映射（`PopulateFromMap` 用，features 为唯一源）**

| FeatureType | TerrainType | WalkFlags | IsObstacle | 说明 |
|-------------|------------|-----------|:---:|------|
| Plain | Plain | TerrainWalkable | 否 | 可走/可建 |
| Tree | Forest | TerrainWalkable | 否 | 可采木 |
| Mountain | Mountain | — | 是 | 阻挡 |
| SnowMountain | Snow | — | 是 | 阻挡 |
| Mine | Quarry | TerrainWalkable（Locked 由 doc 6/7 置） | 否 | 需争夺 |
| OreVein/StonePile/WoodPile | 对应地皮 | TerrainWalkable（Locked） | 否 | 一次性资源 |
| River | River | Water | 是 | 阻挡+水景 |
| Lake | Lake | Water | 是 | 阻挡+水景 |
| Ocean | Ocean | Water | 是 | 边缘环绕 |

> TerrainType 取值随 doc 3 气候带地皮最终订定；映射只保证"可走判定"（`TerrainWalkable` 置位且 Water/Locked/BuildingBlocked 均未置）与 doc 1 §5.1 规则一致。`naturalBuildings` 由 features 派生，默认 1×1，**不反向改可走**。

### 5.2 生成管线（六步）

```
1. 大区块温度带权重随机铺（16×16，4 带等概率占位，单大陆）
2. 特征物按密度填充（本片核心）：每温度带按 climateFeatures 密度灌小区块特征物，空格=该带平原；climateZones 派生为逐格归属
3. 随机放置王国出生点（难度定 AI 数，间距下限，落可走格，否则就近找可走格）
4. 后置校验① 资源：近出生点缺木/石/矿/农田 → 就地补特征物 / 放宽一次性资源
5. 后置校验② 连通性：flood-fill，可走不得全包围，孤立 → 打通走廊
6. 放置威胁刷点（SpawnDef）+ 海洋边缘 + 湖泊河流 + 派生 naturalBuildings
```

**确定性**：步骤 1~6 全部用同一 `System.Random(seed)`，同 seed 同图（训练同源）。

### 5.3 SO 配置（MapGenRulesConfig 2D 版）

| 字段 | 默认 | 说明 |
|------|------|------|
| climateWeights | 4 带等概率 | 温度带分布权重 |
| climateFeatures[4] | 见 §3.3 表 | 每带特征物密度 |
| aiKingdomByDifficulty | {1,2,3} | Easy/Normal/Hard 的 AI 数 |
| spawnMinDistanceCells | 可配 | 出生点间距下限 |
| resourceGuaranteeRadius | 3 大区块 | 就近补资源半径 |
| connectivityThreshold | — | 连通性校验阈值 |

### 5.4 温度带配色（Gizmos/data）

| 温度带 | 主色 |
|--------|------|
| 热带 | 暖黄绿 |
| 亚热带 | 绿 |
| 温带 | 黄绿/褐 |
| 寒带 | 蓝白 |

### 5.5 冒烟验证 / 验收

1. 空场景生成 256² → Gizmos 看温度带色块清晰、出生点/威胁点可见
2. 每个王国出生点 3 大区块内能找到木/石/矿/农田
3. flood-fill 无孤立可走地块；出生点不在阻挡格
4. 同 seed 两次生成逐格一致（确定性）
5. 256² 初始化 < 100ms

### 5.6 实施任务拆分

- **P0**：ClimateZone/FeatureType 枚举、温度带权重铺、特征物填充、**FeatureType→网格层派生映射（PopulateFromMap）**、climateZones 按大区块装配、出生点放置、naturalBuildings 生成、MapData 装配
- **P1**：后置校验（资源就近补 + 连通性 flood-fill）、海洋边缘/湖泊河流、威胁刷点
- **P2**：Gizmos 温度带可视化、性能回归、出生点间距调优

### 6.0 全局规格（2026-08-13 定稿）

- **瓦片形态：等轴菱形（Isometric diamond tile）**，宽:高 = **2:1（64×32）**
