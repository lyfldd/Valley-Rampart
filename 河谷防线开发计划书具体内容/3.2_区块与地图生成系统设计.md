## 一、整体架构：五层结构

```
World（一局游戏，含多张地图）
  │  由 worldSeed 确定性生成
  │  含：玩家初始地图 + N 个敌方王国地图
  │  存档单位：WorldState
  ▼
Map（一张地图 = 一个岛屿/内陆）
  │  大地形类型（岛屿两边出怪 / 内陆一边出怪）
  │  含：M 个大区块（横向排列，M 由地图大小决定）
  │  存档单位：MapData
  ▼
Region（大区块 = 地形段）★ 本规范的核心补齐
  │  程序化生成的最小完整单位
  │  对应一种小地形（平原/林地/荒地/丘陵/矿山/肥沃/雪山）
  │  含：固定 N 个小区块 + 资源点
  │  存档单位：RegionData（地形靠 seed 复现，不存）
  ▼
Cell（小区块 = 单位堆叠最小单元）
  │  cellSize 像素宽（如 32px）
  │  含：堆叠上限 + 单位列表
  │  是战斗系统（堆叠/命中/排队）的最小粒度
  ▼
Layer（子层 = y 轴分层）
  │  地面层（y=0）：城墙/陷阱/地面单位
  │  空中层（y=1）：飞行兵/防空塔
```

### 1.1 与现有项目的关系

| 本规范概念 | 现有项目对应 | 改动 |
|-----------|-------------|------|
| World | 无 | 新增 `WorldState`，挂在 WorldManager |
| Map | 无（WorldManager 只有单 seed） | 新增 `MapData`，WorldManager 持有列表 |
| Region | 原 3.2 预留的空壳 `Region` struct | 落地为完整数据结构 |
| Cell | 原 3.2 的 `GridCell` | 保留设计，接入地图生成 |
| Layer | 原 3.2 的 GridCoord.y | 保留 |
| GridSystem | 原 3.2 的 `GridSystem` Singleton | 保留，新增"当前活跃地图"感知 |
| WorldManager | 现有，只存 2 个 int | 扩展为多地图世界管理器 |
| NewGameConfig | 现有 4 字段 | 加 `worldSize` + `worldSeed` |
| WorldConfig | 现有 SO | 加 `GridConfig` + `MapSizeConfig` 引用 |

### 1.2 关键设计决策

1. **1D 横向滚动**：大区块、小区块都是 1D（x 轴）横向排列，飞行兵用 y 层。不做 2D 网格（与现有 1D 设计一致）。
2. **大区块 = 地形段**：一个大区块对应一种小地形（如"平原大区块""林地大区块"），是地图生成的基本单位。
3. **大区块含固定小区块数**：每个大区块内部固定含 `regionCellCount` 个小区块（GridConfig 配，默认 8）。小区块数固定，地形分布变化。
4. **地图大小决定大区块数**：玩家选大/中/小 → 决定单张地图的大区块数 M。
5. **地形靠 seed 确定性复现**：存档不存地形数据，只存 seed，读档用同 seed 重生成（与现有 WorldManager 设计一致）。
6. **区块系统是无状态运行时索引**：GridSystem 不存档，单位存档后重新 TryEnter，状态自恢复（继承原 3.2 设计）。

## 三、区块层级详细设计

### 3.1 大区块 Region（地形段）

大区块是**程序化生成的基本单位**，每个大区块：
- 对应**一种小地形**（平原/林地/荒地/丘陵/矿山/肥沃/雪山，7 选 1）
- 内部含**固定 `regionCellCount` 个小区块**（横向排列，默认 8）
- 含**资源点**（树/矿洞/农田，按地形约束放置）
- 有一个 `regionIndex`（在地图内的横向索引，0..M-1）

```csharp
/// <summary>大区块：地形段，程序化生成基本单位。</summary>
public class Region
{
    public int regionIndex;              // 在地图内的索引（0..M-1）
    public TerrainType terrain;          // 小地形类型
    public PlainSubState plainSubState;  // 平原子状态（仅 terrain==Plain 时有效）
    public int cellStartX;               // 该大区块第一个小区块的全局 x 坐标
    public int cellCount;                // 含小区块数（= regionCellCount，固定）
    public List<ResourceNode> resources; // 资源点列表（二级约束生成，含等级）
    // TODO: 统一为 BuildingPlaceholder 体系后，resources → buildings
    // ResourceNode 将被 BuildingPlaceholder(含 category/type/grade) 替代
    public int riftCellX = -1;           // 裂隙所在小区块索引（-1=无裂隙/出怪口）
    public bool isEnemyTerritory;        // 是否敌方领土（敌方王国地图的区域标记）
}
```

### 3.2 小区块 Cell（堆叠单元）

小区块是**单位堆叠的最小单元**，保留原 3.2 设计：


### 3.3 子层 Layer

```csharp
public struct GridCoord
{
    public int x;  // 小区块全局列号（在当前活跃地图内）
    public int y;  // 0=地面, 1=空中
}
```

### 3.4 数量关系公式

```
regionCellCount = 16（GridConfig 配，固定）
大区块数 M     = worldSize 决定（Small=10 / Medium=15 / Large=24）
小区块总数     = M × regionCellCount
地图宽度(像素) = M × regionCellCount × cellSize
大区块 i 的起始小区块 x = i × regionCellCount
大区块 i 内的小区块局部 j 的全局 x = i × regionCellCount + j
```

**示例（中地图）**：
- M=10 大区块，每大区块 8 小区块 → 80 小区块
- cellSize=32px → 地图宽 2560px
- 大区块 #3（林地）覆盖小区块 x=24..31

## 四、地形系统

### 4.1 大地形类型（玩家/关卡决定，决定出怪方向）

| 大地形 | 出怪方向 | 资源倾向 | 用途 |
|--------|---------|---------|------|
| 岛屿 | 两边出怪 | 树多矿少 | 标准塔防，难度高 |
| 内陆 | 一边出怪（另一边大山屏障） | 资源均匀 | 难度低，经营向 |
| 无限关卡固定岛屿 | 两边出怪 | 稀疏 | 通关后无限模式 |

> **大地形由 worldSeed 确定性随机决定**（玩家不手选，UI 更简洁）。玩家初始地图与敌方王国地图的**大小均跟随玩家选的 worldSize**（敌方王国不固定较小，保持攻城规模与玩家经营规模对等）。敌方王国地图的大地形固定岛屿（攻城玩法需要两边出怪）。

### 4.2 小地形类型（对应大区块，7 种 + 平原 2 子状态）

| 小地形 | 子状态 | 对应美术资源（Art/TerrainTiles/） | 资源点倾向 | 出现条件 |
|--------|:---:|----------------------------------|-----------|---------|
| 平原 | 普通 | 平原.png | 建造开阔地，少量树 | 中心区/资源区 |
| | 肥沃 | 肥沃拓展.png | 农田位（农场依赖） | 中心区边缘/资源区 |
| 荒地 | — | 荒地，黄沙.png | 无资源，纯战场 | 内陆极端区（出怪侧） |
| 丘陵 | — | 丘陵.png | 矿洞开口 | 资源区/缓冲带 |
| 林地 | — | 林地.png | 树资源点（伐木场依赖） | 资源区 |
| 矿山 | — | 采石场矿山.png | 矿洞开口（采石场） | 资源区外侧 |
| 雪山 | — | 雪山.png | 无资源，高难度地形 | **仅内陆**大山屏障侧 |
| 海岸 | — | 海岸.png（待补美术） | 无资源，出海口+造船厂位 | **仅岛屿**两端 |

### 4.4 三层约束生成规则（沿用 2.0 设计 + 3.2.1 玩法约束补丁）

```
第1层 大地形（岛屿/内陆）← worldSeed + mapIndex 决定
  ├─ 岛屿 → 两边出怪，极端区=海岸（出海口+登陆滩头）
  └─ 内陆 → 一边出怪，极端区=雪山(大山屏障)+荒地(出怪侧)
第2层 小地形（大区块）← System.Random(worldSeed) 确定性生成
  ├─ 5 区结构：[极端区][资源区][中心区(主城)][资源区][极端区]
  ├─ 极端区按大地形固定（海岸/雪山/荒地），不随机
  ├─ 资源区内侧→林地/肥沃(低风险)，外侧→矿山/丘陵(高风险)
  └─ 邻接约束矩阵 + 资源保障校验（见 3.2.1）
第3层 资源点 ← 受小地形约束 + 风险分层
  ├─ 林地 → 树资源点（中风险，城墙边缘）
  ├─ 矿山/丘陵 → 矿洞开口（高风险，城墙外）
  ├─ 肥沃 → 农田位（低风险，城墙内）
  └─ 海岸 → 无资源（出海口+造船厂位）
```

> 三层约束规则用 ScriptableObject 配置（可调不改代码），见 [`3.2.1_地图生成约束规则与玩法保障.md`](3.2.1_地图生成约束规则与玩法保障.md) 第八节 `MapGenRulesConfig`。

## 五、地图生成算法

### 5.1 确定性要求（关键，与存档系统对接）

```csharp
// 生成器必须用 System.Random + seed，禁用 UnityEngine.Random
var rng = new System.Random(worldSeed);
// 后续所有随机走 rng.Next() / rng.NextDouble()
```

**同 seed 同结果**——存档只存 seed，读档用同 seed 重生成，地形/资源点/单位位置完全对得上。

### 5.2 生成流程

```csharp
// WorldManager.GenerateWorld（落地原 TODO）
public void GenerateWorld(int worldSeed, WorldSize size, int difficulty)
{
    var rng = new System.Random(worldSeed);
    int regionCount = MapSizeConfig.GetRegionCount(size);  // M
    int enemyMapCount = GetEnemyMapCount(rng, difficulty);  // 敌方王国数（按难度，不按 worldSize）

    // 1. 生成玩家初始地图
    var playerMap = GenerateMap(rng, worldSeed, 0, size, isPlayerHome: true);
    _maps.Add(playerMap);
    _activeMapId = playerMap.mapId;

    // 2. 生成敌方王国地图
    for (int i = 1; i <= enemyMapCount; i++)
    {
        int mapSeed = rng.Next();  // 派生敌方地图种子
        var enemyMap = GenerateMap(new System.Random(mapSeed), mapSeed, i, size, isPlayerHome: false);
        _maps.Add(enemyMap);
    }
}

// GenerateMap：生成一张地图（M 个大区块）
MapData GenerateMap(System.Random rng, int seed, int mapId, WorldSize size, bool isPlayerHome)
{
    var bigTerrain = isPlayerHome
        ? (rng.NextDouble() < 0.5 ? BigTerrain.Island : BigTerrain.Inland)
        : BigTerrain.Island;  // 敌方王国固定岛屿（攻城）

    var map = new MapData { mapId = mapId, seed = seed, bigTerrain = bigTerrain, regions = new List<Region>() };
    var regionCount = MapSizeConfig.GetRegionCount(size);

    for (int i = 0; i < regionCount; i++)
    {
        var terrain = PickTerrain(rng, bigTerrain);  // 受大地形约束
        var region = new Region {
            regionIndex = i,
            terrain = terrain,
            cellStartX = i * _gridConfig.regionCellCount,
            cellCount = _gridConfig.regionCellCount,
            resources = PlaceResources(rng, terrain, _gridConfig.regionCellCount),
            isEnemyTerritory = !isPlayerHome
        };
        map.regions.Add(region);
    }
    return map;
}
```

### 5.3 坐标转换

```csharp
// 世界坐标 → 小区块坐标（GridSystem）
GridCoord WorldToCoord(Vector2 pos)
{
    int x = Mathf.FloorToInt(pos.x / config.cellSize);
    int y = pos.y > config.flyHeightThreshold ? 1 : 0;
    return new GridCoord(x, y);
}

// 小区块坐标 → 大区块索引
int CellToRegionIndex(int cellX)
    => cellX / config.regionCellCount;

// 大区块索引 → 该大区块起始世界 x
float RegionIndexToWorldX(int regionIndex)
    => regionIndex * config.regionCellCount * config.cellSize;
```

## 六、多地图世界系统

### 6.1 World 结构

一个 `World`（一局游戏）含多张 `Map`：

```csharp
public class WorldState
{
    public int worldSeed;
    public WorldSize worldSize;
    public int difficulty;
    public int activeMapId;              // 当前所在地图
    public List<MapData> maps;           // 所有地图（玩家初始 + 敌方王国）
    public HashSet<int> conqueredMapIds; // 已占领的地图 ID
}
```

### 6.2 Map 结构

```csharp
public class MapData
{
    public int mapId;                    // 地图唯一 ID（0=玩家初始，1..N=敌方王国）
    public int seed;                     // 该地图的生成种子
    public BigTerrain bigTerrain;        // 大地形（岛屿/内陆）
    public List<Region> regions;         // M 个大区块
    public bool isPlayerHome;            // 是否玩家初始地图
    public bool isConquered;             // 是否已被玩家占领
    public EnemyKingdomState enemyState; // 敌方王国状态（仅敌方地图）
```

### 6.4 王国征服


```csharp
{
```

```csharp
    // 落地原 TODO
    void GenerateWorld(int worldSeed, WorldSize size, int difficulty)
    {

        // ... 见 5.2 生成流程

    }

    // 跨岛远征
    public void SwitchToMap(int mapId)
    {
        _world.activeMapId = mapId;
        GridSystem.Instance.PopulateFromMap(_world.ActiveMap);
    }

    // 占领敌方王国
    public void ConquerMap(int mapId)
    {
        var map = _world.maps.Find(m => m.mapId == mapId);
        if (map != null) { map.isConquered = true; _world.conqueredMapIds.Add(mapId); }
    }

    public bool IsCleared => _world?.IsCleared ?? false;

    // ===== ISaveable（扩展存档）=====
    public string SaveId => "WorldManager";
    public SaveLoadPhase LoadPhase => SaveLoadPhase.Global;

    public SavePayload SaveState()
    {
        var data = new WorldSaveData
        {
            worldSeed = _world.worldSeed,
            worldSize = (int)_world.worldSize,
            difficulty = _world.difficulty,
            activeMapId = _world.activeMapId,
            maps = SerializeMaps(_world.maps),
            conqueredMapIds = string.Join(",", _world.conqueredMapIds)
        };
        return new SavePayload { typeName = ..., json = JsonUtility.ToJson(data), version = 2 };
    }

    public void LoadState(SavePayload payload)
    {
        var data = JsonUtility.FromJson<WorldSaveData>(payload.json);
        // 用 worldSeed 重新生成世界（确定性 → 地形/资源完全复现）
        GenerateWorld(data.worldSeed, (WorldSize)data.worldSize, data.difficulty);
        _world.activeMapId = data.activeMapId;
        // 恢复征服状态
        foreach (var id in data.conqueredMapIds.Split(','))
            if (int.TryParse(id, out var mid)) ConquerMap(mid);
        // 切到存档时的活跃地图
        GridSystem.Instance.PopulateFromMap(_world.ActiveMap);
    }
}

}
```

3. **确定性**：同 worldSeed 两次生成，地形完全一致
4. **跨岛**：SwitchToMap 后区块清空重建，单位重新进入

### MCP 调试

可用 Unity MCP `execute_code` 直接验证：
- 生成世界后打印大区块列表 + 地形分布
- 检查 `WorldManager.ActiveMap.regions.Count` 是否符合 worldSize
- 跨岛后检查 `GridSystem._cells` 是否重建
