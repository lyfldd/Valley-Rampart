## 一、决定层总架构：两类东西 + 反馈环

> **2026-07-31 修订**：原架构仅描述三层管线的单向流动。经需求审查，补全为"两类东西（纯管线 + 记忆组件群）+ 反馈控制环"的完整骨架。

### 1.1 两个核心架构原则

**原则一·两类东西**：系统收敛为两类组件，纪律分界铁律--
- **纯计算管线**（L1/L2/L3）：无状态、可重放、可进调试面板。全部决策住这。
- **输入侧记忆组件群**：有状态、需存档、需统一 tick。受击冷却状态机、威胁滞回量化器、保护因子量化器住这。它们和血量、位置一样是"自身状态"，不是管线内部变量。

> 新增任何有状态的东西（疲劳/士气/信任度…）默认归入记忆组件群，管线永不被污染。§9"纯计算无副作用"声明因此成立。

**原则二·反馈控制环**：系统不是单向决策，而是反馈控制环--

```
记忆组件群 Update ──┐
                    ├─> FactorContext ─> 纯管线(L1>L2>L3) ─> BehaviorCommand
                    │                              │
                    │                              ▼
                    └──── BehaviorExecutor 事件(OnArrive/AnchorLost/MoveComplete) ──┘
```

Executor 检测到执行事件 -> NPCBrain 本地分发（主，喂记忆组件，可靠不丢）-> 转发 EventBus（辅，供调度中心/调试/音效订阅）-> 下一 tick 进 FactorContext -> 管线输出新 cmd。到达后砍树 = 管线下 tick 输出 WorkAt，不是 Executor 自己切。

### 1.2 三层裁决管线

```
输入端（刺激源 / 世界状态 / 自身状态）
   ↓
【L1 焦点评分层】—— 去哪 / 做什么
   五层压制 + 层内强度排序 → 焦点（目标位置 + 刺激类型）
   ↓
【L2 姿态裁决层】—— 用哪个行为模块去
   焦点类型 × 威胁评定 × 保护因子 × 性格因子 × 到达态 -> 谱系等级 -> 行为模块
   ↓
【L3 参数计算层】—— 多快 / 多远 / 多久
   因子公式 → 速度 / 距离 / 时长 / 阈值等连续参数
   ↓
输出端（5 个通用行为模块）
```

**三层职责边界（铁律）**：
- L1 只回答"目标是哪"，不回答"怎么去"。同僚压制与排序规则由母文档 3.1-3.4 定义，本文不改。
- L2 只回答"用什么姿态/模块"，不产出具体数值。本文升级为"**谱系 × 焦点类型 × 到达态 三维选模块**"（见 §4.2）。
- L3 只算数值，不做任何选择。公式全部来自 3.0.1_1 + 本文第五节新增，集中可查。

**为什么拆三层**：用户的两个场景（夜晚回城 / 跟军中箭）表面上 behavior 完全不同，拆开后发现它们共享同一管线，只是 L1 的焦点来源、L2 的谱系、L3 的参数各不同——**差异全部下沉为因子配置，管线本身零分支**。

## 二、输出端：行为模块词汇表（5 个通用模块）

输出端**收敛为有限动词表**。所有职业共用，写一次复用；职业差异通过 L3 参数与动作映射体现，不新增模块。

| 模块 | 职责 | 输入参数 | 备注 |
|------|------|---------|------|
| `MoveTowards` | 常规位移 | targetPos, speed | 现有 UnitController 能力 |
| `RetreatMove` | 撤退位移 | targetPos 或 direction, speed, distance | 回避受击方向、可寻掩护（3.0.1_1 撤退链路） |
| `WorkAt` | 工作循环 | targetPos, workSpeed | 砍/挖/建占位，首版"位移即目的" |
| `FollowAnchor` | 跟随动态锚点 | anchor（UnitController）, keepDistance, speed | 目标位置每 tick 随锚点刷新 |
| `Idle` | 原地待机 | duration | 警戒驻留 / 无焦点兜底 |

**纪律**：新增行为需求先问"能否用现有 5 模块 + 参数组合表达"。士兵攻击 = `MoveTowards`（接近）+ 伤害管线（3.4，攻击判定不在本层）；箭塔索敌 = 不调移动模块的特化。**模块表扩张需要文档级评审**，防止决定层退化成行为树。

## 三、L1 焦点评分层：新增两个刺激源

层压制与排序规则沿用母文档（高层任何活跃项 > 低层所有项；层内按 intensity 排序；第一名 = 焦点）。本文只新增刺激源，不改规则。

### 3.1 SafetyStimulus（归巢吸引 · 任务层 D 级 pseudo-task）

**设计意图**：让"没事干就回城墙里待着"成为涌现行为。它是一个 **NPC 自带、无需调度中心下发**的伪任务，住在任务层最底部（D 级，低于 C 级杂务），只在任务层无更高活跃项时兜底成为焦点。

```
safetyUrge = baseSafetyPull                                    // 基础归巢倾向（小值，D 级强度）
           * (1 + nightFactor * nightPullWeight)               // 夜晚放大
           * (1 + (1 - hpRatio) * woundPullWeight)             // 受伤放大
           * professionPullScale                               // 职业系数（工人 1.0 / 士兵 0.2）

目标位置 = HomePoint（安全点，由外部系统设置；默认 = 城墙内驻留点）
```

**层内行为**：砍树任务（B 级）活跃时，B > D，砍树赢；砍完任务消失，D 级浮出 → 焦点 = HomePoint。**它不需要赢过任何任务，只负责兜底**——"天黑没做完也跑回去"不是它的职责，是威胁层的（见场景走查 1）。

### 3.2 FollowStimulus（跟随锚点 · 任务层）

**设计意图**：让"工人跟上部队"成为涌现行为。调度中心/军令下发，目标位置**动态绑定锚点**（部队队长 UnitController），每 tick 刷新。优先级由下发方定（跟随工程 = B 级，随军抢修 = A 级）。

中箭时威胁层压制它（威胁 3 > 任务层全部）；威胁消退后它**仍在任务层原优先级**，自动重新成为焦点 → 工人自然跟上已移动的部队。"跟上"这个动作零硬编码。

### 3.3 刺激源总表（更新版）

| 层 | 刺激源 | 来源 | 首版 |
|----|--------|------|:--:|
| 1 威胁 | ThreatStimulus | 感知广播 / 受击事件 | ✅ 已有 |
| 2 仇恨 | HateStimulus | 留壳 | ⬜ |
| 3 任务 | TaskStimulus | 调度中心 / 君主 | ✅ 已有 |
| 3 任务 | **FollowStimulus（新）** | 调度中心 / 军令 | ✅ 本文 |
| 3 任务 | **SafetyStimulus（新）** | NPC 自带，D 级兜底 | ✅ 本文 |
| 3 任务 | **HoldPositionStimulus（新）** | 状态机 Caution 态注入（动态） | ✅ 本文 |
| 4 感知 | PerceptionStimulus | 空间分区广播 | ✅ 已有 |
| 5 好奇 | CuriosityStimulus | 留壳 | ⬜ |

## 四、L2 姿态裁决层（本文核心）

### 4.1 输入与输出

```
输入：焦点（L1 输出）+ 威胁评定（3.0.1 第五节）+ 保护因子 + 性格因子
输出：谱系等级 → 行为模块 + 参数来源
```

### 4.2 谱系 × 焦点类型 × 到达态 三维裁决表

> **2026-07-31 修订**：原表为单维（谱系->模块），但 WorkAt vs MoveTowards 还依赖"是否到达焦点目标"，且撤退目标需区分战术短撤/战略回城。升级为三维裁决表 + 谱系 4 子裁决（§4.5）。

母文档的谱系只"调速度调姿态"，本文升级为**三维选模块**。谱系选姿态，到达态叠加焦点动作，两个正交维度不压一张表：

| 谱系 | 焦点类型 | 到达态 | 模块 | 参数来源（L3） |
|------|---------|--------|------|--------------|
| 4 | × | × | `RetreatMove`（子裁决见 §4.5） | speed/distance 见 3.0.1_1 + §4.5 |
| 0/2 | 锚点型（FollowStimulus） | ×（永不到达） | `FollowAnchor` | keepDistance 见 §5.2 |
| 0/2 | 位置型 | 未到达 | `MoveTowards` | speed = walkSpeed |
| 0/2 | 位置型 | 已到达 | `Idle` | duration |
| 0/2 | 工作类位置 | 已到达 | `WorkAt` | workSpeed |
| 0/2 | 驻留类位置（HomePoint） | 已到达 | `Idle` | duration |

**两个特例（铁律）**：
- `arrivedAtFocus`（到达态）是**自身状态**进 FactorContext，不是刺激源。到达不改变焦点（树还是那棵树），若做成 ArrivalStimulus 会让焦点排行榜闪烁。
- FollowAnchor 永远"未到达"--跟随是持续过程，到 keepDistance 内自停是模块内置逻辑，L2 不管。

> 谱系 1/3 留口（P1 实装）：谱系 1 = 警惕减速（alertSpeedScale），谱系 3 = 边撤边做（目标偏向 HomePoint）。P0 落 0/2/4 三态。

### 4.3 同源双径（本文最重要的设计）

**安全点 HomePoint 有两条到达路径，由威胁因子裁决走哪条，不由 if-else 裁决**：

```
路径甲·吸引态：无任务 → SafetyStimulus 兜底成焦点 → 威胁 0 → 谱系 0
              → MoveTowards(HomePoint, walkSpeed) → 慢悠悠走回城

路径乙·避险态：威胁超阈值 -> 谱系 4 -> §4.5 子裁决
              ·战略（夜晚 / hitCount≥max）-> RetreatMove(HomePoint, retreatSpeed) 跑回城
              ·战术（单次受击 hitCount<max）-> RetreatMove(方向, retreatDistance) 撤一小段
```

同一个目标点，两种走法。**"白天做完活慢走回城、天黑没做完跑回城"这两个行为在代码里不存在**，存在的只有：安全点定义、时间因子、威胁公式、两条路径。行为是算出来的。

### 4.4 地形闭环（防卡死）

路径乙跑到城里后威胁（夜晚）仍在，会不会卡在撤退态？不会——母文档 5.1 已有**地形因子**（城墙内 = 安全区，负向抵消）：

```
进城 → 地形因子压零威胁评定 → 谱系 4 → 0 自动降级
     → 任务层空 → SafetyStimulus 兜底 → MoveTowards 慢走到驻留点 → Idle
```

回城后自动减速、自动驻留，行为连贯无跳变。

### 4.5 谱系 4 撤退子裁决（双撤退模式）

> **2026-07-31 新增**：修正原 §4.2"谱系 4 目标统一为 HomePoint"与场景 2"撤一小段 4 格"的矛盾。恢复 3.0.1_1 原有的撤退阶梯，判别式为三规则（顺序即优先级），全部走 FactorContext 已有信号，不引入场景 if-else：

```
① hitCount ≥ maxHitCount       -> 战略撤退 HomePoint    // 被打怕了，无条件回家
② 有活跃 ThreatStimulus         -> 战术短撤（方向 + retreatDistance）  // 有具体威胁源：先脱离
③ 无 ThreatStimulus 但威胁超阈  -> 战略撤退 HomePoint    // 纯环境推高（夜晚）：直接回家
```

**为什么不用 hitCount 一条**：夜晚 hitCount 恒为 0，会永远战术短撤 4 格然后站着过夜，场景 1 崩。
**为什么不给 ThreatStimulus 加 source 字段**：环境型威胁根本没有 ThreatStimulus 对象（时间因子推高 rawFactor，不是注入的），加字段还得为夜晚伪造刺激源，改动母文档 §5.1。source 字段降级 P1 增强。

**边界 case**：敌人在感知范围内但没打你（有 ThreatStimulus、hitCount=0）-> 走 ② 战术短撤，撤完敌人还在 -> 3.0.1_1 原有"再撤、距离递增"兜底，多段后等效回家。行为正确，节奏多段，P0 可接受。

**maxHitCount** 住 NpcProfessionDef（第五个职业性格参数，与 courage/obedience/threatSensitivity 同维度）：工人 = 3，士兵 = 99（几乎不触发）。

**谱系 4 覆盖 L1 焦点目标（铁律）**：谱系 4 时 L2 **忽略 L1 焦点目标**，按子裁决重新决定移动目标--战略撤退用 HomePoint，战术短撤用受击反方向。即 L1 焦点（如砍树位置）在谱系 4 下被冻结，撤退完成后威胁降级，L1 焦点才重新生效。这解释了场景 1 傍晚"L1 焦点仍=砍树"却跑去 HomePoint：L1 焦点没变，是 L2 在谱系 4 下覆盖了目标。


## 六、因子三层挂载矩阵

每个因子在哪层起作用一目了然——调场景手感时按表找挂载点，只动因子和公式，不动管线：

| 因子 | L1 焦点评分 | L2 姿态裁决 | L3 参数计算 |
|------|-----------|-----------|-----------|
| courage | 威胁类强度折扣 | 撤退阈值偏移（3.0.1 §4.2） | 撤退距离/速度、警戒/恢复时长、追击范围 |
| obedience | 任务类强度加成 | 撤退阈值偏移、抗命覆盖（3.0.1_1 §5.2） | — |
| threatSensitivity | 威胁类强度放大 | distFactor（3.0.1_1 §4.2） | 撤退距离、恢复时长 |
| perceptionRadius | 感知范围（刺激发现半径） | — | 追击范围基准 |
| hpRatio | — | hpFear（3.0.1_1 §4.2） | 警戒时长、归巢吸引 |
| nightFactor（时间） | SafetyStimulus 放大 | timeFactor 威胁加重（3.0.1 §5.1） | - |
| 职业偏移 professionOffset | - | 撤退阈值（士兵 +x / 工人 -x） | professionPullScale |
| **currentState（状态机输出）** | Caution 态注入 HoldPositionStimulus（§13.3） | - | - |
| **hitCount（状态机输出）** | - | §4.5 双撤退子裁决（≥max 战略 / <max 战术） | 撤退距离阶梯（3.0.1_1 §6.2） |
| **stateThreatBias（状态机输出）** | - | Caution 态直接抬等级：`ThreatLevel = max(quantizerLevel, Alert)`，只抬不降（**不叠 rawFactor**——会与量化器滞回耦合，残余+bias 越威胁 2 升阈可致谱系 4 死循环），不负责原地 | - |
| **stateTaskDiscount（状态机输出）** | Caution 态任务类刺激 ×折扣（让 HoldPosition 胜出） | - | - |
| **arrivedAtFocus（自身状态）** | - | L2 三维表到达态维度 | - |

**关于士兵的"忠诚度"**：不新增 loyalty 因子，**obedience 即通用职责因子**，在士兵身上表现为忠诚、在工人身上表现为听调度。courage × obedience 叉乘出四种性格，行为多样性由此而来：

| | obedience 高 | obedience 低 |
|---|---|---|
| **courage 高** | 敢打且死守（精锐） | 打得猛但局势不对就溜（佣兵） |
| **courage 低** | 吓得发抖但坚守岗位（新兵） | 一触即溃（民兵） |

## 七、场景走查 1：砍树 - 回城（用户场景复现）

**世界参数设置**（这就是全部"配置"，没有任何行为代码）：城墙内驻留点 = HomePoint；城墙内 = 安全区（地形因子）；夜晚 timeFactor 威胁加重；工人 courage=30 / sens=1.5。

| 时刻 | 输入变化 | L1 焦点 | L2 姿态 | L3 参数 | 输出行为 |
|------|---------|--------|--------|--------|---------|
| 白天 | 调度中心发砍树任务（B 级） | 任务层·砍树 | 威胁 0 → 谱系 0 | walkSpeed | MoveTowards(树) → WorkAt |
| 白天·做完 | 任务刺激消失 | SafetyStimulus 兜底（D 级浮出） | 威胁 0 → 谱系 0 | walkSpeed | **MoveTowards(HomePoint) 慢悠悠回城** ✓ |
| 傍晚·没做完 | nightFactor 上升 → rawFactor 推高（**无 ThreatStimulus**，走路径乙避险态非路径甲吸引态） | L1 焦点仍=砍树（未变，谱系4下被冻结） | L2 谱系裁决：威胁 2 无保护 -> 谱系 4，§4.5 ③ 战略（L2 覆盖焦点目标=HomePoint） | retreatSpeed = walk × 1.7 | **RetreatMove(HomePoint) 自己跑回城** ✓ |
| 进城 | 地形因子压零威胁 | SafetyStimulus | 谱系 4→0 降级 | walkSpeed | 慢走到驻留点 → Idle |

**输入端一致性要求**：调度中心同样受 nightFactor 调制（夜间停发 B/C 级户外任务），否则它刚派活、威胁层就撤退，两个系统打架。输入端的纪律和决定层同等重要。

## 八、场景走查 2：跟军中箭（用户场景复现）

**配置**：部队队长 = FollowAnchor；调度中心发 FollowStimulus（B 级）；工人 courage=30 / sens=1.5；对照组士兵 courage=70 / obedience=80 / S 级军令。

| 步骤 | 输入变化 | 工人裁决 | 士兵裁决（对照） |
|------|---------|---------|----------------|
| 1 跟随 | FollowStimulus 活跃；前方有士兵 -> allyFactor 高 -> 威胁 0 | 焦点=锚点，谱系 0，FollowAnchor 跟上 ✓ | 同（S 级任务焦点） |
| 2 中箭 | ThreatStimulus（自身被攻击 = 威胁 3，层压制） | 谱系 4，RetreatMove 撤 **一小段**（hitCount=1 → (2+0)×1.35×1.5 ≈ 4 格）✓ | 威胁 3 ≤ 撤退阈值（基础 2 + S 加成 + 勇气/服从 + 职业偏移）→ **不跑**，谱系 2 谨慎继续战斗 ✓ |
| 3 警戒 | 撤退完成 → CautionState | 原地警戒 cautionDuration ≈ 5×1.7×血量系数 秒 | — |
| 4 试探 | N 秒未再被击 → ProbeState | 敏感度 ×1.5，可移动 | — |
| 5 跟上 | Probe 期间威胁持续衰减 -> 威胁层清空（§13.3：Probe 期任务类恢复，可跟上） | **FollowStimulus 仍在任务层 -> 重新成焦点 -> FollowAnchor(锚点新位置) 跟上部队** ✓ | - |
| 6 再中箭 | hitCount=2 | 撤更远（阶梯）；3 次+ → 直接 RetreatMove(HomePoint) 回城 ✓ | 依然不跑 |

全程零场景 if-else。"撤一小段再跟上" = 威胁层压制（进）+ 任务刺激持续存在（回）+ 受击冷却状态机（节奏），三件已有武器的组合。

```
stimulusPool.AddDynamic(memoryComponents.SelectMany(m => m.GetActiveStimuli()));
```

## 附录 B：可调性设计（因子零硬编码）

### B.1 问题

第十节参数表只解决了"**数值**可调"。但决定层里还有三类东西会被改：**曲线形状**（距离→威胁的映射方式）、**公式结构**（线性 → 平方 → Sigmoid）、**权重配比**。如果这三类留在代码里，"调 AI 手感"就退化成"改代码 + 重编译"，与母文档第九节"Play 模式拖 SO 滑块实时看 500 NPC 反应"的调参纪律直接冲突。本节规定它们的住处与修改路径。

### B.2 可调性四层（修改成本从低到高）

| 层 | 改什么 | 住处 | 例子 |
|----|--------|------|------|
| **L0 数值** | 常量 / 权重 / 阈值 | SO 字段，Play 模式实时拖 | baseSafetyPull、rawFactor 七权重 |
| **L1 曲线** | 输入→[0,1] 的映射形状 | SO 的 `AnimationCurve` 字段，拖曲线 | distFactor 从直线拖成 S 形 |
| **L2 公式变体** | 同一因子的不同计算结构 | 代码枚举 + 静态函数表，SO 选枚举 | DistEvalMode.Linear / InverseSquare |
| **L3 管线结构** | 三层裁决本身 | 代码，文档级评审 | 加第六层、改压制规则 |

**纪律**：L0/L1 覆盖约 80% 调参需求；L2 是"愿意改函数"的正式落点——加一个静态函数 + 一个枚举值，管线不动；L3 才走文档评审。

### B.3 FactorDef：因子数据化（核心）

每个因子不再是公式里写死的一项，而是 SO 里的一条配置：

```csharp
[Serializable]
public class FactorDef {
    public string id;                 // "dist" / "hpFear" / "enemyPower"
    public FactorInput input;         // 输入来源枚举：Dist / HpRatio / EnemyPower / AllyCount / Night...
    public float inputScale = 1f;     // 输入缩放
    public AnimationCurve curve;      // 响应曲线：拖曲线 = 改计算方式
    public PersonalityChannel modBy;  // 受谁调制：None / Courage / Sensitivity / Obedience
    public float modStrength;         // 调制强度（0 = 不受性格影响）
    public float weight;              // 加权和权重
}
```

威胁评定从"写死的七项公式"变为"遍历配置数组"：

```csharp
float EvaluateRaw(in FactorContext ctx, NpcProfessionDef prof) {
    float sum = 0;
    foreach (var f in tuning.threatFactors) {          // SO 里的 FactorDef 数组
        float x = ctx.Get(f.input) * f.inputScale;
        float v = f.curve.Evaluate(Mathf.Clamp01(x));
        v = PersonalityMod.Apply(v, f.modBy, f.modStrength, prof);
        sum += v * f.weight;
    }
    return Mathf.Clamp01(sum);
}
```

由此获得的修改自由度：

| 想改什么 | 怎么改 | 碰代码吗 |
|---------|--------|:-------:|
| 某因子影响大小 | 拖 weight 滑块 | 否 |
| 某因子的计算方式 | 拖 curve（直线 → S 曲线 → 阶梯，所见即所得） | 否 |
| 加新因子 | 数组加一项（新输入源才加枚举值） | 基本否 |
| 删因子 | weight 置 0 或删项 | 否 |
| 性格怎么参与（courage 放大 hpFear 之类） | 配 modBy + modStrength | 否 |
| 全新的输入来源（如"士气"） | FactorInput 加枚举 + ctx.Get 加一个分支 | 是，L2 级小改 |

**3.0.1_1 的全部公式按此重写**：hpFear 的 courage 放大（§4.2）、distFactor 的 sens 参与（§4.2）、撤退距离/速度/警戒/恢复（§6）——全部拆成 FactorDef 配置项，公式里不再出现写死的性格表达式。这也顺带消解了 3.0.1_1 勘误 ①②：负向因子通过 curve 画成下降曲线表达，符号/方向问题不复存在。

> **执行时机（P0/P1 分界）**：FactorDef 化是 **P1 项**，不在 §11 P0 清单内。P0 用"权重入普通 SO 字段的线性加权和"（满足 B.4 零字面量纪律；曲线初始化为直线 y=x 时 FactorDef 数学上退化为线性，故 P1 迁移无缝、行为不变）。P0 实施时不得以本附录为由扩大范围。

### B.4 零字面量纪律

**公式里出现的任何字面量数字都不允许留在代码里**。必须入 SO 的清单：rawFactor 七权重（3.0.1_1 §4.3）、撤退阈值四项加成（§5.3）、撤退距离/速度/警戒/恢复全部系数（§6）、safetyUrge 三 weight（本文 §5.2）、followKeepDistance 系数（§5.2）、谱系速度系数（§4.2）。第十节参数表 + 本节 FactorDef 数组即全部住处。

### B.5 AnimationCurve 使用纪律

- 全部曲线约定 **[0,1] → [0,1]**，`Evaluate` 前 `Clamp01`，防止拖出界炸公式
- SO 资产创建时初始化默认曲线（直线 y = x），防空曲线 NRE
- 曲线只表达"**形状**"，性格调制和权重在曲线外做——**别把 courage 烘进曲线里**，否则职业分化失效（曲线全局共享，性格每职业不同）
- 性能预算：`AnimationCurve.Evaluate` 有插值开销，500 NPC × 每 tick 多因子时可降频（母文档 §7.3 LOD），必要时烘焙为 128 点查找表（P1 优化项，接口不变）

### B.6 与调试面板联动（可调性的最后一环）

可调只是前半，**调了要知道有没有用**才是闭环。母文档附录 A 的 `IAIDebugInfo` 扩展：面板实时显示每个 FactorDef 的四段值--原始输入 -> 曲线后 -> 性格调制后 -> ×权重贡献。哪个因子在推动当前决策一眼可见，调参从"盲拖"变成"看着因果拖"。

### 13.2 两个核心架构原则（升格入 §1.1）

- **两类东西**：纯计算管线（L1/L2/L3）+ 输入侧记忆组件群（状态机/量化器）。新增有状态的东西默认归记忆组件群，管线永不被污染。
- **反馈控制环**：Executor 事件 -> NPCBrain 本地分发 -> EventBus -> 记忆组件/刺激源 -> FactorContext -> 管线 -> cmd。系统是反馈环非单向决策。

### 13.3 受击冷却状态机规格（P0 新补）

- **三态**：Normal / Caution / Probe（完全恢复 = 回 Normal，与 3.0.1_1 §6.1 链路一致，无独立 Recovery 态）
- **双路径更新**：(a) 时长驱动（cautionDuration/recoveryDuration，3.0.1_1 §6.4/6.5）；(b) 事件驱动（受击->任意态->Caution 且 hitCount++；MoveComplete 亦归 Caution）
- **Caution 计时起点**：自 MoveComplete（撤退完成）起算，非受击时刻——否则撤退移动时间吃掉 cautionDuration
- **输出**：currentState / hitCount /（Caution: stateThreatBias 威胁加成 + stateTaskDiscount 任务折扣 + HoldPositionStimulus 驻留刺激源; Probe: 敏感度 ×1.5）
- **Caution"原地不动"的涌现机制（审计补全）**：威胁加成**无法实现**原地--维持威胁 1 则谱系 0 走回岗位（母文档 §5.2），维持威胁 2 无保护则谱系 4 再撤退死循环。正确机制：Caution 期间 ①任务类刺激 × stateTaskDiscount（强度打骨折）②经 `GetActiveStimuli()` 注入 HoldPositionStimulus（目标 = 当前位置，强度中等）-> 驻留焦点胜出 -> 已在目标点 -> 谱系 0 + 位置型已到达 -> `Idle`。威胁加成只负责"保持警戒姿态"（注意力提权威胁层），不负责原地。Probe 期间 `GetActiveStimuli()` 返回空（驻留刺激源撤除）、任务类恢复，敏感度 ×1.5 -> 可跟上也可再被打

### 13.4 BehaviorExecutor 契约

- **可持有**：当前 cmd（相同幂等续做）、到达检测、速度插值（0.2s lerp）、锚点存活检查
- **禁止**：自主切模块、决定到达后行为、改 cmd 参数
- **事件双层分发**：Executor -> NPCBrain 本地（主，喂记忆组件）-> EventBus（辅，供调度/调试/音效）
- **防抖**：cmd 幂等续做 = 第四层（最底层）防抖，与输入侧三层防抖正交
