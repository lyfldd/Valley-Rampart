# 3.5 存档接入设计：NPC 任务与状态持久化

> 日期：2026-08-07（评审稿，代码未动）
> 目的：把 3.5"NPC 中途任务 / 搬运中途 / NPC 状态"怎么进存档、怎么读档恢复，设计到可执行颗粒度，供评审后定从哪下手。
> 前置：3.5 系列（3.5.1-3.5.4）+ 存档框架（`SaveableContracts`/`SaveManager`/`SaveRoot`）+ 3.5 王国任务（训练侧 T-K/T-R + Unity WorkerTask）
> 原则：**只存"不可重算/不可重派的持久状态"；瞬态状态（战斗焦点、威胁、热点）读档后自算，不存**。

---

## 一、现状盘点（已存什么，缺什么）

### 1.1 存档框架（已就绪）
- `ISaveable`：模块自治序列化（`SavePayload` 包裹 JSON）。`SaveManager` 收集/分发，`SaveRoot.modules` 用 List<ModuleSaveEntry> 持久化（JsonUtility 不支持 Dictionary）。
- `ISaveableSpawner`：读档动态重建场景对象（`UnitFactory.SpawnFromSave`，前缀 `"Unit_"`）。
- 加载阶段：`SaveLoadPhase.Global`（常驻系统）→ `Scene`（单位等动态对象）。

### 1.2 单位已存的（`UnitSaveData` v2）
| 字段 | 说明 |
|------|------|
| faction / occupation | 阵营 / 职业 |
| currentHp / maxHp / attack / defense / walkSpeed / runSpeed | 战斗属性 |
| posX / posY | 位置（搬运中途的"人在哪"靠这个恢复）|
| satiety / happiness / equipId | 饱食 / 幸福 / 装备（3.5 P1 生活状态，已存）|

### 1.3 缺口（本次要补的）
| 需求 | 现状 | 缺口 |
|------|------|------|
| NPC **执行任务中途**（Gather/Transport 进行到一半）| ❌ 未存 | WorkerTask 状态未入存档 |
| NPC **搬运中途**（已取货 / 正在往返 Source↔Dest）| ❌ 未存 | 任务状态（MovingToDest）+ carry 未入存档 |
| NPC **被打断挂起**（T-R）| ❌ 未存 | WorkerTask.Suspended 未入存档 |
| NPC **大脑任务焦点**（正在被派谁的任务/编队跟随）| ❌ 未存 | 需评估：存 vs 重派/重算 |

## 二、需求拆解（"NPC 状态"到底指哪些）

按"可重算 vs 需持久"分类，决定存不存：

| # | 子项 | 例子 | 是否需持久 | 依据 |
|---|------|------|:--:|------|
| 1 | **王国任务状态** | 工人采集到一半 / 运输已取货在送往途 | ✅ 必须存 | WorkerTask 是显式任务，读档要续做 |
| 2 | **搬运 carry 中途** | 工人正从仓库往国库搬 | ✅ 存（随任务状态）| 位置 posX + 任务状态 MovingToDest 即还原中途 |
| 3 | **打断挂起恢复** | 工人被敌吓跑，任务挂起中 | ✅ 存 | Suspended + 已过时长，读档续挂起/续恢复 |
| 4 | **生活状态** | 饱食/幸福/装备 | ✅ 已存 | 3.5 P1 已做 |
| 5 | **调度中心派发的搬运/乘员任务** | ScheduleCenterStub 派活 | 🔶 不存（重派）| 调度中心每 1s 运行，读档后自动重派空闲工人；carry 是"走到→Harvest→入国库"一次性，无中途态 |
| 6 | **编队跟随（FollowProvider）** | 士兵站槽位 / 跟随将军 | 🔶 不存（重绑）| 编队由 FormationController 单独存档，读档重建后 re-bind 槽位 |
| 7 | **战斗焦点/威胁/热点** | _chaseTarget / 威胁刺激 | ❌ 不存 | 瞬态，读档后感知自算 |
| 8 | **人口实体附加状态** | childGrowthDays / isVagrantRecruit | 🔶 待定 | 3.5 P0 人口实体化未落地，字段尚无，先不设计 |

> **结论**：本次核心要存的是 **#1/#2/#3（WorkerTask 王国任务状态）**。#5/#6 靠重派/重绑，不存；#7 自算不存；#8 等人口实体化落地再补。

## 三、存档方案（怎么存）

### 3.1 UnitSaveData 升级到 v3，加任务状态字段
在 `Systems/Unit/UnitController.cs` 的 `UnitSaveData` 追加：

```csharp
// v3（3.5 王国任务：NPC 中途任务/搬运状态）
public int taskType = -1;            // -1=无任务，0=Gather，1=Transport（对齐 WorkerTaskType）
public float taskSourceX;            // 取货/采集点 x
public float taskDestX;              // 结算/仓库点 x
public float taskWorkDuration;       // Working 阶段需时长
public int taskState;                // WorkerTaskState（Assigned/MovingToSource/Working/MovingToDest/...）
public float taskWorkElapsed;        // Working 已进行时长
public bool taskSuspended;           // 是否被打断挂起
public float taskSuspendedElapsed;   // 挂起已过时长（读档还原 SuspendedAt 用）
```

### 3.2 WorkerTask 加序列化/反序列化
在 `Systems/Unit/WorkerTask.cs` 加两个方法：
- `WriteToSave(UnitSaveData data)`：把任务全状态写入上面字段。**用"已过时长"而非绝对时刻**（绝对时刻跨存档无意义）。
- `RestoreFromSave(UnitSaveData data)`：还原任务 + 重新置 `brain.IsKingdomTaskWorker=true`（移动独占）。

### 3.3 UnitController.SaveState/LoadState 接入
- `SaveState()`：`saveDataVersion=3`；若 `GetComponent<WorkerTask>()` 且 `Active`，调 `WriteToSave`。
- `LoadState()`：`saveDataVersion>=3 && taskType>=0` 时，若无 WorkerTask 组件则 `AddComponent<WorkerTask>()`，再 `RestoreFromSave`。

### 3.4 兼容性（v1/v2 → v3）
- 旧存档 `saveDataVersion<3` → `taskType` 默认 -1（无任务），不触发任务恢复，行为与现状一致。
- 搬运中途 = 位置（posX 已存）+ MovingToDest 状态，读档后从该位置续走。

### 3.5 明确不做（靠重派/重算）
- ScheduleCenter 搬运/乘员：读档后调度中心自动重派，不存。
- 编队跟随：FormationController 独立存档重建后 re-bind，不存 brainStateJson。
- 战斗焦点/威胁：感知自算，不存。

## 五、验收

| # | 验收项 | 判定 |
|---|--------|------|
| 1 | Gather 采集到一半读档 | 读档后工人从 Working 续做 → Completed，TaskCompleted 增加 |
| 2 | Transport 搬运中途读档 | 读档后工人从当前位置续走到 DestX → Completed（"正在搬运"恢复）|
| 3 | 挂起中读档 | 读档后 Suspended 保持，威胁回落照常恢复（T-R）|
| 4 | 无任务工人读档 | taskType=-1，不挂 WorkerTask，行为不变 |
| 5 | 旧存档读档 | saveDataVersion<3 不触发任务恢复，无回归 |
| 6 | 编译 | 0 错误 |
