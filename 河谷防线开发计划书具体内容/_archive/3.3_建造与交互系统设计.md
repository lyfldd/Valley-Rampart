## 一、需求来源与范围

玩家**自由建造**是白天经营循环的核心。本系统覆盖：

- 建造模式与放置（第三节）
- 建筑数据模型（第四节）
- **通用交互层**（第五节）—— 复用于建筑 / 地图资源点 / 裂隙 / 主城 / 未来 NPC
- 建筑 UI（第六节）

**不覆盖**（由其它模块负责）：移动与障碍处理(3.10)、伤害管线(3.4)、防御建筑自动攻击逻辑(3.5)、波次(3.7)、外交(3.8)。本系统为它们提供「可被放置 / 可被交互 / 可被摧毁」的建筑实体与注册表，是上层玩法的地基。

## 二、系统架构总图

### 2.1 放置流程

```
建造按钮
  → 打开 BuildingMenuPanel（按 category 分组，显示 cost，不够置灰）
  → 选中项 → 进入建造模式
  → ghost 跟随光标，按区块中心吸附
  → 实时校验(占用/地形/阻挡/资源/边界) → 绿/红反馈
  → 点击放置 → 扣资源 → 占用区块 → BuildingPlacedEvent → 注册 BuildingRegistry
  → (可选 buildTime 进度) → 激活
ESC / 再点按钮 → 退出建造模式，丢弃 ghost
```

### 2.2 交互派发（通用层，见第五节）

`InteractionManager` 监听点击 → 命中对象若实现 `IInteractable` → 调 `Interact(ctx)` → 按 `InteractionResult` 打开 UI / 执行动作 / 展开子菜单。

## 三、建筑数据模型（BuildingDef，SO）

**文件**：`Assets/_Game/Data/BuildingDef.cs` + `Assets/Resources/Buildings/*.asset`

```csharp
using System;
using UnityEngine;

/// <summary>
/// 建筑配置（ScriptableObject）。所有建筑属性集中于此，Inspector 可调，数据驱动。
/// 运行时 Building 实例持有本配置引用 + 运行时状态（level/hp/存储）。
/// </summary>
[CreateAssetMenu(menuName = "ValleyRampart/BuildingDef", fileName = "BuildingDef")]
public class BuildingDef : ScriptableObject
{
    [Header("基础")]
    public string id;
    public string displayName;
    [TextArea] public string description;
    public Faction faction;
    public BuildingCategory category;     // Defense / Production / Economy / Special / Wall

    [Header("造价与占位")]
    public ResourcePack cost;             // 金/石/木/粮（走 RulerController）
    public Vector2Int footprint;          // 占用 chunk 尺寸 (w,h)
    public TerrainType[] allowedTerrain;  // 可放置地形白名单

    [Header("行为标记")]
    public bool isObstacle;               // 是否阻挡移动/寻路（城墙=是；资源点=否或按类型）
    public ProducerConfig producer;       // 非空 = 生成物（产资源 or 产单位）
    public CombatConfig combat;           // 非空 = 防御建筑（攻击属性，交 3.5/3.4）
    public BuildingLevel[] levels;        // 升级档位

    [Header("交互与生命周期")]
    public InteractableType interactableType; // own / enemy / resource
    public bool isPlayerBuilt = true;     // false = 地图预置（不可拆/不可移动）
    public bool isDestructible = true;

    [Header("表现")]
    public GameObject prefab;
}

[Serializable] public struct ProducerConfig
{
    public ProduceKind kind;   // Resource / Unit
    public float rate;         // 每秒产出
    public int capacity;       // 存储上限
}

[Serializable] public struct CombatConfig
{
    public int attack;
    public int defense;
    public int maxHp;
    public float range;
    public DamageType damageType;
}

[Serializable] public struct BuildingLevel
{
    public ResourcePack upgradeCost;
    public float statScale;       // 升级后属性乘数
    public string[] prerequisites;// 前置（科技/时代，接未来科技系统）
}

public enum BuildingCategory { Defense, Production, Economy, Special, Wall }
public enum ProduceKind { Resource, Unit }
public enum InteractableType { Own, Enemy, Resource }
```

> **与地图生成(3.2.1)的关系**：3.2.1 的 `ResourceProducer / ResourcePickup / SpecialPoint / Rift / CastleCore` 是**地图预置**建筑，复用同一 `Building` 运行时类 + `IInteractable`，仅 `isPlayerBuilt = false`。这样玩家建筑与地图建筑共用一套放置/交互/存档/摧毁逻辑，不重复造轮子。

## 四、建造模式（BuildController）

**文件**：`Assets/_Game/Systems/Building/BuildController.cs`（Singleton 或挂载于 GameplayRoot）

**职责**：管理建造菜单、ghost 预览、放置校验、放置执行。

- 监听建造按钮 → 打开 `BuildingMenuPanel`（按 `category` 分组，显示 `cost`，资源不足置灰）
- 选中项 → 进入 `BuildMode`：实例化 ghost（半透明 prefab），每帧吸附到区块中心
- 调用 `PlacementValidator.Validate(BuildingDef, chunkPos, rotation)` 实时校验 → 绿/红反馈
- 合法时点击 → `Place()`
- `Place()`：`RulerController` 扣费 → `GridSystem.MarkOccupied`（标记 `isObstacle`）→ `Instantiate` Building → `BuildingRegistry.Register` → `EventBus.Publish(new BuildingPlacedEvent(building))` → 退出或连放（按住 Shift）
- 旋转：R 键修改 `rotation`，影响 footprint 朝向与防御建筑攻击扇形
- **输入锁**：进入 `BuildMode` 时禁用君主移动等冲突输入，退出恢复

## 五、放置校验规则（PlacementValidator）

**文件**：`Assets/_Game/Systems/Building/PlacementValidator.cs`

| 校验项 | 规则 | 失败反馈 |
|------|------|---------|
| 区块占用 | `footprint` 覆盖的所有 chunk 在 `GridSystem` 为空 | 红 |
| 地形合法 | 目标区块 `terrain ∈ allowedTerrain` | 红 |
| 阻挡冲突 | 不与已有 `isObstacle` 建筑重叠 | 红 |
| 资源足够 | `RulerController` 四资源 ≥ `cost` | 按钮置灰 / 红 |
| 边界范围 | 在可建造区（主城/领地/5 区约束）内 | 红 |
| 旋转后 footprint | 旋转后占用 chunk 仍需通过上述全部校验 | 红 |

> 校验依赖 **区块系统(0a / 3.2)**：`GridSystem` 需暴露 `IsOccupied(chunk)`、`MarkOccupied/Free(chunk, building)`、地形查询接口。

## 六、通用交互层（核心）

### 6.1 接口与结果

**文件**：`Assets/_Game/Systems/Interaction/IInteractable.cs`

```csharp
/// <summary>
/// 通用可交互接口。任何需要被点击/选择产生交互的实体（建筑/资源点/裂隙/主城/NPC）
/// 实现本接口即可接入统一交互派发，无需各自写点击逻辑。
/// </summary>
public interface IInteractable
{
    InteractionResult Interact(Interactor ctx);
}

public enum InteractionKind { ShowUI, DoAction, OpenSubmenu, None }

public readonly struct InteractionResult
{
    public InteractionKind kind;
    public IUIPanel panel;     // ShowUI：要打开的面板
    public System.Action action;// DoAction：要执行的一次性动作
}

public readonly struct Interactor
{
    public Faction faction;        // 发起者阵营（决定敌方建筑选项）
    public Vector3 position;       // 用于距离判定
    public UnitController unit;    // 可能为 null（纯玩家点选）
}
```

### 6.2 派发 InteractionManager

**文件**：`Assets/_Game/Systems/Interaction/InteractionManager.cs`（Singleton）

- 订阅输入点击 / 选择事件 → 射线 / 点选命中 Collider → 若 `GameObject` 实现 `IInteractable` → 调 `Interact(ctx)`
- 按 `InteractionResult`：
  - `ShowUI` → 打开对应 `IUIPanel`
  - `DoAction` → 执行 `action`
  - `OpenSubmenu` → 展开子菜单（如敌方建筑的侦察/攻击/标记）
- **悬停高亮**：选中 / 悬停时高亮轮廓
- 点空白 → 关闭当前面板 / 取消选择

### 6.3 实现者（同一接口复用）

| 实现者 | `Interact` 返回 | 说明 |
|------|------|------|
| `Building`（自家） | `ShowUI(BuildingPanel)` | 升级 / 拆除 / 信息 |
| `Building`（敌方） | `OpenSubmenu(侦察/攻击/标记)` | **阵营决定选项**（呼应上一轮 AI 讨论） |
| `ResourceNode` | `DoAction(采集)` 或 `ShowUI(信息)` | 地图资源点 |
| `Rift` | `ShowUI(波次信息)` / `DoAction(封印)` | 裂隙 |
| `CastleCore` | `ShowUI(HQ 面板)` | 主城核心 |
| `NPC`（未来） | `ShowUI(对话)` / `OpenSubmenu(编队)` | 后期 |

→ **一套点击逻辑服务所有可交互物**；建筑 UI 只是 `ShowUI` 的一种。新增可交互物只需实现 `IInteractable`，不改 `InteractionManager`。这正是「通用 NPC 行为 / 阵营分化」讨论里「阵营是交互的输入而非分支」在交互层的落地：敌方建筑的 `Interact` 因 `ctx.faction` 不同直接返回不同 `InteractionResult`。

### 6.4 交互范围（挖出需求，待定）

- 建筑：点哪交哪（RTS 习惯）
- 采集 / 进建筑：可能需发起单位在旁 → 用 `Interactor.position` 距离判定，或「选中单位后才可交互」规则

## 七、建筑 UI（BuildingPanel）

**文件**：`Assets/_Game/Systems/UI/BuildingPanel.cs`（+ `.uxml`）

- **展示**：名称 / 等级 / HP / 攻防（若有）/ 产能速率 / 描述
- **升级按钮**：校验资源 → 扣费 → 应用 `levels[next]`（`statScale` 乘属性）→ `EventBus.Publish(new BuildingUpgradedEvent(building))` → 刷新 UI
- **拆除按钮**：退部分资源（默认 50%，见第十二节待确认）→ `GridSystem.Free`（清 `isObstacle`）→ `EventBus.Publish(new BuildingDestroyedEvent(building))` → `TeardownManager` 清理实例
- **敌方建筑**：仅显示侦察 / 攻击选项，无升级 / 拆除

- **G5 多选 / 框选 / 批量升级拆除**（后期）

- **G7 建造模式输入锁**：禁用君主移动等冲突输入
- **G8 平衡数据 SO 化**：造价 / 产能 / 升级曲线集中调参（贴合 `WorldConfig` 风格）
