## 一、架构总览（双机制串联）

### 1.1 核心关系

五层注意力（机制甲）与三维权衡（机制乙）是**串联关系**，非替代非并行：
- **甲选焦点**（做什么）—— 在前
- **乙调强度与切换**（怎么做、什么时候停）—— 在后

形成完整决策流水线。

### 1.2 完整数据流

```
刺激源持续输入（事件型 / 感知型 / 指令型）
   ↓
【机制甲·五层注意力】持续评分，维护强度排行榜，第一名为候选焦点
   ↓
候选焦点 vs 当前焦点？
   ├─ 相同 → 【机制乙·强度调节】按 威胁×优先级×服从度 算谱系等级
   │           → 调速调姿态，不换行为只调强度
   └─ 不同 → 【机制乙·切换判断】算强度差 + 阈值判断
               → 三种结果：
                  ① 不切换，继续当前
                  ② 部分妥协，往谨慎滑
                  ③ 彻底切换，新焦点上位（切换后回甲确认新状态）
   ↓
焦点 + 谱系等级 → BehaviorExecutor（移动 / 待机 + 职业专属动作）
```

### 1.3 三个关键边界（设计铁律）

**边界一：乙不只是新刺激来了才工作。**
乙有两个作用：① 持续调节强度（环境有威胁就往下调投入度，从全力滑到警惕/谨慎）；② 切换判断（威胁足够大才中断）。妥协谱系中间态是持续动态的，不是切换瞬间才用。甲选了挖矿，乙从一开始就在调挖矿速度，不是等敌人到脸上才跳出来。

**边界二：甲是持续运行的，不是选完就睡。**
注意力系统一直在后台评分，维护刺激源排行榜。只有第一名变了，才触发乙的切换判断。大量弱刺激爬不到第一名，连触发乙的资格都没有，开销很小。

**边界三：「任务优先级」在两处含义不同。**
- 甲里：优先级是**刺激基础强度**，S 级任务天生权重高，更容易成焦点
- 乙里：优先级是**撤退阈值加成**，S 级任务阈值更高，更难被打断

同一属性两阶段作用不同，不能混。

### 1.4 架构坑（必须避免）

最常见错误：把撤退阈值直接当注意力分数用，"威胁分超过任务分就跑"，两机制合并成一个打分系统。

**后果**：
- 做不出边干边观察的中间态，只能二元开关
- 没有确认时间和衰减，敌人路过就反复横跳
- 后面加勇气、服从度、群体效应没地方挂

**正确做法**：两机制严格分层，各司其职。甲管选什么，乙管怎么执行怎么切换。中间态、渐变、性格差异全在乙层做。

## 二、刺激源系统

### 2.1 三种来源

| 来源类型 | 产生方式 | 典型场景 | 成本 |
|---------|---------|---------|------|
| **事件型** | EventBus 订阅转 Stimulus | 生产点满了、建造任务下发、建筑被毁 | 近零（广播） |
| **感知型** | 空间分区广播（敌人主动通知附近 NPC） | 敌人进入攻击范围、友军受伤 | 仅战斗时有 |
| **指令型** | 调度中心 / 君主直接下发 | 将军发号施令、君主下令砍树 | 近零 |

三种来源最终汇合为统一的 `IStimulus` 结构，进入机制甲评分。

**事件型责任链（防刺激列表膨胀）**：事件型刺激源**禁止**每个 NPC 各自订阅全图事件——否则刺激列表随 NPC 数膨胀，分片也救不回来。正确姿势：由区域聚合器 / 调度中心**统一订阅** EventBus → 按位置 / 任务相关度**过滤** → 只向相关 NPC 注入 `TaskStimulus`。7.2 的调度中心承担此分发职责（非 NPC 自订阅）。

### 2.2 按层分多结构（严谨版）

采用按层分结构（非单一扁平结构），每层有自己的字段，但共享基接口：

```
IStimulus（基接口）
  ├─ Layer layer          // 层属：Threat/Hate/Task/Perception/Curiosity
  ├─ Vector2 position     // 焦点对应位置
  ├─ float intensity      // 强度（甲层评分用）
  ├─ object source        // 来源对象 ref
  └─ float expiry         // 有效期/衰减时间
      │
      ├─ ThreatStimulus
      │    ├─ int threatLevel        // 威胁等级 0-3
      │    └─ UnitController enemy   // 敌人 ref
      │
      ├─ TaskStimulus
      │    ├─ TaskPriority priority  // S/A/B/C
      │    ├─ Vector2 targetPos      // 任务目标位置
      │    └─ object issuer          // 发起方（君主/调度中心）
      │
      ├─ PerceptionStimulus
      │    ├─ object perceived       // 感知对象 ref
      │    └─ PerceptionType type    // 感知类型
      │
      ├─ HateStimulus        // 首版留壳
      └─ CuriosityStimulus   // 首版留壳
```

## 三、机制甲·五层注意力

### 3.1 五层结构（高 → 低）

| 层 | 名称 | 典型刺激源 |
|----|------|-----------|
| 1 | 威胁 Threat | 敌人入范围、自身被攻击 |
| 2 | 仇恨 Hate | 被特定目标攻击累积（首版留壳） |
| 3 | 任务 Task | 君主指令、调度中心派工、生产点满 |
| 4 | 感知 Perception | 发现宝箱、看到友军受伤 |
| 5 | 好奇 Curiosity | 闲逛探索（首版留壳） |

### 3.2 层内分数与跨层压制

- **层内分数排序**：同一层内多个刺激源按 `intensity` 排序
- **跨层层压制**：高层任何活跃项 > 低层所有项（威胁层一项压过任务层全部）
- **焦点 = 排行榜第一名**

### 3.3 持续运行机制

- 注意力系统**持续后台评分**，维护刺激源排行榜
- 仅当**第一名变化**时，才触发机制乙的切换判断
- 大量弱刺激爬不到第一名，连触发乙的资格都没有 → 开销很小

### 3.4 任务优先级在甲层的含义

任务优先级（S/A/B/C）在甲层 = **刺激基础强度**。S 级任务天生权重高，更容易成为焦点。这决定了"能不能成为焦点"。

## 四、机制乙·三维权衡

### 4.1 两作用

| 作用 | 触发条件 | 行为 |
|------|---------|------|
| **强度调节** | 候选焦点 == 当前焦点 | 按威胁×优先级×服从度算谱系等级，调投入度/姿态，不换行为（首版仅谱系 4 撤退提速；0↔2 速度相同，见 6.2） |
| **切换判断** | 候选焦点 ≠ 当前焦点 | 算强度差 + 阈值，决定不切换 / 部分妥协 / 彻底切换 |

### 4.2 撤退阈值公式

```
撤退阈值 = 基础阈值 + 任务优先级加成 + 勇气加成 + 服从度加成

决策：
  威胁等级 > 撤退阈值 → 中断任务，进入避险行为
  威胁等级 ≤ 撤退阈值 → 继续执行，按威胁等级调整行为状态（谱系）
```

### 4.3 任务优先级在乙层的含义

任务优先级（S/A/B/C）在乙层 = **撤退阈值加成**。S 级任务阈值更高，更难被打断。这决定了"成了焦点后容不容易被抢"。

| 优先级 | 场景 | 默认执行态度 | 撤退阈值加成 |
|--------|------|------------|------------|
| S 级·军令 | 守城、增援前线 | 高风险必执行 | 极高 |
| A 级·建设 | 危险区建防御塔 | 有风险优先完成 | 高（重伤才撤） |
| B 级·生产 | 挖矿、种田 | 遇明显威胁暂停 | 中 |
| C 级·杂务 | 搬运、闲逛 | 一有风吹草动跑 | 低 |

### 4.4 威胁感知等级

渐变非突变，事件驱动（非每帧全范围扫描），按危险程度分级。不同职业敏感度不同（农民更敏感、士兵阈值更高）——由 `NpcProfessionDef` 的 `perceptionRadius`（感知半径，士兵远 / 农民近）和 `threatSensitivity`（威胁敏感度，农民 +x / 士兵 -x）两个参数落地，不写进职业配置这句差异化就是空话：

| 等级 | 名称 | 触发条件 |
|------|------|---------|
| 0 | 无威胁 | 周边无敌人，处于安全区 |
| 1 | 警戒 | 远处有敌人或获知前方危险 |
| 2 | 危险 | 敌人在攻击范围或友军正在交战 |
| 3 | 致命 | 自身被攻击、血量过低或敌人数量碾压 |

### 4.5 个体属性（性格，预留接口）

- **勇气值**：面对威胁的抗压能力，高勇气更敢冒险（受职业、装备、近期胜负影响）
- **服从度**：执行命令的意愿，高服从更少抗命（受王国士气、近期事件影响）

## 五、威胁评定函数 ThreatAssessment

### 5.1 因子清单

威胁等级不是简单输入，而是多因子评定的子系统。机制乙的核心计算：

| 因子类 | 输入 | 作用 | 首版 |
|--------|------|------|:--:|
| **敌人因子** | 最近敌人距离 / 视野内敌人数量 / 敌人战斗力 | 正向推高 | ✅ |
| **友军因子** | 附近友军数量 / 友军战斗力 | 负向抵消（保护感） | ✅ |
| **地形因子** | 是否在城墙内 / 是否在掩体后 / 是否在安全区 | 负向抵消 | ✅ |
| **自身因子** | 自身血量比例 / 自身战斗力 | 调节敏感度（士兵比工人耐打） | ✅ |
| **时间因子** | 昼夜（夜晚威胁加重） | 可增可减 | ✅ |
| 群体因子 | 同类 NPC 数量（羊群效应） | — | ⬜ 日后测试 |
| 士气+胜负因子 | 王国士气 / 近期胜负 | — | ⬜ 日后测试 |
| 任务进度+领地因子 | 任务完成度 / 己方领地 | — | ⬜ 日后测试 |

函数架构支持扩展，日后测试加因子不破坏结构。

### 5.2 威胁等级 → 谱系映射

```
威胁 0（无）           → 谱系 0（全力执行）
威胁 1（警戒）         → 谱系 0（全力，但注意力提权威胁层）
威胁 2（危险）+ 有保护 → 谱系 2（谨慎：维持工作）
威胁 2（危险）+ 无保护 → 谱系 4（撤退）
威胁 3（致命）         → 谱系 4（撤退，无论有无保护）
```

关键：谱系 2（谨慎）的触发条件是"威胁 2 **且有保护**"——这正是"敌人在近但周围有 NPC/城墙保护→继续正常工作"的落地。

## 六、行为妥协谱系

### 6.1 五级谱系

在"全力执行"与"完全撤退"间设置过渡状态，让 NPC 行为自然。首版实现 0/2/4 三态，1/3 留接口：

| 谱系 | 名称 | 首版 | 表现 | 触发条件 |
|------|------|:--:|------|---------|
| 0 | 全力执行 | ✅ | 正常速度 + 正常执行 | 威胁 0 |
| 1 | 警惕执行 | ⬜留口 | 工作速度略降，偶尔回头，移动偏向友军 | 威胁 1 |
| 2 | 谨慎 | ✅ | 见 6.2 | 威胁 2 且有保护 |
| 3 | 边撤边做 | ⬜留口 | 优先自保，向安全区移动，途中兼顾任务 | 威胁刚超阈值 |
| 4 | 完全撤退 | ✅ | 放弃任务，直接逃 | 威胁 2 无保护 / 威胁 3 |

### 6.2 谨慎态精确定义

谨慎**不改变速度**。其真正含义：敌人在附近但有友军/城墙保护时，维持正常工作。

```
谱系 2·谨慎：
  → 维持当前焦点行为（不切换）
  → 抑制对低优先刺激源的响应（不乱跑、不破坏阵型）
  → 速度不变
  → 注意力提权威胁层（保持警戒，保护消失立即升级到撤退）
```

落地三个场景：
- 工人外面砍树，敌人来了 → 无保护 → 撤退（谱系 4）
- 军队顶前面，工人离得近 → 有友军保护 → 谨慎继续工作（谱系 2）
- 敌人在近，但周围有 NPC 保护 → 谨慎正常工作（谱系 2）

### 6.3 LOD × 谱系关联（架构洞察）

LOD 精度区与谱系联动，低精度区砍掉谨慎态省判定：

```
高精度区（活跃）：谱系 0 / 2 / 4 三态（全力 / 谨慎 / 撤退）
低精度区（休眠）：谱系 0 / 4 两态（正常 / 逃跑）—— 砍掉谨慎
```

低精度区 NPC 本来就"专注本职无威胁"，谨慎态判定（保护因子计算）可省，进一步降成本。

### 6.4 谱系切换防抖（防"模棱两可中死亡"）

离散谱系切换在边界处会抖动，导致 NPC 在状态间横跳、既没干活也没逃跑最后被打死。本节用三层防抖彻底消除。

**抖动剧本（必须解决）**：

1. **保护因子边界**：友军数在 2↔3 波动 → 谨慎↔撤退横跳（最致命，工人边干边跑被流矢打死）
2. **威胁 1↔2 边界**：敌人在攻击范围边缘来回蹭 → 全力↔谨慎抖动
3. **威胁 2↔3 边界**：血量/敌人数在阈值波动 → 谱系反复改判
4. **离开-返回循环**：撤退→跑远→威胁降→全力→回去→又遇敌→撤退... 在战场边缘反复进出

**三层防抖**：

| 层 | 机制 | 解决剧本 |
|----|------|---------|
| 输入侧滞回 | 威胁等级 + 保护因子用双阈值（升/降不同）+ 持续确认 | 1 / 2 / 3 |
| 状态侧驻留 | 进入某谱系后最小停留 N 秒，期间不响应切换 | 1 / 2 / 3 |
| 撤退安全确认 | 跑到威胁 0 区 + 至少待 N 秒才重新评估任务 | 4 |

**输入侧滞回（关键）**：威胁等级不是瞬时判定，而是带滞回的累积判定，符合 7.1 节"上升快、下降慢"原则：

```
威胁因子 X（距离/数量/血量综合）
  1→2 升级：X 持续 > 0.6 达 0.3s
  2→1 降级：X 持续 < 0.4 达 0.5s   // 升快降慢
  中间 0.4~0.6 = 滞回带，保持当前等级

保护因子（友军数）
  达标：≥3 进入保护
  失效：<1 退出保护
  中间 1-3 = 滞回带
  （城墙保护：在城墙内即稳定达标，无边界问题）
```

**状态侧驻留**：进入谨慎至少驻留 1s，进入撤退至少驻留 1.5s，期间不响应切换，防止高频跳变。

**撤退安全确认**：撤退态跑到威胁 0 区后，不立即切全力，至少停留 2s 确认安全才重新评估任务焦点，防止"跑两步就回头"的离开-返回循环。

**正交性**：本防抖不改变谱系定义和触发条件（6.1/6.2 不变），只让切换变稳定。谱系还是那个谱系，只是不再抖。具体配置见第九节防抖参数表。

## 七、性能架构

### 7.1 空间分区感知广播系统

传统做法让每个 NPC 每帧扫描周围敌人，NPC 一多开销呈平方级增长。本系统反转感知逻辑：**不是 NPC 找敌人，而是敌人主动通知附近 NPC**。

```
地图划格（复用 GridSystem 现有 cellSize，首版 2.26 世界单位），每格维护内部 NPC / 敌人列表
  - 实体移动跨格才更新列表，同格内移动零开销
    责任人：UnitController 移动时调 GridSystem.TryEnter 维护实体列表；
    NPCBrain 驱动 UnitController 移动即间接触发，不自行管格子
  - 查周围敌人按感知半径动态算格数：n = ceil(R / cellSize)，查 (2n+1)² 格
    （不硬编码"9 格"——cellSize 已固定为地图设计值，未必大于感知半径 R；
     若 R > cellSize 则 3×3 共 9 格不够覆盖会漏检，必须按半径算）
  - 敌人进新格 → 向周围格 NPC 发"有敌人进入"事件
  - 敌人离开 → 发"离开"事件
  - 无敌人移动时，感知开销为零，与 NPC 总数几乎无关
```

威胁等级分档：**上升快、下降慢**。敌人离开后威胁缓慢衰减，NPC 保持警戒再恢复，避免反复横跳。

复用 `GridSystem`（3.2 已实现）的区块结构做空间分区。

### 7.2 中心化任务调度 + 空闲工人空间池

> **[2026-07-31] 本节移至 3.5.0 经济循环产能调度前置系统。** 本节内容属产能系统范畴，非战斗 AI。3.0.1 保留"NPCBrain 能接收 TaskStimulus"的接口声明，调度逻辑本身归 3.5.0 文档。以下内容保留备查。

工作分配的常见误区是让建筑广播任务、NPC 各自判断接不接，本质都是个体自主决策，规模一大开销爆炸。本系统引入中心化调度中心做中间人：

```
工作点位 → 调度中心发招工请求（位置 / 人数 / 半径 / 优先级）
调度中心 → 维护"空闲工人空间池"，只查点位周围格子的空闲工人
         → 按距离排序依次分配，招满为止
         → 没招满过几秒重试
工人 → 干完活把自己放回池子，接任务移除，移动时更新格子
```

通信量从平方级降到线性级。

**关键优化**：
- 请求节流（同一点位同时只有一个待处理请求）
- 招募半径限制候选数
- 请求队列分片平摊到多帧防爆卡
- 按村庄分区互不干扰
- 高优先级任务优先分配甚至挖人
- 神经元自主选择（后续）：先选最近 N 个候选，只让这批判断接不接，限制候选上限

### 7.3 LOD 三区（首版留接口，不实现）

| 区 | 触发条件 | 精度 | 谱系 |
|----|---------|------|------|
| 活跃区 | 玩家视野内 / 战斗中 / 被围城 / 新建建筑 | 完整高精度 | 0/2/4 |
| 半活跃区 | 视野外但接壤活跃区（前线后方 / 补给通道） | 中等精度 | 0/2/4 |
| 休眠区 | 远离玩家 / 无敌人 / 长期无事件的内陆村庄 | 极简 | 0/4 |

休眠区/半活跃区基本无威胁，NPC 专注本职工作，大幅拉长"生动行为"思考时间，但保留基础流动能力（NPC 可能从王国一边走到另一边，思考时间分配到更长维度）。

**首版**：所有 NPC 同精度（空间分区 + 中心化调度已够扛 500-600 AI），LOD 三区留接口不实现。

### 7.4 对象池改造（实例池 + 空闲逻辑池）

> **2026-08-01 需求讨论定稿**。背景：全项目无对象池，单位 Instantiate 直接创建、死亡 Destroy 直接销毁（RulerController.cs:307）——500-1000+ 规模下成批死亡 = GC 尖峰卡帧。本节定义统一池架构。

**两类"池"的生命周期辨析（铁律）**：空闲池里的 NPC 是**活的**（要渲染、要 Think、要占格子）；实例池里的 GameObject 是**尸体原料**（SetActive(false)，不占格子不思考）。两者不混装，统一方式是**一门面两层分桶**：

```
UnitManager（统一门面：全项目单位生/死/回收唯一入口，挂载 UnitFactory 现有生成路径）
├─ 实例层 UnitInstancePool：按 prefab/职业分桶（工人/士兵/弓箭手/亡灵…）
│    出生 → 取桶 → 初始化 → 激活；桶空 → 动态扩容
│    死亡 → 播死亡动画（延迟回收 1.5s 占位）→ Reset → SetActive(false) 回桶
├─ 逻辑层 IdleRegistry：按职业×格子分桶的空闲劳动力登记
│    空闲工人桶（3.5.0 调度中心消费）/ 空闲士兵桶（3.0.1_3 将军招募消费）
│    任务完成 / 编队解散 → 注册进桶；被调度 / 被招募 → 移出
└─ 联动铁律：回实例池 = 自动移出逻辑池（死人不接活）
```

**重置契约（白嫖现成）**：`IMemoryComponent.Reset()` 已实装（受击冷却/量化器均可重置），池化回收时遍历调用；外加血量/格子登记（GridSystem.RemoveUnit）/脑状态/执行器状态复位。

**预热策略**：开局按职业预热（占位：工人 200 / 士兵 100 / 敌人 200），超额动态扩容——战斗尖峰零 Instantiate；敌人波次生成是最大收益场景。

**与其他系统的关系**：
- **LOD**（3.0.1_LOD）：空闲池 NPC 多在休眠区 0.5Hz 思考，1000 闲人也便宜；实例池对象无 LOD 状态（不在 GridSystem 登记）。
- **存档**：只存活的（激活）单位；实例池中的非激活对象不入档；预热在加载后按存档重建。
- **TeardownManager**：场景切换由 Destroy 改为回池。
- **3.5.0 / 3.0.1_3**：空闲工人池/士兵池此前均为"同构对象是空气"——本节即两者的统一落地架构。

**新增参数**：预热数量表（职业×数量）/ 死亡回收延迟 1.5s / 桶扩容步长 50——住 WorldConfig 或独立 PoolConfig SO（实施时定）。

**实施优先级**：P0 = UnitInstancePool（门面+分桶+预热+延迟回收+Reset 契约）；P1 = IdleRegistry 逻辑层（先士兵桶服务 3.0.1_3 P0 招募，工人桶随 3.5.0）；P2 = 尸体停留表现、池统计进调试面板。⚠️ 依赖链（2026-08-01 审计 D2）：对象池与 3.0.1_3 P0 **正交可并行**——编队 P0 招募绕开 ScheduleCenterStub 自管、ClearFormationState 白嫖已实装的 IMemoryComponent 契约；对象池真正消费场景是敌人波次生成与 500+ 规模。

## 八、通用 NPC 框架（干细胞）+ 细胞分化

### 8.1 设计理念

所有 NPC 共用一套"干细胞"框架（通用 NPCBrain），知道基础行为。装上职业配置（刺激源响应 + 任务层）后，NPC 就知道怎么干。职业差异靠 SO 配置，不靠硬编码子类。

```
NPCBrain（通用，所有 NPC 挂载）
  ├─ AttentionSystem（五层注意力，机制甲，通用）
  ├─ TradeoffSystem（三维权衡，机制乙，通用）
  ├─ BehaviorExecutor（焦点→动作，通用动作集：移动 / 待机）
  └─ NpcProfessionDef（职业配置，SO，决定分化）
       ├─ 响应哪些刺激源
       ├─ 五层权重
       ├─ 专属动作映射
       └─ 服从度 / 勇气基础值
```

细胞分化示例：
- 工人 + 农民都会跑（基础行为） → 农民会种地、工人会搬砖（职业附加）
- 士兵 + 箭塔都会响应敌人 → 士兵移动靠近、箭塔原地攻击（动作映射不同）

### 8.2 通用 NPCBrain 基础能力（首版）

| 能力 | 说明 |
|------|------|
| 移动 | 走到焦点对应位置（MoveTowards） |
| 待机 | 无焦点时原地待机 |
| 权衡 | 三维权衡（机制乙） |
| 注意力 | 五层注意力（机制甲） |

职业专属动作（采集 / 攻击 / 种地）通过 `NpcProfessionDef` 的动作映射附加，首版以占位形式验证（见 8.3）。

### 8.3 首版双职业验证场景

| 职业 | 刺激源类型 | 焦点动作 | 验证目的 |
|------|-----------|---------|---------|
| **工人** | 事件型（生产点满） | 移动到采集点 → 移动到城堡 | 验证事件型刺激源 + 移动链路 |
| **士兵** | 感知型（敌人入范围） | 移动靠近敌人 → 攻击 | 验证感知型刺激源 + 移动型 AI + 战斗闭环 |

> **箭塔不是 NPC**（NPC 以后会站在箭塔上攻击），首版不验证箭塔 AI。非移动 AI（固定哨位 NPC）留后。

**首版含完整伤害管线**（不再是"位移即目的"）：士兵会真攻击、敌人会真受伤死亡、NPC 会被攻击触发威胁 3 致命 → 验证完整的"受击 → 威胁升级 → 撤退"闭环。完整伤害管线（攻击判定 / 血量 / 护甲 / 伤害类型 / 弹道 / 死亡）设计归 3.4 文档（**待写**），3.0.1 首版依赖其完整实现。美术占位复用已实现的 3.1 `PlaceholderSprites`，扩展 NPC / 敌人 sprite 即可。

**避障依赖声明（硬依赖，必须在排期认掉）**：当前 `UnitController.MoveTowards` 是 `Vector2.MoveTowards` 直线移动，**无避障、无 NavMesh、无路径规划**。首版验证场景**必须用空地**，一旦进真实地图 NPC 会卡墙角。`GridSystem` 已有障碍数据（`IsObstacle` / `MarkOccupied`），但移动逻辑未使用。完整避障依赖 3.3《移动与障碍处理》模块，该模块尚未编写，需在排期里单独认掉。

## 附录 A：AI 调试可视化规格（首版个体深查）

### A.1 目的

AI 决策是内部状态，无可视化则黑盒——写完 NPCBrain 跑起来只看到 NPC 乱走，看不出注意力 / 谱系 / 焦点的好坏，SO 滑块拖了也白搭。本附录规格化运行时调试 UI，把内部决策变成可见。**群体概览**（满屏焦点连线 + 谱系色块）留到多 NPC 合作阶段，首版只做**个体深查**。

### A.2 交互流程

1. **F1** 开发者面板（屏幕中间，UI Toolkit）
2. 面板含"选择 NPC 查看 AI"按钮 + 模式说明
3. 点按钮 → 隐藏面板 → 顶部提示"请选择要查看的 NPC"
4. 鼠标悬停 NPC 高亮 + 简略状态预览；点击锁定深查
5. 左上角显示该 NPC 的 AI 状态面板
6. 退出用现有 UI 逻辑

### A.3 左上角面板内容

- 当前焦点（刺激源 / 层 / 强度 / 位置）
- 当前谱系（全力 / 谨慎 / 撤退，色块标识）
- 刺激源排行榜前 5（甲层）
- 威胁等级 + 保护因子
- 最近 5 次切换历史（焦点 / 谱系，带时间戳）

### A.4 技术实现

- UI Toolkit（UXML + USS），符合项目 UI 全面迁移惯例
- NPCBrain 暴露 `IAIDebugInfo` 接口供面板实时读取
