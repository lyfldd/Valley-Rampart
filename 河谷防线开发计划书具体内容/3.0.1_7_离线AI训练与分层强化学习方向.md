## 一、目标与核心思路

- **脱离 Unity 模拟对战**：决策核（纯 C#）双适配——Unity 适配器 + Headless 模拟器适配器，模拟器快速批量跑对局出数据。
- **RL 训练出最佳方案**：分层强化学习（FeUdal Networks 为蓝本）学习"将军意图 + 士兵行为"的完整策略。
- **离线训练 → 回灌**：训练出的策略导出（权重/阈值或网络），映射回 Unity 配置，真实对局生效。

## 二、为什么选 FeUdal Networks（可行性依据）

FeUdal 两层结构与现有架构天然映射：

| FuN 概念 | 现有结构 |
|----------|----------|
| Manager（低频产出 goal 向量） | FormationController / 将军（意图/阵型，低频） |
| Worker（高频吃 goal 输出动作） | 个体 NPCBrain（移动/攻击/站位，10Hz） |
| goal 向量 | 战术意图（"前压 2 格"/"向槽位集中"） |
| 内在奖励 = 状态变化与 goal 对齐 | **士兵是否朝目标槽位/阵型移动 = 队形保持** |

**关键洞察**：用户担心的"单纯以存活为奖励会忽略队形"——FeUdal 的内在奖励机制天然解决：
Worker 奖励 = 外部奖励（击杀/受击/胜负）+ 内在奖励（状态变化与 goal 的 cos 对齐）。
队形保持被编码为内在奖励，无需手工设计"队形保持度"奖励项。**将军意图就是 goal，士兵槽位跟随就是对齐**。

## 三、架构总览（决策核解耦）

```
现有：NPCBrain(MonoBehaviour) ←→ UnityEngine(Vector2/Time/Transform)
                              ↓ 解耦
目标：决策核(纯 C#) ←→ IWorldPort(抽象世界接口)
                      ↙        ↘
            Unity 适配器      Headless 模拟器适配器
```

- **决策核** = AttentionSystem + L1/L2/L3 + FactorContext + 公式计算（几乎纯计算）
- **解耦工作**：UnityEngine.Vector2 → 自研 Vector2x；Time.time → tick 计数器；感知/攻击判定 → 接口
- **模拟器**：单位数组 + 位置(1D x) + HP + 攻击判定 + 感知（线性扫描）+ 伤害公式 + 投射物

**最大陷阱 = 保真度（sim-to-real gap）**：模拟器战斗结果必须与 Unity 一致，否则训练策略在真实游戏失效。
需完整复刻：DamageConfig 伤害公式（atk×(1-def/(def+K))）、CD、overkill、感知半径、think 10Hz、阵型槽位分配逻辑。

## 四、日志/数据设计（两类，分开）

1. **训练态数据**（喂网络）：每决策 tick 输出数值张量
   `[自身位置, HP比, 最近敌距离, 敌数量, 槽位偏差, 当前意图, 威胁等级...] → [动作] → [奖励标量]`
2. **分析态日志**（诊断"为什么学歪"）：JSON Lines 事件流
   `unit_died{职业,位置,击杀者}` / `formation_switched{意图}` / `attack_hit{伤害}` / `retreat{原因}` /
   每 tick `slot_deviation`（成员与槽位偏差均值）时间线

## 五、奖励函数设计（分层）

- **Manager（将军）**：稀疏战略奖励——击杀差、领地推进、最终胜负
- **Worker（士兵）**：密集战术奖励——
  - 外部：击杀 +1 / 受击 -0.5 / 死亡 -10（按职业价值加权）
  - 内在：状态变化与 goal cos 对齐（= 队形保持 + 意图跟随，FuN 自动给）
- 过程指标（战损比/破阵次数）作 shaping 辅助，先不依赖

## 六、动作空间（三条路线对比，定案）

| 路线 | 说明 | 可解释性 | 效果上限 | 收敛难度 | 工作量 |
|------|------|---------|---------|---------|--------|
| A 参数化调参 | RL 输出权重/阈值注入 AttentionTuningConfig 等 | 高 | 低（原公式天花板） | 低 | 低 |
| B 混合 | 将军意图层 RL（FuN Manager），个体仍公式+微调 | 中 | 中 | 中 | 中 |
| C 端到端 FeUdal | Manager(将军)+Worker(士兵) 均为网络，完整 FuN | 低 | **高（无公式天花板）** | 高 | 高 |

**定案（2026-08-02，用户授权"效果优先，代价可接受"）：以 C 端到端 FeUdal 为目标架构；A 作为"模拟器保真验证期"的过渡工具**——
先跑通"模拟器对局 → 数据流 → A 参数化调参闭环"验证管线保真，再演进到 C 端到端分层。
