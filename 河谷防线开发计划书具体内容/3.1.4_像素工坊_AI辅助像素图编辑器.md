## 〇、定位与目标

**像素工坊**是一个服务于本项目美术资产生产的本地工具链：网页像素编辑器 + opencode agent，让 AI 能以"文本网格"为媒介对像素图做像素级精确修改。

**核心洞察**：项目单位图为 32×32、13~16 色小调色板（实测 `Assets/_Game/Art/Units/` 13 张），整图转文本仅 1~2k token——AI 能在单次上下文里"看全"并精确编辑每个像素。这是文生图模型做不到的（重画整张、风格漂移、无法保证未改区域 bit 级不变）。

**服务对象**：
- 单位图：`Assets/_Game/Art/Units/`（13 张，32×32，≤16 色）
- 地块图：`Assets/_Game/Art/Ground/`（8 张，170×200~172×204，4000~6000 色，软边缘手绘风）——走降级管线（§二.3）

**四个核心场景**（用户确认）：
1. 打磨现有图（描边/轮廓/细节/风格统一）
2. 阵营变体工厂（四王国换色变体批量产出）
3. 从零生成（建筑/UI/物件初稿）
4. 分析质检（风格一致性检查：描边有无/光源方向/调色板纪律）

**四项用户决策**（2026-09-01 确认）：
| 决策点 | 结论 |
|--------|------|
| 资产安全 | 暂存区 + 发布：AI 只碰 `workspace/`，人工点"发布"才拷入 Assets |
| 编辑能力 | AI + 人工手绘都要（铅笔/橡皮/吸色/油漆桶，AI 改完差两笔手补） |
| 技术栈 | 单文件 HTML 编辑器 + pwsh 启动脚本，零构建零依赖 |
| 工具范围 | 像素图 + 地块图都管（地块走量化降色 + 分块降级管线） |

### 1.3 两条工作回路

**单图回路（编辑器内 AI 面板，日常打磨）**：
1. 编辑器从 workspace 载入 `.grid.txt`（或现场调用 png2grid 转换）
2. 用户输入自然语言指令（如"头盔加一道高光"）
3. 编辑器将**当前网格全文内联**进 prompt，附带 json_schema 结构化输出约束，POST 到 opencode `/session/:id/message`
4. opencode 返回新网格（schema 校验失败自动重试，默认 2 次）
5. 编辑器渲染 diff 预览（改动像素高亮，改前/改后/差异三视图）
6. 用户点接受 → 写回 `.grid.txt` 并刷新 PNG；点拒绝 → 丢弃
7. **AI 在此回路中不接触任何文件**（网格全程内联），绝对安全

**批量回路（agent 自主，成批任务）**：
1. 用户在编辑器"任务"框输入批量指令（如"13 张单位图全部加 1px 深色描边"）
2. agent 在 workspace 按 AGENTS.md 协议干活：读 `.grid.txt` → 改 → 回写 → 跑 grid2png
3. 编辑器轮询 `GET /session/:id/diff` 展示文件级改动清单，逐张预览
4. 不满意可 `POST /session/:id/revert` 整批回滚
5. 全部确认后才进入发布流程

### 1.4 编辑器界面分区（单文件 HTML）

| 区 | 内容 |
|----|------|
| 顶栏 | 文件列表刷新 / 保存 / 撤销·重做 / 改名（别名）/ 健康状态（AI·Unity 根） |
| 左栏 | 手绘工具：铅笔/橡皮/吸色/油漆桶/直线/矩形 + 网格线开关 + 缩放（4x~32x） |
| 中央 | 像素画布（Canvas 渲染，格子吸附绘制）+ diff 高亮层（半透明叠加改动像素） |
| 右栏上 | 调色板（点击选色，显示十六进制值，支持锁定语义色槽） |
| 右栏下 | AI 面板：单图指令输入 / diff 三视图（改前·改后·差异）/ 接受·拒绝；批量任务框 + 进度日志 |

### 1.5 opencode 接入配置

- 启动：`opencode serve --port 4096 --hostname 127.0.0.1`（start.ps1 探活失败时自动拉起；AI 调用经 serve.mjs 服务端代理，浏览器零 CORS 配置）
- 静态服务：start.ps1 拉起 `node server/serve.mjs --port 5173`（自研零依赖：静态白名单 + workspace API + AI 代理，仅监听 127.0.0.1）
- 会话：单图回路每次任务新建 session（实测 v1.18.19：`POST /session` + `POST /session/{id}/message`，结果落 `info.structured`）；批量回路一个长期 session（协议来自 workspace/AGENTS.md，opencode 原生读取）
- 结构化输出：请求体带 `format: { type: "json_schema", schema: <网格协议 schema>, retryCount: 2 }`，畸形输出被服务端校验拦截并自动重试
- **模型选择**（2026-09-01 增补）：编辑器 AI 面板带模型下拉（`GET /api/models` 代理 opencode `/api/model`），默认=opencode 当前模型（实测 big-pickle），可选 zen 免费池 30 个模型（多模态标 👁、废弃标 ⚠旧、附上下文长度）；选择存 localStorage；`message` 请求体透传 `model:{providerID,modelID}`。**模型能力实测对比**：big-pickle 指令遵循外科级（恰改 1 像素）；nemotron-3.5-lightning-free 格式合法但过度修改（154 像素）——网格编辑是纯文本"摆字符"任务，任何强文本模型可用，指令精度差异靠 diff 预览人工把关；deprecated 模型可能已下线（glm-5-free 实测 500）
- 不设 `OPENCODE_SERVER_PASSWORD`（仅本机 127.0.0.1 监听）

## 二、数据定义

### 2.1 网格文本协议 v1（`.grid.txt`）

```
# forge v1 | name=01_image-1786607542814-u7ibxrayc2e | size=32x32 | colors=15
# palette
. = transparent
0 = #2a1a3a
1 = #4a3a5a
2 = #7a6a8a
...
# grid
................................
.............000000.............
............01111110............
...(32 行，每行恰好 32 字符)......
................................
```

**硬性规则**：
- 字符集：`.`（透明）+ `0-9` `a-z` `A-Z` `#` `$` `%` `&`（66 个色字符；调色板上限约定 ≤64，留 2 字符冗余防越界）
- 调色板色值：`#rrggbb`（不透明）或 `#rrggbbaa`（半透明，alpha≠255 时）；全透明像素（alpha=0）一律 `.`，其 RGB 分量归一化为 0（AI 生图透明区常带杂色 RGB，显示无差、协议不携带）
- 调色板按频率降序分配字符（最高频色用 `0`，方便 AI 记忆）
- 网格行数=图高，每行字符数=图宽，**禁止行尾空白**
- 解析时任何一行宽度不符或字符越界 → 整文件拒绝（见 §五.1）

### 2.2 结构化输出 schema（单图回路）

```json
{
  "type": "object",
  "required": ["palette", "grid"],
  "properties": {
    "palette": {
      "type": "array", "maxItems": 64,
      "items": { "type": "string", "pattern": "^#[0-9a-fA-F]{6}([0-9a-fA-F]{2})?$" }
    },
    "grid": {
      "type": "array", "minItems": 32, "maxItems": 32,
      "items": { "type": "string", "pattern": "^[.0-9a-zA-Z#$%&]{32}$" }
    }
  }
}
```

（48×48 图 minItems/maxItems/pattern 位数随实际尺寸生成。）

### 2.3 地块图降级管线（Ground 专属）

地块图 170×200 ≈ 34,000 像素、数千色，超出单次上下文编辑能力，走三级降级：

1. **量化降色**：`quantize.mjs` 用中位数切割算法压到 ≤48 色，输出预览对比图，**用户确认色损可接受**才落盘（如不可接受则该图退出管线，人工处理）
2. **分块**：切为 32×32 块（170×200 → 6 列 × 7 行 = 42 块），每块独立 `.grid.txt`，AI 每次编辑 1~4 块，块间共享同一份调色板文件（`ground/<图名>.palette.txt`）
3. **降采样概览**：43×50 缩略网格（面积均值采样）作为 `overview.grid.txt`，仅用于"分析质检"场景让 AI 看整体构图，不用于编辑回写

**地块图的四个 AI 场景降级映射**：
| 场景 | 单位图 | 地块图 |
|------|--------|--------|
| 打磨 | 全图网格编辑 | 分块编辑（一次 1~4 块） |
| 变体工厂 | 调色板重映射（纯代码） | 同左（重映射后可再叠加原软边缘 alpha 通道，见 §五.4） |
| 从零生成 | 直接生成 | **不支持全图生成**；改为"生成小物件 → 合成叠加到地块"（物件 ≤48×48 走单位图管线，合成是纯代码 paste） |
| 分析质检 | 全图直读 | 降采样概览 + 抽块深查 |

### 2.4 workspace 资产台账（manifest.json）

```json
{
  "units/01_image-1786607542814-u7ibxrayc2e.png": {
    "alias": "剑士", "source": "Assets/_Game/Art/Units/01_...png",
    "size": "32x32", "paletteCount": 14, "importedAt": "2026-09-01"
  }
}
```

- **文件名保持与 Assets 原名一致**（发布时零映射、Unity 引用不断）
- `alias` 语义别名供 AI 指令引用（"给剑士加描边"而非报哈希文件名），初始可空，随手补

### 2.5 变体工厂数据（palette 变体表）

`workspace/variants/kingdoms.json`：
```json
{
  "kingdom_red":  { "2a1a3a": "3a1a1a", "4a3a5a": "5a3a3a", "...": "..." },
  "kingdom_blue": { "...": "..." }
}
```
- 每王国一套映射表，键=源色，值=目标色，**保持明度关系不变**（HSL 的 L 值偏差 ≤5%）
- 映射表由 AI 一次性设计（用户指令："为四个王国各设计一套配色，保持明暗结构"），产出后存档复用
- `remap.mjs` 纯代码遍历执行：13 图 × 4 王国 = 52 张，秒级完成，**不消耗 AI 调用**

## 三、数据流与生命周期

### 3.1 工具生命周期（过八格）

| 阶段 | 语义 | 实现 |
|------|------|------|
| 诞生 | workspace 初始化 | `start.ps1 -Init`：从 Assets 拷入首批图 → png2grid → 生成 manifest |
| 归属 | 内存态 vs 磁盘态 | 编辑器画布有未保存改动时顶栏黄标；AI 单图回路结果在接受前只存内存 diff 区 |
| 更新 | 磁盘同步 | 保存=写 `.grid.txt` + grid2png 刷新 PNG（双文件原子成对写，见 §五.3） |
| 挂起恢复 | 浏览器刷新 | manifest + 磁盘文件为准，无 localStorage 状态（重启零依赖） |
| 正常终结 | 发布 | 人工点"发布"→ 拷 PNG 到 Assets 对应路径（§3.2），workspace 原文件保留作源 |
| 异常终结 | 回滚 | 单图=拒绝 diff；批量=`/session/:id/revert`；误发布=git 兜底 |
| 清算 | 变体归档 | variants/ 发布后移入 `variants/published/` 记录批次 |
| 持久化 | git | workspace 全部文本（.grid.txt/manifest/json）git 跟踪，PNG 二进制照常跟踪 |

### 3.2 发布流程（进入 Assets 的唯一通道）

1. 编辑器列出"待发布"清单（本次会话中接受过的文件）
2. 用户逐张勾选确认（默认全选，可取消）
3. 拷贝 PNG 到 `manifest.json` 记录的 `source` 路径，**同名覆盖**
4. **铁律：只写 PNG 内容，绝不触碰 `.meta` 文件**——覆盖已有图时保留原 `.meta`（GUID 不变，场景/SO 引用全保）；新图则不生成 `.meta`，回到 Unity 让其自动生成
5. 发布完成后提示："回到 Unity 等重导入，检查 Sprite 导入设置（Filter Mode=Point / Compression=None）"

### 3.3 AI 会话生命周期

- 单图回路：每任务一个 session，任务完成即弃（无清理负担，opencode 本地存档）
- 批量回路：编辑器启动时若 workspace 有未完结批量 session（manifest 记录 session id），提示"继续或放弃"
- 协议头版本化：AGENTS.md 与单图 prompt 内联协议头标注 `forge v1`，v2 起旧 workspace 需跑一次升级脚本

## 五、错误处理与边界情况

### 5.1 网格校验失败
- 解析 `.grid.txt`：行数/行宽/非法字符/调色板缺色任一不符 → 拒绝加载，报错定位到行号
- AI 返回：json_schema 服务端拦截自动重试 2 次，仍失败 → 编辑器丢弃本次结果，AI 面板显示"模型输出不合规，请换个说法再试"

### 5.2 opencode 不可达
- 启动脚本先 `GET /global/health` 探活，失败则报"opencode serve 未启动，请先运行 opencode serve --port 4096 --cors http://localhost:5173"
- 编辑器中 AI 请求超时（30s 无响应）→ 面板红字提示 + 重试按钮；手绘功能完全不受影响（离线可用是底线）

### 5.3 双文件一致性（.grid.txt 与 PNG）
- 真源是 `.grid.txt`，PNG 是它的渲染产物
- 所有写入成对执行（先写 grid 再跑 grid2png）；grid2png 失败则回滚 grid 写入，保证不出现"grid 新 PNG 旧"
- 载入时校验成对时间戳，PNG 比 grid 新 → 提示"检测到 PNG 被外部修改（如手 PS 过），以哪个为准？"二选一

### 5.4 地块量化色损
- 量化前生成并排对比预览；用户否决 → 该图标记 `manual_only`，不出现在 AI 可编辑列表
- 软边缘图量化后边缘可能出现色带：接受为已知代价；变体工厂对 Ground 图在重映射后叠加**原始 alpha 通道**（量化仅压缩 RGB，alpha 独立保留），边缘平滑度不劣化

### 5.5 发布覆盖冲突
- 目标 Assets 文件被外部修改（比 workspace 导入时的快照新）→ 发布前 diff 字节级比对，不一致则弹窗警告"Assets 里的图比导入时新，确认覆盖？"
- `.meta` 存在性检查：目标有 .meta 而发布流程试图写 .meta → 直接阻断（理论上不会发生，防御性编程）

### 5.6 浏览器兼容
- ~~File System Access API 仅 Chrome/Edge 支持~~（实施修订：改用 serve.mjs 本地 API 后不再依赖浏览器文件系统 API）——任意现代浏览器全功能可用（编辑器页面与 API 同源，无 CORS 依赖）
