## 一、审计问题定义（三层规格）

用户原始担忧：「基础建筑的功能链条中断……担心其他最基础系统在生命周期中被别人引用的部分是断掉的」。转译为三层可执行规格：

| 层 | 审计问题 | 产出 |
|---|---------|------|
| **L1 供给面完整性** | 每个基础系统**声称**对外提供的服务（公开 API / EventBus 事件 / 注册表 / SO 配置 / 资源资产），实现真的存在吗？（反幽灵引用） | 幽灵清单（声称-实现差集） |
| **L2 消费链完整性** | 每条「生产→引用→消费」链路，**玩家与 AI 双主体**在**生命周期各阶段**（生成→注册→运作→消费→死亡→存档）都能走到终点吗？ | 断链清单（断点+断环定位） |
| **L3 失败可见性** | 所有可能断链处，有没有日志/告警/异常？（静默失败=断链不可发现，比断链本身更危险） | 静默点清单 |

**生命周期维度叠加**：每片内每条链路按「生成→注册→运作→消费→死亡→存档」六阶段核引用完整性（用户原始担忧的直接映射）。

| **P2** | 语义断层 | 生成端赋值与消费端判定不一致（同字段两套语义） | 流浪汉「未入籍=-1」设计 vs SpawnUnit 默认 0（AI 招募恒拒，三考卡死点） | 生成端赋值点 × 消费端判定点对拍 |
| **P3** | 数据源排除 | 消费循环的数据源集合结构性不含某主体 | 繁殖配对池 _entities 桶 0 专属（AI 单位不在数据源，D539 实锤） | 数据源集合的过滤条件核读 |

| **P6** | 静默失败 | 失败分支无日志/告警，断链不可发现 | ⑥招工 FindRecruitableVagrant null return 零日志（三考卡死点） | 失败分支日志覆盖率 |
