# QQQ.6 AINPC 弹话文案族化与丰富化

> 散乱细节优化文档 · 创建于 2026-09-10
> 本文档收集 1 个散乱需求（弹话文案族化+丰富化+搞怪化），配套执行清单见 QQQ.6_执行清单.md
> 文案稿已用户拍板（2026-09-10）；派活载体=HH.153（策划端→执行端施工任务书），完成报告=HH.154

## 概述

用户（策划端拍板）：AINPC 时不时弹出的头顶话（空闲自动说话 + 点击对话）要**更丰富、更搞怪**，搞怪风格参考选族文案（HH.96 §四 抽象搞怪定稿版），并要求**每一族的话不一样、每一职业不一样**。性能问题之前已考虑（QQQ.2 DR-10 全套管控），本批只需确认文案扩充不引入新开销。

核心缺口：现有对话池（`UnitController.GetTalkPool`，17 职业 × 正常/饥饿/受伤三态）**完全没有种族维度**——兽人战士与人类战士说一模一样的话。本批新增族维度 + 职业池扩充搞怪化。

## 需求 1：双层池结构（族池 + 职业池混合）

### 问题/现状

- `UnitController.PickTalkLine()`（UnitController.cs:1444-1450）：`GetTalkLinesByOccupation(EffectiveOccupation, hungry, injured)` → `GetTalkPool(occ, state)`，只按职业+状态返回硬编码 `string[]`，**不看 `raceId`**。
- 触发源两处共用本口子：① `NPCBrain.TickAutoTalk` 空闲自动说话（15-30s 随机，OverheadSpeechManager 管控）；② `BuildInteractActions` 点击对话。
- `UnitController.raceId`（L57，D467 终身字段）已落地可读——族维度技术上零障碍。

### 方案（已拍板）

**不做"族×职业×状态"笛卡尔**（=17×4×3≈204 池≈近千句，单人 1 个月规模爆炸）。采用**双层池混合**：

```
PickTalkLine(raceId, occ, 状态)
 ├─ 正常态：40% 概率抽【族池】（说话者自身种族口癖，4 族 × 8 句）
 │           60% 概率抽【职业池·正常】
 └─ 饥饿/受伤态：100% 抽【职业池·状态】（状态信息优先，不混族池出戏）
```

1. **族池**：第一人称族味吐槽，化用选族稿已定稿的四族钩子与机制信息量（农耕均衡/以战养战/磐石锻造/视界守护）。一耳朵听出是兽人还是精灵。
2. **职业池**：保留现有三态结构，去共用开场、扩充、搞怪化（文案见需求 3）。
3. **比例 SO 化**：`AttentionTuningConfig` 新增 `talkRaceChance`（默认 0.4），遵 so-data-driven 禁硬编码。
4. **静态池**：现有 `GetTalkPool` 每次调用都 `new string[]`（GC 抖动），池提为 `static readonly` 一次分配；族池同理。

### 影响面

- `UnitController.cs`：`PickTalkLine` 加 raceId 维度 + 双层混合；`GetTalkPool` 文案替换 + 提 static；新增 `GetRaceTalkPool(raceId)`
- `AttentionTuningConfig.cs` + `AttentionTuningConfig.asset`：新增 `talkRaceChance` 字段
- 无新 UI 系统；`OverheadSpeech`/`OverheadSpeechManager`/`NPCBrain.TickAutoTalk` 零改动（触发与管控面不动）

### 验收

- grep `GetTalkPool` 内不再有"随时准备战斗！"共用开场（战斗职业全去重）
- `PickTalkLine` 引用 `raceId`，正常态有 40% 概率返回族池句
- `talkRaceChance` 在 AttentionTuningConfig.asset 在场
- 编译 0 error；弹话频率/上限/冷却行为与 QQQ.2 验收口径一致（无回归）

## 需求 3：十七职业池扩充 + 搞怪改造（已拍板定稿）

> 原则：①去掉 9 个战斗职业共用的"随时准备战斗！"开场；②保留现有可用句，扩充 + 搞怪化；③短句（气泡 2.5s 可读完）；④下划线标记为新增/改造句。

- 正常：正在干活呢。/ 木头、石头、粮食，都得有人搬。/ 今天也要努力工作。/ 嘿咻……这活儿不轻。/ 手艺不能丢，天天练。/ 仓库快满了，加把劲。/ _今天的砖，格外的烫手。_ / _躺平是理想，搬砖是现实。_
- 饥饿：肚子好饿……什么时候开饭。/ 干不动了，想吃东西。/ 粮仓是不是空了？/ _画饼不能充饥，给口饭吧。_
- 受伤：嘶……疼……还能撑住。/ 轻伤不下火线。/ _腰……我的腰……_

### Porter 搬运工

### Resident 居民

## 需求 4：性能与 sim 边界（已确认零风险）

### 问题/现状

用户提醒"之前好像考虑过了"——确认属实：QQQ.2 需求1 DR-10 已做全套弹话管控（视野裁剪/同时上限 6/轮转队列/同 NPC 冷却 8s/每单位复用气泡/15-30s 间隔），本批文案扩充不触碰这些机制。

### 方案

1. **运行时开销**：`PickTalkLine` 仍是从数组随机取一句（O(1)），族池/职业池合计约 300 句为静态数据，无每帧开销。
2. **GC 微优化**：现有 `GetTalkPool` 每次调用 `new string[]`；提 `static readonly` 一次分配，杜绝 GC 抖动（族池同理）。非必须但顺手。
3. **sim 零义务**：弹话文案为纯表现层，**不进 AI.Core 决策核、不进 TuningSnapshot、sim 无需镜像**（sim-sync 边界：表现层不属决策核）。`talkRaceChance` 只作 Unity 本地 SO 字段，不进 `ToSnapshot()`。

### 验收

- 弹话频率（15-30s）/同时上限（6）/冷却（8s）行为与改动前一致（无回归）
- `AttentionTuningConfig.ToSnapshot()` 不含 `talkRaceChance`（sim 无镜像义务成立）
