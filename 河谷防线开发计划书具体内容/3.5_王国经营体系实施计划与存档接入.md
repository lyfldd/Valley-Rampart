## 二、存档系统接入（详细）

### 2.1 现有存档架构（回顾）

- **契约**（SaveableContracts.cs）：`ISaveable`（SaveId / LoadPhase / SaveState / LoadState）+ `ISaveableSpawner`（SaveIdPrefix / SpawnFromSave）

### 2.4 加载时序（新增系统后）

```
Global 阶段（顺序注册即可，SaveManager 按字典序分发，无强依赖）：
  TimeManager → RulerController → KingdomManager → PopulationSystem → DifficultyManager → WorldManager

1.5 Spawner 重建（前缀匹配）：
  UnitFactory（Unit_）→ BuildingFactory（Building_）→ 编队（Formation_，如走 Spawner）

Scene 阶段 LoadState：
  UnitController（含饱食/幸福/装备/brainStateJson）
  → Building.LoadState（恢复 hp/level/storedAmount + GridSystem.MarkOccupiedFootprint 占用）
  → FormationController.LoadState（依赖单位 SaveId 已注册）

后置（下一帧，FormationManager.Update）：
  编队组队恢复（单位重建完成、锚点就绪后）
```

### 2.5 编队存档（关键时序矛盾）

**矛盾**：编队引用单位 SaveId，单位要等 Spawner 重建后才存在；而编队自身是运行时聚合对象，不是独立场景对象。

**推荐方案**：**FormationManager（Global，新）统一保存/恢复编队快照**
- 保存：FormationManager 遍历所有 FormationController，收集 `FormationSnapshot`（将军/成员 SaveId + 意图 + 守城）
- 读档：`FormationManager.LoadState` 只存快照列表（Global 阶段），**不立刻组队**；等 Scene 阶段单位 LoadState 完成后，`FormationManager.Update` 首帧检测"快照未恢复且将军单位已注册"→ 按快照重建：
  - 找到将军单位（SaveManager.HasSaveable(entry.generalUnitId)）→ BindGeneral + SetIntent + 守城时建锚点
  - 成员按存档槽位顺序重招（RecruitStandard 或 RestoreSlots）
- **兜底**：读档后 2 帧内将军未找到（阵亡存档），跳过该编队恢复并记 Warning

> ⚠️ 备选方案：FormationController 自身实现 ISaveable（Scene）。但将军是单位生成时才挂组件，存档时组件 SaveId 与单位生命周期耦合，且成员槽位恢复依赖单位先后注册顺序，脆弱。推荐走 FormationManager 统一恢复。

### 2.6 AI 大脑保存接口（占位，等训练 AI 调取后实现）

**2026-08-03 决策**：AI 底层可能重构，**NPC 状态存档（饱食/幸福/equipId/taskState/brainStateJson）等 AI 重构稳定后一起设计**。本节只立接口、不实现、不接入 UnitSaveData。

**背景**：用户正在调取训练中的 AI 大脑。当前 NPCBrain 决策状态不保存（读档后重新计算）。**本实施先立接口、不实现具体序列化**，等 AI 大脑接入后按接口填充。

```csharp
// ===== 新增：AI 大脑状态导出接口（NPCBrain 实现）=====
public interface IBrainStateExportable
{
    /// <summary>导出决策大脑状态（神经网络权重/LSTM 隐藏态/注意力缓存等）。当前返回 null=不保存。</summary>
    string ExportBrainState();
    /// <summary>导入决策大脑状态。当前为空实现（读档后重新初始化）。</summary>
    void ImportBrainState(string json);
}
```

**接入点（等 AI 定后实施）**：
1. `UnitSaveData.brainStateJson` 字段（v2）——UnitController.SaveState 调 `brain?.ExportBrainState()`，LoadState 调 `brain?.ImportBrainState(...)`
2. NPCBrain 实现 `IBrainStateExportable`：P0 返回 null / 空实现（行为不变）
3. **待定项（等用户调取训练 AI + 重构稳定后定）**：
   - 序列化格式：JSON / 二进制权重 / 只存 checkpoint 引用
   - 是否全量导出（决策上下文）还是只导网络权重（大文件走独立 .brain 文件 vs 内嵌 JSON）
   - 存档体积预算（数百 NPC × 权重）

**迁移**：UnitSaveData v1→v2 加 `version=2`，LoadState 按 version 兼容（v1 缺字段给默认值）。

### 2.7 NPC 行为层接口（AI 接缝，占位）

**2026-08-03 决策**：P0 纯建筑玩法，NPC 行为层整体后置到 AI 稳定后；但**行为接口提前立出来**，隔离 AI 重构对王国经营的冲击。

**设计原则**：接口只定义"行为能做什么"（执行器），不定义"AI 怎么决定做什么"（决策器）。AI 大脑重构只换决策器，执行器与王国玩法不动。

```csharp
/// <summary>
/// NPC 行为执行器接缝（王国经营 ↔ 3.0 AI 隔离层）。
/// P0 不实现（纯建筑玩法）；AI 重构稳定后由 AI 驱动填充。
/// 存档不涉及（P0 无状态）；指派关系若需存，随 AI 定一起设计。
/// </summary>
public interface IWorkerTaskExecutor
{
    /// <summary>指派任务：把工人指派到建筑（后续可换成 AI 自主分配）。</summary>
    void AssignTask(UnitController worker, Building building);
    /// <summary>当前任务描述（null=空闲）。</summary>
    object CurrentTask { get; }
    /// <summary>逐帧驱动执行（移动→站桩→触发产出）。</summary>
    void ExecuteTick(UnitController worker);
    /// <summary>取消当前任务（建筑拆除/工人转职时调）。</summary>
    void CancelTask(UnitController worker);
}
```

**依赖关系**：建筑产出（ProducerComponent）不依赖本接口（自产出）；本接口只影响"NPC 是否站在建筑旁表演采集/加工"。P0 阶段建筑照常产出，无需 NPC。

### 步骤 5：人口系统（PopulationSystem，数据层先行）
