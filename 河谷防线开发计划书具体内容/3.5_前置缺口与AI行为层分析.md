## 二、AI 行为层分析（全任务覆盖）

### 2.1 当前 AI 能做什么（已实现）
- **单点任务**：`TaskStimulus`（第 3 层，`FocusType.WorkPosition`）→ L2 裁决 → `BehaviorModule.WorkAt` → 走到位置 → 站桩执行。
- **搬运（3.3.5 P0）**：走到建筑 → `Harvest()` → 直接入国库（无终点、无携带、一次性）。
- **防堆叠**：`IsIdleForTask`（焦点是任务则忙）。

### 2.2 搬运：起点 + 终点 + 资源转移（确定决策）
**决策：搬运采用"携带态"。** 工人走到源建筑 →"取货"（扣源存储，记入工人携带量）→ 走到目标仓库 →"卸货"（加目标存储）。资源暂存工人 AI 状态，搬运过程可见（工人携带资源走）。

- 任务从"单位置"扩展为**两段任务**（源 node → 终点 node）。
- 目标仓库 = **就近仓库**（含国库，仅当最近）。
- **搬运携带量（2026-08-06 审查补全）**：按资源类型区分，新增 `ResourceCarryDef` SO：
  - 木/石/矿 = 10，粮 = 20，水晶/火油 = 5，面包/肉 = 10。
  - 工人一次搬运 ≤ 携带量；源建筑产出 > 携带量时分批多次搬运。
  - `WorkerTask` 加 `carryAmount` / `carryResource` 字段。

### 2.3 工人任务全集（不只是搬运/生产）
| 任务 | 执行 | 起点→终点 | 判定"谁执行" |
|------|------|-----------|--------------|
| 建造 | 走到工地 → 施工进度条 | 无 | 调度中心派空闲工人 |
| 升级 | 走到建筑 → 升级进度条 | 无 | 调度中心 |
| 重建/修复 | 废墟 → 施工 | 无 | 调度中心（废墟触发） |
| 采集 | 走到产能建筑 → 持续产出 | 产出→就近仓库 | 调度中心派生产任务 |
| 种植 | 农田 → 持续产出 | 粮→就近仓库 | 调度中心 |
| 加工 | 加工坊 → 持续加工（粮→面包） | 粮入/面包出 | 调度中心 |
| 挑水 | 水井 → 挑水送农田 | 井→农田 | 调度中心 |
| 养殖 | 牧场 → 喂粮/宰杀 | 粮入/肉出 | 调度中心 |
| 搬运 | 源→终点 | 源→就近仓库 | 调度中心 |
| 操作机器 | 走到机器 → 值守 | 无 | 调度中心（有敌情） |
| 训练 | 居民走过去（非工人） | 无 | 训练建筑 |

**判定"谁执行"**：所有任务由**调度中心**（3.3.5）检测触发 → 派**空闲通用工人**（`IsIdleForTask`）执行。工人任务本质 = 规则驱动的"走到+WorkAt"，不需要 AI 自主决策。

### 2.4 防"站一下就离开"（确定机制）
- 任务刺激**长 expiry + 完成判定**：任务完成（产出/搬完/施工完）才释放，不靠短 expiry 反复重派。
- L2 抗打断（工作因子）已支持"关键活不被摸走"。
- 生产/施工任务完成前，工人不因任务过期离开。

### 2.5 是否需要模拟器训练？
**确定结论：P0 不需要模拟器训练。** 工人执行派发任务 = 规则驱动（TaskStimulus → WorkAt → 产出/搬运），写行为即可。模拟器训练用于**AI 自主决策升级**（自主选目标/权衡优先级），是后续扩展，非 P0。

### 2.6 粮食消耗链路（确定）
- **普通 NPC**：每日按职业日耗粮，从**就近仓库/粮仓**取粮，**自动降级**（先基础粮 → 面包 → 肉）。
- **军队**：不就近取——士兵在驻地/前线，需**运粮到前线**（搬运任务，工人运粮至军队锚点），士兵每日从军队补给点消耗。
- 军队补给 = 运粮任务的一部分（3.5.3 §3.2 军队补给）。

### 2.7 NPC 非生产行为（散步/闲逛）归属
- **散步/闲逛 = AI 大脑行为**（`CuriosityStimulus` 好奇层，第 5 层最底优先），非王国任务。
- 工人/居民无任务时由 AI 大脑驱动闲逛/回家，不占用任务调度。

## 四、2026-08-06 全链路审查补全

> 本次审查针对 3.5 系列 9 份文档全链路打通情况，补全本档（前置缺口与 AI 行为层）原 §一~三 未覆盖的关键缺口。原章节设计定稿不变。完整决策清单见 3.5_王国经营体系.md §十四。

### 4.1 1D 城墙硬屏障机制（架构洞察，新增缺口）

**缺口**：原 §一/§二 未涉及城墙/防御工事的 AI 行为层。3.5 §3.1 城墙"阻挡敌人"但未说实现。

**决策（来自全链路审查 #12）**：本游戏为 **1D 横版**（仅 x 维度），城墙/城门 = **硬屏障**，敌人**无法绕行**，必须破坏城墙/城门才能通过。**无需 A\* 寻路**，敌方 AI 沿 x 前进 → 遇障碍 → 攻击破坏 → 通过。

**敌方 AI 行为层（新增）**：
- **前进态**：沿 x 向王国方向前进（默认）。
- **遇障态**：x 前方有城墙/城门/拒马（HP > 0）→ 切换攻击该障碍。
- **破障态**：障碍 HP=0 → 恢复前进态，通过缺口。
- **城门特例**：城门开启时 = 可通行（不攻击）；关闭时 = 障碍。
- **拒马特例**：一次性障碍，被摧毁后消失（不阻挡）。

**实现要点**：
- 敌方 AI 无需 `Pathfinder`，仅需"沿 x 前进 + 前方障碍检测"。
- 城墙/城门/塔类/拒马均需 `HP` 字段（3.5.4 §8.2 HP 表）。
- 城门状态机见 3.5.4 §8.4（昼夜自动 + 玩家覆盖）。

### 4.2 战斗降速触发（新增缺口）

**缺口**：原 §一~三 未涉及时间加速与战斗降速的 AI 行为层影响。

**决策（来自全链路审查 #18/19）**：
- **时间加速**：全局 `Time.timeScale`，仅 2 倍速（不做 4x）。
- **战斗降速**：感知到敌人 = 降速（任何我方单位感知到敌 → 1x）。

**AI 行为层影响**：
- 2x 加速时，所有系统（AI/生产/搬运）同步加速，AI tick 频率不变（仅表现加速）。
- 战斗降速触发后，`TimeManager` 强制 `timeScale = 1`，UI 灰显 2x 按钮。
- `TimeManager` 订阅 `AttentionSystem.EnemyDetectedEvent`（感知到敌事件）。
- 夜晚波次期间 = 战斗状态，强制 1x。

**待定**：2x 加速下 AI tick 是否需要子步长（P1 实施时调优）。

### 4.3 资源点锁格（新增缺口）

**缺口**：原 §一 资源点缺口仅说"地图生成未实现"，未说资源点与建筑放置的冲突。

**决策（来自全链路审查 #11）**：**资源点锁格，禁止重叠**（玩家需先采集才能建）。

**影响**：
- `GridSystem` 占用层包含资源点（占格标记）。
- 建筑放置校验：目标格非资源点。
- 玩家流程：发现资源点 → 派工人采集 → 资源点消失 → 解锁地块 → 可建建筑。

**与 3.3 建造交互的关系**：3.3 建筑放置时的"空地校验"需扩展为"非资源点校验"。
