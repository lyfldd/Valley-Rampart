# 详细文档制作（Detailed Documentation）

基于 2026-08-04 河谷防线卡定义细化讨论（约 2 小时）提炼的方法论。核心：**用户要求"详细"时，详细程度必须达到今天这种颗粒度**——每个系统都拆出子场景、覆盖组合、验收、边界，不用模糊词、不绝对化、不遗漏系统间联系。

适用于：游戏开发、系统设计、需求细化、技术方案等任何需要"把思想做成可执行详细文档"的场景。

---

## 一、详细文档的标准（做到什么程度才算"详细"）

用户说"详细"时，**不等于多写几句**，而是达到**可执行颗粒度**。判据：拿着文档能直接落地（写代码/生成场景/训练），不靠现场猜。

**每张卡/每个系统/每个功能都要包含**：
1. **本质**：它到底是干什么的（一句话说清，和相邻系统区分）
2. **子场景清单**：大方向拆成所有细分小方向（逐一列，不合并）
3. **覆盖组合**：所有维度组合（敌方构成/我方构成/状态/梯度），列全
4. **辅助场景**：精确定位某些行为的少数场景
5. **关键因子**：要调的参数（路径）
6. **验收**：目标参考值（接近即可，不卡死）
7. **训练师/执行动作**：具体怎么做

**反例（偷懒）**：只写"目标：XXX / 指标：YYY / 验收：达标"——没有子场景、没有覆盖组合、没有边界，等于没写。

---

## 二、规范化集合表达（消除歧义的第一步）

详细文档最大的敌人是**模糊词**。用"集合 + 子集"的规范表达，让"谁 vs 谁"无歧义。

**方法**：
1. 定义**最上级集合**（如构成集合：普通编队/混合编队/散兵/战争机器/防御建筑）
2. 定义**子集**（最上级集合内部的成员，如兵种：近战/远程/机动/经济）
3. 表达"谁 vs 谁"只用集合，**禁止用模糊词**（如"步兵/兵种单位/一些敌人"）

**关键**：
- 高层分类（如骑兵/远程）不是独立集合，是低层集合（编队/散兵）内部的子集
- 状态（如满编/残编）是集合的属性，不是独立集合
- 连续值（如残编 1%-99%）不用固定档位，保留层次感

**例子**（今天 T 卡细化）：
- 构成集合 = 普通编队满编/残编、混合编队满编/残编、散兵、战争机器、防御建筑（7 种）
- 兵种全集 = 近战（战士/重装/盾卫）、远程（弓手/弩手/法师/法师/治疗/主教）、机动（骑兵）、队长（将军）、经济（工人）
- 骑兵/远程不是独立构成，是编队/散兵内部的兵种子集

## 三、逐项确认（AskUserQuestion 逐点拍板）

详细文档不能我自己拍板，**每一个决策点都要用户确认**，但用"推荐选项"引导。

**方法**：
1. 每轮最多 4 个问题（工具上限）
2. 每个问题 2-4 个选项，第一个标"（推荐）"并给理由
3. 选项要具体（带数值/方案/影响），不要模糊
4. 逐卡/逐系统推进，确认一张记一张，不累积

**推进节奏**：做一张卡 → 用户确认 → 记入文档 → 下一张。用户说"继续"才继续。

---

## 四、系统间结合（最重要的能力）

详细文档不能孤立的对待每个系统，**必须找出系统之间的联系**。这是用户特别强调的"系统与系统之间的结合"。

**三类联系**：
1. **依赖（地基）**：一个系统依赖另一个系统的能力（如上层卡依赖下层卡，先练地基）
2. **共享能力**：同一能力被多个系统复用（如"保护"能力在 T08/T17/T18，"编队调度"在 T04/T05/T11）
3. **能力叠加**：一个系统的能力在另一个系统的场景中体现（如 T18 工人保护用到 T06 散兵拦截 + T08 保护）

**方法**：
- 列出所有系统，逐个问"它用到哪些系统？"
- 找出共享因子（如 protectPower 被多卡改，改动时先跑依赖卡确认不倒退）
- 画依赖关系表 + 拓扑训练顺序

---

## 五、抽象提取能力（从具体问题提炼普遍规律）

今天对话里，用户一次次从单点问题提取出**通用原则**。要主动这样做：

- "T04 只有混合编队" → 提取：**所有编队卡都要覆盖普通+混合编队**
- "T08 只有散兵保护" → 提取：**保护 = 保护者×被保护者×关系，不是一个固定形式**
- "T16 骑兵目标单一" → 提取：**每张卡都要覆盖它面对的所有可能情况**
- "为什么配套场景" → 提取：**随机场景=主验收（广度），辅助场景=精确定位（深度）**

**方法**：用户指出一个具体 bug 时，问自己"这个 bug 是不是一类问题的代表？"（同类全卡都查），不修单个点。

## 六、偷懒行为教训（反面教材，每次做文档自查）

以下是从今天对话中发现的**文档偷懒行为**，做详细文档时逐条自查：

| # | 偷懒行为 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 描述不清楚（"合理协作""达标"） | 验收无法执行 | 给数值/判定标准 |
| 2 | 绝对化定义（"残编=50%减员"） | 失去层次感 | 用连续值（1%-99%）|
| 3 | 用模糊词（"步兵/兵种单位"） | 歧义 | 用规范化集合表达 |
| 4 | 漏掉状态（只有满编没残编） | 覆盖不全 | 编队状态满编/残编都覆盖 |
| 5 | 只写大方向不拆细分 | 子能力没测 | 列子场景清单 |
| 6 | 看单点不提普遍（只修 T04 不修全体） | 同类问题复现 | 抽象成通用原则 |
| 7 | 孤立系统（不找卡间联系） | 上层卡在残缺地基训练 | 画依赖/共享/叠加 |
| 8 | 默认"一定有/一定没有"（不敢确认） | 可能错 | 主动问用户确认 |
| 9 | 验收卡死（"必须达 X"） | 训练师做不到 | 目标参考，接近即可 |
| 10 | 高层分类当独立集合（骑兵单列） | 结构错误 | 骑兵/远程是编队内部子集 |

**自查清单**（写完文档逐条过）：
- [ ] 每个大方向都拆了细分小方向？
- [ ] 所有维度组合都覆盖？（敌我构成/状态/梯度）
- [ ] 用了规范化集合还是模糊词？
- [ ] 状态（满编/残编）都处理了？
- [ ] 这个系统和相邻系统区别清楚？联系找到了？
- [ ] 验收有数值（目标参考）还是空的？
- [ ] 有没有绝对化/默认，需要用户确认的？

## 七、工作流（完整流程）

1. **完整读取**目标文档/需求（不读片段）
2. **建立规范化集合表达**（消除歧义）
3. **逐系统分解**：本质/子场景/覆盖组合/辅助场景/关键因子/验收/动作
4. **找系统间联系**（依赖/共享/叠加），画依赖表 + 拓扑顺序
5. **逐项确认**：AskUserQuestion 逐点拍板，确认一张记一张
6. **自查偷懒清单**（第七节）
7. **写入文档**，更新对应主文档（细化替换原内容）

---

## 八、通用性

本 skill 不局限于游戏/训练体系，适用于任何详细文档场景：
- 需求细化
- 系统设计
- 技术方案
- 训练/验收体系设计
- 任何"把思想做成可执行详细文档"的讨论

核心方法论：**规范化集合 → 逐系统分解 → 找系统联系 → 逐项确认 → 自查偷懒 → 写入文档**。
