## 〇、一句话结论

**矿山锚点（`FeatureType.Mine`）地图生成能稳定产出，且每个王国出生点半径内保底有一颗** —— 这一层没问题。
**但用户心中「矿山↔矿石持续产出」的那条链，现状是断的/错位的**：地图上的矿山锚点上，玩家当前能建的是 **`quarry`（采石场，产石）**；而 **`mine`（矿洞/矿场）本体既不产石、也不进玩家建造菜单**，只在地图预置链里以「恒产三副产」的过渡态存在。本报告逐条摆出实盘证据与三处缺口。

## 三、问题二：`mine`（矿洞/矿场）当前根本不产石 —— 这是最需要主策划知道的一条

### 3.1 实盘证据：mine 本体不挂产能组件

[mine.asset](file:///c:/Users/trs/Desktop/Valley%20Rampart/Valley%20Rampart/Assets/Resources/Buildings/mine.asset) 关键字段：

```
id: mine
outputResource: 1          # = Stone（主产石）
isResourceNode: 1          # ← 关键
isPlayerBuilt: 0
isMineByproduct: 1
footprint: {x: 2, y: 2}
```

挂载判定 [BuildingFactory.AttachComponents L295](file:///c:/Users/trs/Desktop/Valley%20Rampart/Valley%20Rampart/Assets/_Game/Systems/Building/BuildingFactory.cs#L281-L328)：

```csharp
if (def.producer.rate > 0f && def.producer.kind == ProduceKind.Resource && !def.isResourceNode)
```

`mine.isResourceNode == 1` → **整条产能分支被排除** → 既不会挂 `StorageComponent`，也不会挂 `ProducerComponent`。
**即：mine 的"石头主产"当前没有任何组件在执行。** 它只走下一段：

```csharp
if (def.isMineByproduct)
    b.gameObject.AddComponent<MineByproductComponent>()?.Init(b);   // L316-319
```

而 [MineByproductComponent](file:///c:/Users/trs/Desktop/Valley%20Rampart/Valley%20Rampart/Assets/_Game/Systems/Building/MineByproductComponent.cs) 只恒产三样副产（**水晶 / 火油 / 矿石**，各 `rate=0.05/s`，无等级门槛），**不产石**。

### 3.2 那"石头"现在从哪来？

| 来源 | 载体 | 性质 | 证据 |
|---|---|---|---|
| 开局过渡 | `stone_pile`（一次性石堆） | 一次性 | [GridTypes.cs:L101](file:///c:/Users/trs/Desktop/Valley%20Rampart/Valley%20Rampart/Assets/_Game/Systems/Grid/GridTypes.cs#L101) |
| **可持续** | **`quarry` 采石场**（`rate=5`，需建在矿山锚点上） | 玩家可建 | [quarry.asset:L31](file:///c:/Users/trs/Desktop/Valley%20Rampart/Valley%20Rampart/Assets/Resources/Buildings/quarry.asset) + [ResourceNodeMapping L12](file:///c:/Users/trs/Desktop/Valley%20Rampart/Valley%20Rampart/Assets/_Game/Systems/Building/ResourceNodeMapping.cs#L10-L14) |

**所以「矿山=石头持续产出的核心玩法」在现状里是靠 `quarry` 兑现的，不是靠 `mine`。** 这正好呼应总表 v2 §2 把 quarry 列入退役、让 `mine` 接管的动机——但**接管尚未施工**（归建筑体系重构批件③ / D613 决策2）。

### 3.3 玩家目前根本见不到 mine

建造菜单过滤 [BuildingMenuPanel.cs:L209](file:///c:/Users/trs/Desktop/Valley%20Rampart/Valley%20Rampart/Assets/_Game/Systems/Building/BuildingMenuPanel.cs#L205-L236) 只收 `def.isPlayerBuilt`；`mine.isPlayerBuilt=0` → **不进菜单**。
地图生成侧 [DeriveNaturalBuildings L419-L438](file:///c:/Users/trs/Desktop/Valley%20Rampart/Valley%20Rampart/Assets/_Game/Systems/World/MapGenRules.cs#L419-L438) 只派生 `OreVein/WoodPile/StonePile` 三类实体，**Tree/Mine 不派生**（A+ 数据化，[HH.2]）→ 地图上也不会"自动长出一座 mine 建筑"。

**mine 建筑实体当前唯一出现路径 = AI 立国预置链**：[KingdomFoundry.PlaceBuildings L143-L174](file:///c:/Users/trs/Desktop/Valley%20Rampart/Valley%20Rampart/Assets/_Game/Systems/Kingdom/KingdomFoundry.cs#L143-L182) 按六模板 `baseBuildingDefIds` 实例化，六模板均含 `mine`（如 [Kingdom_Bedrock.asset:L37](file:///c:/Users/trs/Desktop/Valley%20Rampart/Valley%20Rampart/Assets/Resources/Config/Kingdoms/Kingdom_Bedrock.asset)）。**注意此路径不经过 `PlacementValidator`**，即 AI 的 mine 不受矿山锚点约束（环带取点 [BuildingCell L185-L202](file:///c:/Users/trs/Desktop/Valley%20Rampart/Valley%20Rampart/Assets/_Game/Systems/Kingdom/KingdomFoundry.cs#L184-L202) + `NearestWalkable` 兜底）。

## 四、问题三：三处结构缺口（目标态落地前必清）

### 缺口 A（🔴 最高）：2×2 的 mine 需要 2×2 矿山锚点簇，生成器只撒 1×1

- `mine.footprint = {x: 2, y: 2}`（[mine.asset:L29](file:///c:/Users/trs/Desktop/Valley%20Rampart/Valley%20Rampart/Assets/Resources/Buildings/mine.asset)，D613 已裁）；
- 而 `allowedTerrain = 04000000`（= `TerrainType.Quarry`，即矿山地形）在 [PlacementValidator L111-L117](file:///c:/Users/trs/Desktop/Valley%20Rampart/Valley%20Rampart/Assets/_Game/Systems/Building/PlacementValidator.cs#L111-L117) 中**在 footprint 循环内逐格校验**；
- 生成器只随机单格撒 Mine + 保底补 1 格（[EnsureOne L293-L312](file:///c:/Users/trs/Desktop/Valley%20Rampart/Valley%20Rampart/Assets/_Game/Systems/World/MapGenRules.cs#L292-L312) 只补一格）；
- → 自然形成 2×2 连续矿山簇的概率极低 ⇒ **mine 一旦开启玩家建造（`isPlayerBuilt` 转 1 + 进菜单），会大面积"无合法落点"**。

此为 HH.161 决策2 / D613 明确「归建筑体系重构批件③」的**尚未定档项**，原话：

> 目标态「矿山节点限位」节点逐格 1×1 语义（2×2 需节点簇 vs 单格表征多格建筑）…留重构批件③一并定

**处置建议（供裁）**：重构批件③定档时须二选一 —— ①生成器新增"矿山簇"撒布/保底（改 `FillFeatures` 或 `EnsureNearbyResources` 产出 2×2 连续 Mine）；②改节点判定语义为"单格表征多格建筑"（`IsResourceNodeAvailable` 支持 footprint 锚点单格命中）。**推荐 ①**：与"锚点=可争夺资源点"的原始设计（D113/D138/D190「任意阵营可采、冲突战斗」）语义一致，且不改判定契约。

### 缺口 B（🟡）：水域生成在补矿之后，可能冲掉锚点

管线顺序（[WorldManager L167-L183](file:///c:/Users/trs/Desktop/Valley%20Rampart/Valley%20Rampart/Assets/_Game/Systems/World/WorldManager.cs#L145-L197)）：
`FillFeatures(步骤4) → EnsureNearbyResources(步骤7) → PlaceWater(步骤9) → …`

[PlaceRiver L348-L368](file:///c:/Users/trs/Desktop/Valley%20Rampart/Valley%20Rampart/Assets/_Game/Systems/World/MapGenRules.cs#L348-L368) 只避让湖（`!= FeatureType.Lake` 才覆写），**会直接覆盖沿途 Mine**；湖泊只避出生点 1 大区块（[PlaceLakes NearAnySpawn L340](file:///c:/Users/trs/Desktop/Valley%20Rampart/Valley%20Rampart/Assets/_Game/Systems/World/MapGenRules.cs#L332-L345)），可能冲掉半径 1~3 区块环带上的保底矿。
属概率性削顶，不至断供（保底半径 48 格 > 湖避让 16 格），但**「保底」语义被削弱**。

**处置建议**：`PlaceWater` 后追加一次 `EnsureNearbyResources` 复跑（或让 PlaceRiver 同时避让 Mine），成本一行级。

### 缺口 C（🟡）：AI 预置 mine 不走锚点校验，与目标态冲突

[KingdomFoundry.PlaceBuildings](file:///c:/Users/trs/Desktop/Valley%20Rampart/Valley%20Rampart/Assets/_Game/Systems/Kingdom/KingdomFoundry.cs#L143-L182) 直接 `CreateBuildingInstance`，不经 `PlacementValidator` ⇒ AI 的 mine 可落在非矿山格。重构批时若 mine 转为"必须建在矿山节点"，**AI 侧需同步补锚点寻位**（总表 v2 §4 咬合面 2 已列「baseBuildingDefIds 六模板 quarry×7→mine（矿山节点摆放）」，但**预置链本身缺校验闸门**这层未在清单中显式列）。

**处置建议**：重构批 §4 咬合面补一条 —— AI 预置 mine 亦须过矿山锚点寻位（或 KingdomFoundry 增加锚点选择分支）。
