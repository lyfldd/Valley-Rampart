## 📝 设计动机：3.2.1 之后还有什么没说

`3.2.1` 把"地图怎么生成才能玩"写透了——5 区结构、四资源保障、邻接矩阵、Building 占位规则。但它产出的 `MapData` 是一份**静态生成快照**：

```
MapData（生成结束时刻的快照，只读）
  ├─ regions[i].terrain          ← 地形，seed 复现，永不变
  ├─ regions[i].resources        ← BuildingPlaceholder 占位列表
  ├─ regions[i].riftCellX        ← 裂隙位置
  └─ regions[i].isEnemyTerritory ← 敌方领土标记
```

而游戏运行时是**动态**的：

| 运行时变化 | 谁负责 | 改的是什么数据 |
|-----------|--------|--------------|
| 玩家在平原建城墙 | 建造系统 | 建造系统自己的 BuildingRegistry，**不写回 MapData** |
| 矿洞被怪物破坏 | 战斗系统 + 资源经济 | Building 实例的 HP/状态，**不写回 MapData** |
| 裂隙被玩家消灭 | 波次系统 | Building 实例标记死亡，**riftCellX 不变**（位置还在，只是不出怪） |
| 玩家砍光一片林子 | 资源经济 | Building 实例库存，**resources 列表不变** |
| 跨岛远征 | 远征系统 | 切换 `activeMapId`，**不修改任何 MapData** |

**本补丁的定位**：明确地图生成与十大系统的**读写边界、介入时机、接口契约**，避免三类灾难：

1. **数据重复存储**——建造系统又存一份地形，存档膨胀
2. **状态不一致**——资源点被破坏，MapData 没同步（其实不该同步，但要约定谁存运行时状态）
3. **接口耦合**——建造系统直接改 `MapData.regions[i].resources`，破坏 seed 复现确定性

> **核心原则**：`MapData` 是**只读快照**（seed 复现，永不修改）。运行时状态由各系统各自持有（ISaveable 自存档）。地图生成层只负责"开局摆好棋子"，不负责"棋局进行中的状态"。

## 一、对接总览：十大系统一览表

| # | 系统 | 状态 | 从地图生成**读**什么 | **写回** MapData？ | 主要介入阶段 |
|:-:|------|:--:|---------------------|:--:|------------|
| 1 | 区块系统（GridSystem） | 🚧 | MapData → PopulateFromMap 填充区块 | ❌ | 加载 Phase2 |
| 2 | 建造系统 | ⬜ | BuildingPlaceholder、Region.zone、主城位置 | ❌（自存 BuildingRegistry） | 运行时 |
| 3 | 波次系统 | ⬜ | riftCellX（裂隙出怪点）、主城位置（寻路终点） | ❌（自存波次进度） | 运行时（晚上） |
| 4 | 资源经济系统 | ⬜ | ResourceProducer/Pickup 占位、grade 等级 | ❌（自存 Building 实例状态） | 运行时 |
| 5 | 世界系统（难度/时间） | ✅ | difficulty（生成时读，决定资源密度/等级） | ❌ | 生成时 + 运行时 |
| 6 | 存档系统（SaveManager） | ✅ | worldSeed/activeMapId/conqueredMapIds | ❌（只存 seed+meta） | 存档/读档 |
| 7 | 加载/销毁系统 | ✅ | MapGenRulesConfig/ResourceGenConfig SO | ❌ | Phase1/Phase2/Teardown |
| 8 | 战斗系统（移动/伤害/AI） | ⬜ | 主城位置、裂隙位置、Building 实例（IDamageable） | ❌ | 运行时 |
| 9 | 攻城/远征系统 | ⬜ | 敌方王国地图、海岸区（造船厂位）、SwitchToMap | ❌（改 activeMapId） | 运行时（中后期） |
| 10 | EventBus / 摄像机 / UI | ✅🚧 | 地图宽度、worldSize、5 区边界 | ❌ | 加载 + 运行时 |

> 状态图例：✅ 已实现 / 🚧 部分实现 / ⬜ 待实现（无设计文档）

**关键结论**：**没有任何系统写回 MapData**。MapData 在 `GenerateMap` 返回后即冻结为只读。所有运行时变化（建造/破坏/消灭裂隙）都落在各系统自己的运行时数据结构里，存档各自走 ISaveable。

## 二、数据所有权矩阵（核心契约）

每个数据字段的**唯一 Owner**（谁负责存档/恢复）和**Reader**（谁只读访问）：

| 数据 | 类型 | Owner（写 + 存档） | Reader（只读） | 存档方式 |
|------|------|------------------|---------------|---------|
| `WorldState.worldSeed` | int | WorldManager | 地图生成器、存档系统 | WorldSaveData（直接存） |
| `WorldState.activeMapId` | int | WorldManager（远征切换） | GridSystem、UnitFactory | WorldSaveData（直接存） |
| `WorldState.conqueredMapIds` | HashSet | WorldManager（ConquerMap） | 远征系统、通关判定 | WorldSaveData（直接存） |
| `MapData.seed` | int | WorldManager（生成时定） | 存档系统 | 不存（靠 worldSeed 派生复现） |
| `MapData.bigTerrain` | enum | 地图生成器 | 战斗系统、远征系统 | 不存（seed 复现） |
| `Region.terrain` | enum | 地图生成器 | 建造系统、美术渲染 | 不存（seed 复现） |
| `Region.zone` | enum | 地图生成器（5区） | 建造系统（城墙保护圈判定） | 不存（seed 复现） |
| `Region.riftCellX` | int | 地图生成器 | 波次系统（出怪点） | 不存（seed 复现） |
| `BuildingPlaceholder` 占位 | 列表 | 地图生成器（生成时） | BuildingFactory（转实例） | 不存（seed 复现） |
| Building 运行时实例 HP/状态 | 对象 | **建造/资源经济系统** | 战斗系统、波次系统 | **各自 ISaveable** |
| 玩家建造的建筑 | 列表 | **建造系统**（BuildingRegistry） | 战斗系统、GridSystem | **建造系统 ISaveable** |
| 资源点库存/损坏状态 | 对象 | **资源经济系统** | 建造系统、UI | **资源经济 ISaveable** |
| 裂隙是否已被消灭 | bool | **波次系统** | 战斗系统 | **波次系统 ISaveable** |
| 波次进度/入侵事件 | 对象 | **波次系统** | 外交系统、UI | **波次系统 ISaveable** |
| 君主四资源（金/石/木/粮） | int | RulerController | UI、建造系统消费 | RulerSaveData |

> **铁律**：左列"Owner"列**唯一**负责该数据的存档与恢复。Reader 列只能读，不能写。若某系统需要"修改"MapData 里的数据，说明它的运行时状态放错了地方——应该建自己的运行时数据结构，而不是污染生成快照。

### 2.1 为什么资源点状态不写回 MapData

以"矿洞被破坏"为例，说明数据流：

```
生成结束：MapData.regions[i].resources 里有 {Mine, grade=Rich}  ← 冻结，永不变
                              │
                              ▼  BuildingFactory 转换
运行时：MineBuilding 实例 { hp=100, state=Normal, stock=500 }  ← 资源经济系统持有
                              │
                              ▼  怪物攻击
        MineBuilding 实例 { hp=0, state=Damaged, stock=500 }  ← 只改实例，MapData 不动
                              │
                              ▼  存档
        资源经济系统 ISaveable 存 { mineId, hp=0, state=Damaged, stock=500 }
                              │
                              ▼  读档
        worldSeed 复现 MapData（Mine 占位还在）→ BuildingFactory 再转实例
        → 资源经济系统 LoadState 覆盖实例的 hp/state/stock
```

**确定性保证**：读档时 MapData 靠 seed 完整复现（占位位置/类型/等级全对），运行时状态靠各系统 ISaveable 覆盖。两层分离，互不干扰。

## 三、生命周期对接（五大阶段）

地图生成数据在游戏生命周期中的流转：

```
┌─────────────────────────────────────────────────────────────────┐
│ 阶段 0：静态配置加载（LoadManager Phase 1）                       │
│   Resources.Load<MapGenRulesConfig>("Grid/MapGenRulesConfig")   │
│   Resources.Load<ResourceGenConfig>("Grid/ResourceGenConfig")  │
│   Resources.Load<MapSizeConfig>("Grid/MapSizeConfig")          │
│   Resources.Load<GridConfig>("Grid/GridConfig")                │
│   → ConfigsLoadedEvent                                          │
└──────────────────────┬──────────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────────┐
│ 阶段 1：世界生成（Phase 2a 新游戏 / Phase 2b 读档复现）            │
│   WorldManager.GenerateWorld(worldSeed, worldSize, difficulty)  │
│     ├─ 生成玩家初始地图（mapId=0）                                │
│     └─ 生成 N 个敌方王国地图（mapId=1..N）                        │
│   GridSystem.PopulateFromMap(ActiveMap)                         │
│   → 世界冻结：MapData 只读快照定稿                                 │
└──────────────────────┬──────────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────────┐
│ 阶段 2：Building 实例化（Phase 2 结束前）                          │
│   BuildingFactory.InstantiateFromMap(ActiveMap)                 │
│     遍历 regions[i].resources（BuildingPlaceholder）             │
│       → 按占位创建 Building 实例（树/矿洞/农田/裂隙/主城）         │
│     遍历 regions[i].riftCellX                                   │
│       → 创建 RiftBuilding（出怪点）                              │
│     遍历主城位置（GetCastleRegionIndices）                        │
│       → 创建 CastleCore 实例                                     │
│   → 各系统拿到运行时实例，开始持有状态                             │
└──────────────────────┬──────────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────────┐
│ 阶段 3：运行时（Playing 状态）                                     │
│   地图生成层：完全静默（MapData 只读，不再介入）                    │
│   各系统各自消费：                                                 │
│     建造系统：读 Region.zone/terrain 判定可建造位                  │
│     波次系统：读 riftCellX 在晚上刷怪                              │
│     资源经济：Building 实例产出 → RulerController 资源             │
│     战斗系统：读主城位置作为敌人寻路终点                            │
│     远征系统：SwitchToMap 切换 activeMapId → 回到阶段 1.5         │
└──────────────────────┬──────────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────────┐
│ 阶段 4：存档/销毁                                                  │
│   存档：WorldSaveData 存 seed+meta；各系统 ISaveable 存运行时状态  │
│   销毁：TeardownManager → GridSystem.ClearAll + WorldManager.ResetState │
│         → Building 实例销毁（各系统清引用）                        │
└─────────────────────────────────────────────────────────────────┘
```

### 3.1 跨岛远征的"回到阶段 1.5"

远征切换地图时，**不重新生成世界**（worldSeed 不变），只切换活跃地图并重新实例化：

```
ExpeditionStartedEvent(fromMapId, toMapId)
  → WorldManager.SwitchToMap(toMapId)
     ├─ _world.activeMapId = toMapId
     ├─ GridSystem.ClearAll()（清旧地图区块）
     ├─ GridSystem.PopulateFromMap(ActiveMap)（填新地图区块）
     └─ BuildingFactory.InstantiateFromMap(ActiveMap)（新地图的 Building 占位转实例）
  → 时间跳跃到下一天清晨（TimeManager）
```

> 敌方王国地图在 `GenerateWorld` 时就已生成（靠 worldSeed 派生的 mapSeed），远征只是"切换视角"到那张已生成的地图。敌方地图上的建筑（已建成高度王国）是**另一套生成逻辑**（见 3.2.1 第 4.3 节 TODO），当前只生成地形骨架 + 裂隙。

## 四、与建造系统对接

建造系统⬜ 是地图生成最大的消费方。对接三件事：占位转换、建造位判定、城墙保护圈。

### 4.1 BuildingPlaceholder → Building 实例（BuildingFactory）

地图生成产出的是 `BuildingPlaceholder`（数据占位），运行时需要 `BuildingFactory` 转为带行为的 `Building` 实例：

```csharp
/// <summary>建造系统⬜ 的工厂：把地图生成的占位转为运行时 Building 实例。</summary>
public class BuildingFactory : Singleton<BuildingFactory>
{
    // 阶段 2 调用：遍历 MapData 所有占位，创建实例
    public void InstantiateFromMap(MapData map)
    {
        foreach (var region in map.regions)
        {
            // 1. 资源点占位 → ResourceProducer/ResourcePickup 实例
            foreach (var ph in region.resources)
                CreateBuilding(ph, region);

            // 2. 裂隙占位 → RiftBuilding 实例
            if (region.riftCellX >= 0)
                CreateRift(region);

            // 3. 主城占位 → CastleCore 实例（仅玩家地图）
            if (map.isPlayerHome && IsCastleRegion(region.regionIndex, map))
                CreateCastleCore(region);
        }
    }

    Building CreateBuilding(BuildingPlaceholder ph, Region region)
    {
        var worldPos = GridSystem.Instance.CoordToWorld(
            new GridCoord(region.cellStartX + ph.localCellX, 0));
        var building = Instantiate(GetPrefab(ph.type), worldPos, Quaternion.identity);
        building.Initialize(ph);  // 把 grade/isConsumable 等灌进去
        BuildingRegistry.Instance.Register(building);  // 建造系统自存的注册表
        return building;
    }
}
```

> **接口预留**：`BuildingFactory` 和 `BuildingRegistry` 是建造系统⬜ 的范畴，地图生成层只定义 `BuildingPlaceholder` 数据契约（见 3.2.1 第 6.2 节），不实现工厂。建造系统 GDD 落地时按此签名对接。

### 4.2 建造位判定（小区块是否可建造）

建造系统放建筑前，要判定"这个小区块能不能建"。判定逻辑**统一走 Building 占位**（3.2.1 第 6.8 节）：

```csharp
// 建造系统判定可建造性
public bool CanBuildAt(GridCoord coord, BuildingType toBuild)
{
    // 1. 该小区块是否已有 Building 占位（资源点/裂隙/主城/玩家建造）
    if (BuildingRegistry.Instance.HasBuildingAt(coord)) return false;

    // 2. 该小区块所属大区块的地形是否允许建造（查 MapGenRulesConfig）
    int regionIdx = GridSystem.Instance.CellToRegionIndex(coord.x);
    TerrainType terrain = ActiveMap.regions[regionIdx].terrain;
    if (!MapGenRulesConfig.Instance.IsBuildableTerrain(terrain, toBuild)) return false;

    // 3. 极端区（海岸/雪山/荒地）不允许玩家建造（纯战场/屏障）
    MapZone zone = MapGenRules.GetZone(regionIdx, M);
    if (zone is MapZone.LeftExtreme or MapZone.RightExtreme) return false;

    return true;
}
```

> 建造系统读 MapData 的 `terrain` 和 `zone`，但**不写回**——它把"已建造"状态存在自己的 `BuildingRegistry`。

### 4.3 城墙保护圈（读 5 区结构）

3.2.1 第 6.9 节定义的城墙保护圈，建造系统落地时需要读 5 区结构判定资源点风险档：

```csharp
// 建造系统：判定一个资源点是否在城墙保护圈内
public bool IsUnderWallProtection(Building building)
{
    // 城墙是玩家建造的 Building，围成多边形保护圈
    // 这里读 BuildingRegistry 里所有 WallBuilding，做范围判定
    return _wallPolygons.Any(poly => poly.Contains(building.Position));
}

// 建造系统：获取资源点风险档（用于显示/UI）
public RiskLevel GetRiskLevel(Building building)
{
    int regionIdx = GridSystem.Instance.CellToRegionIndex(building.CoordX);
    MapZone zone = MapGenRules.GetZone(regionIdx, M);
    return zone switch
    {
        MapZone.Center => RiskLevel.Low,           // 中心区，城墙内
        MapZone.LeftResource or MapZone.RightResource
            => IsResourceInner(regionIdx, M) ? RiskLevel.Low : RiskLevel.High,
        _ => RiskLevel.None                         // 极端区无资源点
    };
}
```

> **地图生成层的保证**（3.2.1 已落地）：农田在中心区/资源区内侧（低风险），矿山在资源区外侧（高风险）。建造系统的城墙保护圈是动态的（玩家可扩张），但**初始资源分布**由地图生成保证合理。

## 五、与波次系统对接

波次系统⬜ 从地图生成读两个关键数据：**裂隙位置**（出怪起点）和**主城位置**（寻路终点）。

### 5.1 裂隙作为出怪点

```csharp
// 波次系统：晚上刷怪（订阅现有 TimePhaseChangedEvent）
public class WaveManager : Singleton<WaveManager>, ISaveable
{
    private void OnTimePhaseChanged(TimePhaseChangedEvent evt)
    {
        if (evt.NewPhase != TimePhase.Night) return;

        // 读当前活跃地图的所有裂隙
        var map = WorldManager.Instance.ActiveMap;
        foreach (var region in map.regions)
        {
            if (region.riftCellX < 0) continue;  // 无裂隙

            // 查波次系统自存的"裂隙是否已被消灭"
            if (_destroyedRifts.Contains(GetRiftId(map.mapId, region.regionIndex)))
                continue;  // 裂隙被玩家消灭了，不出怪

            // 在裂隙位置刷怪
            int cellX = region.cellStartX + region.riftCellX;
            Vector2 spawnPos = GridSystem.Instance.CoordToWorld(new GridCoord(cellX, 0));
            SpawnWave(spawnPos, GetCurrentWaveConfig());
        }
    }
}
```

> **关键**：`region.riftCellX` 是生成时定的位置（只读），"裂隙是否消灭"是运行时状态（波次系统自存）。位置不变，只是被消灭后不再出怪。

### 5.2 主城作为寻路终点

敌人 AI 寻路到主城，需要主城的世界坐标：

```csharp
// 战斗系统/敌人 AI：获取主城世界位置（寻路终点）
public Vector2 GetCastlePosition()
{
    var map = WorldManager.Instance.ActiveMap;
    int M = map.regions.Count;
    var (a, b) = MapGenRules.GetCastleRegionIndices(M);
    // 主城跨两个大区块，取中点
    int centerCellX = (map.regions[a].cellStartX + map.regions[b].cellStartX
                       + map.regions[b].cellCount) / 2;
    return GridSystem.Instance.CoordToWorld(new GridCoord(centerCellX, 0));
}
```

### 5.3 难度因子 → 怪物强度（与世界系统联动）

波次系统的怪物强度读 `DifficultyManager.CurrentFactor`（已实现）：

```csharp
// 波次系统：怪物属性 × 难度系数
WaveConfig GetCurrentWaveConfig()
{
    float factor = DifficultyManager.Instance.CurrentFactor;  // 现有 API
    return new WaveConfig
    {
        enemyHp   = baseEnemyHp * factor,
        enemyCount = Mathf.RoundToInt(baseCount * factor),
        // ...
    };
}
```

> 难度系数随季节线性增长（2.2 设计：初始 3，每季 +0.25，每年 +1.0），影响怪物强度。但**不影响已生成的资源点**——资源密度/等级在生成时就定了（生成时读当时的 difficulty 一次性算死）。

## 六、与资源经济系统对接

资源经济系统⬜ 持有 Building 运行时实例（树/矿洞/农田）的产出状态，对接四资源（金/石/木/粮）流回君主。

### 6.1 产出 → 君主资源（EventBus）

```csharp
// 资源经济系统：Building 产出时发布事件（复用现有 RulerResourceChangedEvent）
public class ResourceProducer : Building  // 持续性资源
{
    public ResourceGrade grade;     // 从 BuildingPlaceholder 灌入
    public ResourceType product;    // Tree→Wood, Mine→Stone, Farmland→Food

    void ProduceTick()
    {
        if (state != BuildingState.Normal) return;  // 损坏/修复中不产出
        int amount = Mathf.RoundToInt(baseProduce * GradeMultiplier(grade));
        RulerController.Instance.AddResource(MapToRulerResource(product), amount);
        // AddResource 内部会发布 RulerResourceChangedEvent
    }
}

// 一次性资源
public class ResourcePickup : Building
{
    void OnCollected()
    {
        RulerController.Instance.AddResource(...);
        BuildingRegistry.Instance.Unregister(this);
        Destroy(gameObject);  // 用完消失
    }
}
```

> `ResourceType`（Tree/Mine/Farmland，地图生成层）与 `RulerResource`（Gold/Stone/Wood/Food，1.3 EventBus 枚举）的映射：
>
> | BuildingType | 产出 RulerResource |
> |---|---|
> | Tree / WoodPile | Wood |
> | Mine / StonePile / OreVein | Stone |
> | Farmland | Food |
> | 市场/码头/税收（未来） | Gold |

### 6.2 资源点损坏/修复（运行时状态自存）

## 八、与存档系统对接（ISaveable）

存档系统✅ 已实现 ISaveable 架构。地图生成的存档策略：**seed 复现 + 各系统自存运行时状态**。

### 8.1 WorldManager 的存档（已设计，见 3.2 第 7.6 节）

```csharp
// WorldSaveData（version=2）
public class WorldSaveData
{
    public int worldSeed;          // 存 → 读档复现整个世界
    public int worldSize;          // 存
    public int difficulty;         // 存
    public int activeMapId;        // 存 → 读档切到存档时的地图
    public string maps;            // 只存 meta（mapId/seed/bigTerrain/isConquered），不存地形
    public string conqueredMapIds; // 存 → 已征服的敌方王国
}
```

> **不存的内容**：`Region.terrain`、`Region.resources`（BuildingPlaceholder）、`Region.riftCellX`——全部靠 worldSeed/mapSeed 确定性复现。存档体积可控（中地图约 1-2KB meta）。

### 8.2 各系统运行时状态各自 ISaveable

| 系统 | 存什么 | SaveId | LoadPhase |
|------|--------|--------|----------|
| WorldManager | worldSeed/activeMapId/conqueredMapIds | "WorldManager" | Global |
| 建造系统⬜ | BuildingRegistry（玩家建造的位置/类型/HP） | "BuildingSystem" | Scene |
| 资源经济⬜ | Building 实例的 hp/state/库存 | "ResourceEconomy" | Scene |
| 波次系统⬜ | 裂隙消灭标记/波次进度 | "WaveSystem" | Global |
| RulerController | 四资源数值 | "RulerController" | Scene（现有） |

> **读档恢复顺序**（关键）：
> 1. Global 阶段：WorldManager.LoadState → GenerateWorld(worldSeed) 复现 MapData → 切到 activeMapId
> 2. Scene 阶段：BuildingFactory.InstantiateFromMap（占位转实例）→ 各 Building 系统 LoadState 覆盖运行时状态
> 3. Scene 阶段：RulerController.LoadState 恢复四资源
>
> 若先 LoadState 再 InstantiateFromMap，会找不到 Building 实例（实例还没创建）——所以 Building 系统的 LoadState 必须在 Factory 实例化之后。

### 8.3 完整快照存档（可选，未来）

3.2.1 第 6.5 节定义的 `MapDebugData` JSON 可作为**完整快照存档**（当玩家修改了地图，如拆了资源点、消灭了裂隙，想保留修改时）。但当前设计倾向"seed 复现 + 运行时状态分离"，完整快照留待建造系统做好后再定。

### 10.2 Building 作为 IDamageable

战斗系统的伤害管线（3.0 第 2 模块）定义 `IDamageable`，Building 实例实现它：

```csharp
public abstract class Building : MonoBehaviour, IDamageable
{
    public int hp;
    public BuildingState state;
    public void TakeDamage(int damage, DamageType type)
    {
        hp -= damage;
        if (hp <= 0) OnDestroyed();
        EventBus.Publish(new BuildingDestroyedEvent(this));  // 规划中事件
    }
    protected virtual void OnDestroyed()
    {
        state = BuildingState.Damaged;  // 资源点损坏（3.2.1 第6.9节），不消失
        // 玩家建造的建筑被摧毁则 Destroy
    }
}
```

> **资源点 vs 玩家建造的区别**：资源点（ResourceProducer）被破坏进入 `Damaged` 状态（停产，可修复，不消失）；玩家建造（城墙/箭塔）被摧毁则 `Destroy`。这是 3.2.1 第 6.9 节"平衡失落感"设计的落地。
