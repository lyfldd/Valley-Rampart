## 一、老系统与新系统的衔接

### 1.1 现状（1D 无寻路）

1D 移动 = 直线走 + 撞墙即停（`UnitController.MoveTowards`），无寻路。2D 后彻底失效（会被城墙/水域/建筑卡死）。

### 1.2 衔接总图

```
老链路：NPCBrain/任务 → MoveTowards(目标) → 直线走 → 撞墙停
新链路：NPCBrain/任务 → PathRequester → PathfindingService(微格 A*/流场/成本场)
                          → PathResult → PathFollower(2_3) → 逐路径点 MoveTowards
                          → 遇动态阻挡/路径失效 → 重新请求
```

**关键**：`MoveTowards` 保留（2_3），寻路只算点，跟随只喂点，移动规则零重写。

### 1.3 阶段拆分（2026-08-13 审计决策）

| 子集 | 内容 | 阶段 |
|------|------|------|
| **P0a 最小 A\*** | 微格 8 向 A\* + BinaryHeap + FindPathImmediate + RequestPath 单队列 | **阶段 0**（提前，支撑 2_3"绕障碍 A→B"验收） |
| P0b 服务化 | 票据制队列、分帧预算、取消、失效重寻冷却 | 阶段 0 尾 |
| P1 | 流场 + 成本场 + IsReachable + 动态障碍响应 | 阶段 1 |

## 五、要开发的新系统（详细设计）

### 5.1 程序集分层

```
Pathfinding.Core/（新 asmdef，纯 C#，零 UnityEngine —— sim 共用）
├─ IPathGrid（微格契约，doc 1）
├─ AStarSolver        // 微格 A* 单请求
├─ FlowFieldBuilder   // 流场构建（积分场+方向场）
├─ CostFieldBuilder   // 成本场（威胁/安全 → 微格成本）
├─ PathTypes          // PathResult/PathStatus/PathRequest
├─ GridMathCore       // 格单位距离（doc 1 §1.6 纯 C# 实现，与 2_5 GridMath 同源）
└─ BinaryHeap         // 开放列表（确定性平局裁决）

Systems/Pathfinding/（Unity 侧）
├─ PathfindingService : Singleton   // 请求队列/分帧/流场/成本场注册表
├─ PathFollower : MonoBehaviour     // 2_3 的跟随组件
├─ PathfindingDebugDrawer           // Gizmos
└─ Data/PathfindingConfig (SO)
```

### 5.2 核心类型

```csharp
public enum PathStatus { Pending, Ready, Partial, Unreachable, Cancelled }

public sealed class PathResult
{
    public PathStatus status;
    public GridCoord[] waypoints;   // 微格序列（池化）
    public int version;             // 失效检测
    public bool reachedExactGoal;
}

public struct PathTicket { public int id; public byte priority; }
```

### 5.3 成本场（AI 看见机制，F8，P1）

**大脑把判断转成微格成本惩罚，喂给寻路核**：
```
成本场 CostField：每微格一个 float cost
  威胁带（敌人附近微格）→ cost 提高（绕开）
  **守卫区域（受守卫保护的高价值点附近，D86）→ cost 降低（吸引）**；编队位 → cost 降低
  地形代价（Plain=1.0/Hills=1.5...）
寻路 = A*/流场在 cost 场上搜索（代价= 地形×成本场）
```

- **LOD 联动切换规则（审计定细）**：活跃带内（2_4 Active/SemiActive 中区块）= 细粒度成本场（逐微格）；休眠区 = 纯目标搜索（成本场不参与，等价 cost=1）；切换以中区块为单位整块生效，不做半细半粗
- 成本权重**先 SO 手配，训练后置**（2_9 才入训）
- 确定性：成本场合成顺序 Unity/sim 一致
- **守卫区域来源**：2_8 守卫部署系统（IsGuarded，D90/D116）输入守卫覆盖区 → 成本场低点

**成本场合成公式（D250，2026-08-14 终审定稿）**：
```
costField(cell) = clamp(1.0 + threatWeight×threatLevel(cell) - safetyWeight×safetyLevel(cell) - formationWeight×formationLevel(cell), 0.1, 10.0)
```
- threatLevel/safetyLevel/formationLevel 均归一化 [0,1]（威胁带/守卫区域/编队位的覆盖强度）
- 权重占位：threatWeight=2.0 / safetyWeight=0.5 / formationWeight=0.8（CostBias SO，训练后置）
- **寻路代价 = terrainCost × costField**（A* 与流场同源）
- 下限 0.1 防负成本环路；上限 10 防过度排斥致不可达
- 按 faction 维护独立成本场（玩家/怪物各一份）；**守卫区域对称翻转：玩家场=低点（吸引），怪物场=威胁高点（驱避）**

### 5.4 PathfindingService API

| API | 说明 | 阶段 |
|-----|------|:---:|
| `PathResult FindPathImmediate(from, to)` | 同步（调试/sim/阶段 0 冒烟） | P0a |
| `PathTicket RequestPath(PathRequest, Action<PathResult>)` | 异步主入口 | P0b |
| `void Cancel(ticket)` / `CancelAll(requesterId)` | 取消 | P0b |
| `bool IsReachable(from, to)` | 连通性查询 | P1 |
| `CostFieldHandle RegisterCostField(Faction)` | 注册成本场 | P1 |
| `void UpdateCostField(CostFieldHandle, RectInt rect, delta)` | 增量更新 | P1 |
| `FlowFieldHandle RegisterFlowGoal(goal, faction)` | 流场目标（战略级） | P1 |

**守卫区域数据接口（D265，2026-08-14 终审修订）**：2_8 GuardDeploymentSystem 提供 `GetGuardRegions() -> IReadOnlyList<GuardRegion>`（GuardRegion 含 RectInt+faction），本篇订阅 GuardRegionChangedEvent 增量更新成本场（点查询 IsGuarded(pos) 由 2_8 直接供 2_7 使用）。

### 5.5 微格 A* 要点

- 邻居 8 向，顺序固定 E/NE/N/NW/W/SW/S/SE
- 代价 = `terrainCost × costField`（斜走 √2，格单位，doc 1 §1.6）
- 启发 = Octile × 最小代价（可采纳）
- 平局 `f 相同 → 索引小优先`（确定性）
- 早停/展开上限截断（Partial）/不可达最近点

### 5.6 流场（P1）与目标聚合策略（审计定细）

- 积分场 + 方向场（微格）；增量修补（dirtyRect 局部重积）；共享 key = (goal, faction, overlayId)
- **流场只给战略目标（D85）**：**高价值点（矿洞/满仓仓库/营地）+ 撤退点/集结点**（数量有限，≤8 天然成立；计数规则=按 (faction, 目标类型) 分组计数，各组独立 ≤8（多阵营多目标共用总池），2026-08-14 终审修订）；不再默认主城
- **个体 A\* 给散点目标**：资源采集/任务点/游荡；距离 >64 格先 IsReachable 预检，失败走流场到最近战略点再局部 A\*
- **敌潮默认流场（goal=当前高价值目标，价值驱使 D56/D94）**，同目标 200 单位寻路请求=0（纯采样）
- **群体移动 = 自有阵型算法 + 流场优化结合（D89）**：编队移动走流场到战略目标 + 编队内保持阵型（2_8 §5.2 详讨）；流场与阵型槽位可走校验协同，避免 8 上限挤兑
- **流场积分消费成本场（D251，2026-08-14 终审修订）**：积分场用 `terrainCost×costField`（与 A* 同源代价）；CostFieldBuilder.UpdateCostField 变更时标记相关流场 dirtyRect 触发增量重积——怪物走流场自动绕开守卫区域（与 2_14 §4.2 闭环）

### 5.7 PathFollower（2_3 细化）

- 朝当前微格路径点 MoveTowards
- 失效检测：下一路径点不可走 → 冷却后重寻
- 连续 3 次失败 → `PathFailedEvent`（AI 换目标）
- LOD 分级：低档 Think 决策降频，寻路移动仍每帧（D79，2026-08-29 裁决修订 D414），不降采样/不跳格

## 六、确定性保障

1. Pathfinding.Core 禁 `using UnityEngine`，用 Vector2X/MathfX
2. 禁字典遍历序参与结果；禁 GetHashCode 排序
3. 浮点仅代价累加，顺序固定；√2 走常量
4. sim goldenReplay：固定种子 → 路径哈希一致

## 七、验收标准

1. **阶段 0（P0a）**：微格 A* 绕 U 型墙；FindPathImmediate 可用；2_3 冒烟通过
2. 微格 A* 对角寻路 ≤3 帧；200 并发不卡帧（P0b）
3. 封死 → Unreachable + 最近可达点
4. 破墙 → 受影响单位 ≤1s+1帧走上新路径
5. 流场：200 敌人同目标，寻路请求=0（纯采样）
6. **成本场：敌人附近微格成本高 → AI 绕开威胁（看见机制）**
7. 确定性：sim 1000 次混合请求路径哈希一致
8. 禁穿角：两墙对角夹缝不可斜穿
