## §〇 范围与红线（先读）

**资源 P0 交付**：AI 王国资源底座——经济诊断块真值（快照经济块占位→四件真值）+资源断裂三通道扩全资源（D531①：任一资源触发，严重度排序 粮→金→石→木）+派工活权重（类型死表保留+资源偏向）+MustHave 断链检测。心跳四成员（粮/金/石/木）统一断路器。

**红线（违反即 FAIL）**：
1. **AI.Core 零直改**——诊断块 sim 镜像走批C 跨仓协同（sim-sync 纪律），不碰 `Assets/_Game/Systems/AI.Core/` 既有文件；
2. **零改动声明（2_23 §六）**：效用四因子/焦点防抖/常设底线机制/2_12 资源链/训练系统结构/玩家建造入口零触碰；
3. **TaskScheduler 死表保留**：类型优先级 S 级（修复保命）不动——活权重是**乘在死表之上的偏向层**，不是替换；
4. **派工活权重住 TaskScheduler（Unity 侧执行层）不进 AI.Core**（D525 打分器同型注记）；
5. **确定性红线**：同 seed 同诊断信号→同排序（活权重是纯函数非随机）；三通道判据顺序固定；
6. **⑤行动号不变**：⑤屯粮执行层改三通道分诊（语义归位），不是新增行动；
7. **不设第五底线级**：断链走诊断层注入（MustHave 缺失→对应建造行动 NeedScore 拉满），不进常设底线序列；
8. **单通道响应不叠加**：每次断裂只对最大根因下药。

## §六 执行顺序与门禁

```
批A（经济诊断块真值+SO）──→ 批B（派工活权重）──→ 批C（⑤三通道分诊+断链注入+冒烟收口）
   ↑ 批序依据=依赖链：B 通道响应（⑤分诊）需要活权重在场，一次到位零占位
```

- **每批门禁**：编译 0 警 0 错；该批行为级探针过（正/负双侧——路由类改动必含行为探针）；既有冒烟零退化；交付前 git diff HEAD 全量+逐项在场性 grep 双自查；批 commit 随批策划端验收。
- **总门禁（资源 P0 收口）**：Smoke_2_23RP0 ALL PASS（三通道正负对照+偏向+自愈+确定性）；同 seed 逐字节一致；15_账本 S-B1 登记；既有冒烟零退化。
- **执行流程**：每批开工回执→实施→交付报告→策划端验收。
