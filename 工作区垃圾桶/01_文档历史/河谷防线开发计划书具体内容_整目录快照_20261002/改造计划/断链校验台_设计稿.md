# 断链校验台 · 设计稿（ChainAudit）

> 日期：2026-09-12
> 状态：设计定稿（用户逐点确认 · 待批准实施）
> 决策依据：**D691**（0.6 §二百二十）
> 立项由来：`D690`（HH.235 交付复议）独立复核抓出 `DZ-148`——㉗ 采集行动**定义齐全、逻辑自洽、跑局零触发**（入口结构性不可达），而现有 `LifecycleAudit`（R1 事件/R2 存档）**结构上扫不到**这类断链。
> 用户定案（2026-09-12）：**治本机制优先** · 四维覆盖（资源供给链／AI 决策可达性／六阶段／文档↔代码漂移）· **代码化自动校验器** · 载体=**新建校验台**（方案B）· 声明面=**双源对拍** · 可达层=**扩 smoke 探针矩阵** · 门禁=**分级** · 框架=**重构入共用框架** · R5=**只做机器可判子集** · 运行=**菜单手动＋验收强制**。
> 归属：本稿 = 策划端单写者；实施走 `so-data-driven` + `unity-mcp-first`（Editor 工具）。

## 一、问题陈述：为什么现有设施拦不住

### 1.1 断链的统一模型 = 「三角」缺角

项目迄今全部断链，归一到一句话：

```
        声明（设计说该有）
        ／              ＼
   实现（代码里有）——  观测（跑局真走到）
```

| 缺角 | 表现 | 实证案例 |
|---|---|---|
| **声明⊥实现** | 文档说 X，代码是 Y | `DZ-110` 措辞、`_目录` 漂移、`D637` 登记表 39→40 def |
| **实现⊥观测** | 代码有、跑局永不走 | **`DZ-148`（㉗ `need` 恒 0）** · `DZ-072`（水晶/火油零产出）· P8 家族 |
| **观测⊥声明** | 代码有力、设计没这需求 | 死资产（`farmland`/`rift`） |

### 1.2 现有设施覆盖（实读）

| 设施 | 覆盖 | 形态 | 盲区 |
|---|---|---|---|
| `Assets/Editor/Lifecycle/LifecycleAudit.cs` | R1 事件双向对拍／R2 存档覆盖对拍 | Editor-only 反射校验器 | **只证"实现存在"，不含供给链与可达性** |
| `改造计划/生命周期登记表.md` | 建筑 40 def × 双主体 × 六阶段＋事件 54＋单例 53 | **人工**矩阵（活文档） | 与代码无**自动**对拍 ⇒ 漂移靠人偶遇 |
| 断裂模式 **P1~P8** | P8＝触发方缺席等分类学 | 人工判据 | 无自动扫描 |
| 缺陷台账 `DZ-xxx` | 存量断链登记 | 活台账 | 登记不是检测 |

### 1.3 核心判断（本设计的立论）

> **可达性只能由行为层证明。** 静态永远证不了"永不选中"——因为那依赖运行时状态（国库值、断供触发、评分权重）。
> `DZ-148` 的 ㉗ 正是：**定义齐全、评分分支在位、执行分支在位，但触发条件与适用场景互斥 ⇒ 跑局零触发**。
> ⇒ **单层静态必然漏**；治本形态 = **静态层 ＋ 行为层**双层校验。

## 二、总体架构（方案 B：新建校验台）

```
Assets/Editor/ChainAudit/                          ← 新建（Editor-only · 零运行时开销）
├── ChainAuditCore.cs        框架层：违规模型 / 豁免表 / 幂等报告 / 扫描域 / 分级判定
├── ChainAuditMenu.cs        菜单聚合入口（Valley/审计/ChainAudit）
├── ChainAuditSpec.cs        声明面：能力清单（人工维护 + 半自动提取）
├── Validators/
│   ├── R3_SupplyChain.cs    资源供给链
│   ├── R4_ActionReach.cs    AI 行动声明可达
│   ├── R5_SixStage.cs       六阶段完整性（机器可判子集）
│   └── R6_DocDrift.cs       文档↔代码漂移 ＋双源对拍
└── Probes/
    └── ChainProbeFacade.cs  行为探针门面（挂 smoke 正门 → 能力观测矩阵）
```

**R 号从 R3 续**（R1/R2 已被 `LifecycleAudit` 占用）。

### 2.1 框架提取（用户定案：重构入共用框架）

把 `LifecycleAudit` 已验证的四件地基抽成 `ChainAuditCore`，`LifecycleAudit` 改造为**调用方**：

| 抽取件 | 来源 | 说明 |
|---|---|---|
| **违规模型** | `LifecycleAudit` 现有四面（1a/1b/1c/2a/2b） | 统一 `Violation{Kind, Severity, Anchor, Advice}` |
| **豁免表** | `ExemptEvents`/`ExemptSingletons`/`ExemptResetState` | 代码内静态清单；**D561 硬红线：变更须策划端确认** |
| **幂等报告** | `WriteReports`（稳定名＋时间戳副本） | `Logs/ChainAudit/chain_audit_report.txt`（无时间戳＝幂等基准） |
| **扫描域纪律** | 反射只扫 `Assembly-CSharp`／源码只扫 `Assets/_Game` | Editor 程序集不入扫描（防自噪） |

> **回归门（硬条款）**：重构后 `LifecycleAudit` 的 R1/R2 报告须**逐字节等于**重构前（同库重复运行），否则重构失败。这是保护既有资产的验收线。

## 三、四个校验器（判什么 / 能抓什么 / 边界）

### R3 资源供给链（静态）

- **扫描**：`ResourceType`（`GameEvents.cs:176`）的**供给点** ↔ **消费点**。
  - 供给：`ProducerComponent`（`outputResource`/`rate`）· `MineByproductComponent` · `Gather`/`OnGatherCompleted` · `StorageComponent.Transform` 产出侧
  - 消费：`costXxx` 字段 · `StorageComponent.Transform` 输入侧 · 训练/建造成本 · 建造消耗
- **判据**：`有消费 ∧ 供给==0 ⇒ 🔴`；`有供给 ∧ 消费==0 ⇒ 🟡`（蓄水）。
- **能抓**：`DZ-072`（水晶/火油/Ore **全游戏零产出**＝P8 反向首案）。
- **边界**：只判"有没有"，不判"够不够"（后者属调优）。

### R4 AI 行动声明可达（静态＋行为）

- **静态三层绑定**：每条 action（`UtilityActionConfig.asset` 26 条）必须有
  ① `NeedKind` 绑定（`UtilityScorer.cs:55`）
  ② `UtilityScorer` 评分分支
  ③ `KingdomBrain.ExecuteFocus` 执行分支
  —— 缺一 ⇒ **幽灵行动 🔴**。
- **静态"必要不充分条件"**：need 引用的 gap 是否**可能** >0、`Feasible` 的门是否**可能**满足（如 `DZ-135`：`costGold:50` vs 国库 `3~8` ⇒ 静态即可判"当前值域内恒不可行"）。
- **🔴 静态证不了**：「入口永不可达」（`DZ-148` 的 ㉗ 定义全齐、逻辑自洽、跑局零触发）⇒ **交 `ChainProbeFacade`**。
- **能抓**：`DZ-043`（行动池缺 Well/Blacksmith）、`DZ-135`（金门静态可判）、`DZ-148`（须行为层）。

### R5 六阶段完整性（静态·**只做机器可判子集**）

- 复用登记表六阶段定义，对每个 def 查**机器可判**锚点：
  - ① 生成入口存在性（至少一个 `生成` 列 ✅）
  - ② 存档 `ISaveable`（对应实体类是否实现）
  - ③ 注册注销**成对**（订阅↔退订 / Register↔Unregister / 创建↔回收）
- **语义面不自动化**（如"`gate` 的 `GateStateChangedEvent` 零订阅算不算断"）——机器判不了，留人工审计。
  > **理由（用户定案）**：语义面若交给校验器，需海量豁免表维护，**误报会淹没真信号**。
- **能抓**：生成入口缺失（P1 幽灵引用）、`DZ-074/075`（存档缺席）。

### R6 文档↔代码漂移 ＋ 双源对拍（静态）

- **双源对拍**（用户定案）：
  - **源A（实现面）** = 代码反射/源码/SO 自动提取
  - **源B（声明面）** = `生命周期登记表.md` / `美术资源接入映射表.md` / `ChainAuditSpec.cs`
  - **双向列报**：`A有B无` = **代码漏登**（新内容没登记）；`B有A无` = **登记表漂移**或实现缺失。
- **解析方式**：登记表为 Markdown 表格 ⇒ 正则提取 def 名行；**只比对名字集合**（不比语义），保证鲁棒。
- **能抓**：`D637` 登记表 39→40 def（曾人工抓过一次，本机制**自动**抓）、`DZ-110` 类措辞漂移的"键/名"面。

## 四、行为可达层：`ChainProbeFacade`（用户定案：扩 smoke 探针矩阵）

- **走正门**：`TestHarnessApi.EnterTestRun(cfg, speed?)`（`test-harness-first` 铁律1：禁裸跑）。
- **每个"声明能力"配一探针**：跑局中观测**是否被触发 ≥1 次**（被选中／产出>0／建成>0）。
- **产出「能力观测矩阵」**：

| 能力 | 被选中次数 | 产出>0 | 建成>0 | verdict |
|---|---|---|---|---|
| 行动㉗ 采集 | 0 | — | — | 🔴 入口不可达 |
| 行动③ 建产能 | 12 | — | 0 | 🔴 `feasible` 恒 False |
| 行动② 建仓库 | 8 | — | 4 | ✅ |

- **必配列**（`test-harness-first` §8.6 硬条款 · 缺列不得开跑）：
  - 〔**可判定最早日** ＋ **命中即停**〕
  - 〔**服务哪条验收句**〕
  - 〔**作用域**：全批 any-国 / 指定国〕
  - 〔**口径来源与排除项**（`L-35`/D670）〕
- **门禁**：探针矩阵的 verdict 回灌 R4 的"观测角" ⇒ 与静态报告合并 = **三角闭合判定**。

## 五、分级门禁（用户定案）

| 级 | 判据 | 处置 |
|---|---|---|
| 🔴 | 结构性断链（有消费零供给 / 幽灵行动 / def 缺失 / 生成入口缺失） | **硬拦**（报告判定="有违例" ⇒ 交付/验收不通过） |
| 🟡 | 语义可疑（蓄水 / 措辞漂移 / 未登记新内容） | 列报不拦 |
| **豁免** | 设计内例外 | 不计违例；**变更须策划端确认**（`D561` 硬红线） |

## 六、数据流与运行时机（用户定案：菜单手动＋验收强制）

```
改代码/SO → ChainAuditMenu.Run() → {R3,R4,R5,R6} → 合并违规 → 分级判定
          → 幂等报告 Logs/ChainAudit/chain_audit_report.txt
跑局（正门）→ ChainProbeFacade → 能力观测矩阵（补"观测"角）
          → 与静态报告合并 = 三角闭合判定
```

- **日常**：Editor 菜单 `Valley/审计/ChainAudit` 手动跑（同 `LifecycleAudit` 惯例）。
- **强制**：交付/验收时**必跑**（列入任务书验收句）。
- **后续可选**：`AssetPostprocessor` 编译后自动跑（**本批不做**，避免拖慢开发循环）。

## 七、与既有设施的关系（不重复建设）

| 既有 | 本设计关系 |
|---|---|
| `LifecycleAudit`（R1/R2） | **重构为调用 `ChainAuditCore`**；输出逐字节不变（回归门） |
| `生命周期登记表.md` | R6 双源对拍的**声明面源B**；不替代、不自动回写（防双源，`L-15`） |
| `断裂模式 P1~P8` | R3/R4/R5 的**判据来源**（把分类学代码化） |
| `test-harness-first` 正门 | `ChainProbeFacade` 的**入口**（禁裸跑） |
| `缺陷台账 DZ` | 校验器发现**新**违例 ⇒ 提策划端登记（校验器不直接写台账） |
| `sim-sync` | 若某校验器触 `AI.Core`，遵其同源义务（本批四校验器均不触） |

## 九、验收标准

1. **回归门**：重构后 `LifecycleAudit` R1/R2 报告逐字节不变。
2. **复现既有断链**：R3 抓 `DZ-072`、R4 抓 `DZ-043`、R6 抓 40 def、探针抓 `DZ-148`（四案复现）。
3. **双源对拍双向列报**：`A有B无`/`B有A无` 均能列。
4. **探针矩阵**：走正门、四列必填、能判"入口不可达"。
5. **分级门禁**：🔴硬拦／🟡列报／豁免不计，判定行正确。
6. **幂等**：同库重复运行报告逐字节一致。
7. **零生产代码改动**：Editor-only，编译 0 错。

## 十、风险与边界

| 风险 | 说明 | 缓解 |
|---|---|---|
| 重构破坏既有资产 | `LifecycleAudit` 已在用 | 回归门逐字节对拍（S1） |
| R5 语义误报 | 机器判语义必误 | **只做机器可判子集**（用户定案） |
| 双源漂移 | 校验器 + 登记表双写 | 校验器**只读不改**登记表；发现新违例提策划端 |
| 探针挂错判据 | 重蹈 `L-34` | 探针必填四列（§8.6 硬条款） |
| 报告膨胀 | 违例多致不可读 | 🔴/🟡 分级 + 豁免表抑噪 |
