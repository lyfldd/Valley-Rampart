## 一、判定口径

### 1.1 取值枚举（逐模块 API 逐个判定）

| 取值 | 含义 | 是否列缺陷 |
|---|---|---|
| **✅ 已对称** | 公开 API 已携带 `kingdomId`（或主体句柄），且**无玩家特权路径**（无参重载=语义中性） | 否（范本） |
| **🟡 内核已参数化 · 有玩家便捷重载（合规）** | 内核已 `kingdomId` 参数化；仅保留「玩家无参便捷重载」，其**语义 = 调 `0`**（不代表玩家特权） | 否（**合规**，见 1.2） |
| **🔴 缺主体参数** | 公开 API **完全无主体参数**，或内部硬编码 `Faction.PlayerCamp` / 桶 `0` / `RulerController.Instance` 而无 per-kingdom 出口 | **是** |
| **🔴 AI 侧无等价入口** | 玩家侧有下令入口，AI 侧**零等价入口**（轴B O-1） | **是** |
| **⚪ 不适用** | 该模块无王国主体语义（附理由） | 否 |

### 1.2 「无参重载=调 0 ⇒ 判 🟡 合规」声明

**本项目一致口径（对齐提案 §三 目标态第 1/5 条）：**
> **玩家无参便捷重载 ≠ 玩家特权路径。** 只要该无参重载的实现体**语义等价于「传 `0`」**（即 `Foo() => Foo(0)`），内核参数化已就位、AI 走同一内核通道，则判 **🟡 合规**，**不列缺陷**。
> 反例（判 🔴）：无参重载内部**不走内核**、另开一套玩家专属分支（如硬编码 `RulerController.Instance` 直通、桶 `0` 全局单值、`Faction.PlayerCamp` 前置守卫且**无** per-kingdom 对应口）。

**依据范例**：`WaterNetwork.cs:62 AddWater(float amount) => AddWater(amount, 0)`（无参=调 0）⇒ 🟡 合规；`WaterNetwork.cs:34 Stored` 为玩家桶只读便捷口，其 per-kingdom 对应口＝`GetStored(kid):48` ⇒ 🟡 合规。

### 1.3 轴B 断链四类（操作侧判定，对齐提案 §7.2）

| 类 | 定义 |
|---|---|
| **O-1 单端缺入口** | 一端有下令入口、另一端完全没有 |
| **O-2 意图缺失** | 底层有能力、派工侧有源，但决策核无「下发该类任务」的意图出口 |
| **O-3 越界直调** | 决策核跳过派工层直调「须工人到场」的执行 API（无劳动语义的建造/升级类＝已裁合规，不算 O-3） |
| **O-4 有意图无可达目标** | 意图成立、派工已发，但源不可达／无空闲工人／无仓可卸／工人中途死亡 ⇒ 运行期静默失败（违轴A §四「失败可见」） |
